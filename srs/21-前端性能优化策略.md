# 前端性能优化策略

## 状态

- 本文件是前端性能问题的定位方法、修复模式和验收门禁的固定入口。
- 只要出现“页面卡、输入卡、切换慢、拖动假死、滚动掉帧”等反馈，先按本文件执行，不允许只凭感觉调整样式。

## 参考技能

- `react19-concurrent-patterns`：本机已安装，覆盖 React 19 的 `useTransition`、`useDeferredValue`、`Suspense`、`use()`、Actions 和 `useOptimistic`。涉及并发能力或 React 19 API 取舍时必须优先参考。
- `build-web-apps:react-best-practices`：本机已安装，提供 Vercel 维护的 React/Next.js 性能规则，覆盖瀑布请求、包体积、客户端数据、重渲染、渲染和 JavaScript 性能。本项目是 Vite SPA，采用其中适用规则，跳过 Next.js/RSC 专属部分。
- 技能用于辅助定位和提出方案，最终结论仍以本文件要求的真实浏览器测量、生产构建对比和视觉验收为准。

## 定位流程

1. 先固定复现步骤、页面、数据量、视口和交互频率；确认是持续卡、首次进入卡，还是特定手势触发。
2. 必须同时对比 Vite 开发模式和生产构建。开发模式包含按需编译和 HMR，不能作为运行时性能结论。
3. 生产验证使用 `npm run build` 后启动 `npm run preview -- --host 127.0.0.1 --port 4173 --strictPort`，并确认 `/api/v1/health` 可访问。
4. 用本机 Edge 采集真实浏览器数据；采集项至少包含 `requestAnimationFrame` 帧间隔、`PerformanceObserver(longtask)`、CDP `ScriptDuration`、`TaskDuration`、`LayoutDuration`、`RecalcStyleDuration`。截图视觉验收由视觉模型直接完成，Playwright 负责截图与性能采集，不承担文本验收。
5. 使用 `Emulation.setCPUThrottlingRate` 模拟弱机，常规巡检用 4x；验证交互至少包含滚动、hover、连续输入和页面切换。
6. 逐项关闭可疑效果做对比：`backdrop-filter`、大面积渐变、无限动画、box-shadow、filter。只有关闭后数据显著改善，才能把样式定为卡点。
7. 页面切换问题要记录生产/开发的首屏和 lazy 路由耗时；不要把首次 Vite 编译误判为业务渲染卡点。
8. 开发模式 DevTools 卡顿时必须检查依赖预打包代码量与内联 Source Map 量；图标、Radix 等聚合入口不得在开发模式加载全家桶。Lucide 图标在 Vite 预转换阶段改为具体图标模块，Radix 组件必须从官方子路径导入，避免 Edge 解析数 MB Source Map 导致控制台卡顿。

## 修复模式

### 长列表与行内编辑

- 行组件必须 `memo`；传入行组件的数据优先使用服务端原始行 + 当前编辑补丁，不要每次输入重建整批合并对象。
- 回调必须稳定：事件处理使用 `useCallback`；需要读取最新数据时通过 ref，不要让行组件 props 随父组件输入变化。
- React 默认浅比较仍可能被新对象、新数组或新回调击穿。若确认输出字段未变，应使用只比较渲染输出字段的行级比较器。
- 编辑补丁只在目标行生效；保存成功后清理本地补丁，保存失败后回滚显示，不得让用户误以为已保存。
- 如果行数可能超过 100 或输入仍有长任务，再评估虚拟滚动；不要在数据量未证明时提前引入复杂度。

### 浏览器拖拽与选择

- 先区分正常文本选择、原生 drag-copy 拖影和文件拖入。Edge/Chromium 对选中静态文字继续拖动会启动原生 drag-copy，复杂页面可能被放大成假死。
- 静态文字的拖影用应用根部捕获阶段拦截 `dragstart`；输入框、文本域、contenteditable 和显式可拖拽元素不受影响。
- 复制交互保留 `Ctrl+C`；文件投放区保留文件拖入，不得全局禁用 dragover/drop。

### 样式与动效

- 大面积渐变、backdrop-filter、多层阴影和无限动画必须先通过开关对比证明代价，再优化。
- 动画只允许 transform、opacity、filter、box-shadow、color、background-color、border-color 等约定属性；继续尊重 reduced-motion。
- sticky + backdrop-filter、整页 radial-gradient 和逐卡片光晕要重点检查滚动/选择重绘；不能为了视觉直接删除，先用数据证明并保留层次。

### 路由与数据

- lazy 路由首跳慢时，先记录生产/开发耗时和长任务，再考虑预加载高频路由；不要为了首跳把所有页面提前打包。
- TanStack Query 失败回滚、成功刷新和本地补丁清理必须成对出现，避免刷新后又用旧 patch 覆盖服务端数据。
- 批量上传要保留真实字节进度；性能修复不得改变上传、落盘、入库、刷新反馈链路。

## 验收门禁

1. 生产构建下，使用 4x CPU 降速和代表性数据量完成交互；连续输入、滚动、hover 期间不得出现持续超过 100ms 的长任务。
2. 修复前后必须给出同口径数据：长任务数量、最大长任务耗时、`ScriptDuration`、`TaskDuration`、`LayoutDuration`、`RecalcStyleDuration`。
3. 性能修复不能破坏功能：对应页面必须完成 `npm run check`，涉及接口的用真实 HTTP 验证，涉及表格编辑的验证输入、失焦保存、失败回滚和刷新回显。
4. 临时压测数据必须指定测试项目并在验证后清零；禁止污染正式项目数据。
5. 若方案改变了默认约定，必须回写本文件；只影响单次问题且不可复用的过程数据不写入 SRS。

## 本次基线示例

- 数据：80 行待确认工作对象；Edge + 4x CPU；连续输入 14 个中文字符。
- 优化前：14 个长任务，单个 348-427ms，`ScriptDuration` 约 5.265 秒。
- 优化后：0 个长任务，`ScriptDuration` 约 0.173 秒。
- 方法：行级 `memo` + 稳定回调 + 行级渲染输出比较器；未变更行不重渲染。

## 2026-09-22 增量优化

- 需求树按来源一次分组，完整度统计和树节点构建改为单次遍历。
- 需求搜索使用 `useDeferredValue`，避免每次输入都同步阻塞目录渲染。
- 接收文件摘要合并为单次遍历，减少同一批资产上的重复 `filter`。
- 首页项目关键词筛选使用 `useDeferredValue`，保留输入即时响应。

## 2026-09-23 增量优化

- 候选需求行渲染函数改用 `useCallback` 稳定身份，删除未使用的行级 `onSelect` prop，减少 `react-arborist` 行树的无意义更新。
- 树动画请求删除已废弃的 `settle-close` 分支；展开仍使用 React 提交后的 GSAP Flip，收缩直接在同一动画回调中完成 close 与 Flip，避免额外状态提交。
- 候选需求搜索继续使用 `useDeferredValue`，树结构、来源索引和过滤结果保持 `useMemo`，本轮不额外引入 `startTransition`，避免把本地小列表更新复杂化。
