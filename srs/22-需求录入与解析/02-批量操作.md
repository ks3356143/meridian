# 批量操作

> 返回 [需求录入与解析](../22-需求录入与解析.md)

## 批量修改确认需求

1. 左侧目录工具栏提供"批量编辑"入口，点击进入批量选择模式：需求行显示 Checkbox，来源行显示三态聚合框（全选/部分/未选）；再次点击退出并清空勾选。
2. 批量选择支持跨来源版本：不同来源下的需求可同时勾选，唯一性校验按各需求所属来源版本分别执行。
3. 勾选后树面板底部出现浮动操作栏：显示"已选 N 项"（`role=status` 播报上下文）、"批量修改"按钮和"清除选择"按钮；1101px 以上操作栏随树滚动常驻，1100px 以下改为树内容后的静态尾部，不遮挡最后一行。紧凑面板内保持单行，按钮可见文案可用"修改 / 删除 / 清除"并通过 `aria-label` 保留完整语义。进入批量模式时，操作栏使用 240-280ms 的上浮淡入，按钮组作为整体跟随出现；禁用按钮不得因入场动画被误读为可点击。复选框使用 160-200ms 的淡入缩放。动画只操作 transform 与 opacity，`prefers-reduced-motion` 下直接呈现，不阻塞交互。
4. 批量修改使用单个 Dialog 双分区，可只用其一，也可同时生效：修改属性分区提供主类型单选与副类型多选，默认"不修改"，仅设置的字段生效；查找替换分区提供查找词（必填）与替换词（可空，表示删除匹配片段），通过 Checkbox 选择应用字段（名称/标识），至少勾选一个；仅支持精确子串匹配，大小写敏感。
5. 批量修改弹窗使用 `noValidate` 自定义校验：启用查找替换时查找词必填，替换词可空；应用字段至少勾选一个；副类型与需求新主类型冲突时在字段旁显示错误。仅修改属性而未启用查找替换时，不强制填写查找词。
6. Dialog 预览先行：按当前输入实时计算每条需求的新旧值 diff（旧片段删除线、新片段高亮），无变化行折叠；前端预检同版本有效需求名称与标识冲突（含本次批量组内互相冲突），冲突行标红并禁用提交。
7. 提交按钮文案显示影响数量（如"应用到 12 条需求"）；两个分区都未填写或存在冲突时禁用。提交中按钮 loading，弹窗不可关闭。
8. 后端在事务内逐条更新并写入 update 审计事件；服务端严格执行同版本候选/正式需求的名称与标识唯一性校验，冲突时返回 409 与冲突明细，不落库。
9. 完成后 sonner 提示"已更新 N 条需求"，树与详情自动刷新，退出批量模式并清空选择。

## 批量删除确认需求

1. 批量选择模式下，浮动操作栏提供 destructive 的"批量删除"入口，显示当前选中数量；未选择需求时禁用。
2. 批量删除使用 Radix AlertDialog 二次确认，展示待删除需求的数量、章节号和名称摘要，明确"从已确认基线移除并保留审计记录"，不执行物理删除。
3. 删除原因可选，最多 500 字；确认框提交中禁止关闭和重复提交，失败时保留原因并展示错误。
4. 确认后复用既有需求状态接口的 `exclude` 动作，将全部选中需求在一个事务中从 `official` 迁移到 `excluded`，并逐条写入 `exclude` 审计事件。
5. 成功后 sonner 提示"已删除 N 条确认需求"，退出批量模式、清空选择并刷新树、统计和已删除需求管理；单条删除与批量删除共享同一状态语义。
