# 需求树组件（实现契约、性能口径与坑清单）

> 返回 [工作台视觉与交互](./01-布局与视觉.md)

本页是需求树（已确认需求树 / 待确认需求树）的实现契约、性能口径与**踩过的坑**的单一入口。两棵树行为必须一致；改树之前先读本页。

## 一、组成与技术栈

| 关注点 | 落点 |
| --- | --- |
| 树状态、键盘、虚拟滚动 | `react-arborist` 3.16 + `react-window` 1.8.11（`rowHeight={30}`、`openByDefault`） |
| 折叠/展开动效、结构变化过渡、选中联动滚动 | `useRequirementTreeMotion`（两棵树共用） |
| 行视觉、层级导线、徽章、空态 | `requirements-tree.module.css`（两棵树共用） |
| 行渲染 | 已确认树 `requirements-tree.tsx`、待确认树 `requirements-candidate-tree.tsx` |
| 动效引擎 | GSAP（只 tween 一个 `progress` 代理，不直接 tween DOM 属性） |

## 二、组件契约（改代码前必须遵守）

1. **DOM 钩子**：行容器 `[role="treeitem"]`（react-window 写内联 `top` 与 `height:30px`）；行内容 `[data-tree-row="true"]`；节点 id 在 `data-node-id`、类型在 `data-node-type`；层级取 `[role="treeitem"]` 的 `aria-level`；动画期额外挂 `data-motion-block` / `data-motion-follow`。
2. **CSS 变量**：`--tree-row-h`（行高）、`--tree-row-top`（行相对子树顶部偏移，逐行裁剪用）、`--tree-motion-line`（裁剪线）、`--tree-motion-shift`（后续行位移）、`--tree-scrollbar-width`（滚动条宽度补偿）。
3. **交互约定**：点 chevron 只折叠/展开、不选中行（shell 用 `onClickCapture` 拦截）；点需求行才选中；树内点击已可见行不二次滚动，外部选中（右侧表格、撤回跳转）才 `setSelection + openParents + scrollTo(id,"center")`；方向键交给 react-arborist。
4. **`prefers-reduced-motion`**：全部直接切换，不做动画、不做扩窗。
5. **两棵树必须同时改**：动效与 CSS 共用；行渲染各自实现，改行结构时两边都改并分别验证。

## 三、折叠/展开算法（当前实现）

1. **只做高度裁剪 + 后续行同步位移**：折叠时保持树打开，对子树逐行写 `--tree-row-top` 并 `clip-path: inset(0 0 <隐藏量> 0)` 从底部向上擦除，后续行整体 `translateY(--tree-motion-shift)` 上移；展开反向（裁剪线自上而下，后续行从展开前的位置回到原位）。
2. **裁剪线与位移共用同一个 `travel`**（GSAP 推进 `progress` 代理，逐帧只写 2 个 CSS 变量 + 内层高度）。方向写反 = 重影。
3. **子树比视口高时按可视比例重排时间轴**：视口外位移只占固定一小段时间，避免"先静止一大半时长再飞快擦掉"。
4. **分批扩窗**：首次只挂 `FIRST_BOOST_ROWS=24` 行保证点击即起动画，其余按 `BOOST_CHUNKS=2` 在动画期间补齐；每次扩窗后用幂等 `applyMotionMarks` 把标记补给新挂载的行。
5. **扩窗窗口保留 1.5s** 再回缩：连续切换同一节点不反复挂载/卸载同一批行。
6. **子树超过 `MAX_ANIMATED_BLOCK_ROWS=200` 行直接切换**，不播动画。

## 四、性能口径与验证方法

1. **指标**：`PerformanceObserver` 的 `long-animation-frame`（`duration` / `blockingDuration` / `scripts[].forcedStyleAndLayoutDuration`）+ 逐帧 `requestAnimationFrame` 间隔；视觉结论必须看截图。
2. **必须做 A/B**：怀疑页面其它部分拖累树时，先把它 `display:none` 再测（实测：隐藏未虚拟化的候选表后，树滚动 77ms/帧 → 17ms/帧）。
3. **大树压测夹具**：拦截 `GET /api/v1/projects/{id}/requirements`，在真实响应上追加合成章节与需求（只读夹具，禁止改真实数据），可造 400+ 行树。
4. **基线（生产构建 2026-09-29，425 行夹具、隐藏表格后）**：首次折叠 53 行子树起动画 37ms（长任务 63ms/阻塞 13ms + 55ms/阻塞 3ms）；再次展开起动画 39ms（51ms/阻塞 0ms）；窗口已热折叠起动画 15ms（52ms/阻塞 2ms）；小叶子无长任务；全折叠走无动画分支无长任务。**结论：JS 阻塞 ≤13ms，剩余长任务来自样式/布局（forced）。**

## 五、坑清单（现象 → 原因 → 规避）

1. **子树占满视口时没有动画** → 元素引用 FLIP：子树行立即移除、只对剩余行做位移，子树占满视口且其后没有已渲染行时没有可动画对象 → 改"高度裁剪 + 后续行同步位移"。
2. **展开出现重影** → 展开方向后续行位移写反，和正在展开的子树对向交叉 → 裁剪线与位移共用同一个 `travel`。
3. **像"整棵树消失又出现"** → 早期对整树 `autoAlpha` 渐隐渐显 → 折叠/展开不做透明度过渡。
4. **滚动条动画期消失、结束才回来** → 动画期把 `overflow: auto` 切成 `hidden` → 动画期不要改 `overflow`。
5. **短树展开时滚动条中途冒出、行宽被挤、徽章跳** → `scrollbar-gutter` 只在"动画前有滚动条"时挂 → 改为"动画前有滚动条 **或** 动画后会溢出"就提前占位。
6. **无滚动条时徽章贴边** → 行宽 = `clientWidth`，少了一段滚动条留白 → 维护 `data-has-scrollbar`，无滚动条时补 `calc(0.35rem + var(--tree-scrollbar-width))` 右内边距（只补内容，行盒子保持满宽，避免底色缺口）。
7. **每行做内容固有宽度测量** → react-arborist 内联 `min-width: max-content` → `.tree [role="treeitem"] { min-width: 0 !important }`（forced 58ms → 4–8ms）。
8. **强制同步布局居高不下** → 循环里"写样式 → 读 rect"交错 → 先批量读（内联 top / 高度，不触发布局）再批量写；快照与当前值不要混用 rect 与内联 top（padding 常量误差）。
9. **首次展开大子树 50–100ms 长任务** → 一次性挂 60+ 行 → 分批扩窗 + 行内容按原始值 `memo` + 树行 `content-visibility: auto` + `contain-intrinsic-size: auto 30px`。
10. **展开比折叠多一次整树布局** → 扩窗量等 render 后才补 setState → 在点击的同一次提交里按数据模型推算（`countExpandableRows` + `openState` + `openByDefault`）。
11. **滚动时整窗口重渲染** → react-window 滚动时重渲染窗口内所有行、行内容被重建 → 行内容拆 `memo` 组件、props 只用原始值（选中/展开态走行上 `data-*` + CSS）。
12. **扩窗后新挂载的行在动画中跳位** → 标记只写给动画开始时就存在的行 → `applyMotionMarks` 幂等，扩窗量每变一次补一次。
13. **虚拟列表窗口外的行没挂载 → 动画中段空白** → 只靠渲染窗口不够 → 动画前按需扩窗，扩窗量取「子树行数 ∩ 窗口下方剩余行数」。
14. **标签页切换 400-800ms 卡顿** → Radix Tabs 默认卸载非活动面板 → `TabsContent` 加 `forceMount` + `.tabContent[data-state="inactive"]{display:none}`；之后 DOM 里有两份 tab 触发器，自动化查询必须 scope 到 `:visible`。
15. **大树滚动掉帧** → 同屏未虚拟化的候选审阅表（317 行 ≈ 6300 单元格）常驻 DOM，整页样式重建都算它 → 树侧已到位；表格侧需虚拟滚动（`@tanstack/react-virtual`，当前未安装）或限制渲染行数。

## 六、已知限制与后续可选方案

1. 超过 200 行的子树直接切换；`prefers-reduced-motion` 下全部直接切换。
2. 候选审阅表未虚拟化，是"树 + 表"同屏滚动掉帧的主因（坑 15）。
3. 若还要继续压首帧：可做**悬停预热**（指针进入 chevron 时用 transition 提前扩窗）或**分帧渲染**（一次挂载拆多个 rAF 批次）；本轮分批扩窗已把 JS 阻塞压到 ≤13ms，暂不需要更激进的方案。

## 七、改动后的必做验证

1. `npm run check`（format / lint / typecheck / build）。
2. 真实项目 R2657：折叠/展开 §4、§4.3、§4.2，确认动画方向、无空白无重影、滚动条不闪、徽章不跳、`data-motion-*` 与 CSS 变量清理干净。
3. 压测夹具（425 行）：折叠/展开大子树、连点 6 次、全折叠、滚动；用 Long Animation Frame 记录起动画时延、阻塞时长与长任务分布。
4. 截图由视觉模型确认：行渲染、层级导线、图标、徽章、选中高亮、空态。
