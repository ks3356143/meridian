# 录入与字段

> 返回 [需求录入与解析](../22-需求录入与解析.md)

## 定位

需求与追踪模块必须提供两条录入路径，并写入同一个项目需求基线池：

1. **树状手动录入**：适合没有可解析电子文档、文档解析效果不佳，或用户希望按 SRS 目录快速建立需求树的场景。
2. **SRS 自动解析**：适合已确认的软件需求规格说明电子文档，系统生成候选需求，用户确认后进入正式需求基线。

两条路径不得形成两套需求模型或两个孤立页面。手动录入与自动解析产生的正式需求统一进入需求树、追踪矩阵和后续测试项创建流程。

## 来源与入口

1. 自动解析入口只允许选择状态为 `confirmed` 的工作对象版本。
2. 对象类型为 `软件需求规格说明` 的已确认版本是主 SRS 解析来源。
3. 第一版自动解析范围只包含软件需求规格说明；研制总要求、软件研制任务书、技术要求等顶层依据先完成登记和版本管理，不生成软件需求。
4. 顶层依据后续是否生成顶层需求、隐含需求或仅作为追踪依据，等需求主链跑通后再确认；不得因为来源类型不同而建立第二套需求模型。
5. 需求必须绑定来源工作对象版本。手工新增需求也必须挂到某个已确认来源版本下，不允许出现无来源的游离需求。
6. 已确认主 SRS 的原始电子文件为 `.doc` 时，允许为该版本补传一个 `.docx` 解析副本。副本替换仅更新解析来源，不改变对象名称、版本号、接收信息和原始文件哈希。

## 需求字段

| 字段 | 口径 |
| --- | --- |
| 来源工作对象版本 | 必填，来自已确认工作对象。 |
| 父章节 | 树状结构中的章节节点。 |
| 章节号 | 必填，用于排序、原文定位和版本比对。 |
| 标识 | 用户可录入，或保存 SRS 中已有的 A1、SSS-001 等编号；留空时按名称拼音首字母生成四位。同一来源版本内非空标识不重复。 |
| 需求名称 | 必填；同一来源版本内候选/正式状态不得重复。 |
| 需求描述 | 可留空；第一版使用保留换行的多行纯文本，段落直接保存，表格和图片以占位保留。空描述标记为“待补描述”，补全前不得进入测试项创建、关联、追踪和导出链路。后续必须支持结构化表格、图片资产和原文锚点。 |
| 需求类型 | 单选：功能、接口、性能、安全性、可靠性、其他。 |
| 副类型 | 可选多选，选项与需求类型一致，但不得与主类型重复；用于标记复合性质，不作为附加标签保存。 |
| 附加标签 | 多选或自由标签，只作辅助筛选，不参与主性质统计。 |
| 原文锚点 | 自动解析需求保留章节、段落或表格定位，用于回看原文。 |
| 状态 | 见需求状态口径。 |
| 关联测试项 | 测试项模块落地后实现，软件需求与测试项多对多。 |

软件需求不保存平台字段。项目平台是唯一权威；需求、测试项、用例不因平台重复建模，平台相关统计从项目上下文推导。

需求描述的演进口径：

1. 第一版不引入富文本编辑器，先用多行纯文本保存需求文字，保证需求树、确认和追踪主链先落地。
2. Word SRS 中常见富文本、图片和表格不能被长期丢弃；自动解析接入后，原文锚点必须保留来源位置。
3. 后续需求描述升级为结构化富文本时，必须支持加粗、上下标、图片、表格和原文片段迁移，并保留纯文本投影用于比对和搜索。
4. 首版遇到无法转为纯文本的图片或复杂表格时，候选页必须提示“该片段需保留原文查看”，不得伪装成完整需求描述。

## 树结构口径

1. 树节点分为章节节点和需求节点。
2. 章节节点只承载目录结构和层级，不进入追踪矩阵，不生成测试项。
3. 空描述需求可以作为正式基线中的待补描述骨架节点，但补全描述前不得进入测试项创建、关联、追踪和导出链路；只有章节号和标题的节点是章节节点。
4. 左侧树展示来源文档、章节和需求的层级；测试项、用例、问题单可作为追踪子节点预览，但不在需求树内直接编辑。
5. 需求章节号必须与 SRS 实际章节号一致。根节点手工录入不预填 `1`、`2` 这类顺序号；只有选中已有父章节时，才可按该章节下的已有章节和需求预填下一个子级编号。预填值不能静默成为权威值。
6. 有电子 SRS 时，章节号必须与原文标题锚点匹配，或由用户在候选确认时明确确认。无电子文件的手工登记场景，章节号由用户确认后保存。
7. 章节号保存前校验空值、格式、同级重复和跨层级明显冲突；对无法与原文匹配的编号给出警告，不自动替用户改写。
8. 手工登记服务测试关注的章节和需求，不要求补齐 SRS 全书目录。保存需求时只创建该需求对应的章节节点；父章节存在则挂载，不存在则保持根节点显示，禁止自动创建与测试无关的父章节占位节点。
9. 修改确认需求的章节号时，目标章节已登记则挂接既有章节，未登记则创建该需求对应的手动章节；父章节规则与新增需求一致，不自动补齐无关父章节。
10. 章节号字段行内说明只保留“与 SRS 章节号一致”单行短口径；父章节是否自动补齐属于系统行为规则，不用长说明增加表单高度。
11. 自动解析识别并保存整本 SRS 目录；测试作业面通过 `inScope` 动态计算。候选/正式需求所在章节及其祖先进入测试需求视图；参考资料、背景说明等无需求目录保留在全文视图中，不污染作业树。排除候选后，其章节自动退出作业面，重解析不会丢全文目录。

## 手动录入交互

1. 用户可在左侧树选中章节后新增子章节或需求节点。
2. 保存需求后直接进入正式需求基线，不额外要求二次确认。
3. 支持“保存并沿用”，保存后保留当前来源、章节层级、主类型和副类型，自动预填下一条章节号，焦点回到需求名称。
4. 支持批量粘贴需求节点，详细格式、校验和入库边界见[批量操作](02-批量操作.md)。
5. 支持搜索章节号、名称、描述、外部标识和标签。
6. 支持批量修改主性质和附加标签。
7. 手动录入页必须优先服务连续作业：常用字段在一屏内完成，键盘 Tab / Enter 流不得被弹窗打断。

### 已实施易用性优化

1. 新增确认需求弹窗根据当前选中需求预填同来源、同层级的下一个章节号；“保存并沿用”成功后按刚创建的章节号继续预填下一条。预填只是建议，用户可以修改。
2. 章节号输入实时校验格式和同来源有效章节冲突；冲突提示显示已有章节号与需求名称，冲突未消除时禁止提交。系统不因预填自动创建无关父章节。
3. 正式需求详情和需求树节点右键菜单均提供“复制新增”：继承当前详情中的名称、描述、主类型、副类型和原需求标签；标识清空，章节号预填原章节的下一个同级编号。用户必须在弹窗中确认章节号和名称后保存。
### 待讨论易用性方案

以下方案只记录口径，未确认前不进入开发：

1. 完整度筛选：待补描述提醒已实现；后续可补充“只看待补描述”筛选和“待确认标识”筛选。
2. 键盘流强化：补充树焦点到详情、新节点高亮、关闭前草稿提示等连续录入体验。
3. 草稿保护：误关新增弹窗或切换页面时明确提示，或把未提交草稿保留到当前会话。
4. 录入侧轻审计：在详情显示最近修改时间和修改人，不替代完整审计弹窗。
5. 标识冲突预览：标识留空时按名称预估拼音首字母四位，并说明保存时可能因冲突调整。
6. 暂缓项：富文本描述、自由拖拽树节点和整本章节树维护不作为当前手动录入优化优先级。
