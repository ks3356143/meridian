# 正文图片与表格尺寸口径

> 上级：[需求录入与解析](../22-需求录入与解析.md)｜块模型见 [需求正文块模型](./06-需求正文块模型.md)｜Word 生成侧见 [Word 生成](../08-Word生成.md)

> **状态：已定稿（2026-10-01 用户口述确认；Web 预览观感由实现方定稿；第八节四项待确认已于同日确认）。** 只定义口径，不定义实现。本文件同时约束 **Web 只读预览** 与 **Word 生成**，两端共用同一套适配参数，保证"预览 ≈ Word"。

## 一、总原则

1. **尺寸由渲染层算，对齐由富文本定**：`assetImage.align`（左 / 中 / 右，缺省居中）必须原样映射到预览与 Word；图片尺寸由容器宽度（页面内容宽 / 单元格宽）与长宽比计算。
2. **永远等比、绝不失真**：不做非等比拉伸；导出时 `wp:extent` 与 `a:ext` 必须一致。
3. **同一套参数驱动两端**：预览与 Word 使用同一组占比、高度上限与极端比例收缩；差别只在溢出策略——Web 容器内横向滚动，Word 压缩列宽。
4. **不放大**：输出宽度不超过图片真实像素宽按 96dpi 折算的物理宽度，避免小图放大后发糊。

## 二、参数（初值，落地时从模板节属性读取真实页面尺寸）

| 参数 | 含义 | 初值 |
| --- | --- | --- |
| `W_text` | 正文内容宽度（页宽 − 左右页边距） | A4 常规 ≈ 15.9cm |
| `H_text` | 正文内容高度（页高 − 上下页边距） | A4 常规 ≈ 24.7cm |
| `PARA_WIDTH_RATIO` | 段落图片目标宽度占比 | **0.75（约 3/4 页宽）** |
| `PARA_HEIGHT_LIMIT` | 段落图片高度上限 | `0.60 × H_text` |
| `CELL_HEIGHT_LIMIT` | 单元格图片高度上限 | `0.35 × H_text` |
| `EXTREME_RATIO` | 极端长宽比阈值 | `6:1` |
| `EXTREME_SHRINK` | 极端长宽比额外收缩 | `×0.8` |
| `MIN_WIDTH` | 图片最小宽度 | 段落 `1cm`；单元格 `0.8cm` |

## 三、段落内图片（顶层 `assetImage`）

1. 目标宽度 `w = min(PARA_WIDTH_RATIO × W_text, 真实像素宽折算的物理宽)` → 约页宽 3/4，且小图不被放大。
2. 高度约束：`w ÷ (像素宽 ÷ 像素高) ≤ PARA_HEIGHT_LIMIT`；超出时按高度上限反算宽度——瘦高长图自动变小，不出现细长条占满整页。
3. 宽度下限 `MIN_WIDTH`（1cm）。
4. 宽度 ≤ `W_text`、高度 ≤ `PARA_HEIGHT_LIMIT`，不允许溢出页面。
5. 对齐按 `align` 输出到图片所在段落；`align` 缺省居中。

## 四、表格单元格内图片

1. 单元格有效宽度 `w_cell = 列宽 − 左右内边距`，列宽取表格逻辑列宽（合并单元格按 `colspan` 展开）。
2. 基础目标宽度 = `w_cell × 占比`，占比按单元格宽度分档——大单元格约 60%，小单元格占比更高以免图太小看不清：

| 单元格有效宽度 | 目标宽占比 |
| --- | --- |
| ≥ 8cm | 60% |
| 6–8cm | 65% |
| 4–6cm | 70% |
| 2–4cm | 80% |
| < 2cm | 100%（保留 0.1cm 边距） |

3. 高度上限 `CELL_HEIGHT_LIMIT`（≈ 8.6cm）：超出按高度上限反算宽度。
4. 极端长宽比（宽 : 高 或 高 : 宽 > `EXTREME_RATIO`）：在档位占比上再 × `EXTREME_SHRINK`，即最窄落在基础占比的 80%。
5. 宽度下限 `MIN_WIDTH`（0.8cm）；同样不放大。
6. 对齐按 `align`；缺省在单元格内水平居中，单元格自身的文字对齐（短文本居中 / 长文本左对齐）不得覆盖图片对齐。

## 五、表格自身口径

- 列宽真源是单元格 `colwidth`（合并单元格必须按 `colspan` 展开成逻辑列，否则与 Word 的 `w:tblGrid` 对不上）。
- 有列宽 → `fixed` 布局 + `w:tblGrid`；无列宽 → `auto` 布局，宽度随内容。
- 表格总宽 > `W_text` 时按正文宽**等比压缩列宽**（Word 无横向滚动），**字号与行距不变**；压缩后每列不低于最小可读宽度（初值 1.5cm）。
- 表格 `align` 映射到 `w:tblPr/w:jc`；Web 预览用 `margin` 表达同一语义。
- 单元格文字统一五号 10.5pt，不随列宽压缩改字号。

## 六、Web 只读预览观感（2026-10-01 定稿）

目标四条硬指标：**不溢出、不糊、不跳动、不刺眼**。

- 图片：块级卡片，最大宽 100%、等比、不放大；细边框 + 极浅底 + 小圆角（贴合直角风格）；悬停只变边框与底色（180–220ms，不允许位移）；按显示宽度取档请求缩略图，避免糊与浪费；`align` 生效，缺省居中。
- 单元格内图片：与本文件第四节同一套分档规则，保证预览与 Word 观感一致。
- 表格：整体居中；`max-width: 100%`；超宽时容器内横向滚动（细滚动条、主色系），表头 `sticky`；表头浅绿底 + 黑体 + 居中；数据格五号，长文本左对齐 / 短文本与数值居中、垂直居中；行悬停 3–4% 主色底；有 `colwidth` 时按列宽渲染。
- 一致性：预览与编辑器共用同一套列宽与尺寸判定，避免再次出现"预览与实际宽度不同"；表格 DOM 规模与虚拟化按《23-数据加载与渲染性能》执行。

## 七、生成后校验（排版 lint）

| 检查 | 断言 |
| --- | --- |
| 段落图片 | 段落 `w:jc` 与 `assetImage.align` 一致（缺省 center）；宽度 ≤ `W_text` |
| 单元格图片 | 宽度 ≤ `w_cell`；高度 ≤ `CELL_HEIGHT_LIMIT` |
| 等比不失真 | `wp:extent` 与 `a:ext` 一致，且与真实像素比一致（误差 ≤ 0.5%） |
| 表格 | 总宽 ≤ `W_text`；有列宽时 `tblLayout=fixed` 且 `tblGrid` 存在 |

## 八、已确认口径（2026-10-01 用户确认）

1. **富文本记录的图片尺寸不参与 Word 输出**：`assetImage.width` / `height` 只服务 Web 端展示与编辑态；Word 输出尺寸一律按本文件第三节、第四节重算，**只有 `align` 生效**。若将来要支持"用户尺寸优先"，必须先补"用户尺寸先钳制、再受页宽与单元格上限约束"的规则。
2. **`W_text` / `H_text` 从模板节属性读取**：A4 常规页边距下取 15.9cm / 24.7cm 作为初值，落地时用真实交付模板校准，不写死。
3. **极端长宽比按初值执行**：`EXTREME_RATIO = 6:1`、`EXTREME_SHRINK = ×0.8`；实施后用真实交付文档回归微调，参数集中在第二节，调参不改结构。
4. **计算顺序固定**：先定表格列宽（必要时已压缩到 `W_text`），再按压缩后的列宽计算单元格内图片宽度。
