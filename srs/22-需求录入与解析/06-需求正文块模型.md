# 需求正文块模型

> 上级：[需求录入与解析](../22-需求录入与解析.md)｜通用内容块与节点白名单见 [内容块模型](../15-内容块与附件模型/01-内容块模型.md)｜Step 2 方案见 [数据加载与渲染性能](./05-数据加载与渲染性能.md)

> **状态：已定稿（2026-09-29），并于 2026-09-30 按用户最新要求修订。** 存储位置采用方案 A（`content_blocks`，`owner_type=requirement`、`block_key=requirement.body`）。本文件是 Step 2 切片 1 的交付物：把「需求正文」的块模型定稿，作为解析、渲染、编辑和 Word 生成的共同依据。只定义口径，不定义实现。

## 一、范围

- 「需求正文」= 从 DOCX 解析进来的需求原文 + 人工录入 / 修改的内容。
- 一套块模型同时服务三端：**详情只读渲染**、**轻量结构化编辑**、**Word 生成**。
- 正文编辑面使用 Tiptap（ProseMirror JSON），保留受限节点模型；段落、表格、多级有序列表和图片在编辑器中直接编辑，预览仍使用只读块渲染（见本文第十节）。

## 二、块类型（最小集）

| 块类型 | 字段 | 说明 |
| --- | --- | --- |
| `heading` | `level`(2–4)、`runs[]` | 层级来自 Word 样式；**章节号是派生值，不入库** |
| `paragraph` | `attrs.align`、`attrs.firstLineIndent`、`attrs.variant`、`runs[]` | 正文段落；保留对齐、首行缩进 2 字符识别和表题 / 图题语义 |
| `orderedList` | `attrs.style`、`items[]` | 只保留有序列表，支持多级嵌套 |
| `table` | `rows[]`、`align` | 表格整体左/中/右对齐；表头由首行 `tableHeader` 决定 |
| `image` | `assetId`、`width`、`height`、`alt`、`align`、`caption?`、`sourceAlign?` | 图片 |

- 段落内文字用 `runs[]` 承载：`{ text, bold?, ... }`。**解析时只保留粗体与选区高亮，斜体/下划线降级为普通文本**；粗体在 Web 只读渲染和 Word 生成中保留，高亮用于工作区标注，其他行内格式不提供。
- 识别不了的块一律降级为 `paragraph`，**不允许丢内容**。

> 图片与表格的尺寸、列宽、极端长宽比与预览观感口径见 [正文图片与表格尺寸口径](./07-正文图片与表格尺寸口径.md)（2026-10-01 定稿）；本文件只定义块结构，不重复尺寸规则。
> 
> 注意：`assetImage.width` / `height` 只服务 Web 端展示与编辑态，**Word 输出尺寸由生成层按上述口径重算**，前端记录的尺寸不参与。

### 块类型 ↔ 存储节点白名单对齐（校验用）

与 [内容块模型](../15-内容块与附件模型/01-内容块模型.md) 的节点白名单逐项对齐结果：

| 本文块类型 | 白名单节点 | 对齐处置 |
| --- | --- | --- |
| `heading` | `heading` | ✅ 一致 |
| `paragraph` | `paragraph` + `text` + `marks` | ⚠️ 段内文字必须落成 `text` + `marks`（不是自定义 `runs` 结构），本文的「runs」只是叙述叫法 |
| `list` | `bulletList` / `orderedList` / `listItem` | ❌ 存储层必须拆成两类列表节点，`style`（`ordered-paren` / `letter-paren`）只作为区块元数据 |
| `table` | `table` / `tableRow` / `tableHeader` / `tableCell` | ✅ 一致 |
| `image` | `assetImage` | ❌ 统一改名 `assetImage` |
| `pagebreak` | **历史兼容读取** | ❌ 需求正文不支持分页符：新导入不产出、编辑/渲染不展示、保存时清洗；历史数据兼容读取后忽略 |
| （未列） | `blockquote` | ❌ 白名单已有，需明确「解析时是否产出引用块」，不产出则从白名单移除 |

**处置结论：本文的块类型是对白名单的语义化叫法，存储层一律以白名单节点名为准。`list` 拆分、`assetImage` 改名、`blockquote` 去留已闭环；`pagebreak` 不进入需求正文业务数据，仅保留历史兼容读取。**
## 三、对齐与缩进口径（2026-09-30 最新）

1. 段落只保留以下信息：
   - `align`：`left` / `center` / `right` / `justify`，用户可编辑；未显式设置时按正文规范渲染。
   - `firstLineIndent`：`0` 或 `2`；导入时识别 Word 的 `firstLineChars=200` 或等价的 2 字符缩进。
   - `variant`：普通段落或 `tableCaption`。
2. 正文字体不落库；Web 预览、编辑和 Word 生成统一按小四 12pt 处理。
3. 居中 / 右对齐时首行缩进归零；表格单元格内段落不应用首行缩进。
4. 其他字体、字号、颜色、行距、段距、斜体、下划线、分页符、浮动对象和复杂样式在导入与保存时清洗。

## 三点五、表格与有序列表规范（2026-09-30 最新）

### 表格

- 表格整体 `align` 默认 `center`，用户可编辑为 `left` / `center` / `right`。
- 表头由首行单元格类型决定，可有可无；有表头时表头单元格居中、五号黑体，数据单元格五号。
- 表格支持增删行列、切换首行表头、合并 / 拆分单元格；表头行边框加粗由生成层按模板处理。
- 表格文字统一五号 10.5pt；Web 预览和编辑区按该口径显示。

### 有序列表

- 只保留 `orderedList`，不支持 `bulletList`。
- 支持任意层级的嵌套 `orderedList`；子级缩进由渲染层统一控制，建议每级左缩进约 2 个字符。
- 有序列表字体与正文一致（小四 12pt），编号形态默认 `ordered-paren`。
- 旧 `bulletList` 读取后转换为 `orderedList`，保证内容不丢；保存时不再产出 `bulletList`。

## 四、题注口径（2026-09-30 最新）

- 表格题注位于表格上方，固定格式为居中的 `表X-X xxx`，五号黑体；表题使用表格上方独立 `paragraph` 表达，`variant=tableCaption`。
- 图片题注位于图片下方，固定格式为居中的 `图X-X xxx`，五号黑体；图题同样用独立 `paragraph` 表达，`variant=figureCaption`，与表题共用居中、无首行缩进的清洗规则（2026-10-09 补齐）。
- 题注编号 `X-X` 由生成层按章节与顺序计算，不入库；题注段落的间距方向相反：表题向表格留 0.28rem、图题向图片留 0.28rem。
- 浮动题注和自定义题注位置暂不保留。

## 五、不支持项（2026-09-30 最新）

1. 浮动图片 / 文字环绕：不支持，导入时降级为 inline 居中或忽略。
2. 嵌套表格、公式、图表、文本框、形状：首版不解析。
3. 斜体、下划线、删除线、上下标、超链接、颜色、字号、行距、段距：不保留。
4. 分页符、页眉页脚、批注、修订痕迹：不进入正文块。
5. 行内格式白名单见第二节；本节只记录未保留格式。
## 六、与 OOXML 的映射原则

| 块 | OOXML 落点 |
| --- | --- |
| `heading` | `pStyle` = 模板 Heading N 样式（不写字号 / 字体） |
| `paragraph` | `pStyle` = 模板正文样式；模板已含 `firstLineChars=200` 时不再显式设置 |
| `table` | `tbl` + `tblPr/jc=center`（模板表格样式已含则不再设置） |
| `image` | inline drawing + 所在段落 `align` 跟随富文本（缺省 center） |
| `bold` | run 级别 `w:b`；斜体 / 下划线不输出 |
| `highlight` | 当前仅工作区渲染；Word 是交付内容，按口径不映射为底纹或文字高亮 |
| `caption` | `pStyle` = 模板题注样式 |

**总原则：优先用模板样式表达规范，只在必要时显式覆盖；每一处显式覆盖都要记录原因。**

## 七、生成后校验（排版 lint）

生成文档后按属性选择器批量断言，输出违规清单：

| 检查 | 断言 |
| --- | --- |
| 正文段落 | `firstLineChars = 200`、字号 12pt（小四） |
| 表格 | `table.align = center` |
| 表格内文字 | 10.5pt（五号）、`font.ea=宋体`、`font.latin=Times New Roman` |
| 图片段落 | `align` 与富文本一致（缺省 center） |
| 题注 | 10.5pt、居中 |
| 表头行单元格 | `align=center` + `valign=center` + 下边框 ≥ 1.5pt |
| 长文本单元格 | `align=left` + `valign=center` |
| 短文本 / 数值单元格 | `align=center` + `valign=center` |
| 正文列表 | `lvlText` 命中 `%1）`（decimal 或 lowerLetter）或 bullet |

## 八、切片 1 决策记录（2026-09-29 用户确认）

1. **存储位置：方案 A** —— 需求正文进 `content_blocks`（`owner_type=requirement`、`owner_id=需求 id`、`block_key=requirement.body`），一行一条需求，`body_json` 承载完整文档树。Word 装配统一从 `content_blocks` 取数。
2. **白名单对齐处置**：
   - `list` 在存储层拆为 `bulletList` / `orderedList` / `listItem`，`style`（`ordered-paren` / `letter-paren`）挂在列表节点 `attrs` 上。
   - `image` 统一改名 `assetImage`。
   - `pagebreak` 不进入需求正文业务数据；历史数据兼容读取后忽略，保存时清洗。
   - `blockquote` 从白名单移除（需求文档无引用块场景，保持白名单最小）。
3. 最终业务节点白名单：`doc` / `paragraph` / `text` / `heading` / `bulletList` / `orderedList` / `listItem` / `table` / `tableRow` / `tableHeader` / `tableCell` / `assetImage`。`pagebreak` 仅为历史数据兼容读取，不允许新导入、编辑或生成。
4. 号数映射、长短文本阈值、行内格式保留策略按本文档建议执行，实施时用真实文档回归校准。

## 十、正文编辑面（2026-09-30 最新用户确认）

1. 详情面板中的正文区域保持独立外边框卡片，标题固定为 **“测试项的需求描述”**；默认展示只读块预览。
2. 点击“编辑正文”后打开大尺寸 Dialog，预览不弹窗；Dialog 内部独立滚动，底部固定“取消 / 保存正文”。
3. 编辑器使用 Tiptap，保存 Tiptap JSON 到受限 `body_json`；禁止保存 Word HTML。
4. 保留能力仅包括：
   - 段落：识别首行缩进 2 字符，可编辑左 / 中 / 右 / 两端对齐；
   - 表格：默认居中，可切左 / 中 / 右；表头可有可无；表头居中五号黑体；支持增删行列、合并 / 拆分；
   - 表题：表格上方居中的 `表X-X xxx` 五号黑体段落；
   - 有序列表：只保留 `orderedList`，支持多级缩进，字体与正文一致；
   - 行内格式：按第二节白名单执行，编辑器不得扩展未登记 mark。
5. Word 粘贴先经 `transformPastedHTML` 清洗，只映射上述保留信息；其他字体、字号、颜色、行距、段距、斜体、下划线、分页符全部丢弃。
6. 单元格内容与后端白名单对齐（2026-10-09）：`tableCell` / `tableHeader` 下**只允许段落**，编辑器 schema 同样收紧为 `paragraph+`，避免单元格里塞列表或图片时编辑期不报错、保存才被拒。粘贴带来的单元格内列表（含 Word 自动编号）一律压平成段落。
7. Word 自动编号段落在**单元格内**不做列表转换（单元格没有跨格编号上下文），也不沿用 Word 的字面标记（Word 常给每格都是“1.”），改为按**该列行序**补字面数字“1.”“2.”…（2026-10-09 真实粘贴反馈：序号列原本整列空白）。
8. Word 题注段落（`class=MsoCaption`，或去编号后正文以“表 N …” / “图 N …”开头）按**表题 / 图题**摄入：去掉纯数字编号标记、不转列表，并强制独立成段——ProseMirror 把首块并入上一段时会沿用原段属性，表题属性会被丢掉。
9. Word 剪贴板表格的表头是 `<td>`（没有 `<th>`）：首行整行加粗或有底纹时自动提升为表头，其余情况用户可手动「转为表头」。
10. 正文末尾以表格 / 图片收尾时，载入编辑器即补一个空段落；粘贴内容以表格 / 图片收尾且落点在文末时同样补一个（2026-10-09 用户确认代价可接受：保存后正文末尾会多一个空段落）。原因：ProseMirror 的 GapCursor 在“块下方留白”点击时会把落点解析到最近的文字（表格内部），光标落不到块后，所以正文末尾必须以文本块收尾。实现见 `ensureTrailingParagraph`（载入）与 `shapePastedSlice`（粘贴）。
11. 用户对正文的修改使用显式“保存正文”；取消、关闭或切换需求且存在未保存修改时提示确认。
12. 旧纯文本描述首次编辑时转换为段落块，保存后进入 `content_blocks`。

## 十一、正文权威源与 `description` 列（2026-10-09 落地）

- `content_blocks`（`owner_type=requirement`、`block_key=requirement.body`）的 `plain_text` 是正文唯一权威源；`software_requirements.description` 只保留解析/登记写入的历史文本，**保存正文不再回写它**——过渡桥接已撤除。
- 列表摘要 `descriptionExcerpt`、`hasDescription`（“待补描述”完整度）、按正文搜索、详情纯文本回退、测试项创建资格判定，统一走 `internal/modules/requirements/bodytext.go`：有正文块用块的 `plain_text`，没有正文块才回落到 `description`。
- 事务内取正文必须用 `bodyPlainTextWith(ctx, tx, id)`：SQLite 写事务里另开连接读同一库会互相等待（实测卡死到超时）。
- 详情表单保存仍会带上 `description`（它没有独立编辑入口），因此该列可能被写成正文纯文本；所有读取路径都以正文块为准，列值不影响展示与统计。
