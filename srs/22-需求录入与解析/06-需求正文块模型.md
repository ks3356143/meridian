# 需求正文块模型

> 上级：[需求录入与解析](../22-需求录入与解析.md)｜通用内容块与节点白名单见 [内容块模型](../15-内容块与附件模型/01-内容块模型.md)｜Step 2 方案见 [数据加载与渲染性能](./05-数据加载与渲染性能.md)

> **状态：草案，待用户评审。** 白名单对齐与存储位置两项未闭环前不得视为切片 1 完成。本文件是 Step 2 切片 1 的交付物：把「需求正文」的块模型定稿，作为解析、渲染、编辑和 Word 生成的共同依据。只定义口径，不定义实现。

## 一、范围

- 「需求正文」= 从 DOCX 解析进来的需求原文 + 人工录入 / 修改的内容。
- 一套块模型同时服务三端：**详情只读渲染**、**轻量结构化编辑**、**Word 生成**。
- 阶段一不引入富文本编辑面（见 [内容块模型 · 编辑器选型调研](../15-内容块与附件模型/01-内容块模型.md)）。

## 二、块类型（最小集）

| 块类型 | 字段 | 说明 |
| --- | --- | --- |
| `heading` | `level`(2–4)、`runs[]` | 层级来自 Word 样式；**章节号是派生值，不入库** |
| `paragraph` | `runs[]` | 正文段落，默认首行缩进 2 字符 + 两端对齐 |
| `list` | `ordered`、`style`（`ordered-paren` / `letter-paren` / `bullet`）、`items[]` | 有序 / 无序列表，形态见三点五节 |
| `table` | `rows[]`、`align`、`caption?`、`sourceAlign?` | 表格 |
| `image` | `assetId`、`width`、`height`、`alt`、`align`、`caption?`、`sourceAlign?` | 图片 |
| `pagebreak` | — | 分页符 |

- 段落内文字用 `runs[]` 承载：`{ text, bold?, italic?, underline?, ... }`，**解析时读出行内格式并只读渲染**；阶段一编辑面不暴露行内格式编辑（见第五节）。
- 识别不了的块一律降级为 `paragraph`，**不允许丢内容**。

### 块类型 ↔ 存储节点白名单对齐（校验用）

与 [内容块模型](../15-内容块与附件模型/01-内容块模型.md) 的节点白名单逐项对齐结果：

| 本文块类型 | 白名单节点 | 对齐处置 |
| --- | --- | --- |
| `heading` | `heading` | ✅ 一致 |
| `paragraph` | `paragraph` + `text` + `marks` | ⚠️ 段内文字必须落成 `text` + `marks`（不是自定义 `runs` 结构），本文的「runs」只是叙述叫法 |
| `list` | `bulletList` / `orderedList` / `listItem` | ❌ 存储层必须拆成两类列表节点，`style`（`ordered-paren` / `letter-paren`）只作为区块元数据 |
| `table` | `table` / `tableRow` / `tableHeader` / `tableCell` | ✅ 一致 |
| `image` | `assetImage` | ❌ 统一改名 `assetImage` |
| `pagebreak` | **未登记** | ❌ 需在内容块模型登记为自定义节点后才能使用 |
| （未列） | `blockquote` | ❌ 白名单已有，需明确「解析时是否产出引用块」，不产出则从白名单移除 |

**处置结论：本文的块类型是对白名单的语义化叫法，存储层一律以白名单节点名为准；其中 `list` 拆分、`assetImage` 改名、`pagebreak` 登记、`blockquote` 去留四项必须在实施前闭环。**
## 三、对齐口径（2026-09-29 定稿）

**对齐不是用户意图，是交付规范 + 原文档既成事实。** 因此：

1. 每个块带三态属性 `align: inherit | left | center | right`，默认 `inherit`。
2. `inherit` = 按块类型规范：`paragraph` → 首行缩进 2 字符 + 两端对齐；`table` → 居中；`image` → 居中；`caption` → 居中。
3. **段落级不提供对齐开关**：若某段不该首行缩进（注释、公式说明等），应改用对应块类型，用语义表达意图，而不是用格式表达。
4. 导入时读出的原文档对齐存进 `sourceAlign`，**默认不生效**，只作保真参考；确需保留时由用户显式提升为 `align`。
5. 展示与生成分离：详情面板可选「保真模式」（用 `sourceAlign`）或「规范模式」；**生成 Word 一律走规范**，`sourceAlign` 不得泄漏进交付文档。

| 内容 | 对齐来源 | 用户可改 | 存储 |
| --- | --- | --- | --- |
| 正文段落 | 规范 | ❌ | 不存 |
| 标题 | 模板样式（只存 level） | ❌ | 只存 level |
| 表格整体 | 规范（居中） | 可显式偏离 | 仅偏离时存 `align` |
| 表格单元格 | 表格块 schema | 仅表格编辑器内改 | 存单元格覆盖值 |
| 图片 | 规范（inline + 段落居中） | 可显式偏离 | 仅偏离时存 `align` |
| 题注 | 规范（居中、五号） | ❌ | 不存 |

## 三点五、表格排版规范（2026-09-29 用户确认）

### 单元格对齐

| 单元格类型 | 水平 | 垂直 | 实现属性 |
| --- | --- | --- | --- |
| 表头 | 居中 | 居中 | `align=center` + `valign=center`，且表头行单元格边框加粗 |
| 长文本（句段、描述） | 左 | 居中 | `align=left` + `valign=center` |
| 短文本（版本号如 `V1.10`、日期、编号） | 居中 | 居中 | `align=center` + `valign=center` |
| 数值 | 居中 | 居中 | `align=center` + `valign=center` |

- **表头行边框加粗**：对表头行单元格设置 `border.bottom="single;1.5pt;000000"`（需要四边时用 `border.all`）。OfficeCLI 的 `table-cell` 原生支持 `border.top/bottom/left/right/all`，不需要走 raw XML。
- **长 / 短文本判定**：优先按**列语义**——表格块 schema 中每列声明 `text | short | number`；导入的原文表格没有 schema 时用启发式（数值正则命中 → 居中；有效长度 ≤ 8 字符 → 居中；其余 → 左对齐）。判定只影响渲染，不写入数据。

### 表格字体

- 全表统一：`size=10.5pt`（五号）、`font.ea=宋体`、`font.latin=Times New Roman`、`font.hint=eastAsia`。
- 优先由模板表格样式承担；模板未覆盖时在生成层显式设置，并记录覆盖原因。

### 正文列表编号形态

模板 `numbering.xml` 实测（7 份模板均存在）支持两种正文列表形态。块模型只声明**形态**，不硬编码 `numId`：

| 形态键 | 模板 `lvlText` | 呈现 |
| --- | --- | --- |
| `ordered-paren` | `%1）`（decimal） | `1）` |
| `letter-paren` | `%1）`（lowerLetter） | `a）` |
| `bullet` | bullet | 项目符号 |

生成时按块声明的形态在模板 `numbering.xml` 中查找匹配的 `numId`；**找不到就阻断生成并报错，禁止回退到 Word 默认编号**。
## 四、题注口径（2026-09-29 确认）

- **表格题注在表格上方，图片题注在图片下方**，位置由块类型固定，不做配置。
- 题注是块上的字段 `caption: { text, autoNumber }`，不是独立块。
- 编号支持 `auto`（生成时按章节 / 顺序计算，如「表 4-1」「图 3-2」）与 `manual`；**编号值是派生值，不入库**（沿用「章节号、表号、图号不进入源数据」的既有口径）。
- 题注样式（居中、五号）由模板样式承担。

## 五、不支持项（首版）

1. **浮动图片 / 文字环绕：不支持**，导入时降级为 inline 居中（用户已确认实际文档不存在浮动图）。
2. 嵌套表格、公式、图表：首版不解析。
3. 阶段一编辑面为纯文本：段落含行内格式时，**文本未改则保留原 `runs`，文本有改则合并为单一 run**（已知限制，阶段二挂富文本编辑面后消除）。

## 六、与 OOXML 的映射原则

| 块 | OOXML 落点 |
| --- | --- |
| `heading` | `pStyle` = 模板 Heading N 样式（不写字号 / 字体） |
| `paragraph` | `pStyle` = 模板正文样式；模板已含 `firstLineChars=200` 时不再显式设置 |
| `table` | `tbl` + `tblPr/jc=center`（模板表格样式已含则不再设置） |
| `image` | inline drawing + 所在段落 `align=center` |
| `caption` | `pStyle` = 模板题注样式 |

**总原则：优先用模板样式表达规范，只在必要时显式覆盖；每一处显式覆盖都要记录原因。**

## 七、生成后校验（排版 lint）

生成文档后按属性选择器批量断言，输出违规清单：

| 检查 | 断言 |
| --- | --- |
| 正文段落 | `firstLineChars = 200`、字号 12pt（小四） |
| 表格 | `table.align = center` |
| 表格内文字 | 10.5pt（五号）、`font.ea=宋体`、`font.latin=Times New Roman` |
| 图片段落 | `align = center` |
| 题注 | 10.5pt、居中 |
| 表头行单元格 | `align=center` + `valign=center` + 下边框 ≥ 1.5pt |
| 长文本单元格 | `align=left` + `valign=center` |
| 短文本 / 数值单元格 | `align=center` + `valign=center` |
| 正文列表 | `lvlText` 命中 `%1）`（decimal 或 lowerLetter）或 bullet |

## 八、待确认（阻碍切片 1 收口）

1. **需求正文的结构化数据存哪**（架构级，必须拍板）：
   - 方案 A：进 `content_blocks`（`owner_type=requirement`、`block_key=requirement.body`）—— 统一块校验、完善度、渲染与 **Word 装配单一取数通道**；代价是要从 `software_requirements.description` 迁移，并同步维护 `plain_text` 摘要。
   - 方案 B：给 `software_requirements` 加 `body_json` 列 —— 与需求记录同表、无 join、生命周期天然绑定；代价是 Word 装配要从两个通道取数，块校验要在两处实现。
   - 倾向：**方案 A**（Word 装配统一取数对七类文档生成影响最大）。
2. `list` 拆分为 `bulletList` / `orderedList`、`image` 改名 `assetImage`、`pagebreak` 是否登记为自定义节点、`blockquote` 去留 —— 见第二节后的对齐表。
3. 中文号数 ↔ pt 的**完整**映射表（当前已确认并使用的只有表格五号 10.5pt、正文小四 12pt）。
4. 长短文本 8 字符阈值需用真实交付文档回归校准（表格列宽不同时阈值可能要按列宽调整）。
5. 行内格式在阶段一的具体保留策略需在实施时用真实文档回归验证。
