# 附件模型

> 返回 [内容块与附件模型](../15-内容块与附件模型.md)

## 附件模型

`assets` 保存附件元数据，文件内容存放在程序数据目录：

```text
data/assets/<前两位哈希>/<完整哈希>.<安全扩展名>
```

| 字段 | 说明 |
| --- | --- |
| `id` | 附件 UUID。 |
| `project_id` | 所属项目。 |
| `content_block_id` | 初次插入的内容块，可为空。 |
| `sha256` | 文件内容哈希，用于去重和完整性校验。 |
| `storage_key` | 相对数据目录路径。 |
| `mime_type` / `file_ext` | 安全类型信息。 |
| `file_size` | 文件大小。 |
| `width` / `height` | 图片尺寸，非图片为空。 |
| `caption` | 默认题注，可被节点题注覆盖。 |
| `created_at` | 上传时间。 |

同一哈希只存一份文件，数据库允许多条引用记录或引用计数字段。删除内容块时不立即物理删除文件，后续由引用扫描清理。

## 类型与限制

- 首批图片类型：PNG、JPEG、WebP；Word 输出前统一转换为 PNG 或 JPEG。
- 禁止脚本、SVG 动画、远程 URL 图片和外链自动下载。
- 单文件和单项目容量上限待定；实现前必须给出上传前校验和超出提示。
- 附件接口必须校验项目归属，禁止仅凭附件 UUID 越权读取。

## API 方向

内容块按拥有者路由，不做无权限边界的通用写接口：

```text
GET    /api/v1/projects/{code}/content-blocks
PUT    /api/v1/projects/{code}/content-blocks/{blockKey}
GET    /api/v1/projects/{code}/rounds/{roundId}/content-blocks
PUT    /api/v1/projects/{code}/rounds/{roundId}/content-blocks/{blockKey}
POST   /api/v1/projects/{code}/assets
GET    /api/v1/projects/{code}/assets/{assetId}
```

问题单、需求、测试项等专属内容块跟随各自业务模块 API 保存，不绕过所属业务校验。
