# 内容块与附件模型

## 目标

用统一内容块承接富文本、章节引言、结构化表格和图片引用，服务三类能力：

1. 前端按业务块录入和回显。
2. 后端按块校验、保存和统计完善度。
3. Word 生成层按受限节点模型直接渲染 OOXML。

## 数据分类

数据分类用于选择存储方式、校验方式和渲染方式，不作为物理拆库依据。全系统分为八类：

| 分类 | 例子 | 存储方式 | 渲染方式 |
| --- | --- | --- | --- |
| 基准数据 | 项目、相关方、人员、依据标准、被测对象基础字段、时间锚点。 | 关系表。 | 字段、封面、键值网格。 |
| 章节内容块 | 软件概述、接口说明、静态环境、动态环境、测评数据、差异分析、报告叙述。 | `content_blocks`。 | 富文本、结构化表格、图片和题注。 |
| 过程数据 | 需求、测试项、用例、轮次、执行记录、问题单。 | 关系表和轮次实例表。 | 明细表、用例表、问题单和汇总叙述。 |
| 关联数据 | 需求-测试项、测试项-用例、用例-问题单、影响域、需求符合情况。 | 关系表。 | 追溯矩阵、树和影响分析表。 |
| 专项证据数据集 | 外部比对数据、接口报文、参数矩阵、日志抽样、性能采样等大规模外部数据。 | 数据集定义 + 数据集行。 | 大表、差异分类、专项统计和回归子集。 |
| 单源片段 | 有效性声明、保密声明、固定方法话术。 | 版本化片段库。 | 模板引用和占位符展开。 |
| 派生统计 | 执行率、通过率、问题矩阵、需求符合统计、时间推导值。 | 生成时计算。 | 统计表和填空叙述；只在输出快照中留存。 |
| 输出快照 | 生成的 DOCX、模板快照、数据快照、版本记录。 | 文档实例和附件。 | 只读预览、下载和追溯。 |

“一次性数据”统一改称“章节内容块”。它不是只能用一次，而是有明确拥有者和生命周期：软件概述属于项目，动态环境属于轮次，报告人工结论属于文档章节。章节号、表号、图号不进入源数据，由生成装配层按模板上下文编号。

## 块定义注册表

所有内容块必须先登记再使用。注册表是前端表单、后端校验、完善度统计和 Word 装配的共同元数据来源，不允许在页面和生成器里各写一套。

```text
blockKey             稳定键
ownerType            project / round / requirement / issue / document_section
lifecycle            project_once / round_once / document_section
dataClass            chapter_block / process_data / relation / evidence_dataset / derived
title                展示名
renderer             richtext / editable_table / kv / image_gallery / mixed
payloadSchema        结构化数据校验定义
required             是否阻断生成
readinessRule        完善度判断
wordSlots            可输出的文档槽位
headingOffset        相对标题层级到 Word Heading 的映射
copyPolicy           轮次继承时深拷贝、不复制或禁用
defaultDraft         自动起草模板
```

注册表属于系统内置配置，可提供管理员只读展示；确需扩展时通过版本化配置变更，不允许运行时随意添加未定义块。

## 内容块表

`content_blocks` 保存所有可编辑内容块，主键为 UUIDv7 字符串。

| 字段 | 说明 |
| --- | --- |
| `id` | 内容块 UUID。 |
| `project_id` | 所属项目，用于权限和数据隔离。 |
| `owner_type` | `project` / `round` / `requirement` / `test_item` / `test_case` / `issue` / `document_section`。 |
| `owner_id` | 拥有者 UUID；项目级块使用项目 UUID，保证唯一约束可生效。 |
| `block_key` | 稳定键，如 `dut.software_overview`、`round.dynamic_env.software_items`。 |
| `body_json` | Tiptap JSON 文档，富文本权威源。 |
| `payload_json` | 块专属结构化数据，如表格行、选项、默认引言。 |
| `plain_text` | 从富文本提取的纯文本，用于完善度和搜索。 |
| `schema_version` | 内容结构与块 payload 的版本。 |
| `origin` | 当前主要来源：`manual` / `auto_draft` / `imported`。 |
| `authoring_mode` | `auto` / `manual` / `mixed`，用于自动重起草时保护人工内容。 |
| `sort_order` | 同一拥有者下的展示顺序。 |
| `created_at` / `updated_at` | 创建与更新时间。 |

唯一约束：`project_id + owner_type + owner_id + block_key`。SQLite 中 JSON 字段使用 `TEXT` 存储，查询用 JSON1，不使用 PostgreSQL JSONB。

## 富文本口径

- 编辑器使用 Tiptap，保存 `getJSON()` 结果到 `body_json`。
- `body_json` 是唯一权威源；前端预览可临时生成 HTML，但数据库不保存 HTML 作为生成依据。
- Word 生成使用受限 Tiptap JSON 到 OOXML 的映射，不采用通用 HTML 转 OOXML。
- 每个块声明允许的节点和属性，后端拒绝未登记节点。
- 首批允许节点：`doc`、`paragraph`、`text`、`heading`、`bulletList`、`orderedList`、`listItem`、`blockquote`、`table`、`tableRow`、`tableHeader`、`tableCell`、`assetImage`。
- Tiptap 表格只用于说明性小表；参与校验、统计、追溯或固定 Word 表样的业务表必须拆成结构化表格块。
- `assetImage` 是自定义节点，只保存 `assetId`、替代文本、展示宽度和题注，不保存 base64。
- 标题层级限制在 2 到 4 级；具体 Word Heading 映射由文档槽位配置决定。

## 块键规划

项目级示例：

| 块键 | 内容 |
| --- | --- |
| `dut.software_overview` | 软件概述富文本。 |
| `dut.interface_description` | 接口说明富文本。 |
| `dut.interface_items` | 外部接口信息表。 |
| `environment.static.description` | 静态测试环境描述。 |
| `environment.static.software_items` | 静态软件项表。 |
| `environment.static.hardware_items` | 静态硬件和固件表。 |
| `report.narrative.*` | 测评报告人工叙述段。 |

轮次级示例：

| 块键 | 内容 |
| --- | --- |
| `round.dynamic_env.description` | 动态环境描述。 |
| `round.dynamic_env.software_items` | 动态软件项表。 |
| `round.dynamic_env.hardware_items` | 动态硬件和固件表。 |
| `round.dynamic_env.location` | 测评场所说明。 |
| `round.test_data.description` | 测评数据引言。 |
| `round.test_data.items` | 测评数据表。 |
| `round.diff_analysis.description` | 环境差异性分析描述。 |
| `round.diff_analysis.items` | 差异分析表。 |
| `round.software_changes.*` | 回归轮软件更改部分。 |

一个复杂文档章节拆成多个块，避免单个 JSON 承载全部章节。结构化表格优先拆独立块并用 `payload_json` 保存行数据。

结构化表格的列名、必填规则、默认宽度和枚举由块 schema 或模板表格定义驱动。不同模板允许同一业务表有不同列集合，例如硬件项表可按模板增加 `IP`、`检定有效期` 或 `部署位置`。

## 校验规则

- `block_key` 必须来自后端登记的块定义。
- `owner_id` 必须存在且属于当前项目。
- `body_json` 必须通过允许节点和属性校验。
- `assetImage.assetId` 必须引用当前项目下未删除附件。
- 表格块按块定义校验列、必填字段、行数上限和枚举值。
- 空白富文本按未填写处理；判断依据为 `plain_text`、表格行和图片引用，不以 HTML 字符串长度判断。
- 保存成功后重新提取 `plain_text` 和完善度统计，不在前端自行推断最终口径。

## 叙述模板与占位符

报告叙述、测试有效性说明和每类测试执行情况支持“自动起草 + 人工修改保护”。

- 叙述模板存模板资产，项目侧生成草稿时写入对应章节内容块。
- 模板中的统计数据使用结构化占位符节点，不用裸字符串替换。
- 重新起草或重新生成时只刷新占位符和明确允许自动更新的字段；人工修改的文本默认保留。
- 用户选择覆盖人工修改时必须展示差异并二次确认。
- 占位符显示为可识别的轻量徽标，导出 Word 前必须全部解析成功；无法解析则阻断生成。

## 附件模型

`assets` 保存附件元数据，文件内容存放在程序数据目录：

```text
data/assets/<前两位哈希>/<完整哈希>.<安全扩展名>
```

| 字段 | 说明 |
| --- | --- |
| `id` | 附件 UUID。 |
| `project_id` | 所属项目。 |
| `content_block_id` | 初次插入的内容块，可为空。 |
| `sha256` | 文件内容哈希，用于去重和完整性校验。 |
| `storage_key` | 相对数据目录路径。 |
| `mime_type` / `file_ext` | 安全类型信息。 |
| `file_size` | 文件大小。 |
| `width` / `height` | 图片尺寸，非图片为空。 |
| `caption` | 默认题注，可被节点题注覆盖。 |
| `created_at` | 上传时间。 |

同一哈希只存一份文件，数据库允许多条引用记录或引用计数字段。删除内容块时不立即物理删除文件，后续由引用扫描清理。

## 类型与限制

- 首批图片类型：PNG、JPEG、WebP；Word 输出前统一转换为 PNG 或 JPEG。
- 禁止脚本、SVG 动画、远程 URL 图片和外链自动下载。
- 单文件和单项目容量上限待定；实现前必须给出上传前校验和超出提示。
- 附件接口必须校验项目归属，禁止仅凭附件 UUID 越权读取。

## API 方向

内容块按拥有者路由，不做无权限边界的通用写接口：

```text
GET    /api/v1/projects/{code}/content-blocks
PUT    /api/v1/projects/{code}/content-blocks/{blockKey}
GET    /api/v1/projects/{code}/rounds/{roundId}/content-blocks
PUT    /api/v1/projects/{code}/rounds/{roundId}/content-blocks/{blockKey}
POST   /api/v1/projects/{code}/assets
GET    /api/v1/projects/{code}/assets/{assetId}
```

问题单、需求、测试项等专属内容块跟随各自业务模块 API 保存，不绕过所属业务校验。
