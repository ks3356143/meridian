# 技术路线

## 成熟方案选型铁律

- 遇到通用交互、动画、虚拟滚动、表格、路由、数据请求、文件解析、Word 渲染等能力时，先检查项目内已有封装，再核对官方文档和主流生态的成熟组件或库；默认不手搓核心算法、状态机和复杂动画时序。
- 候选方案必须与当前技术栈兼容：前端需适配 React 19、Tailwind CSS 4、shadcn/Radix、深浅主题、无障碍和 reduced motion；后端优先 pure Go、可测试、可 Windows 与麒麟 V10 携带运行。
- 成熟方案之间出现取舍时，优先选择维护活跃、API 官方明确、侵入性更小、与现有架构更一致的一项；不盲目叠加功能重复的依赖。
- 手写仅限业务编排、视觉适配，或成熟生态确实缺少对应能力的局部补齐；实施前必须在对应 SRS 记录不用成熟方案的原因、手写边界和验证口径。

## 后端

- Go
- Huma v2
- GORM
- SQLite
- SQLite 驱动使用 `github.com/glebarez/sqlite`，保持 pure Go 路线，避免 CGO。
- 数据库结构使用显式 migration，不长期依赖 AutoMigrate。
- 数据库、附件、模板、报告等运行数据使用程序目录下的相对路径。

## 前端

- Vite
- React
- React Router 8 SPA Data Mode，使用 `createBrowserRouter` + `RouterProvider`。
- 不使用 React Router framework mode 的 `routes.ts` 文件约定。
- 前端源码使用传统 `web/src` 目录。
- Tailwind CSS v4
- shadcn/ui + Radix UI
- Zustand
- TanStack Query
- TanStack Table
- GSAP + `@gsap/react`
- React Bits 炫酷组件（shadcn registry `@react-bits`，动画依赖 `motion`）
- `lucide-react`
- `cmdk`
- `sonner`
- 前端检查使用 OXC 工具链：`oxlint` 负责 lint，`oxfmt` 负责格式化。

## 版本要求

依赖版本跟随当前最新稳定版。React Router 相关包必须保持同一版本，TypeScript 使用当前最新稳定版。

## 主题

默认使用浅色主题，界面上提供明确的深浅色切换；深色主题保留，但不作为默认形态。

## 交叉编译

- 优先选择 pure Go 依赖，确保 Windows 与麒麟 V10 可携带运行。
- 不引入依赖 CGO 的本地库。
