# 跨会话记忆

本文件是跨会话记忆的固定入口。每次会话开工先读本文，再按需读取对应主题 SRS；历史会话流水已清理，只保留当前事实、约束和下一步目标。

## 当前状态

1. 项目 Go 版本为 1.27.1，本机 Go 发行包已恢复干净，直接 `go build` 可用。
2. 需求与追踪页已按“左侧目录 + 可拖拽把手 + 右侧 hero 与详情容器”重构：目录宽度在一级 TAB 切换后保留，整页刷新后恢复默认；hero 只保留“已确认需求”“自动解析未确认需求”两个统计。
3. 左侧当前为 `已确认需求` TAB：一级是依据类工作对象和版本，二级是该来源下已确认正式需求；终极节点不显示展开位。
4. 手动录入流程已可新增确认需求并在详情实时编辑。章节号、标识、名称、需求类型、描述的顺序已确认；来源文档只在详情标题展示；必填校验、失焦保存、保存状态动画和全局错误展开动画均已落地。
5. 同版本有效需求名称唯一、非空标识唯一；标识留空时按名称拼音首字母生成四位，冲突时保留前三位并替换第四位。修改章节号只挂接或创建该需求对应章节，不自动补齐无关父章节。
6. 后端自动解析能力保留：`.doc` 主 SRS 可补传同版本 DOCX 解析副本，解析器支持标题、多级编号、显式章节号、表格和图片占位；解析结果先进入候选，人工确认后进入已确认需求。
7. `R2657` 当前按手动流程验证，仅保留 `§4.4 指令准确率性能测试` 一条确认需求；不要在未获用户明确要求时重新解析或写入测试数据。
8. 需求与测试项为多对多；测试项模块落地后再实现关联展示和追踪矩阵。
9. `knowledge-base/接收文件/` 是用户真实资料，禁止提交、移动或删除。

## 本周目标

1. 全力完成“自动解析 -> 候选需求 -> 人工确认 -> 已确认需求”的完整可用链路，包括解析入口、候选审阅、批量确认或排除、失败提示和真实 DOCX 验证。
2. 同步完善“手动录入 -> 已确认需求 -> 详情修改”流程，保持字段口径、校验、保存状态和树交互一致。
3. 两条链路稳定后，全面审查 `srs/` 与 `docs/` 的链接、逻辑、重复内容和过期描述。
4. 审查后执行代码 Ponytail 优化：删除死代码和重复抽象，收敛边界，保持最小实现，再跑前后端验证。

## 固定偏好

1. 始终使用简体中文；Commit 信息使用中文。
2. 用户要求一步一步做功能：只做用户点名的下一块，不提前铺开。
3. 前端必须先读《07-前端体验》，组件优先 shadcn/ui 与 Radix，表格用 TanStack，树用 `react-arborist`。
4. 界面反馈与动效必须尊重 `prefers-reduced-motion`。
5. 用户说“下班”时：跑验证、检查 `git status`、只提交相关文件、中文 Commit、推送 `origin`。
