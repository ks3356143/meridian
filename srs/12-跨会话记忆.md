# 跨会话记忆

本文件是跨会话记忆的固定入口。每次会话开工先读本文，再按需读取对应主题 SRS；历史会话流水已清理，只保留当前事实、约束和下一步目标。

## 当前状态

1. 项目 Go 版本为 1.27.1，本机 Go 发行包已恢复干净，直接 `go build` 可用。
2. 需求与追踪页采用左侧目录、可拖拽把手和右侧 hero + 详情结构；刷新后目录默认 380px、最大 680px，1100px 以下改为纵向布局且只保留工作区路由一个主滚动。左侧树为“来源文档 -> 已确认需求”两级，需求与测试项保持多对多契约。
3. 手动录入支持章节号、标识、名称、主类型、副类型、描述和标签；副类型不能与主类型重复。详情失焦自动保存，新增弹窗按选中需求预填同级章节号并校验同来源有效章节冲突；支持“保存并沿用”、详情复制新增和树节点右键复制新增；`Ctrl+Enter` / `Meta+Enter` 可连续提交，快捷键说明使用独立 Dialog。
4. 同版本有效需求的名称和非空标识唯一；标识留空按名称拼音首字母生成四位。后端保留 DOCX 解析、候选确认和批量入库链路。
5. “需求回收站”统一管理两类排除记录：统计卡计数含已删除确认需求与已排除候选需求。已排除候选可“撤回排除”回到待确认队列（`excluded -> candidate`，支持单条与勾选批量），已删除确认需求可“恢复确认”回到正式基线（`excluded -> official`），恢复目标由最新 `exclude` 事件来源决定，恢复前做章节、名称、标识冲突检查。支持复制新增、查看审计、单条彻底删除、勾选批量删除和删除全部；彻底删除必填原因并只针对曾进入基线的已删除确认需求，候选排除记录不提供彻底删除且勾选框禁用。
6. 已确认需求支持树内批量编辑和批量删除：跨来源版本勾选、浮动操作栏、单弹窗同时修改主/副类型并按精确子串大小写敏感替换名称或标识；预览先行展示 diff 与同版本唯一性冲突，提交走事务与 `update` 审计。批量删除复用 `exclude` 状态迁移，使用二次确认、可选原因和逐条审计，不执行物理删除。
7. 需求树由 `react-arborist` 负责状态、键盘和虚拟滚动，展开收缩统一由 `useRequirementTreeMotion` 处理，机制是「高度裁剪 + 后续行同步位移」：折叠时保持树打开，把子树从底部向上逐行 `clip-path` 裁剪（不改透明度、不做位移），后续行同步上移；展开时裁剪线从子树顶部向下推进，后续行从展开前的位置回到原位；裁剪线与位移必须共用同一个 travel（方向写反会出现重影）；子树比视口高时按可视比例重排时间轴，视口外位移只占一小段时间；动画期间用 overscan 扩窗，把会进入视口的行提前挂载，否则动画中段空白（扩窗量取「子树行数」与「窗口下方剩余行数」的较小值，展开量在同一次提交里按数据模型算出，扩窗窗口保留 1.5s 再回缩）；超过 200 行的子树直接切换；行坐标统一读内联 top、读写分批，避免强制同步布局（生产构建：小节点 14ms 起动画且无长任务，§4 折叠 27ms 起动画且无长任务）；脚本通过 `data-tree-row` 定位行；行内容按原始值 memo、树行加 `content-visibility: auto` + `contain-intrinsic-size: auto 30px`，`prefers-reduced-motion` 下直接切换。压力验证（拦截夹具 425 行树）：折叠/展开基本无长任务、起动画 12-54ms，全折叠走无动画分支正常；树的完整契约、性能口径与 15 条坑清单见 `srs/22-需求录入与解析/04-编辑删除与体验/02-工作台视觉与交互/03-需求树组件.md`；候选审阅表已改为窗口化渲染（`@tanstack/react-virtual`，整页 DOM 10.4k→1.5k、树滚动 77→9ms/帧），列表只渲染 50 字摘要；加载分层与后续步骤见 `srs/23-数据加载与渲染性能.md`（全局契约）；但候选审阅表未虚拟化（317 行 ≈ 6300 单元格）会把页面滚动拖到 ~70ms/帧，隐藏表格后同一操作降到 ~17ms/帧——下一页性能任务优先给该表加虚拟滚动。两个工作台标签页用 Radix `forceMount` 保持挂载、`data-state=inactive` 时 `display:none` 隐藏，避免每次切换重建面板（生产构建切换长任务 124ms/阻塞 72ms、折叠 51ms/0ms；dev 模式放大约 3 倍属正常）。`vite.config.ts` 已补 preview 代理（本地验证生产构建用 `npm run preview`）。外部选中通过 `setSelection` 同步并 `openParents` + `scrollTo(id, "center")` 滚动到可见（右侧表格点击、批量选中跳转等场景）；点击已可见行用自定义 `renderRow` + `focus(node, { scroll: false })` 跳过库内二次滚动，键盘导航保留自动定位。批量勾选状态通过行级 Context 传递，保持行渲染函数身份稳定。

2. 需求与追踪开发流程固定为“用户真实项目手动体验 -> 反馈问题和需求 -> 讨论方案 -> 确认后开发 -> 验证 -> 下班提交”；未确认方案前只讨论，不提前编码或修改真实数据。
3. 技术选型必须优先成熟方案、成熟组件、成熟库，能使用就不手搓；先查项目内封装、官方文档和主流生态，确需手写时记录原因、边界和验证口径。
4. 前端优先 shadcn/ui、Radix、TanStack Table 和 `react-arborist`；组件视觉使用 CSS Module，动效尊重 `prefers-reduced-motion`。
5. 每次功能或修复汇报必须包含实现内容、自动验证、剩余风险和人工浏览器审核步骤。
6. 终端命令必须使用 PowerShell；普通回复不主动播报时间。
7. 用户说“下班”时：先清理临时文件、死代码和临时验证脚本，检查冗余代码与重复 MD 并做 scoped 模块化拆分；再跑对应验证、检查 `git status`、只提交相关文件，使用中文 Commit 并推送 `origin`。
8. 前端界面视觉验收一律使用截图后由视觉模型直接查看；浏览器任务统一使用 Playwright MCP（本机 Edge channel），Codex 应用内浏览器在第三方 API key 认证下不可用（2026-09-25 实测 cua_repl 报 unsupported Codex auth method: apikey；改用内置浏览器需先用 ChatGPT 官方账号认证登录 Codex），不再重复尝试切换。不再要求用户切换模型，也不用 DOM 文本断言替代视觉判断。
9. 每次会话开工或要求打开前后端时先检查全部依赖更新；有更新时升级到兼容的最新稳定版并验证，再启动或重启。依赖变化后必须同步更新锁文件，不跳过后端或前端任一侧的检查。OfficeCLI 属于必查项：对比 `npm view @officecli/officecli version` 与本机 `officecli --version`，有更新即升级，并把新增命令与快捷能力记入 `srs/03-技术路线.md`。
10. React 性能优化优先参考本机技能 `react19-concurrent-patterns` 与 `build-web-apps:react-best-practices`；Next.js/RSC 专属规则不直接套用到 Vite SPA，所有优化仍以《21-前端性能优化策略》的生产测量和截图视觉验收为准。
11. 启动时更新全部前后端依赖库，包含 Huma v2 等后端库和前端构建、UI、数据依赖。下班时列出本次使用的 skills 并提醒用户决定由代理更新还是用户更新；未获用户明确决定前不自动升级 skills。
12. 微动画偏好为“华丽但克制”：选中、联动和局部状态反馈优先使用 180-280ms 的背景、边框、语义色条、透明度或轻光晕变化；禁止真实位移、内容遮挡、滚动条抖动和字体突变造成布局跳动，并支持 reduced-motion。
13. 前端性能优先铁律：任何页面、组件、表格、树、弹窗和动效先按生产构建测量性能；本地工具也不允许用“能用/数据少”代替流畅。无法压到流畅时必须提供明确加载态（Skeleton / spinner / `aria-busy` / 进度面板），性能验收统一用 `npm run build` + `npm run preview`；开发时可用 `npm run preview:watch` 跑 production React 自动重建（需手动刷新）。
14. 列表/详情分层硬契约：需求、测试项等数据量可能大的模块，列表接口禁止携带原文描述、富文本或图片，只返回摘要和 `hasDescription/hasXxx`；详情与编辑按 id 重新请求完整内容。前端隐藏字段不算分层，后续测试项必须复用同一契约。完整规则、分步路线图与遗留风险台账见 `srs/23-数据加载与渲染性能.md`。
15. 乐观交互铁律：先提交用户意图，再等待服务端。点击、切换、展开、提交和保存必须先在本地可见状态或 Query 缓存中落位，再用 pending / `aria-busy` / 乐观条目 / 按钮 spinner 表示后台同步；服务端返回后 reconcile，失败必须原子回滚并给出可重试反馈。加载态只说明同步过程，禁止让用户面对无反馈的旧界面判断操作是否生效。
16. Playwright MCP 卡死看门狗：任一 `browser_*` 调用超过 15–20 秒未返回，立即按浏览器渲染进程卡死处理，禁止继续等待 300 秒；按 `--user-data-dir` 找到 `mcp-msedge-*` 根进程强制结束，重新打开 `about:blank` 恢复。页面脚本里的 `goto`、`click`、`waitFor` 必须显式设置短超时。
