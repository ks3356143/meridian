# 测试项与执行

> 返回 [需求索引](README.md)

测试项是项目主链路（需求 → **测试项** → 用例 → 执行 → 问题单 → 文档）的关键环：它是测评大纲 6.2 节的载体、测试说明与测试记录的骨架，也是"这一轮测什么"的答案。本主题覆盖测试项与用例的录入、静态测试项（DC/SA/CR/CW）流程、执行记录与轮次范围的衔接。

## 第一刀范围

做：

1. 测试项页：左树 + 右详情（Word 表格观感），树为"类型分组 → 文件夹 / 测试项 → 用例"（子项不上树，见 02）；搜索 + 筛选 + 类型覆盖视图。
2. 测试项字段与测试子项（测试方法）；"子项 → 用例"一键生成按钮。
3. 用例：用例表 + 步骤表（富文本单元格）+ 执行三态 + 快捷键 / 复制 / 拖拽。
4. 需求 ↔ 测试项多对多关联（显式关联，不再"保存需求自动建测试项"）。
5. 静态测试项：DC 审查单列表 + 逐项结果 + 受审文档清单；SA 四张表单（C.1 需录入，其余默认全部通过）；CR 按语言的审查目标三态；CW 源代码文件清单；按项目安全等级生成与删除。
6. 轮次衔接：全局轮次切换器作用域、新建回归轮向导（第一版默认只带上轮未通过用例）、逻辑层与轮次实例两层标识。
7. 面向大纲表 61/62 的"类型覆盖"视图（24 类；未选类型需填写不测评说明）。

不做（后续排期）：

- 问题单层与"未通过 → 立单"闭环（问题单模块就绪后接；树是否挂问题单节点届时再定）。
- 文档生成取数（第 N 轮测试说明 / 测试记录）、时间锚点推导引擎。
- 从 DOCX 批量导入大纲测试项、静态审查单模板的管理端配置页（第一版内置数据）、SA 质量度量报表输出。
