# 七类文档数据映射

## 文档类型

知识库当前有 7 份模板，但项目文档实例数量随轮次扩展。

| 文档种类 | 模板 | 实例规则 |
| --- | --- | --- |
| 测评大纲 | `测评大纲.docx` | 每个项目一份，可随大纲变更生成新版本。 |
| 测试说明 | `测试说明.docx` | 第 1 轮一份。 |
| 回归测试说明 | `回归测试说明.docx` | 第 N 轮（N ≥ 2）各一份。 |
| 测试记录 | `测试记录.docx` | 第 1 轮一份。 |
| 回归测试记录 | `回归测试记录.docx` | 第 N 轮（N ≥ 2）各一份。 |
| 测评报告 | `测评报告.docx` | 每个项目一份，汇总全部轮次。 |
| 问题单合集 | `问题单.docx` | 每个项目一份，按静态和动态问题分组连续排版。 |

内部 `document_kind` 建议使用：`outline` / `test_description` / `test_record` / `report` / `issue_report`，轮次差异由 `round_id` 和轮次号表达，不扩展 `TD2`、`TD3` 这类枚举。

## 数据源总表

| 数据域 | 主要表或块 | 输出文档 |
| --- | --- | --- |
| 项目基础与状态 | `projects` | 全部文档封面和概述。 |
| 相关方与人员 | `related_parties`、项目人员关联 | 大纲、报告、签署和组织分工。 |
| 依据标准与引用文件 | `reference_standards`、来源文档、交付文档 | 大纲、测试说明、报告。 |
| 被测对象 | 项目字段、`dut.*` 内容块 | 大纲、测试说明、记录、报告。 |
| 静态测试环境 | `environment.static.*` | 大纲、测试说明、报告。 |
| 动态测试环境 | `round.dynamic_env.*` | 大纲汇总、当轮测试说明、报告。 |
| 测评数据与差异分析 | `round.test_data.*`、`round.diff_analysis.*` | 当轮测试说明、报告。 |
| 软件更改 | `round.software_changes.*` | 回归测试说明、报告相关性分析。 |
| 需求与追溯 | `requirement_sources`、`requirements`、追溯关系 | 大纲附录、测试说明、报告附件。 |
| 测试设计 | `test_items`、`test_cases` | 大纲、测试说明。 |
| 轮次范围 | `round_test_items`、`round_test_cases` | 当轮测试说明、记录、报告。 |
| 执行结果 | 执行记录、步骤实测、人员和时间 | 测试记录、报告。 |
| 问题与回归 | `issues`、影响域、回归结果 | 问题单合集、报告。 |
| 时间信息 | 时间锚点、推导值、人工锁定值 | 大纲、报告、封面签署。 |
| 专项证据数据 | `evidence_datasets`、数据集行、回归子集 | 大纲或说明附录、测试记录附录、报告专项附件。 |

## 文档实例模型

`generated_documents` 保存输出实例，不作为业务源数据：

- `id`、`project_id`、`round_id`
- `document_kind`
- `document_no`
- `status`：`draft` / `generated` / `locked` / `archived`
- `template_id`
- `current_revision_id`
- `generated_at`、`generated_by`
- `created_at`、`updated_at`

`generated_document_revisions` 保存每次生成结果：

- `document_id`、`version`、`change_summary`、`modified_sections`
- `template_snapshot_asset_id`
- `data_bundle_snapshot_asset_id`
- `file_asset_id`
- `generated_at`、`generated_by`

同一项目 + 文档种类 + 轮次允许多个版本。生成或重新生成时深拷贝模板配置和 Document Bundle 到快照附件；已锁定文档不再被模板和数据修改影响。

## 生成流程

1. 绑定模板并确认适用条件。
2. 执行文档预检，输出缺失数据、校验错误和警告。
3. 组装受限结构化数据和 Tiptap JSON 内容块。
4. Go 渲染 OOXML：字段、表格行、图片、题注、编号和样式。
5. 写入文档实例、版本记录和文件元数据。
6. 提供下载和只读预览。

生成失败必须保留前一个可用版本，不得用半成品覆盖已生成文件。

## 生成装配架构

Word 灵活性来自“模板可配置 + 渲染积木受控”，不来自任意文档转换。装配链路固定为：

```text
块定义注册表 + 数据资源字典 + 文档模板
  → DocumentBundle（项目、轮次、集合、统计、关系）
  → Document IR（章节、段落、表格、图片、题注、占位符）
  → OOXML Renderer（样式、编号、分页、页眉页脚）
  → DOCX
```

### 数据资源字典

所有模板可绑定的数据源必须登记，分四类：

| 类型 | 例子 | 提供者 |
| --- | --- | --- |
| 简单值 | 项目标识、软件名称、研制单位、测评性质、密级、版本。 | 基准数据模块。 |
| 集合 | 测试项、用例、执行记录、问题单、轮次、交付文档。 | 各业务模块。 |
| 统计 | 测试项数、用例数、通过率、问题矩阵、闭环率。 | 统计查询服务。 |
| 关系 | 需求追溯、影响域、历轮结果、文档引用。 | 追溯模块。 |

模板只引用资源 key，不直接写 SQL、不感知表结构。数据提供者负责权限、过滤、排序和项目隔离。

### 文档模板模型

模板属性包含：名称、适用平台、测评性质、文档种类、编号规则、版本规则、状态、模板版本、大纲树、复杂表格、叙述模板和默认标志。

项目创建时按平台和测评性质自动绑定默认已发布模板组；用户可在首份文档生成前更换。生成后项目模板绑定不再整体替换，后续模板演进通过派生模板和显式迁移向导处理，避免历史文档口径漂移。

大纲行角色：

- `heading`：1 到 4 级标题，编号由渲染器生成。
- `content`：正文，绑定 inline、单源、表格、叙述或内置积木。
- `cover`：封面。
- `sign`：签署页。
- `toc`：目录，从大纲树生成。
- `revision`：文件状态表。
- `pagebreak`：分页和纵横向切换。

绑定方式：

| kind | 说明 |
| --- | --- |
| `inline` | 固定话术加占位符。 |
| `singlesource` | 版本化系统单源片段。 |
| `table` | 复杂表格定义。 |
| `narrative` | 可自动起草、可人工修改的叙述组。 |
| `block` | 代码注册的内置渲染积木。 |

### 内置渲染积木

真实 Word 中存在大量无常规表头的连续网格表，必须用受控积木精确复刻，不能用“字段 / 内容”通用表偷懒。首批登记：

- `projectInfoGrid`：项目与被测对象信息横表。
- `testItemSheet`：测试项 10 行结构表。
- `testCaseSheet`：测试用例 12 行结构表。
- `testCaseRecordSheet`：测试记录用例表，含实测结果和通过与与否。
- `environmentBlock`：静态与动态环境组合。
- `traceabilityTable`：需求对照和追踪表。
- `issueReportSheet`：问题报告单三区连续表。
- `changeAnalysisBlock`：软件更改和影响分析。
- `organizationTable`：组织分工表。
- `reviewChecklist`：文档、代码、静态分析审查单。
- `evidenceDatasetTable`：登记过 schema 的大规模专项数据表，支持分块、筛选、差异状态和跨页表头。

积木只消费 Document IR 或已登记数据集，不查数据库、不拼 HTML。

### 复杂表格带区

跨页表、统计矩阵和汇总表使用带区模型：

- `header`：表头，可含占位符和动态列头。
- `detail`：逐记录重复。
- `footer`：合计或说明。
- `group`：按测试类型、问题状态、轮次等分组。

表格定义包含数据集、轮次上下文、排序、过滤、空集合策略、列、合并规则、跨页重复表头、列宽和页面方向。列语义必须绑定已登记字段或统计项，不支持任意表达式。

### 条件渲染与排序

- 未开展的测试类型自动裁剪对应章节、表格和目录项。
- 已开展类型按军标固定顺序输出，不按录入时间排序。
- 空表策略由模板定义：保留空表、跳过章节或输出说明行。
- 目录、章节号、表号和图号在大纲遍历中统一分配。
- 总页数在 DOCX 生成完成后回填，不能提前伪造。

## 版本与锁定

- TO、TR 为外部评审文档：初版 `V1.00`，评审后重新生成升 `V1.10`，再次生成时用户选择保持或升级。
- TD、TN、回归系列和问题单合集恒为 `V1.00`，重新生成只追加文件状态记录。
- 文档生成时固化模板快照和数据快照；已锁定文档不被模板和数据修改影响。
- 单源片段若被系统声明为共享语义资产，修改后可影响后续生成，但必须提示受影响文档。
- 定稿锁定可逆，解锁记录操作者、时间和原因。
- 支持一键打包下载全部已生成且状态正常的文档。

## 导入与回流

- 支持从外部 DOCX 导入软件概述、报告叙述、问题单处理意见等章节。
- 导入采用比对采纳：平台现状与外部内容分栏展示、差异高亮、逐块保留或采纳。
- 未匹配章节只展示，不自动入库。
- 研制方回流的问题单 DOCX 可导入处理意见、原因分析、改正措施和影响域，再进入回归验证。
- 导入来源、采纳时间和采纳人写入内容块变更记录。

## 预检规则

| 文档 | 必查项 |
| --- | --- |
| 测评大纲 | 项目基础、相关方、依据文件、被测对象、静态环境、动态环境、测试项、时间锚点。 |
| 测试说明 / 回归测试说明 | 当轮环境、测评数据、差异分析、轮次范围、用例定义、需求追踪；回归轮另查软件更改。 |
| 测试记录 / 回归测试记录 | 当轮执行结果、步骤实测、执行人员、监测人员、时间、未执行原因、未通过建单。 |
| 测评报告 | 全部轮次闭环情况、历轮汇总、需求符合情况、遗留问题登记、结论叙述。 |
| 问题单合集 | 问题字段、处理意见、影响域、回归结果、签字和时间。 |

预检结果按文档章节聚合，每项提供跳转入口。可警告项允许继续生成，阻断项必须补齐。

## Word 渲染约束

- 模板底座来自 `knowledge-base/` 真实 DOCX，不重画样式。
- 富文本从受限 Tiptap JSON 直接映射 OOXML，不做 HTML 转换主链路。
- 图片通过附件存储路径读取，写入 DOCX media 并维护关系文件。
- 表格列、合并单元格、题注和编号由模板槽位配置驱动。
- 固定话术、单源段落和数据资源引用必须登记，不允许散落在代码字符串中。
- 连续网格表、区带表、跨页表头、横页和签署页必须由内置积木或表格带区模型表达。
- 模板中的明显文字错误可通过槽位映射修正，但必须记录“模板原文 / 生成口径”的差异，便于追溯。
- 大规模记录按真实交付样本压力场景设计：354 个用例、199 张图片、1409 行大表和约 156 页文档必须可生成。
- OOXML 生成使用流式写入和临时文件原子替换，图片和大表不得一次性载入内存。
