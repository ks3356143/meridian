# 需求录入与解析

## 定位

需求与追踪模块必须提供两条录入路径，并写入同一个项目需求基线池：

1. **树状手动录入**：适合没有可解析电子文档、文档解析效果不佳，或用户希望按 SRS 目录快速建立需求树的场景。
2. **SRS 自动解析**：适合已确认的软件需求规格说明电子文档，系统生成候选需求，用户确认后进入正式需求基线。

两条路径不得形成两套需求模型或两个孤立页面。手动录入与自动解析产生的正式需求统一进入需求树、追踪矩阵和后续测试项创建流程。

## 来源与入口

1. 自动解析入口只允许选择状态为 `confirmed` 的工作对象版本。
2. 对象类型为 `软件需求规格说明` 的已确认版本是主 SRS 解析来源。
3. 第一版自动解析范围只包含软件需求规格说明；研制总要求、软件研制任务书、技术要求等顶层依据先完成登记和版本管理，不生成软件需求。
4. 顶层依据后续是否生成顶层需求、隐含需求或仅作为追踪依据，等需求主链跑通后再确认；不得因为来源类型不同而建立第二套需求模型。
5. 需求必须绑定来源工作对象版本。手工新增需求也必须挂到某个已确认来源版本下，不允许出现无来源的游离需求。
6. 已确认主 SRS 的原始电子文件为 `.doc` 时，允许为该版本补传一个 `.docx` 解析副本。副本替换仅更新解析来源，不改变对象名称、版本号、接收信息和原始文件哈希。

## 需求字段

| 字段 | 口径 |
| --- | --- |
| 来源工作对象版本 | 必填，来自已确认工作对象。 |
| 父章节 | 树状结构中的章节节点。 |
| 章节号 | 必填，用于排序、原文定位和版本比对。 |
| 标识 | 用户可录入，或保存 SRS 中已有的 A1、SSS-001 等编号；留空时按名称拼音首字母生成四位。同一来源版本内非空标识不重复。 |
| 需求名称 | 必填；同一来源版本内候选/正式状态不得重复。 |
| 需求描述 | 必填，第一版使用保留换行的多行纯文本，段落直接保存，表格和图片以占位保留；后续必须支持结构化表格、图片资产和原文锚点。 |
| 需求类型 | 单选：功能、接口、性能、安全性、可靠性、其他。 |
| 副类型 | 可选多选，选项与需求类型一致，但不得与主类型重复；用于标记复合性质，不作为附加标签保存。 |
| 附加标签 | 多选或自由标签，只作辅助筛选，不参与主性质统计。 |
| 原文锚点 | 自动解析需求保留章节、段落或表格定位，用于回看原文。 |
| 状态 | 见需求状态口径。 |
| 关联测试项 | 测试项模块落地后实现，软件需求与测试项多对多。 |

软件需求不保存平台字段。项目平台是唯一权威；需求、测试项、用例不因平台重复建模，平台相关统计从项目上下文推导。

需求描述的演进口径：

1. 第一版不引入富文本编辑器，先用多行纯文本保存需求文字，保证需求树、确认和追踪主链先落地。
2. Word SRS 中常见富文本、图片和表格不能被长期丢弃；自动解析接入后，原文锚点必须保留来源位置。
3. 后续需求描述升级为结构化富文本时，必须支持加粗、上下标、图片、表格和原文片段迁移，并保留纯文本投影用于比对和搜索。
4. 首版遇到无法转为纯文本的图片或复杂表格时，候选页必须提示“该片段需保留原文查看”，不得伪装成完整需求描述。

## 树结构口径

1. 树节点分为章节节点和需求节点。
2. 章节节点只承载目录结构和层级，不进入追踪矩阵，不生成测试项。
3. 需求节点必须具备需求文字，才算一条软件需求；只有章节号和标题的节点是章节节点。
4. 左侧树展示来源文档、章节和需求的层级；测试项、用例、问题单可作为追踪子节点预览，但不在需求树内直接编辑。
5. 需求章节号必须与 SRS 实际章节号一致。根节点手工录入不预填 `1`、`2` 这类顺序号；只有选中已有父章节时，才可按该章节下的已有章节和需求预填下一个子级编号。预填值不能静默成为权威值。
6. 有电子 SRS 时，章节号必须与原文标题锚点匹配，或由用户在候选确认时明确确认。无电子文件的手工登记场景，章节号由用户确认后保存。
7. 章节号保存前校验空值、格式、同级重复和跨层级明显冲突；对无法与原文匹配的编号给出警告，不自动替用户改写。
8. 手工登记服务测试关注的章节和需求，不要求补齐 SRS 全书目录。保存需求时只创建该需求对应的章节节点；父章节存在则挂载，不存在则保持根节点显示，禁止自动创建与测试无关的父章节占位节点。
9. 修改确认需求的章节号时，目标章节已登记则挂接既有章节，未登记则创建该需求对应的手动章节；父章节规则与新增需求一致，不自动补齐无关父章节。
10. 章节号字段行内说明只保留“与 SRS 章节号一致”单行短口径；父章节是否自动补齐属于系统行为规则，不用长说明增加表单高度。
11. 自动解析识别并保存整本 SRS 目录；测试作业面通过 `inScope` 动态计算。候选/正式需求所在章节及其祖先进入测试需求视图；参考资料、背景说明等无需求目录保留在全文视图中，不污染作业树。排除候选后，其章节自动退出作业面，重解析不会丢全文目录。

## 手动录入交互

1. 用户可在左侧树选中章节后新增子章节或需求节点。
2. 保存需求后直接进入正式需求基线，不额外要求二次确认。
3. 支持“保存并继续”，保存后保留当前来源与父章节，焦点回到需求名称。
4. 支持批量粘贴章节结构，兼容 `章节号 名称 主性质` 格式；粘贴内容先进入预览，用户确认后批量入库。
5. 批量粘贴预览必须逐行识别章节号、名称和主性质，展示格式错误、章节号重复、层级无法识别和主性质无效等问题；用户修正或明确跳过后才能入库。
6. 批量粘贴首版不强制填写描述，入库后通过详情页补充；后续可扩展 `章节号 | 名称 | 主性质 | 描述` 完整格式。
7. 支持搜索章节号、名称、描述、外部标识和标签。
8. 支持批量修改主性质和附加标签。
9. 手动录入页必须优先服务连续作业：常用字段在一屏内完成，键盘 Tab / Enter 流不得被弹窗打断。

## 自动解析与确认

1. 自动解析只生成候选需求，不得直接写入正式需求基线。
2. 章节识别优先使用 Word 标题样式和多级编号；无样式的显式 `1.1 标题` 仅作为兜底，目录样式、表格内段落和日期/版本号不得生成章节。
3. 标题形如 `[RQGN001-XXX-001] 名称` 的叶子功能识别为候选需求，外部标识写入需求外部标识字段；其下“子功能概述 / 输入信息 / 业务处理需求 / 输出信息”合并为该叶子需求描述，不单独生成候选。
4. 功能需求组之外的章节仅当标题包含“功能 / 需求 / 要求 / 约束”且描述含“应、须、确保、能够”等规约词时生成候选，降低背景、术语和文档说明误报。
5. 自动解析把全书目录写入章节表；重解析只清理“原文中已不存在且无子节点、无需求引用”的解析章节，手工章节和已有需求引用章节保留。作业面由需求状态动态推导，不删除全文参考目录。
6. 表格第一阶段只保留 `[表格]` 占位，图片保留 `[图片]` 占位；后续升级为结构化表格、图片资产和原文锚点。
7. 候选确认页使用左树右表：左侧为需求章节链，右侧为候选需求表。
8. 候选需求必须展示原文片段或原文上下文，便于判断解析是否漏项、重复或误把说明文字识别为需求。
9. 用户可逐条或批量确认、排除、合并、拆分、修改后再确认。
10. 确认后的候选需求进入正式需求基线；排除项保留排除结果，避免下次重复解析时反复出现在待确认列表。
11. 自动解析不得阻塞手动录入；两种路径可以并行使用。

## 需求状态

状态用于隔离未确认内容、保留审计和支撑版本演进，不是为了增加用户管理负担。日常界面只在必要位置展示状态。

| 状态 | 用途 |
| --- | --- |
| 候选 | 自动解析产生，尚未人工确认。 |
| 正式 | 人工录入保存后，或候选需求确认后，进入当前有效需求基线。 |
| 已排除 | 人工判断不是软件需求、重复或不应采纳；保留排除记录，避免重复识别。 |
| 已替代 | 新 SRS 版本采纳差异后，旧版本需求退出当前基线，但保留历史追踪。 |

版本差异中的新增、删除、描述变化、章节移动、性质变化是比对结果，不落成新的需求状态。界面用差异标签展示，用户采纳后才写入对应版本基线。

## 自动创建测试项

1. 需求保存或确认为正式需求后，系统默认自动创建关联测试项。
2. 需求与测试项采用多对多追踪；自动创建策略、测试项名称、标识、挂载位置和类型映射在测试项模块设计时确定，不得在需求侧硬编码一对一限制。
3. 测试项模块尚未实现前，本条只作为需求侧契约记录：需求保存不得因测试项能力未落地而失败，必须保留自动创建意图或待执行关系。
4. 后续实现测试项模块时，必须补齐自动创建结果、失败重试和需求与测试项的追踪关系。
5. 来源需求被排除后，需求与测试项关系保留。测试项列表、统计入口、详情和追踪矩阵必须提示“来源需求已移出基线”，报告生成预检将其列为风险；完全没有需求来源的测试项另行提示“无来源需求”并提供筛选。

## 编辑与删除

1. 当前基线中的正式需求允许修正名称、描述、主性质和附加标签，保存时记录修改审计。
2. 需求已有关联测试项或后续追踪关系时，编辑需求不自动改写测试项内容，只提示受影响范围。
3. 正式需求不提供无痕物理删除；不再适用时使用带原因的排除或替代流程，保留历史追踪。
4. 候选需求可以删除或排除；排除必须尽量记录原因，用于下次解析降噪。
5. 已确认需求树提供需求节点右键菜单，使用 Radix ContextMenu 展示“删除需求…”；右键时先选中当前需求，来源节点和空白区域不提供删除。菜单打开与关闭使用 Radix 状态动画，`prefers-reduced-motion` 下关闭动画。
6. 需求详情头部提供 destructive outline 的“删除”按钮，与右键菜单共用同一个 AlertDialog 二次确认。确认框展示章节号、名称与来源版本，明确“从已确认基线移除并保留审计记录”；删除原因可选、最多 500 字，提交中禁止重复确认，失败时保留已填内容。
7. 详情头部删除按钮为 destructive outline 的“图标 + 删除”文字按钮，保留 Tooltip；宽度由文字自然撑开，不挤压状态徽标，便于识别危险操作。
8. 删除确认需求复用既有 `official -> excluded` 状态接口，不做物理删除；新增和删除后的树行位置变化使用 GSAP Flip 处理，新增行只做淡入，删除行先在真实 DOM 上淡出再刷新，不克隆被移除行。树行渲染组件必须保持稳定身份，避免选中项变化时 React 更换行 DOM 导致动画落在旧节点。
9. 顶部统计卡提供“已删除需求”入口，仅统计最新删除事件从 `official` 进入 `excluded` 的记录；整张统计卡可点击，并显示带图标的“管理”操作胶囊，使用危险色左轨、浅色底与 hover/focus 反馈，空态仍保留入口。
10. 已删除确认需求管理使用 Radix Dialog + TanStack Table：展示章节、名称、来源、删除原因和删除时间；窄屏隐藏低优先级列，仅表格自身必要时横向滚动，不得造成整页横向溢出。
11. “恢复已确认”仅允许最新删除来源为 `official` 的 `excluded` 记录执行，状态接口必须校验需求属于当前项目，恢复前检查同版本有效章节、名称和标识冲突；成功后回到 `official`，测试项任务恢复为待建，并写入 `restore` 审计事件。恢复失败时保持管理弹窗打开并展示当次错误。
12. “复制新增”从删除记录继承名称、描述、主类型、副类型和标签；章节号预填原章节在当前有效基线中的下一个兄弟编号，标识留空自动生成，不继承原文锚点、状态、测试项任务和审计历史。
13. “查看审计”打开独立 Radix Dialog，按事件追加顺序倒序展示动作、状态迁移、说明、操作人和操作时间；审计接口返回操作人显示名，历史记录不可编辑。
14. 已删除确认需求管理提供“彻底删除”：仅允许最新删除来源为 `official` 的 `excluded` 记录执行，必须填写 1-500 字原因并使用 AlertDialog 二次确认。执行后物理删除该需求及需求审计事件，不再出现在已删除管理和任何统计中，也不可恢复；确认框必须明确该不可逆影响。
15. 测试项模块落地后，彻底删除有关联测试项的需求前必须先处理关联：列出受影响测试项，将其来源变更为“隐含需求”或由用户明确解除关联；未完成处理不得物理删除。来源为已排除但未彻底删除的需求仍保留关联，并提示“来源需求已移出基线”。

## 界面与体验要求

1. 需求与追踪页采用左树右详情布局；桌面端可左右拉伸，右侧任务卡、编辑区和候选区必须同步重排；树节点展开收起不得造成右侧内容横向抖动。
2. 两个入口使用同一个模块内的分段选择或任务卡表达：`解析 SRS` 与 `手动建立需求树`，不得让用户猜测入口归属。
3. 空态必须直接给出两条路径，并显示已确认 SRS 的对象名称和版本。
4. 树节点需要完整名称悬浮提示、主性质徽标、需求计数和未完成提醒；长文本省略但不丢信息。
5. 候选确认表必须支持批量选择、状态筛选、原文上下文展开、差异高亮和错误定位。
6. 页面视觉延续工作区工程风：层级清晰、留白舒适、语义色克制；可用品牌绿做进度和确认态，用蓝色做解析态，用橙色做待确认提醒，用红色做误识别或冲突。
7. 交互组件优先使用 shadcn/ui、Radix、TanStack Table；需求树使用 `react-arborist` 专业树组件，保留虚拟滚动、键盘导航、ARIA treeitem、焦点和筛选能力。业务侧禁用拖拽、多选和内联重命名，章节顺序只由 SRS 实际章节号决定。
8. 录入过程不得因装饰动效拖慢输入；动画只用于路径切换、状态反馈、节点加入、树节点展开收缩和批量确认进度。

### 紧凑工作台视觉

1. 需求树默认使用紧凑密度：正文 12px，树节点行高 30px，章节子级缩进 14px；徽标、计数和状态点使用 11px 左右小字号。
2. 桌面端需求树是主作业面：整页刷新后默认 380px 宽，最小 22%、最大 680px；从一级导航下方延伸到可视区域底部，右侧详情与候选区共享剩余宽度。树面板高度必须逐级继承工作区真实剩余高度，不得用 `100svh` 减固定偏移估算；页面和左栏外框不产生纵向滚动，仅树内容超过可用高度时在树内部滚动。1100px 以下退出左右拉伸并按树、统计、详情纵向排列，只保留工作区路由一个主纵向滚动：树按当前展开内容的自然高度完整参与路由滚动，统计和详情正文随内容展开；详情内多行文本达到最大高度或表格确实横向溢出时才允许局部滚动，禁止路由、树、详情同时出现纵向滚动条。1101px 以上的树宽在项目工作区一级 TAB 切换后必须保留；该记忆仅存在于当前 SPA 页面会话，整页刷新后回到默认 380px，不写入长期浏览器存储。
3. 项目说明、SRS 选择、解析入口和统计卡合并为右上紧凑任务卡，不再横跨页面顶部；任务卡主标题使用 16px，右栏其余标题默认 14px，表单、说明和候选表以 12-13px 为主，输入/下拉/按钮高度约 28px，需求描述默认 4 行并可手动拉伸。章节号等窄字段的说明必须单行显示；需求录入表单关闭浏览器自动填充，不显示 Edge 保存的历史内容。
4. 树节点纵向间距控制在 2-4px，工具栏与树内容间距不超过 8px，优先保证一屏能看到更多章节和需求。
5. 密度收紧仍必须保留层级识别：不同层级使用浅色底、左侧 2px 语义色轨或缩进导线区分，不允许只靠缩进硬撑层级。
6. 需求节点显示主性质徽标、前 1 个附加标签和追踪计数；章节节点显示子需求数。徽标保持短标签、统一宽度和对齐，不占用长文本空间。
7. 树节点章节号、名称、附加标签和徽标文字必须省略号显示，真实溢出时用 Radix Tooltip 展示完整内容；禁止原生 `title`。
8. 左侧目录区从 `已确认需求` TAB 开始逐个重建；该视图仅展示已确认正式需求，后续候选、全文和列表视图必须等用户逐项确认信息架构后再加入。方向键由 `react-arborist` 处理。
9. 顶部统计卡的章节计数使用“作业面 / 全文”双口径；切换主视图不改变统计口径。
10. hover 与选中态使用背景、边框和轻阴影变化，不做位移；选中行保持高对比左轨与浅色底，保证长树滚动时定位清晰。
11. 窄屏允许把树收进抽屉；抽屉内仍使用紧凑密度，不得退回大间距移动端列表。
12. 拉伸把手必须有可见焦点态、键盘调整能力和 `aria-label`；1101px 以上启用左右拉伸，1100px 以下退出面板布局并按“头部 -> 树 -> 详情”纵向排列，禁止窄屏出现横向滚动。
13. 右上任务卡拆为上下两区：上区承载标题、状态徽标和四项统计，下区承载主 SRS 选择、解析和批量粘贴操作。主 SRS 下拉与两个操作按钮同排并弹性占满剩余宽度，优先完整显示“对象名 + 版本号”；弹层保留视口碰撞边距。
14. 720px 以下操作区改为单列，SRS 下拉占满可用宽度，两个操作按钮等宽分列；统计在空间不足时换行，不遮挡标题和操作。
15. 四个统计小卡片使用完整贴边的左侧语义色轨：章节为中性色，正式需求为主色，候选需求为警告色，待建测试项为信息色。
16. 需求工作台内部所有滚动条（需求树、右侧详情、候选表格横向区域）统一使用 8px 直角样式，轨道与滑块跟随浅深主题和品牌主色；滑块 hover 加深，不做圆角胶囊滚动条。
17. 需求树内部不显示空态提示；录入引导只保留在右侧编辑区和任务卡，筛选无结果时保持树区域安静。
18. 需求树层级导线参考老项目软件需求与测试项目录：子级行左侧绘制 2px 主题色连接轨，一级连接使用信息蓝，二级使用品牌青绿，后续层级依次使用警告橙与危险红；当前末级导线带短横向肘形连接，深浅色下保持可辨且不遮挡文字。展开收缩继续由 `react-arborist` 负责状态、键盘与虚拟滚动；`react-arborist` 未内置展开动画，呈现层使用 GSAP Flip 的成熟 FLIP 方案处理仍存在行的位置变化，新增行只做淡入，折叠先让真实子行原地淡出，不在每行自己的补间结束点清理样式，而是等整组完成后同步提交 close 并统一清理，避免 stagger 造成前面的文字闪回；不做进入退出位移，避免克隆行或文字在行容器内漂移；虚拟列表行本身已是绝对定位，Flip 不额外启用 absolute，树内容链路横向裁剪，防止动画期间出现底部横向滚动条；每次补间控制在 160-220ms，`prefers-reduced-motion` 下直接切换。

### 易用性与华丽感

1. 需求工作台默认一屏完成选择路径、定位章节和录入需求；不得把连续录入拆成多个跳转页面。
2. 手动录入右侧详情采用分区表单：基础信息、需求描述、性质标签、原文确认和测试项契约依次排列；常用字段优先，低频字段折叠。
3. 自动解析确认页桌面端采用三区布局：左侧紧凑章节树，中间候选需求表，右侧原文上下文；1280px 以下原文上下文可折叠为侧边抽屉或分段页签。
4. 批量粘贴使用“粘贴输入 -> 解析预览 -> 错误修正 -> 批量入库”四步，不直接入库；预览表支持行内修正和错误定位。
5. 键盘流必须完整：树节点上下移动、展开收起、进入详情；表单内 `Ctrl+Enter` 保存并继续，`Esc` 取消编辑；快捷键不得与浏览器和输入法常用组合冲突。
6. 快捷键说明入口必须常驻在需求树工具栏，不占用树内容高度；说明弹窗支持键盘 Tab 导航、Esc 关闭和横向滚动，窄屏不得出现整页横向滚动。说明内容只记录当前已实现能力，不预告未落地快捷键。
7. 保存并继续后保留当前来源版本、父章节、主类型和副类型默认值，焦点回到需求名称，并用轻量插入动画标记新节点。
8. 候选确认支持按章节全选、按解析置信度分组、按主性质批量赋值；批量操作显示进度和失败行，失败后不回滚已成功行。
9. 正式需求详情提供“复制新增”：继承名称、描述、主性质和附加标签；章节号自动预填为原章节的下一个兄弟编号，用户必须确认实际章节号。复制不得继承原文锚点、测试项任务状态、状态和审计历史。
10. 视觉上允许使用克制的华丽效果：章节树左轨和选中行轻光晕、候选确认进度流光、主性质徽标浅色渐变、原文差异高亮；装饰不得遮挡文字、增加输入延迟或造成滚动抖动。
11. 空态和低置信度候选用说明卡引导下一步，但不使用营销式大图；所有入口按钮必须一眼可点击。
12. 深浅色模式下均需验证紧凑树的文字对比度、焦点环、徽标可读性和原文差异高亮；reduced-motion 下只保留状态变化。

### 老项目对照

1. 借鉴老项目的高价值能力：需求详情可复制新增、树节点显示状态与性质标签、需求/测试项/用例/问题单可筛选、批量导入有预览、来源文档和章节号明确展示。
2. 暂缓老项目的追溯矩阵和标注总览：等待测试项、用例、问题单和富文本原文锚点真实建模后再进入字段级设计，不先做静态假视图。
3. 屏蔽老项目的混层编辑：需求树只编辑章节和需求；测试项、用例、问题单作为后续追踪预览，不在需求树内直接新增或改名。
4. 屏蔽需求级版本号和物理删除：需求版本由来源 SRS 版本驱动，正式需求通过排除或替代留痕，不允许无审计删除。
5. 需求与测试项多对多，但同一需求-测试项关系对必须唯一；老项目原型中重复关系记录的形态不得复用。
