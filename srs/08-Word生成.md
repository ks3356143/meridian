# Word 生成

## 路线

文档生成采用“原始 DOCX 模板 + 结构化数据 + Go 渲染 OOXML”。

## 要求

- 模板底座来自 `knowledge-base/` 中的真实交付文档。
- 保留封面、页眉页脚、字体、表格样式和编号格式。
- 业务数据存放在 SQLite 中。
- Go 根据受限的报告文档模型渲染字段、章节和表格行。
- Go 根据受限的文档数据模型和 JSON 内容块渲染字段、章节、表格行和图片。
- 正文图片与表格的尺寸、对齐与列宽口径见《[正文图片与表格尺寸口径](22-需求录入与解析/07-正文图片与表格尺寸口径.md)》：段落图片约正文宽的 3/4、单元格内图片按单元格宽度分档（大格约 60%）、极端长宽比自动收缩；居中 / 靠左完全跟随富文本，全程等比不失真。
- 支持多被测系统和多类报告。
- 七类知识库模板与业务数据映射见《17-七类文档数据映射》。
- 模板大纲、数据资源字典、内置渲染积木、复杂表格带区、叙述占位和导入比对是生成灵活性的六个基础能力。

## 外部引擎分工（OfficeCLI）

- 选型结论、边界和前置验证见《技术路线》的「外部文档引擎（OfficeCLI）」。
- 交给 OfficeCLI 的三件事：**模板合并**（`merge` / `dump` + `batch`）、**OpenXML schema 校验**（`validate`）、**生成后页面预览**（`view --render html` / `view screenshot`）。
- 仍然由 Go 负责：文档内容模型、数据装配、JSON 内容块 → OOXML 的映射、入库与状态流转。
- 预览产物由后端渲染并缓存为静态资源，前端只消费产物；`view html` 不进入生成链路，「不采用通用 HTML 转 OOXML」的结论不变。
- OfficeCLI 不可用时退回 Go 原生渲染路径，生成与预检功能不得整体不可用。
## 不采用

不采用通用 HTML 转 OOXML 作为主方案。HTML 可用于页面预览，但不是 Word 生成的中间格式。
