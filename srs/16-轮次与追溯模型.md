# 轮次与追溯模型

> 轮次的权威模型是“每轮复制 `test_items` 子树”；复制与静态项规则见 [05 轮次树与轮次复制](24-测试项与执行/05-轮次树与轮次复制.md)，标识规则见 [01 数据模型与标识](24-测试项与执行/01-数据模型与标识.md)。本文只保留轮次定位、所有权与追溯口径。

## 核心定义

一轮测试是一份测试说明、一份测试记录和一组本轮执行数据的组合。轮次不是所有业务数据的父节点，而是测试范围和执行数据的快照上下文。

项目创建成功后在同一事务中自动创建第 1 轮，初始状态为 `draft`；**历史项目在首次进入测试项页时懒补齐同一轮**（不批量改写存量数据）。项目列表可显示项目状态，项目状态与轮次状态分开维护。

## 数据所有权

| 层级 | 数据 | 规则 |
| --- | --- | --- |
| 项目级 | 项目基础、相关方、人员、依据文件、被测对象、静态环境、时间锚点、需求树、测试项逻辑定义。 | 全轮共享，不随轮次复制。 |
| 轮次级 | 动态环境、测评数据、差异分析、软件更改、轮次范围、执行记录、本轮新问题。 | 每轮独立，修改不影响历史轮和已生成文档。 |
| 逻辑层 | 需求、测试项、用例的稳定标识和追溯关系。 | 跨轮保持同标识，用于历轮汇总。 |
| 实例层 | 某轮纳入的测试项、用例及其执行结果。 | 只归属当前轮，可从逻辑定义生成。 |

## 大纲评审与第一轮（2026-11-03 口径）

- 项目时序的第一个节点是「测评大纲评审生成」，在轮次执行之前；此时测试项已经存在（测试项是测评大纲 6.2 节的载体），不要求先有轮次执行数据。
- 不建独立阶段对象、不做阶段门槛、不新增页面；该节点只决定报告中的大纲评审时间字段如何渲染。时间值后续由测试人员手工填写。
- 项目状态由测试人员手动从「编制大纲中」改为「大纲已评审」，当前不校验前置条件；状态选项统一为 编制大纲中/大纲已评审/测试执行中/回归验证中/报告编制中/已完成。
- 第 1 轮在项目创建时生成，用于承载执行数据；它与大纲评审节点是先后关系，不是同一状态机。

## 轮次模型

`test_rounds` 核心字段：

- `id`、`project_id`
- `round_number`：项目内从 1 连续递增。
- `name`：默认“第 N 轮”，允许修改。
- `round_type`：`initial` / `regression`（内部标识，分别对应“首轮 / 后续轮”；不作为用户可见文案）。
- `status`：`draft` / `ready` / `executing` / `closed`。
- `started_on` / `ended_on`
- `dut_version`
- `dynamic_test_location`
- `change_reason`：`problem_fix` / `requirement_change`
- `reason_summary`
- `source_round_id`：第二轮及以后轮次的基准轮。
- `created_at` / `updated_at`

唯一约束：`project_id + round_number`。删除轮次仅允许删除未生成文档的草稿轮，后续以归档为主。

轮次起因只有问题修复和需求变更两类。“软件出了新版本”是更改的结果，不作为单独建轮原因。一轮只对应一个被测件版本；版本升级链由各轮 `dut_version` 组成。

## 轮次基线与阶段

每轮保存输入基线：被测软件版本、需求等技术文档版本、专项数据集版本、测试设计和静态 / 动态阶段状态。第二轮及以后轮次的更改分析从上一轮基线推导。

`round_stages` 属于早期规划：当前迁移没有该表，静态/动态阶段门槛尚未实现；项目策略“静态问题闭环后再启动动态测试”也未落地。

## 测试项与用例模型

- `test_item_types` 是全项目唯一类型字典，字段包含：类型代号、展示名、静态 / 动态分类、军标输出顺序、适用平台、默认测试方法和是否系统内置。DC、SA、CR、CW 等静态类型由系统预置；功能、性能、接口等动态类型按字典输出，不在前端硬编码。
- 类型字典同时声明测试项后缀和用例序号的长度、字符集与唯一性作用域；后缀可以是 4 到 6 位，不把“固定 4 位”写死在通用模型里。
- `test_item_folders` 保存项目级文件夹树，与测试项使用同一容器排序规则，支持文件夹和测试项在同容器内穿插排序。
- `test_items` 每轮一份，`round_id` 归属轮次，`lineage_key` 串联跨轮同源对象；`test_sub_items`、`test_cases`、`test_case_steps` 都挂在当轮测试项下。
- 需求与测试项按当轮测试项 ID 建立多对多关联；跨轮复制时关联随子树复制，历史轮修改不影响当前轮。
- 旧 `round_test_items` / `round_test_cases` 及 `reuse / modified / new` 来源类型不实现；整树复制、执行字段清空与静态项规则统一以 [05](24-测试项与执行/05-轮次树与轮次复制.md) 为准。

## 静态审查数据

> 2026-11-03 更正：早期设想的 `test_item_review_targets` / `review_checklists` / `review_results` / `quality_metrics` 物理表未落地（迁移中不存在）。实际实现以 [24-测试项与执行/04-静态测试项.md](24-测试项与执行/04-静态测试项.md) 与 [07-审查单模板与问题单闭环.md](24-测试项与执行/07-审查单模板与问题单闭环.md) 为准：

- 静态工作台整体存 `static_test_workbenches.payload_json`，按 `version` 做乐观并发控制。
- 审查单模板存 `review_checklist_templates`，管理员在「设置 → 审查单配置」维护；已绑定审查单是快照。
- DC 不通过项可立正式问题单，存 `issues`，状态 `open` / `closed`，关闭后回写 DC 审查项的闭环展示。
- 审查单输出由模板与结果组装，不在 Word 渲染器里硬编码检查项。

## 回归范围默认规则

第 N 轮（N ≥ 2）默认范围：

1. 上轮未通过用例及其所属测试项。
2. 上轮问题单影响域关联的测试项，其下用例默认全选。
3. 需求或被测对象变化关联的测试项，作为提醒项供人工勾选。
4. 测试人员自由追加或移除，最终范围以人工确认结果为准。

新建轮次向导分三步：范围勾选、轮次数据继承策略、版本和时间信息。默认动态环境、测评数据、差异分析沿用上一轮，可切换为空白新建。

## 轮次内容继承

- 沿用上一轮时，深拷贝对应 `content_blocks` 的 `body_json` 和 `payload_json`，不共享对象。
- 附件文件不复制，实例节点继续引用同一 `assetId`。
- 软件更改部分不自动继承，第二轮及以后轮次手动填写。
- 第 1 轮也包含环境差异性分析。
- 时间推导重算时，仅覆盖未人工锁定的推导值。

## 需求追溯

链路为：

```text
来源文档 → 需求 → 测试项 → 用例 → 执行记录 → 问题单
```

- 需求树项目级唯一，不复制到轮次。
- 需求详情显示关联测试项和历轮执行结论。
- 测试项详情显示来源需求、用例覆盖和历轮结果。
- 当前轮视角下，需求树按当前轮实例自底向上显示；切换“全部”时显示全量逻辑树。
- 需求符合情况默认按历轮结果推导，允许人工覆盖并记录覆盖原因。

## 缺陷与报告单

- 缺陷 `issues` 归属发现轮，状态 `open` / `closed`；当前与审查结果、用例、下一轮复测均未建模关联，只作独立记录（2026-11-03 口径）。
- 对外报告单 `issue_reports` 是独立聚合载体，可聚合多个缺陷；统计时区分缺陷数和报告单数。
- 缺陷关联用例、回归结果回填、报告单分层仍待单独确认，确认前不实现联动。

## 完善度口径

- 测试项完善度：有追踪关系、至少 1 个子项且每个子项的“操作步骤 / 通过准则”非空、充分性要求非空；树与详情必须同口径。
- DC/CR 进入即视为完成（默认全部通过），只有存在不通过项时才标记未完善。
- 完善度由后端统一计算，前端只展示，不在多个组件内重复推导。

## 全局轮次切换与信息录入口径（2026-10-10 定稿）

- **作用域**：全局轮次切换器只作用于 **测试项、轮次、问题单、文档生成** 四块（取轮次级数据）；作业台、资料与对象、需求与追踪不联动。需求树是项目级唯一一棵，将来要看"本轮覆盖情况"用需求页内筛选，不用全局切换器。
- **位置与显隐**：工作区顶栏、项目名右侧；仅在作用域内的页面显示，其他页面隐藏，避免"切了没反应"。
- **选项**：第 1 轮 … 第 N 轮；测试项与问题单额外提供「全部」（全部 = 逻辑层全量，节点挂历轮徽标）。
- **默认值**：最新进行中的轮次，无进行中则取最后一轮；状态写入 URL 查询参数，刷新、回退、分享都保持。
- **切换后**：当前选中的测试项 / 用例不属于新轮时自动改选该轮第一个测试项（静态项优先），180–320ms 过渡，不闪白；轮次页内选中与切换器双向同步。
- **轮次信息录入（第一版）**：动态测试环境、测评数据、环境差异性分析、软件更改部分用**内容块**存储——章节正文用富文本块，软件项 / 硬件和固件项等用结构化表格块（列固定、可校验）；文档生成按模板章节直接取块，不采用固定字段表单。
- **第二轮及以后范围（第一版）**：新建第二轮及以后轮次默认只带入"上轮未通过用例及其所属测试项"，其余人工勾选增删；"问题单影响域"与"需求变更提醒"两条在上游模块就绪后接入。
- **首轮范围不做硬锁定**：提供"范围已确认"标记与后续变动提示即可（个人工作站定位）。
