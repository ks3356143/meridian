# 路由与布局

> 返回 [项目工作区与前端模块](../14-项目工作区与前端模块.md)

## 定位

项目列表只做全局索引、筛选和待办入口。点击项目后先进入项目详情状态页；项目详情负责展示阶段、完成度、关键指标和缺失项，再通过常显主操作进入独立项目工作区。工作区承载该项目的资料、需求、测试设计、轮次执行、问题单和文档产出。

工作区是“独立全屏路由 + 一级导航 + 模块二级导航”，不是单个巨型页面组件。所有业务模块可独立开发、懒加载和验证。

## 路由结构

| 路由 | 模块 | 说明 |
| --- | --- | --- |
| `/projects/:code` | 项目详情 | 只读状态驾驶舱，不承载录入。 |
| `/projects/:code/workspace` | 作业台 | 当前任务首屏，展示任务队列、测试项组织树、需求导入链路和数据主链路。 |
| `/projects/:code/workspace/outline` | 大纲编制 | 过渡保留入口；后续并入作业台任务簇。 |
| `/projects/:code/workspace/profile` | 资料与对象 | 接收文件录入、工作对象、文档版本、代码包，并兼容原项目资料。 |
| `/projects/:code/workspace/dut` | 被测对象 | 过渡保留入口；后续并入资料与对象。 |
| `/projects/:code/workspace/requirements` | 需求与追踪 | 需求池、导入工作台、版本比对、追踪矩阵、覆盖分析。 |
| `/projects/:code/workspace/test-items` | 测试与执行 | 测试项、静态测试工作台、用例、轮次、记录和问题入口。 |
| `/projects/:code/workspace/rounds/:roundId` | 轮次工作区 | 动态环境、测评数据、差异分析、本轮范围、执行与回归。 |
| `/projects/:code/workspace/issues` | 问题单 | 跨轮问题列表、详情、处理意见、回归链。 |
| `/projects/:code/workspace/documents` | 交付与文档 | 文档实例、生成预检、时间口径试算、生成记录和导出。 |
| `/projects/:code/workspace/evidence` | 专项证据 | 项目能力启用后显示，用于专项数据集导入、校验、筛选和回归子集。 |

路由参数使用项目业务标识 `code`，服务端内部再解析为项目 UUID；页面跳转和用户分享不得依赖数据库 UUID。

## 工作区布局

工作区是独立全屏路由，不挂系统后台 `BasicLayout`，不显示全局左侧导航。项目详情仍保留在系统后台中；点击“进入工作区”后才进入单项目作业系统。

1. 独立顶部 Cockpit：
   - 第一行：返回项目详情、项目标识、项目名称、状态徽标、执行与风险摘要、当前用户、主题和退出；轮次入口保留在测试与执行上下文中。
   - 顶栏主题感知：浅色模式使用浅色玻璃、品牌绿淡渐变和深色文字；暗黑模式使用深绿 cockpit 和浅色文字。顶栏统一使用细边框、轻阴影、左侧品牌色轨和底部流光线；移动端项目身份与操作区允许折行，但不得出现横向页面溢出。
   - 项目标识使用主色等宽数字；项目名称可截断，完整名称通过悬浮提示或详情页查看。
   - 顶栏标签必须形成视觉层级：项目状态徽标沿用软色 Badge 变体；安全等级徽标升级为实心语义色标签（A 红 / B 橙 / C 蓝 / D 中性软色），带 ShieldCheck 图标、加粗字重和小面积投影，成为顶栏最醒目的身份标签；实心语义色在浅色玻璃与暗色 cockpit 上都必须保持文字对比度，reduced-motion 与深浅色下分别验证。
   - 顶栏不提供全局轮次切换器，避免项目级资料、需求和轮次执行数据被误联动。
2. 一级导航：
   - 由工作区壳提供横向 TAB：作业台、资料与对象、需求与追踪、测试与执行、交付与文档。
   - TAB 与路由同步，支持刷新、后退和深链；激活指示条有 180-260ms 过渡。
3. 二级导航：
   - 由各业务模块自带：大纲用章节树，需求用来源 / 需求树 / 矩阵视图，测试设计用树详情 / 矩阵 / 覆盖，轮次用轮次导航，文档用文档列表。
   - 二级导航不得提升到工作区壳，也不得复制系统后台侧栏。
4. 内容区：
   - 概览、资料、文档产出采用分区化页面。
   - 需求、测试项采用左树右详情。
   - 轮次工作区左侧为轮次导航和范围摘要，右侧为当前数据块。
5. 模块占位壳（WorkspaceModulePlaceholder）：
   - 侧栏头部一行化：模块图标框与标题同行，说明文字紧随其下；删除"二级导航"元信息徽标，导航身份由结构本身表达，不得出现解释界面结构的可见文案。
   - 壳高度跟随内容并保留 480px 下限，禁止为撑满视口制造大面积空白画布。
   - 模块色允许小华丽但服务层级：壳右上角一层模块色径向光晕（浅色不超过 10%、暗色不超过 14% 透明度，静态不动画）；侧栏激活项使用模块色左导轨与浅色底；模块图标框带模块色轻投影；内容必须始终清晰位于光晕之上。
   - 执行总览 KPI 卡遵循 07 的数字层级：等宽、放大、加粗、tabular-nums 主数值，semibold 指标名。

轮次切换器只出现在测试与执行模块，仅轮次相关数据联动。工作对象、项目资料、概览为项目级数据，不随轮次切换。

## 大纲编制流

项目进入工作区后的第一任务是“从模板开始编制大纲”，不是让用户面对空白模块。大纲编制流采用旧项目的超级工作区交互，但实现仍保持模块化：

- 左侧为测评大纲目录树，按模板章节展示完成度、阻断项和当前定位。
- 右侧为当前章节任务卡，提供“下一步录入”按钮，跳转到对应业务模块或内容块。
- 固定话术和模板段落由文档模板预填；用户只补项目数据、章节内容块和表格行。
- 大纲编制流不重复承载所有业务表单，只做任务导流、章节预览和生成预检。
- 新建项目先进入项目详情；用户点击“进入工作区”后默认落在作业台，由当前任务跳转大纲编制流。
