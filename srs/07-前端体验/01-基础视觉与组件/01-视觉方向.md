# 视觉方向

> 返回 [基础视觉与组件](../01-基础视觉与组件.md)

## 需求录入铁律

- 所有界面需求、视觉调整、交互反馈和动效要求必须先录入 SRS，再进入实现；不允许只留在对话记录或代码注释里。
- 全局审美、布局、控件质感、反馈、动效和无障碍要求维护在本文；具体模块的信息架构、页面结构、模块颜色和局部交互维护在对应模块 SRS。
- 录入界面需求时必须写清：设计读法、布局层级、信息密度、语义色、组件库选型、交互状态、响应式断点、动效时长和移动端表现。
- 美化需求是界面需求录入的必填项：每个页面、卡片、TAB、表格、空态和状态反馈都必须写明视觉层级、轻阴影、语义色或浅色渐变、图标使用、 hover 反馈和动效边界；未写美化口径的需求不得进入实现。
- 卡片类容器必须默认满足“轻阴影 + 颜色层次”：至少包含小面积投影、语义色条 / 语义色浅渐变底 / 等效视觉分组；禁止把纯白底加灰边、无阴影、无语义色的方案作为默认卡片样式。
- 用户验收后提出的“好看 / 不好看 / 顺眼 / 不顺眼”反馈，必须翻译成可执行口径录入 SRS，例如间距、对齐、色彩、层级、留白、边框、阴影、动画范围或状态反馈。
- 每次前端实现前先检查本文和对应模块 SRS；实现后如实际方案与 SRS 有差异，必须回写文档并说明原因。
- 代码验证必须同时覆盖深浅色、键盘可达、焦点可见、文字不溢出、控件不遮挡和 320px 最窄视口。

## 视觉方向

- 未登录访问任何业务深链时，必须在发起业务 API 前进入统一的“访问未授权”全屏状态页，不得显示普通 404、空白页或接口错误页。
- 用户主动退出登录不是未授权访问：必须清空会话与查询缓存，并直接回跳登录页，不得展示 401 状态页。
- 授权状态页和路由 404 使用同一套视觉语言：品牌标识、状态码、路由地址、语义色轨、轻量网格背景和克制的扫描动效；主按钮为“返回登录界面”。
- 从未授权页进入登录并成功后，默认返回原深链；跳转地址必须是本站相对路径，禁止开放跳转。
- 已登录状态下的未知路由显示统一的 404 状态页，提供返回首页和重新加载操作；未登录状态下的未知路由优先按未授权处理。
- 性能优先是本地工具的硬门槛：页面、表格、树、弹窗和动效先按生产构建测量；若当前成熟方案无法压到流畅，必须用 Skeleton、spinner、`aria-busy` 或进度面板提供明确加载态，禁止让已显示页面冻结或无反馈。
- **默认炫酷，不默认素**（2026-11-05 用户明确要求，已写入跨会话记忆）：新增或调整界面默认交出炫酷方案，不得以「克制」「避免过度」为默认口径；判定顺序是先问「这里够不够炫」，再问「会不会干扰操作」。能用 HUD 语言（细边框、角标、等宽标签、扫光、进度条、常驻呼吸微光、语义色轨）就用；现有 token 强度低于本文件规定数值时直接上调，不要停在几乎看不见的强度。不干扰操作、性能优先两条约束不变。
- 安全等级徽标必须带语义色：A 红（danger）、B 橙（warning）、C 蓝（info）、D 中性（outline）；表格与详情用浅色底徽章，工作区顶栏用实心渐变。禁止把 A/B/C 映射为无底色描边样式（2026-11-05 用户纠正历史退化）。
- 默认按个人自用工具的舒适感优先：界面可以大胆使用品牌装饰与语义色，但必须服务识别、层级和操作愉悦感；交互反馈柔和清晰，避免生硬、干瘪或模板化。
- 默认使用浅色工程风格，支持深浅色切换。信息密度服务任务，不强制高密度，常用页面允许舒适留白。
- 本项目界面设计体系正式命名为 **「直角集中色风」**（2026-10-27 命名；2026-11-02 用户把原「单色」表述改为「集中色」）：以绿色为品牌主色、浅色工程底与深浅色双主题为基底，直角、细边框、满高语义色轨和克制的光效统一全站。「集中色」指主视觉集中使用一套品牌色，不追求全站只用一种颜色；在此基础上允许附带 **警告色**、**错误色**、**强调色**、**普及色** 四类语义色，同一语义全站只用一个颜色，不做无理由的彩色堆叠。后续新增页面和组件必须先对齐这套语言，不得改成圆角 SaaS、蓝紫营销页或暗色驾驶舱。
- 边界必须清晰：相邻容器、卡片与背景、表格行之间至少要有一项可辨差异——1px 细边框或明确的明度差；禁止靠大面积阴影或模糊留白把区块糊成一片。
- 质感由阴影和光晕承担：基础态至少一层小面积软阴影（扩散 ≤14px）；需要抬升的层级可叠加极淡光晕（品牌色或语义色外发光），但不得遮挡内容、不得降低文字对比度，也不得用重阴影制造悬浮感。
- 保持直角、细边框、清晰层级和克制的品牌绿色与语义色；装饰围绕品牌经线、状态语义和数据层级展开，避免圆润卡片堆叠、单一蓝紫渐变和营销页式布局。
- hover 反馈禁止真实位移；卡片、按钮和选项只通过阴影、边框、背景和颜色变化制造上浮感。active 按压可保留轻微下沉。
- 全站装饰基调：登录面板、筛选栏、指标卡、风险卡、待办分区、项目创建分组、工作台概览和字典管理区统一使用左侧语义色长条；同层级卡片共享小面积软阴影。
- 所有卡片必须有可见的轻阴影和颜色层次：基础态至少包含 1 层小面积投影、1 条语义色线或浅色渐变底；不得交付纯白底加灰边的“素卡片”。阴影扩散控制在 14px 内，hover 只增强轮廓与轻投影，不做大范围悬浮。
- 指标卡 hover 阴影保持小面积软投影：外层扩散不超过 14px，边缘轮廓用 1px outline 单独过渡，禁止大范围重阴影制造生硬悬浮感。
- 首页与工作台指标卡必须形成明显数字层级：项目总数、执行率等主数值使用等宽字体、放大字号、粗体和 `tabular-nums`；指标名称用小字号 semibold，补充说明用弱色常规字重，禁止三类文字看起来同层级。
- 页面功能标题统一使用 `PageHeader`，标题为 foreground 黑色 700 粗体；语义图标、计数徽标、经线光带和低强度网格/光晕装饰可以叠加，但不得遮挡内容或降低对比度。
- `ChenMeridian` 品牌字标使用炫彩渐变和慢速流动动画，应用在登录页品牌区、侧边栏和移动抽屉；页面功能标题不使用炫彩渐变。
- 全局控件采用 Material 质感语言，但不引入 MUI 组件库：按钮、输入框、卡片和标签使用主题感知阴影、颜色和边框反馈；**全站直角**（2026-10-12 收口：清除 2px / 3px 微圆角，圆点、胶囊、圆形图标等圆形语义元素除外）。
- 界面与小号文字统一走 `--font-sans` 字体栈：`"PingFang SC"`（含用户自行下载安装的同名字体，命中后同时承担拉丁与中文字形）→ `"Geist Variable"`（无 PingFang 时的拉丁兜底）→ `-apple-system / BlinkMacSystemFont / "Segoe UI" / Roboto` → `"Microsoft YaHei"` → `sans-serif`；数字和标识数据使用等宽字体，避免表格列宽跳动。注意本机只装单一字面（如仅 Bold）时所有字重都会落到该字面，视觉复核需确认正文没有整体变粗。
- 按钮必须有 pointer 位置触发的点击水波纹，并有 hover 阴影增强和 active 轻微下沉反馈。按钮与下拉框 hover 状态禁止位移。
- 按钮质感按「实心 + 清晰描边 + 紧实投影」表达，不使用拟态内高光：主按钮使用实色底、深一档同色描边（`color-mix(primary 74%, foreground)`）和 `0 1px 2px` 紧贴投影，hover 时底色加深、描边变实，禁止大范围柔散光晕和顶部白色内高光。次按钮与破坏性按钮使用同口径的紧凑投影。
- 按钮扫光（sheen）只在 hover / focus-visible 时播放一次，时长 640ms；登录页 `.btn-sheen` 为 700ms，两者保持同档。
- 表格表头一律水平居中，基础 `TableHead` 组件必须内置居中；数值、状态、标签、徽标、操作等短列的表头和单元格内容必须同时居中，长文本列仅正文单元格可左对齐，表头不允许左对齐。表头必须比普通单元格更重，统一使用 `font-semibold` 与 foreground，允许用浅底色区分但不允许弱化成普通正文。
- 表格长文本统一用 `TruncatedText`：单元格显示省略号，只有真实溢出时用 Radix Tooltip 展示全文，延迟控制在 150ms 左右，禁止原生 `title` 提示。
- 接收文件队列的非待确认行使用只读文本展示对象类型、名称、版本和提供方，不用禁用输入框模拟只读；视觉上保持灰底、降透明度和不可点击光标，只读文本同样遵守省略号与 Tooltip 规则。平台不展示、不编辑，由项目平台派生。
- 表格可排序表头使用透明边框 Button，默认只显示文字与排序箭头，hover / focus 时才出现浅底和边框；已排序列用 `primary/5` 轻底和主色文字说明当前状态。操作列按钮仍必须可辨，破坏性操作用 destructive 色表达。
- Tooltip 出现和消失必须使用 120-180ms 微动画。
- Dialog、AlertDialog、Sheet 和 Select 打开、关闭动画期间必须保持页面滚动条和内容宽度稳定，禁止 body 滚动锁造成横向抖动。
- 项目工作区一级导航切换的懒加载期不得继续保留旧路由内容；必须立即切换为统一加载面板。工作区路由与卡片入场只做透明度过渡，不做纵向位移，避免临界高度下滚动条闪现。
- 模块内真实数据加载时必须使用 `aria-busy` 和 `QueryLoading` 骨架，禁止长时间保留旧内容且无反馈。加载态是前端视觉验收必查项。
- 模块内缓存数据的视图切换（如需求工作台两个视图）使用 160-220ms 纯透明度淡入；禁止纵向位移、骨架替换和滚动条宽度抖动。真实路由懒加载与数据请求仍必须使用 `QueryLoading`。
- 加载完成后的视图切换只使用 180-280ms 的透明度入场，直接呈现内容。
- 选中态和跨面板联动选中使用“华丽但克制”的微动画：180-280ms 内完成背景、边框、语义色条、透明度或轻光晕反馈；允许树目录与表格行共用同一节奏，禁止真实位移、字体粗细突变引起布局跳动、内容遮挡或滚动条抖动。
- 高频局部操作可使用按钮 pending 态；整块视图切换必须用整面板加载态，避免用户误以为点击失败或页面冻结。

## 外部设计参考：Command Code 用量页（2026-10-21）

用户提供的 Command Code `设置 → 用量` 页面可作为工作台数据页的后续参考，参考范围为信息组织和视觉语言，不复制品牌与业务内容。访问入口：`https://commandcode.ai/zh`（登录后进入设置 → 用量）。

可借鉴的稳定特征：

- **技术图纸式网格**：近白底、细灰边框、直角模块；卡片交叉点可用小方块定位点，形成工程仪表盘感，而不是普通 SaaS 圆角卡片堆叠。
- **章节符号克制使用**：二级标题可用 `//` 前缀形成技术注释感，但只用于数据分区标题，不扩散到正文、按钮和表单标签。
- **大字数字 + 小字标签**：核心指标使用超大粗体数值，标签和辅助信息保持小字号弱色；数字使用等宽字体和 `tabular-nums`。
- **分段式数据条**：进度和额度优先采用方格分段条，而非整根胶囊进度条；分段色可用于区分不同指标，但必须保持语义一致。
- **低饱和分类色**：紫、橙、薄荷绿等只用于图表分类，不作为全站主色。ChenMeridian 继续保持绿色主色，分类色映射现有 `--chart-*` token。
- **克制的操作区**：右上角操作按钮采用浅底、细边框和图标，hover 只增强边框与底色；不使用大面积渐变按钮。
- **侧栏与表格的轻层级**：侧栏为静态浅底列表，当前项用整行弱底色；主表格用细网格线、稀疏行高和轻量状态块。

适配约束：

- 保持 ChenMeridian 浅色工程风格、直角、绿色主色和现有品牌经线；不得照搬 Command Code 的黑色营销页、紫色主视觉或品牌字标。
- 数据页可以借鉴方格、定位点、`//` 分区符和分段条，但必须优先保证中文可读性、键盘焦点、深浅色对比和 320px 下不溢出。
- 任何具体页面落地前，仍按模块 SRS 先写清布局、组件状态、动效和响应式，不得以“参考网站如此”为理由跳过现有设计系统。

## OpenDesign 视觉强化方法（2026-10-21）

- OpenDesign 内置技能中，`design-review`、`impeccable-design-polish`、`emil-design-eng`、`ui-ux-pro-max` 可作为工作台视觉审计与打磨方法；只借用审计顺序、动效纪律和信息层级判断，不引入新依赖、不替换现有组件库。
- 强化现有页面时先保留原信息架构、主色和直角工程语言，再做少量高影响修正；禁止借“设计升级”之名重做布局、堆叠装饰或改变业务层级。
- 技术图纸式点阵 / 网格、微型工程标签、状态刻线和短促反馈只服务识别与分组；正文与按钮不使用装饰性 `//`，hover 仍不产生真实位移。

## 全站舒适化基线（2026-10-22）

- OpenDesign 的 `soft-skill`（Soft Structuralism）、`frontend-design`、`impeccable-design-polish`、`emil-design-eng`、`apple-hig` / `platform-design` 作为本轮全站审计方法：先看空间节奏、可读性和交互状态，再改视觉，不改业务流程与信息架构。
- 全站内容区使用 `--content-max: 1680px` 与 `--content-gutter: clamp(1.25rem, 2.25vw, 2.25rem)`；默认页面保持 4px / 8px 节奏，卡片默认内边距 18px、紧凑卡 14px。
- 控件默认高度提高一档：普通按钮 36px、`sm` 32px、`xs` 28px，普通输入框与下拉框 36px、紧凑下拉 32px；图标按钮与相邻控件同高。高密度表格仍可使用 `xs` / `sm`。
- 焦点态统一为 2px 可见轮廓或 2px ring，不再使用过大的 3px 光圈；禁用态保持低透明度并使用 `not-allowed` 光标；hover 不位移，active 才允许 1px 下沉或轻微缩放。
- 下拉 / Popover / Command 统一使用 150–200ms 的淡入与轻微缩放，选项行使用 8px 纵向内边距和 `primary/8` 高亮；排序表头默认透明，hover / focus 才出现浅底边框，已排序列显示 `primary/5` 轻底。
- 表格行高按操作按钮实际高度校准：虚拟化估算行高 56px；375px 下隐藏创建时间等非关键列，保证用户名、显示名和操作列不被压缩成不可读省略。
- 页面与 TAB 切换只使用 180–220ms 透明度入场，起始透明度不得低于 0.84，禁止纵向位移和整页灰闪；懒加载仍显示统一 Skeleton / `aria-busy`。
- 浮层表面统一：Dialog、AlertDialog、Sheet 必须使用 `panel-surface`（主题渐变底 + elevation-1），Popover、Select、Tooltip、右键菜单使用同一套「主色极淡渐变 + 偏实描边」，不得退回纯 `--popover` 平色；弹窗内的纯文字清单必须收进带左色条的浅底卡片，行间加分隔线，不得直接裸列。弹窗自定义 `max-width` 时必须用 `min(…rem, calc(100vw - 2rem))` 保证窄屏两侧留边。
- 事件与历史列表（审计记录、生命周期）每项使用卡片 + 左侧 2px 语义色条：确认/恢复用 success，被替代用 info，撤回用 warning，删除/作废用 destructive，登记纠错用 primary，动作名称同步取色；hover 只做 180ms 背景过渡，条目入场为 200ms 淡入 + 3px 上移。
- 视觉层级靠现有 token 的强度表达，不新造颜色：表格表头底色 `primary 10%`、行分隔线 `border 78%`；tone 卡描边 `40%`（hover `66%`）；tonal 面板描边 `42%`、底色 `12% → 4%`；普通卡片渐变 `primary 8% → 3.5%`。低于这些值时浅色主题下近乎不可见，禁止再往下调。
- 纯文字信息区（项目详情元信息、工作区基础信息等）必须给字段加左侧细竖线和内边距，形成网格分隔；禁止把多个 label/value 直接平铺在同一底色上。
- 侧栏当前项使用 2px 主色轨、13% 主色浅底、18% 主色边框和 600 字重，不再用 3px 轨、粗边框和 700 字重制造跳动。

## 设置页与只读状态页统计带（2026-11-05）

- 设置页（用户管理、字典配置、审查单配置）与只读状态面板（项目详情·被测对象 / 需求追溯 / 文档产出、工作区问题单）必须在标题与表格/清单之间给出统计带，禁止交付「标题 + 素表格」。
- 统计卡沿用现有 `Card size="sm" data-tone` 或模块同款左语义色轨面板：数字用 `font-mono tabular-nums`，页面级不小于 1.3rem、面板内不小于 1.2rem；数字文本色使用对应语义 token 的文本变体（`text-warning-ink` 等），描边与色轨仍用原始 token，保证浅色主题大字号对比度 ≥ 3:1、说明文字 ≥ 4.5:1；不新造颜色、不改直角与平面风格。
- 比率类指标（做法配置覆盖率、文档类型覆盖率、字典类型占比）必须配 `SegmentedProgress` 方格分段条；计数类指标给数值 + 一句口径说明。
- 用户管理固定四段：账号总数（info）、系统管理员（primary）、普通成员（success）、近 30 天新增（chart）；技术字典按编程语言 / 运行环境 / 开发环境三类出分布；审查单配置强化现有五段统计；问题单按重大 / 严重 / 一般 / 建议改进四个等级出统计。
- 用户管理弹窗头部与审查单模板弹窗对齐：英文 kicker（`USER ACCOUNT`）+ 3px 主色左轨 + 主色淡渐变底，正文仍是直角平面输入框。
- 新增统计块必须接入页面已有的 `useSubtleReveal`、`dictionary-reveal`、`routeContentIn` 动效链路，不新增动画系统。全局主题、既有特效和布局不改。

## 加载态可见性（2026-11-05）

- 页面级数据加载统一用 `QueryLoading`：必须同时给出可见 spinner + 文案（「正在加载…」）与 Skeleton 行，禁止只给骨架或只给 `sr-only` 文案。
- 局部区块加载统一用 `InlineLoading`（`components/shared/inline-loading.tsx`）：可见 spinner + 一句说明，替代纯文字「加载中…」；保留 `role="status"` 与 `aria-live="polite"`。
- 纯骨架区块保留 `aria-busy`。
