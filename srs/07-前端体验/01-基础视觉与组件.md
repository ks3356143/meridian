# 基础视觉与组件

> 返回 [前端体验](../07-前端体验.md)

## 需求录入铁律

- 所有界面需求、视觉调整、交互反馈和动效要求必须先录入 SRS，再进入实现；不允许只留在对话记录或代码注释里。
- 全局审美、布局、控件质感、反馈、动效和无障碍要求维护在本文；具体模块的信息架构、页面结构、模块颜色和局部交互维护在对应模块 SRS。
- 录入界面需求时必须写清：设计读法、布局层级、信息密度、语义色、组件库选型、交互状态、响应式断点、动效时长、reduced-motion 和移动端表现。
- 美化需求是界面需求录入的必填项：每个页面、卡片、TAB、表格、空态和状态反馈都必须写明视觉层级、轻阴影、语义色或浅色渐变、图标使用、 hover 反馈和动效边界；未写美化口径的需求不得进入实现。
- 卡片类容器必须默认满足“轻阴影 + 颜色层次”：至少包含小面积投影、语义色条 / 语义色浅渐变底 / 等效视觉分组；禁止把纯白底加灰边、无阴影、无语义色的方案作为默认卡片样式。
- 用户验收后提出的“好看 / 不好看 / 顺眼 / 不顺眼”反馈，必须翻译成可执行口径录入 SRS，例如间距、对齐、色彩、层级、留白、边框、阴影、动画范围或状态反馈。
- 每次前端实现前先检查本文和对应模块 SRS；实现后如实际方案与 SRS 有差异，必须回写文档并说明原因。
- 代码验证必须同时覆盖深浅色、键盘可达、焦点可见、文字不溢出、控件不遮挡和 320px 最窄视口。

## 视觉方向

- 未登录访问任何业务深链时，必须在发起业务 API 前进入统一的“访问未授权”全屏状态页，不得显示普通 404、空白页或接口错误页。
- 用户主动退出登录不是未授权访问：必须清空会话与查询缓存，并直接回跳登录页，不得展示 401 状态页。
- 授权状态页和路由 404 使用同一套视觉语言：品牌标识、状态码、路由地址、语义色轨、轻量网格背景和克制的扫描动效；主按钮为“返回登录界面”。
- 从未授权页进入登录并成功后，默认返回原深链；跳转地址必须是本站相对路径，禁止开放跳转。
- 已登录状态下的未知路由显示统一的 404 状态页，提供返回首页和重新加载操作；未登录状态下的未知路由优先按未授权处理。
- 默认按个人自用工具的舒适感优先：界面可以大胆使用品牌装饰与语义色，但必须服务识别、层级和操作愉悦感；交互反馈柔和清晰，避免生硬、干瘪或模板化。
- 默认使用浅色工程风格，支持深浅色切换。信息密度服务任务，不强制高密度，常用页面允许舒适留白。
- 保持直角、细边框、清晰层级和克制的绿色状态色；装饰围绕品牌经线、状态语义和数据层级展开，避免圆润卡片堆叠、单一蓝紫渐变和营销页式布局。
- hover 反馈禁止真实位移；卡片、按钮和选项只通过阴影、边框、背景和颜色变化制造上浮感。active 按压可保留轻微下沉。
- 全站装饰基调：登录面板、筛选栏、指标卡、风险卡、待办分区、项目创建分组、工作台概览和字典管理区统一使用左侧语义色长条；同层级卡片共享小面积软阴影。
- 所有卡片必须有可见的轻阴影和颜色层次：基础态至少包含 1 层小面积投影、1 条语义色线或浅色渐变底；不得交付纯白底加灰边的“素卡片”。阴影扩散控制在 14px 内，hover 只增强轮廓与轻投影，不做大范围悬浮。
- 指标卡 hover 阴影保持小面积软投影：外层扩散不超过 14px，边缘轮廓用 1px outline 单独过渡，禁止大范围重阴影制造生硬悬浮感。
- 首页与工作台指标卡必须形成明显数字层级：项目总数、执行率等主数值使用等宽字体、放大字号、粗体和 `tabular-nums`；指标名称用小字号 semibold，补充说明用弱色常规字重，禁止三类文字看起来同层级。
- 页面功能标题统一使用 `PageHeader`，标题为 foreground 黑色 700 粗体；语义图标、计数徽标、经线光带和低强度网格/光晕装饰可以叠加，但不得遮挡内容或降低对比度。
- `ChenMeridian` 品牌字标使用炫彩渐变和慢速流动动画，应用在登录页品牌区、侧边栏和移动抽屉；页面功能标题不使用炫彩渐变。
- 全局控件采用 Material 质感语言，但不引入 MUI 组件库：按钮、输入框、卡片和标签使用主题感知阴影、颜色和边框反馈；直角仍是主规则，控件最多 2px 微圆角。
- 界面与小号文字使用系统字体栈：`-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif`，中文回退 Microsoft YaHei；数字和标识数据使用等宽字体，避免表格列宽跳动。
- 按钮必须有 pointer 位置触发的点击水波纹，并有 hover 阴影增强和 active 轻微下沉反馈。按钮与下拉框 hover 状态禁止位移。
- 表格表头一律水平居中，基础 `TableHead` 组件必须内置居中；数值、状态、标签、徽标、操作等短列的表头和单元格内容必须同时居中，长文本列仅正文单元格可左对齐，表头不允许左对齐。表头必须比普通单元格更重，统一使用 `font-semibold` 与 foreground，允许用浅底色区分但不允许弱化成普通正文。
- 表格长文本统一用 `TruncatedText`：单元格显示省略号，只有真实溢出时用 Radix Tooltip 展示全文，延迟控制在 150ms 左右，禁止原生 `title` 提示。
- 接收文件队列的非待确认行使用只读文本展示对象类型、名称、版本和提供方，不用禁用输入框模拟只读；视觉上保持灰底、降透明度和不可点击光标，只读文本同样遵守省略号与 Tooltip 规则。平台不展示、不编辑，由项目平台派生。
- 表格可排序表头和操作列按钮必须使用带边框、浅底和 hover 变化的 Button；操作列禁用灰色无边框 ghost 图标导致用户看不出可点击，破坏性操作用 destructive 色表达。
- Tooltip 出现和消失必须使用 120-180ms 微动画，并在 reduced-motion 下关闭。
- Dialog、AlertDialog、Sheet 和 Select 打开、关闭动画期间必须保持页面滚动条和内容宽度稳定，禁止 body 滚动锁造成横向抖动。
- 项目工作区一级导航切换的懒加载期不得继续保留旧路由内容；必须立即切换为统一加载面板。工作区路由与卡片入场只做透明度过渡，不做纵向位移，避免临界高度下滚动条闪现。

## 组件库铁律

### CSS Module 铁律

1. 组件自定义样式必须与组件同目录同名：`Button.tsx` 对应 `Button.module.css`，组件内 `import styles from './Button.module.css'`，自定义 `className` 使用 `styles.xxx`。
2. 变体使用 `styles.primary` / `styles.ghost` 等语义类；状态使用 `data-state`、`data-invalid`、`data-selected` 等 data 属性和 CSS 属性选择器，不在 JS 中拼接表现类。
3. Tailwind 仅保留少量布局工具和 shadcn/Radix 既有组合；业务视觉、主题变体、动画、状态和密集选择器必须进入 CSS Module。
4. CSS Module 选择器和导出名使用 camelCase；第三方子元素通过 `:global([data-slot='...'])` 定位，不用标签选择器扩大影响面。
5. 新增或改造组件时必须同步迁移该组件既有自定义全局样式；同一业务域允许按布局、树、表单、弹窗拆分多个同名组件 Module，禁止继续增长全局大 CSS。

需求与追踪页已完成本轮迁移：布局、树、统计卡、详情、创建、删除、彻底删除、审计、已删除管理和快捷键说明分别使用同目录同名 `.module.css`；树导线偏移由 `data-guide-level` CSS 属性选择器定义，不在组件中写 inline style。基础 `Button`、`ContextMenu` 和 `Textarea` 也已迁移，Button 变体使用 `styles.primary` / `styles.outline` / `styles.ghost` 等类。

- 接收文件录入页紧跟工作区一级 TAB，减少无用顶部留白；桌面端左侧只保留窄版文件投放区和接收信息，右侧工作对象队列占据主要宽度。
- 删除工作对象必须使用 AlertDialog 二次确认，确认文案说明数据库记录和接收文件会一起删除；已确认对象不提供直接删除入口。
- 撤回确认和作废必须填写操作原因；已确认、已被替代、已作废版本在接收队列中只读，并用独立状态徽标区分。
- 已确认版本的对象类型、名称、版本或提供方录入错误使用“登记纠错”弹窗处理，必须展示原始值、填写新值和纠错原因；不得引导用户通过作废或撤回修正录入错误。平台不参与登记纠错。
- 生命周期记录使用 Dialog 展示，按时间倒序呈现状态迁移、原因和操作时间。
- 上传全流程需要完整加载态：上传请求、文件落盘、数据库保存和列表刷新期间应提供工作区级动画进度条或进度面板，禁止只显示局部 spinner 导致页面其余区域像可操作状态。
- 上传加载态必须区分“真实字节传输”和“服务端处理”：批量上传使用 `XMLHttpRequest.upload` 读取已发送字节与总字节；网络传输完成后切换为服务端落盘与入库处理态；接口返回后切换为列表刷新态。大文件期间用户必须看到文件数、总量、已传输量和百分比，禁止把不确定等待伪装成已完成。
- 上传进度层使用 shadcn/Radix Dialog 呈现：模态遮罩覆盖页面；上传请求、服务端处理和列表刷新期间禁止关闭按钮、Esc 和点击遮罩中断上传，避免用户误以为已取消。完成后进入“保存完成”态，保留结果并允许用户通过关闭按钮、Esc 或点击遮罩手动关闭，不得自动消失。内容包含品牌工程面板、动画进度条、阶段轨、当前状态和文件摘要。浅色模式使用品牌绿与信息蓝的细渐变进度，深色模式保持足够对比；流光只作用于 transform / opacity，周期不短于 2.6 秒，reduced-motion 下保留静态进度与完成图标。
- 接收文件工具栏的空白区域禁止作为文本选择起点；从工具栏空白处按住拖动不得扩展选择区或触发浏览器选择异常。标题、说明文字节点本身仍允许正常选中，操作按钮和表单控件不受影响。
- 全局静态文字选中后不得触发浏览器原生拖拽复制和拖影；用户仍可用鼠标创建选择区、用 `Ctrl+C` 复制，输入框、文本域、内容可编辑区域和显式标记为可拖拽的元素不受影响。文件投放区继续支持文件拖入。
- 前端设计、改版和视觉问题处理必须先读取并使用项目本地 `.agents/skills` 中匹配场景的技能：数据密集界面优先 `ui-ux-pro-max`、`shadcn`、`tailwind-4-docs`；动效优先 GSAP 系列；仅营销页、作品集或探索性视觉才考虑 `design-taste-frontend` 等风格技能。实现仍以当前主题、组件体系和本文件铁律为准。
- 前端卡顿、输入长任务、滚动掉帧、切换慢和拖动假死必须先按《21-前端性能优化策略》定位与验收；不允许只凭感觉删除视觉层或引入新依赖。
- 每次修改页面、组件、样式、交互或动效前，必须横向检查同类型页面和组件，并先划分影响域：全局基础组件、业务组件、单页面或全局主题。凡属于同类结构的能力必须保持整体结构一致，不能只修当前反馈页面或留下同类页面不一致。
- Select 打开和关闭过渡期间页面纵向滚动条必须保持可见，布局宽度不得变化。
- 标签使用 shadcn/Radix Badge 体系，不同语义变体保持一致尺寸；不得通过外扩阴影制造视觉高度差。
- 能使用成熟组件库的交互组件必须使用组件库：优先 shadcn/ui 与 Radix UI；表格、路由、数据使用 TanStack、React Router 等专业组件库。仅纯展示、布局或确无组件库能力时允许手写，但必须补齐无障碍、键盘操作、焦点态和微动效。
- 新增交互组件前先检查 `web/src/components/ui` 是否已有对应组件。
- 数据表格统一基于 TanStack Table 与 `DataTable` 封装，排序、空态、选中态、行键盘操作不得在业务页重复手写。
- 查询加载态统一使用 Skeleton 与 `QueryLoading`，错误态统一使用 Alert 与 `QueryError`，禁止裸文本居中充当状态页。
- 表单内多选统一使用 `Popover + Command + Badge` 组合的 `MultiSelectCombobox`，必须提供搜索、已选徽标、键盘选择和错误态。
- 多选已选徽标选入时必须有轻量插入动画，移除时先做压缩淡出再卸载；动画只使用 transform/opacity，并在 reduced-motion 下关闭。
- 启用/停用等二元设置使用 Radix Switch；Checkbox 仅用于批量选择或明确的多选项语义。
- 移动端抽屉导航使用 shadcn Sheet，不使用居中 Dialog 模拟侧边栏。
- 图标按钮和图标型触发器需要 Tooltip 或明确的 `aria-label`。
- 提供自研快捷键的高频作业面必须在工具栏提供快捷键说明入口：图标按钮带 Tooltip，点击打开 Radix Dialog；说明按“快捷键”和“功能说明”分组，快捷键使用键帽、适用范围和结果三列表达，功能说明解释对应业务行为。弹窗支持键盘导航和 Esc 关闭，窄屏仅允许说明表横向滚动。
