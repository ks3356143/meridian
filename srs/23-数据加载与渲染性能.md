# 数据加载与渲染性能（全局契约）

> 定位与修复方法见 [前端性能优化策略](./21-前端性能优化策略.md)｜需求模块的实测数据与实施记录见 [需求与追踪：数据加载与渲染实施记录](./22-需求录入与解析/05-数据加载与渲染性能.md)

## 状态

- 本文件是“列表 / 详情 / 大文本 / 富文本 / 图片”类数据模块的**固定契约入口**，优先级高于各模块 SRS 的实现记录。出现“列表卡、切换慢、正文加载慢、图片爆内存”一类反馈时，先按本文件核对契约，再进模块记录找证据。
- 适用范围：需求、测试项、测试用例、问题单、文档预览，以及后续任何可能上量或带富文本的模块。
- 与 [前端性能优化策略](./21-前端性能优化策略.md) 的分工：本文件管“数据怎么分层、什么时候加载、正文怎么存和怎么渲染”；21 管“卡了怎么定位、怎么修、怎么验收”。两者要求不一致时按更严格的一条执行。
- 与模块 SRS 冲突时以本文件为准；确需例外必须在模块 SRS 写明原因、边界和回退方式。
- 2026-09-29 由 `srs/22-需求录入与解析/05-数据加载与渲染性能.md` 提升为全局契约，用户确认“以后都照着看”。

## 一、列表 / 详情分层硬契约

1. **列表接口禁止携带原文描述、富文本正文、图片**，只返回 `descriptionExcerpt`（约 80 字）与 `hasDescription` / `hasRichContent` 一类存在性标记。
2. 详情、编辑、复制一律按 id 重新请求完整内容（样板：`GET /api/v1/software-requirements/{id}/content`）。隐藏字段不算分层，禁止“把重字段放进列表、前端不渲染”。
3. 创建 / 更新单条响应可以返回完整正文：复制和失焦保存需要，不必二次请求。
4. 列表单元格只渲染服务端摘要，**不挂 Tooltip / Portal**。长文本列一律左对齐、短文本列居中：章节 / 标识 / 名称 / 原文描述左对齐，来源 / 操作 / 勾选居中。
5. 新模块从第一天按此契约设计，禁止“数据量大再优化”。

### 容量基线（判断该不该分层的依据）

| 量级 | 纯文本正文 | 图片内联（base64） |
| --- | --- | --- |
| 300 条 | ≈ 600 KB | — |
| 1000 条 | ≈ 2 MB | 1000 条 × 200 KB ≈ **270 MB（不可用）** |

## 二、加载态契约

1. 加载态延迟显示：请求超过 **250ms** 才出现骨架 / spinner，避免正常速度下闪一下；用 CSS `animation-delay` 实现，禁止用定时器。
2. 加载态必须可访问、可恢复：Skeleton / spinner / `aria-busy` / 进度面板；错误态必须给出重试入口，不允许只留空白。
3. 允许且推荐“先切页面再加载”：切换 TAB / 路由先提交界面，再显示加载态，不允许让用户面对冻结的旧界面。
4. 分块渲染是合法手段：首屏只渲染首屏需要的块，其余进视口再渲染。

## 三、虚拟化与渲染契约

1. 行数可能超过 **100** 的表格、树、列表必须走成熟窗口化方案（`@tanstack/react-virtual` / `react-arborist`），禁止手搓虚拟滚动算法。
2. 共享 `DataTable` 的 `virtualized` 默认关闭，由调用方按数据量显式开启；开启后必须回归六项：勾选、批量栏、行激活（点击 / 回车）、空态、响应式隐藏列、排序。任何一项不通过就用开关回退到非虚拟化。
3. 行组件必须 `memo` + 原始值 props + 稳定回调；数组 / Set 一类 props 必须归一化成稳定引用，禁止调用方内联字面量击穿 memo。
4. 表格容器必须撑满面板剩余高度、底部不留空白；内部滚动条统一 8px 直角主题样式，出现原生白色宽条即视为缺陷。
5. 长正文按块渲染 + 块级虚拟化，禁止整篇塞进一个 `pre` 或一个巨型 HTML 节点。
6. `content-visibility: auto` + `contain-intrinsic-size` 只用于行级 / 块级高度稳定的容器；高度不稳定会造成滚动抖动。

## 四、富文本与图片契约（Step 2 目标）

1. 正文存结构化块（受限 JSON 内容块，结构对齐 ProseMirror）：`paragraph / heading / list / table / image`；禁止存 HTML 字符串，禁止内联 `style` 字符串。
2. 图片走独立资源：正文只存 `assetId + width + height + alt`；提供原图与 `?w=320` 缩略图接口；前端 `loading="lazy"` + 宽高比占位，禁止 base64 内联。
3. DOCX 解析必须按块输出：表格给真实表格块、图片抽二进制存资源；不允许把表格 / 图片拍平成 `[表格]` / `[图片]` 文字后长期当正文保存。
4. Word 导出必须能按 `assetId` 取原图；资源缺失走“占位图 + 告警”，禁止静默丢图。
5. 存量纯文本数据的迁移策略、回退开关必须在实施前写进模块 SRS 并经确认。

## 五、验收门禁

1. 性能验收统一 `npm run build` + `npm run preview`（4173 生产预览）；`npm run dev` 只验功能，不作性能结论。
2. 统一阈值：进入模块 TTI <1.5s、长任务 <50ms；滚动 60Hz ≤16.7ms/帧、144Hz ≤20ms/帧；滚动期间长任务 0。
3. 分步指标：Step 1 首屏 payload <300KB、详情首块 <150ms；Step 2 含 20 张图的正文首屏 <300ms 且无布局跳动；Step 3 1000 条需求初始渲染 ≤30 行、内容请求 ≤3 个、内存 <200MB。
4. 压测必须用专用测试项目或 Playwright 路由拦截夹具，验证后清零；禁止在真实项目数据上触发保存、删除或状态变更。

### 加载策略分层（目标形态）

- 树按章节懒加载：根节点只带计数；展开章节时按游标分页拉取（默认 100 条/页），滚到底再取下一页。
- 表格：虚拟化 + 游标分页，首屏只请求第一页，接近底部再取下一页。
- 详情：点击行才拉正文；hover / 聚焦预取相邻 1 条。
- 缓存：TanStack Query key 分片（如 `["requirements", projectId, sectionId, cursor]`），编辑只失效受影响分片。
- 搜索：服务端化（章节号 / 名称 / 标识 / 标签 + 正文命中定位），前端不做全量过滤。
- 编辑：受限 JSON 内容块 + PATCH 单条（编辑器选型见内容块模型）。

## 八、回退口径

1. 列表契约回退：只还原列表 mapper 即可；详情内容接口与创建 / 更新单条完整正文都保留，回退不影响编辑与复制。
2. 虚拟化回退：关闭 `DataTable.virtualized` 即回退到非虚拟化。开启范围按模块逐个决定，不批量扩大；当前只对「待确认需求」候选审阅表开启，字典 / 用户 / 项目列表等其它表格保持现状。
3. 加载态回退：任何懒加载失败必须可重试；不允许因为“加载态可能闪”就取消加载态。
4. 富文本迁移回退：Step 2 必须保留旧纯文本列与读取路径，迁移失败可整体回退。
