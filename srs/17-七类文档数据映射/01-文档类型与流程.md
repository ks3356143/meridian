# 文档类型与流程

> 返回 [七类文档数据映射](../17-七类文档数据映射.md)

## 文档类型

知识库当前有 7 份模板，但项目文档实例数量随轮次扩展。

| 文档种类 | 模板 | 实例规则 |
| --- | --- | --- |
| 测评大纲 | `测评大纲.docx` | 每个项目一份，可随大纲变更生成新版本。 |
| 测试说明 | `测试说明.docx` | 第 1 轮一份。 |
| 回归测试说明 | `回归测试说明.docx` | 第 N 轮（N ≥ 2）各一份。 |
| 测试记录 | `测试记录.docx` | 第 1 轮一份。 |
| 回归测试记录 | `回归测试记录.docx` | 第 N 轮（N ≥ 2）各一份。 |
| 测评报告 | `测评报告.docx` | 每个项目一份，汇总全部轮次。 |
| 问题单合集 | `问题单.docx` | 每个项目一份，按静态和动态问题分组连续排版。 |

内部 `document_kind` 建议使用：`outline` / `test_description` / `test_record` / `report` / `issue_report`，轮次差异由 `round_id` 和轮次号表达，不扩展 `TD2`、`TD3` 这类枚举。

## 数据源总表

| 数据域 | 主要表或块 | 输出文档 |
| --- | --- | --- |
| 项目基础与状态 | `projects` | 全部文档封面和概述。 |
| 相关方与人员 | `related_parties`、项目人员关联 | 大纲、报告、签署和组织分工。 |
| 依据标准与引用文件 | `reference_standards`、来源文档、交付文档 | 大纲、测试说明、报告。 |
| 被测对象 | 项目字段、`dut.*` 内容块 | 大纲、测试说明、记录、报告。 |
| 静态测试环境 | `environment.static.*` | 大纲、测试说明、报告。 |
| 动态测试环境 | `round.dynamic_env.*` | 大纲汇总、当轮测试说明、报告。 |
| 测评数据与差异分析 | `round.test_data.*`、`round.diff_analysis.*` | 当轮测试说明、报告。 |
| 软件更改 | `round.software_changes.*` | 回归测试说明、报告相关性分析。 |
| 需求与追溯 | `requirement_sources`、`requirements`、追溯关系 | 大纲附录、测试说明、报告附件。 |
| 测试设计 | `test_items`、`test_cases` | 大纲、测试说明。 |
| 轮次范围 | `round_test_items`、`round_test_cases` | 当轮测试说明、记录、报告。 |
| 执行结果 | 执行记录、步骤实测、人员和时间 | 测试记录、报告。 |
| 问题与回归 | `issues`、影响域、回归结果 | 问题单合集、报告。 |
| 时间信息 | 时间锚点、推导值、人工锁定值 | 大纲、报告、封面签署。 |
| 专项证据数据 | `evidence_datasets`、数据集行、回归子集 | 大纲或说明附录、测试记录附录、报告专项附件。 |

时间信息不要求在业务录入前整体建立。业务表只保存接收、执行、闭环等事实时间；封面、签署、章节叙述等交付时间在文档生成向导中按锚点统一试算，并随文档版本快照。

## 文档实例模型

`generated_documents` 保存输出实例，不作为业务源数据：

- `id`、`project_id`、`round_id`
- `document_kind`
- `document_no`
- `status`：`draft` / `generated` / `locked` / `archived`
- `template_id`
- `current_revision_id`
- `generated_at`、`generated_by`
- `created_at`、`updated_at`

`generated_document_revisions` 保存每次生成结果：

- `document_id`、`version`、`change_summary`、`modified_sections`
- `template_snapshot_asset_id`
- `data_bundle_snapshot_asset_id`
- `file_asset_id`
- `generated_at`、`generated_by`

同一项目 + 文档种类 + 轮次允许多个版本。生成或重新生成时深拷贝模板配置和 Document Bundle 到快照附件；已锁定文档不再被模板和数据修改影响。

## 生成流程

1. 绑定模板并确认适用条件。
2. 执行文档预检，输出缺失数据、校验错误和警告。
3. 选择输出范围、聚合方式、时间锚点和推导规则，试算全量时间槽位并展示差异预览。
4. 组装受限结构化数据和 Tiptap JSON 内容块。
5. Go 渲染 OOXML：字段、表格行、图片、题注、编号和样式。
6. 写入文档实例、版本记录、时间口径和文件元数据。
7. 提供下载和只读预览。

生成失败必须保留前一个可用版本，不得用半成品覆盖已生成文件。
