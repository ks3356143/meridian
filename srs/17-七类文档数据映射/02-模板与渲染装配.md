# 模板与渲染装配

> 返回 [七类文档数据映射](../17-七类文档数据映射.md)

## 生成装配架构

Word 灵活性来自“模板可配置 + 渲染积木受控”，不来自任意文档转换。装配链路固定为：

```text
块定义注册表 + 数据资源字典 + 文档模板
  → DocumentBundle（项目、轮次、集合、统计、关系）
  → Document IR（章节、段落、表格、图片、题注、占位符）
  → OOXML Renderer（样式、编号、分页、页眉页脚）
  → DOCX
```

### 数据资源字典

所有模板可绑定的数据源必须登记，分四类：

| 类型 | 例子 | 提供者 |
| --- | --- | --- |
| 简单值 | 项目标识、软件名称、研制单位、测评性质、密级、版本。 | 基准数据模块。 |
| 集合 | 测试项、用例、执行记录、问题单、轮次、交付文档。 | 各业务模块。 |
| 统计 | 测试项数、用例数、通过率、问题矩阵、闭环率。 | 统计查询服务。 |
| 关系 | 需求追溯、影响域、历轮结果、文档引用。 | 追溯模块。 |

模板只引用资源 key，不直接写 SQL、不感知表结构。数据提供者负责权限、过滤、排序和项目隔离。

### 文档模板模型

模板属性包含：名称、适用平台、测评性质、文档种类、编号规则、版本规则、状态、模板版本、大纲树、复杂表格、叙述模板和默认标志。

项目创建时按平台和测评性质自动绑定默认已发布模板组；用户可在首份文档生成前更换。生成后项目模板绑定不再整体替换，后续模板演进通过派生模板和显式迁移向导处理，避免历史文档口径漂移。

大纲行角色：

- `heading`：1 到 4 级标题，编号由渲染器生成。
- `content`：正文，绑定 inline、单源、表格、叙述或内置积木。
- `cover`：封面。
- `sign`：签署页。
- `toc`：目录，从大纲树生成。
- `revision`：文件状态表。
- `pagebreak`：分页和纵横向切换。

绑定方式：

| kind | 说明 |
| --- | --- |
| `inline` | 固定话术加占位符。 |
| `singlesource` | 版本化系统单源片段。 |
| `table` | 复杂表格定义。 |
| `narrative` | 可自动起草、可人工修改的叙述组。 |
| `block` | 代码注册的内置渲染积木。 |

### 内置渲染积木

真实 Word 中存在大量无常规表头的连续网格表，必须用受控积木精确复刻，不能用“字段 / 内容”通用表偷懒。首批登记：

- `projectInfoGrid`：项目与被测对象信息横表。
- `testItemSheet`：测试项 10 行结构表。
- `testCaseSheet`：测试用例 12 行结构表。
- `testCaseRecordSheet`：测试记录用例表，含实测结果和通过与与否。
- `environmentBlock`：静态与动态环境组合。
- `traceabilityTable`：需求对照和追踪表。
- `issueReportSheet`：问题报告单三区连续表。
- `changeAnalysisBlock`：软件更改和影响分析。
- `organizationTable`：组织分工表。
- `reviewChecklist`：文档、代码、静态分析审查单。
- `evidenceDatasetTable`：登记过 schema 的大规模专项数据表，支持分块、筛选、差异状态和跨页表头。

积木只消费 Document IR 或已登记数据集，不查数据库、不拼 HTML。

### 复杂表格带区

跨页表、统计矩阵和汇总表使用带区模型：

- `header`：表头，可含占位符和动态列头。
- `detail`：逐记录重复。
- `footer`：合计或说明。
- `group`：按测试类型、问题状态、轮次等分组。

表格定义包含数据集、轮次上下文、排序、过滤、空集合策略、列、合并规则、跨页重复表头、列宽和页面方向。列语义必须绑定已登记字段或统计项，不支持任意表达式。

### 条件渲染与排序

- 未开展的测试类型自动裁剪对应章节、表格和目录项。
- 已开展类型按军标固定顺序输出，不按录入时间排序。
- 空表策略由模板定义：保留空表、跳过章节或输出说明行。
- 目录、章节号、表号和图号在大纲遍历中统一分配。
- 总页数在 DOCX 生成完成后回填，不能提前伪造。
