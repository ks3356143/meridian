# 首页与项目导航

## 信息架构

- `/`：项目列表页（应用首页），以多项目为中心，一眼看清全部在跑的项目。
- `/projects/new`：真实项目创建页。
- `/projects/:code`：项目详情状态页，只读展示该项目的阶段、模块完成度、关键指标与缺失项，不承载录入表单。
- `/projects/:code/workspace/*`：单项目超级工作区，按项目阶段默认进入大纲编制流或执行总览，承载该项目的资料、大纲、需求、测试设计、轮次执行、问题单、文档产出和文档生成。
- 登录后默认进入 `/`；点击项目行或“详情”按钮进入项目详情。详情页提供常显的“进入工作区”主操作，并可按当前状态 TAB 直达对应工作区分区。
- 桌面端使用固定左侧导航；窄屏隐藏侧栏时，顶栏必须保留小菜单按钮，点击后以左侧抽屉展示同一套导航，点击导航项后自动关闭。
- 工作区是独立全屏“大页面”，不在首页内嵌；后续功能模块都挂在项目工作区路由下。

## 首页（项目列表）布局

1. 顶栏（一行）：页面标题 + 日期 + 快捷操作（新建项目、生成文档占位）。
2. 筛选条：关键词（标识、名称、研制单位、负责人）+ 状态、等级、平台筛选；筛选状态保存到 localStorage，展示结果数量并支持一键清空。
3. KPI 密排条：一行 6 个微型指标（数字 + 小标签），不使用大卡片。指标包括：项目总数、执行中、编制中、已完成、用例执行率、未闭环问题（重大/严重红色高亮），并补充执行率微进度与问题级别拆解。
4. 风险与活动摘要条：仅从项目字段推导，重大/严重未闭环问题优先，其次未闭环总数与待执行用例；点击条目进入项目详情。
5. 项目表（主体）：TanStack Table 分列展示，紧凑行高（约 44px），一屏 15 行以上。列：标识、项目名称、测评性质、软件类型、安全等级、平台、研制单位、负责人、用例执行（n/m）、未闭环问题、状态、更新时间、操作。支持排序、键盘 Enter 导航与左侧 hover 指示线；点击行进入项目详情。操作列必须提供常显的“详情”按钮，项目入口不能只依赖整行点击这一条隐含路径。
6. 右侧栏（约 320px）：我的待办（未闭环问题 Top5、待执行用例、最近更新项目）。
7. 视觉延续品牌动效规范：经线球背景装饰、匀速流光分隔线、面板 hover 辉光、入场 stagger、数字滚动。

首页统计口径：KPI、风险摘要、待办栏和项目表均跟随当前筛选结果；页面标题、日期和快捷操作不参与筛选。生成文档保持占位操作；新建项目跳转到真实项目创建流程，字段口径见《13-项目创建与基础字典》。

## 项目数据模型

- 项目标识：`R` + 4 到 5 位数字，创建时用户输入数字后缀，前缀 `R` 固定。
- 测评性质：鉴定测评 / 第三方测评 / 二方测评。
- 测试平台：FPGA / CPU/非嵌。
- 软件类型：新研 / 改造 / 沿用。
- 密级：公开 / 内部 / 秘密 / 机密 / 绝密。
- 安全等级：关键A / 重要B / 一般C / 不重要D。
- 编程语言、运行环境、开发环境、依据标准、负责人和成员口径见《13-项目创建与基础字典》。
- 状态机：编制大纲中 → 大纲已评审 → 测试执行中 → 回归验证中 → 报告编制中 → 已完成。
- 用例执行：`已执行/总数` 与百分比。
- 问题单：未闭环数量按级别（重大/严重/一般/建议改进）统计。

## 项目详情与工作区边界

项目详情是状态驾驶舱，工作区是作业面。两者必须保持职责分离，不得因为模块增多而把录入表单塞回详情页。

### 项目详情

- 顶部为项目 Hero：项目标识、名称、状态、安全等级、负责人、更新时间和关键指标。
- Hero 是状态驾驶舱的主视觉：使用品牌绿主色、信息蓝和阶段色组成低强度斜向渐变与网格纹理，左侧保留品牌色轨；关键指标使用图标、等宽大数字和语义色，形成“项目牌面”而不是普通表单头部。
- Hero 主操作是“进入工作区”；详情页不得出现新增、编辑、导入、生成等作业按钮。
- 详情 TAB 只读，按“总览、项目资料、被测对象、需求追溯、测试设计、轮次执行、问题单、文档产出”展示模块状态。
- 总览模块状态卡必须有模块图标、左侧语义色条、浅色渐变底、完成度进度和状态徽标，禁止只放文字与灰底框。
- 阶段条的当前阶段使用流动渐变和柔光扫过动画，已完成阶段使用静态成功色，未开始阶段保持弱化；模块卡的“部分具备”状态使用低速微光，表示仍在推进。
- 总览中第一个未具备的模块标记为“当前处理焦点”，使用与当前阶段一致的流动渐变；其余待补齐模块保持静态弱化，避免所有卡片同时闪烁。
- 项目资料 TAB 分为“基准档案、环境配置、项目人员、依据标准”四类信息分区：每区有图标、计数、语义色和轻阴影；列表值使用徽标或行卡，不得把所有字段混在一组普通定义列表里。
- 每个 TAB 可跳转到工作区对应分区，但跳转入口必须是明确的单一操作，不能把状态页变成二级导航壳。
- TAB 切换只切换内容区，不得触发整页刷新、重挂载 Header 或造成滚动位置丢失。

### 项目工作区

- 工作区是独立全屏页面，不显示系统后台左侧导航；顶部 Cockpit 展示返回、项目标识、项目名称、状态、全局轮次、当前用户和基础操作。
- 主体分区：大纲编制、执行总览、项目资料、被测对象、需求追溯、测试设计、轮次工作区、问题单、文档产出；各分区自带二级导航或工作面板。
- 编制大纲阶段默认进入大纲编制流，通过目录树和下一步任务引导录入；大纲评审后进入执行总览，展示完善度、下一步待办、当前轮次风险和模块统计。
- 路由、模块边界、高效录入和动效基线见《14-项目工作区与前端模块》。
