# 项目创建与基础字典

## 定位

项目是全部测评流程的基点。测试大纲、测试项、用例、执行记录、问题单和报告都挂接到具体项目下。本轮实现项目创建、基础字典和依据标准管理，不实现文档模板选择、大纲编辑和 Word 渲染。

## 新建项目

表单分为基本信息、技术属性、依据标准、项目人员四段；所有业务字段必填。

### 基本信息

- 项目标识：前缀 `R` 固定展示，只输入 4 到 5 位数字后缀；保存后完整标识为 `R` + 4 到 5 位数字，全局唯一。
- 项目名称：必填；研制单位不在创建时设置，进入项目后作为大纲元数据补录（对齐团队工具依据文档字典口径）。
- 测评性质：鉴定测评 / 第三方测评 / 二方测评。
- 测试平台：FPGA / CPU/非嵌；影响后续模板选择和测试项默认内容。
- 软件类型：新研 / 改造 / 沿用。
- 密级：公开 / 内部 / 秘密 / 机密 / 绝密；生成 Word 首页时展示。
- 安全等级：关键A / 重要B / 一般C / 不重要D；影响测试项必备类型和测评策略。
- 项目状态初始为 `编制大纲中`，统计快照初始为 0。

### 技术字典

编程语言、运行环境、开发环境分别多选，且各自至少选择一项。

- 选项来自启用字典，预置基础数据独立维护。
- 新建项目页支持新增自定义值。
- 自定义值与项目创建保存在同一事务中，项目失败不得污染字典。
- 同一类别内按展示名去重，忽略首尾空白和大小写。

### 依据标准

依据标准是独立字典，新建项目时从启用项中多选，至少选择一项。

- 文档名称：必填，例如 `GJB 438C-2021`。
- 标识 / 版本、发布日期、来源单位：必填，按已有资料填写。
- 排序值决定后续测评大纲依据文件章节顺序。
- 文档名称全局唯一，比较时忽略大小写。

### 项目人员

- 负责人必选，来源为系统用户；负责人自动成为成员。
- 成员可多选，支持按用户名或显示名搜索。
- 同一用户在同一项目只保留一条成员记录。
- 本轮只保存归属关系，不做项目内角色和权限细分。

## 数据模型

- `projects` 保存项目基础字段、负责人、状态和统计快照；完整项目标识唯一，项目名称不作为唯一键。
- `dictionary_items` 保存三类通用技术字典，字段包括类别、展示名、排序、启用状态和是否预置。
- `reference_standards` 独立保存依据标准，不复用字段较简单的通用字典表。
- `related_parties` 保存相关方字典（委托方 / 研制方 / 测评中心），同类别名称唯一。
- 项目通过关联表保存语言、运行环境、开发环境、依据标准和成员关系，不在项目行内存 JSON。
- 所有业务主键使用 UUIDv7 字符串；所有表保留 `created_at`、`updated_at`。

## API 口径

- `GET /api/v1/project-options`：返回启用技术字典、启用依据标准和可分配用户。
- `POST /api/v1/projects`：一次性保存项目基础信息、字典项、自定义字典、依据标准和成员。
- `GET /api/v1/projects`：返回项目列表聚合结构。
- `GET /api/v1/projects/{code}`：按 `R` + 4 到 5 位数字返回项目详情。
- `GET/POST/PUT /api/v1/related-parties`：相关方字典管理，写操作仅 admin。

## 字典管理

管理入口为 `/settings/dictionaries`，包含技术字典、依据标准、相关方字典三个页签。

- 两者都支持新增、编辑、启用/停用和排序；不提供物理删除。
- 预置项和自定义项均可编辑和停用，保证历史项目可追溯。
- 停用项不再出现在新建项目选项，但历史关联保持不变。
- 管理接口写操作仅 admin 可用。

### 相关方字典

- 相关方指委托方、研制方（研制单位）和测评中心，预置在字典中，项目设置时从此处选择或新建。
- 一个项目使用一次：选中后作为项目内元数据快照，停用或修改字典不影响已保存的项目。
- 弹窗表单与依据标准同规范：必填标记、noValidate 自定义校验、组件库日期/下拉控件。
- 字段：单位名称（必填）、联系人、联系电话、单位地址（选填，供测评大纲文档引用）；同类别名称唯一，忽略大小写；支持排序、启用/停用，不提供物理删除。

## 后续与不做

- 本轮不做模板绑定、Word 渲染、大纲草稿、项目编辑/删除/归档、成员角色权限。
- 继续根据操作反馈优化校验时机、错误文案、字段分组、自定义字典、依据标准和人员选择体验。
- 优先整理 Dialog 表单状态初始化方式，避免用 effect 同步重置表单。
