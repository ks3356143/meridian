# 版本与验证

## 版本

- 版本号从 `V0.0.1` 开始。
- `V1` 之前是个人原型和快速迭代阶段。
- `V1` 定位为覆盖测试项、用例、记录、报告、Word 生成主流程的可用版本。
- 版本变化记录在根目录 `版本记录.md`。

## 验证铁律

每次代码修改后，必须先执行可运行验证，再汇报完成。

验证清单必须包含：

- 已验证项
- 验证方法
- 剩余风险
- 用户人工浏览器审核步骤：前端可验证改动必须提供入口地址、前置状态、逐步操作和每步预期结果；纯后端或无浏览器界面的改动明确说明原因，并提供接口、数据或日志等替代人工验证步骤
- 浏览器自动化验证默认使用路由拦截夹具或专用测试项目，不得在真实项目数据上触发保存、删除或状态变更；确需真实数据验证时先说明范围并获得用户确认

## 常规检查

- 后端：`gofmt`、`go test ./...`、`go vet ./...`，必要时构建和请求接口。
- 前端：类型检查、lint、格式检查和构建；视觉验收生成截图后由视觉模型直接查看，不以 DOM 文本断言代替视觉判断。
- 数据库：迁移测试和关键 API 集成测试。

## 启动前依赖更新检查

每次会话开工时（用户说“开始工作”或要求打开前后端），必须先检查并更新全部前后端依赖，禁止直接跳过；若服务已经运行，依赖升级后必须重启服务。

- 后端：执行 `go list -u -m all`，检查全部 Go 依赖库，明确包含 Huma v2、GORM、SQLite 驱动等；有更新时执行 `go get -u ./...` 和 `go mod tidy`。依赖变化后至少执行 `go test ./... -count=1`、`go vet ./...` 和 `go build -o bin/chenmeridian.exe ./cmd/chenmeridian`，通过后再启动。
- 前端：在 `web/` 执行 `npm outdated`，检查全部 npm 依赖库，包含 React、Vite、React Router、Tailwind、TanStack、Radix、shadcn 相关依赖和构建工具等；有更新时升级到最新稳定版并更新 `package-lock.json`。依赖变化后至少执行 `npm run check`，通过后再启动。
- 兼容约束：保持 pure Go SQLite，不引入 CGO；React Router 相关包保持同一版本；禁止用 `--force` 掩盖 peer dependency 冲突。
- 结果记录：无更新时在启动汇报中明确“已检查”；有更新时说明升级项、未升级项、原因和验证结果。影响长期选择的兼容问题同步记录到跨会话记忆或项目记忆。

## 下班 Skills 更新提醒

- 每次下班时列出本次会话实际使用的 skills，并检查本地安装或插件市场是否有可用更新。
- 必须提醒用户决定由代理更新还是由用户更新；未获明确决定前不得升级、重装、删除或替换 skills。
- 无法自动检查更新来源时说明限制，并至少列出本次使用的 skills 供用户判断。
- 用户决定由代理更新后，再执行更新并验证技能可用，结果写入下班汇报。
