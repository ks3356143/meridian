# 测试项页面与交互

> 返回 [测试项与执行](../24-测试项与执行.md)

- 路由：项目工作区 `测试与执行 → 测试项`（沿用现有 `/projects/{code}/workspace/test-items`）。本页形态已于 2026-10-10 按静态图定稿（一张测试项表 + 子项卡片 + 用例概况卡）。
- 总原则：**一屏完成**（左树 + 右详情，不跳页），**像写 Word 表格**（表格化排版 + 单元格直接编辑），**键盘优先**，**保存无感**。

## 详情卡片的 Word 表格观感（铁律）

- 版式：整表 100% 宽，`border-collapse` 1px 硬边框；label 列 120–160px、浅灰底、居中加粗；value 列白底左对齐，行内边距 6–8px，紧凑但不拥挤。
- 直角、无圆角、无斑马纹；标识与 YL_ID 用等宽字体；表格外框一层轻阴影（共享 Table 组件），滚动时表头吸顶。
- 与全站设计体系一致：浅色 + 绿色主色 + 玻璃；不引入第二套配色。
- 单元格编辑：**点击即编辑**；普通字段用统一输入组件（单行 `Input` / 自动增高 `Textarea`），富文本字段用 Tiptap 内联编辑器（聚焦浮出工具栏）；`Esc` 取消本次编辑，失焦自动保存。
- 焦点与错误：
  - 可编辑单元格 hover 时极淡蓝底 + 内描边；聚焦时品牌绿描边 + 2px 荧光 ring + 外扩散阴影（沿用表单铁律）。
  - 必填为空：红色描边 + 2px 红色荧光脉冲，修正后 160–220ms 淡出。
  - 保存成功：单元格 1.2s 绿色轻脉冲 + 行尾状态点；保存失败：红色描边 + `sonner` 点名，重试按钮就地给出。
- 键盘：`Tab` / `Shift+Tab` 走格，`Enter` 进入下一行同列，`Ctrl+Enter` 在末行新增一行并聚焦；`Alt+↑/↓` 移动子项 / 步骤行；`Ctrl+Z` 撤销（单实体快照，上限 20）。

## 测试方法（子项卡片）

> 现行口径（2026-10-13 复核）：子项存**名称 / 描述 / 操作步骤 / 通过准则**四栏（操作步骤与通过准则按行 1:1）；工具条 = 子项计数 + 从上个复制 + 新增子项；卡片 = 5 色循环色条 + 拖拽手柄（@dnd-kit，空格拿起/方向键移动）+ `{测试项标识}_{3位序号}` + 四栏就地编辑 + 生成用例/复制/删除；操作步骤与通过准则的 label 行各带一个「自动编号」图标按钮。空名卡片红色脉冲。

- 每个子项一张紧凑卡片：左侧 4px 彩色条（5 色循环）、拖拽手柄、`标识 + 名称`、可选描述行、**操作步骤 | 通过准则** 双栏对照（条数必须 1:1）。
- 工具：从上个复制、自动编号、标注（选中文字加高亮，点击可取消）、删除、新增；空字段红色脉冲提示。
- "**子项 → 用例**"：一键把当前子项转换为一条用例（1:1），转换后跳出提示可继续编辑；不做批量场景拆分。
- 充分性要求为空时自动按子项名生成模板话术，子项增删改名后局部刷新。

## 动效与反馈

- 树展开 / 收缩走 FLIP（同需求树口径）；用例行增删、徽章变化使用短动效，不打断当前焦点。
- 吸顶切换：主色玻璃底 + 标题主色 + 按钮实心→描边，180–320ms；`prefers-reduced-motion` 下直接切换。
- 保存反馈遵循"无感优先"：只做局部脉冲与状态点，不弹模态；失败才用 `sonner`。
- 页面级入场：轻微上浮淡入 + 分区 stagger，尊重 reduced-motion。

## 编辑口径（实时编辑）

- 点击单元格即编辑（**光标落在点击处**：按点击坐标换算字符偏移；键盘激活才回退到末尾）；`Esc` 取消本次编辑；失焦自动保存（并行保存，失败保留脏值并可重试）；**编辑器必须保留浏览器原生撤销（Ctrl+Z，含失焦后再次进入同一单元格）**——内联编辑器用非受控 `defaultValue` + ref，且编辑框常驻 DOM（展示/编辑用 `data-editing` 切显示，不卸载），禁止受控 `value` 与条件渲染。
- 普通字段用统一输入组件（单行 `Input` / 自动增高 `Textarea`）；长文本（需求描述、充分性要求、通过准则）用多行框。
- 富文本字段（用例步骤的"输入及操作 / 实际结果"）用 Tiptap 内联编辑器，聚焦时浮出工具栏。
- 状态可视化：正在编辑＝绿色荧光（内描边 + 4px 外发光 + 轻浮起）；必填未填＝红色荧光脉冲 + 字段内提示；悬停＝淡蓝底 + 内描边；保存成功＝单元格 1.2s 绿色轻脉冲；保存失败＝红色描边 + `sonner` 点名。
- 子项卡片（测试方法行内）：拖拽手柄排序、复制、删除、从上个复制、自动编号、标注；空字段红色脉冲；**操作与预期条数必须 1:1**；卡片内一切字段实时编辑。

## 标签与超长文本（不换行铁律）

1. 标签 / 徽章 / 状态 pill / 按钮文字：**永不折行**（`white-space:nowrap`，`flex:none`）。
2. 标签组允许**整块换行**到第二行（`flex-wrap` + `row-gap:6px`），禁止把标签内部文字折断。
3. 同一行里**先牺牲名称**：名称区 `min-width:0` + 省略号 + 悬停浮层显示全称，标签保持完整。
4. 表格 label 列以最长标签为宽度下限（约 158px）并单行显示；宁可加宽列，不折行。
5. 编号 / 标识用等宽字体且不折行；列不足时整列加宽，最后才尾部省略（悬停补全）。
6. 禁止：标签内部折行、编号断字、因标签换行导致行高跳动。

## 视觉与动效口径（2026-10-10 二轮定稿，用户 14 条反馈）

- **类别色相**：静态=信息蓝、功能验证=品牌绿、性能强度=琥珀、环境适配=紫、专项分析=青、审查摸底=红（映射主题 `--primary/--info/--warning/--chart-*`）；树节点色点、类型 chip、类型下拉、Hero 徽章、标题竖线同源。
- **主题色竖线**：Hero 标题与卡片标题前 4px 圆角竖线，颜色跟类型类别，带同色光晕。
- **动效（默认都要有，且「华丽但无卡断」）**：切换测试项时右详情 300ms 上浮淡入；编辑态荧光 220ms 由细渐粗；未完善琥珀呼吸（2.4-2.6s 循环）；保存成功 1.3s 绿脉冲；手风琴展开用 `grid-template-rows` 0fr→1fr 过渡 260ms；未完善行 label 单元格琥珀左色条。全部 `prefers-reduced-motion` 下退化为直切、不产生位移。
- **编辑不跳版**：展示态与编辑态共用盒模型（`min-height:2rem`、同 padding 与行高），点进编辑行高与表格位置不变。
- **徽章与标签**：标签徽章按语义着色（类型=类别色、优先级=红/绿/灰、隐含需求=琥珀虚线、未完善=琥珀荧光），标签内部永不折行。
- **删除按钮**：低频危险操作降权——描边红常驻、hover 实底红 + 光晕（2026-10-12 调整），与完善度卡片同行右对齐。
- **新增测试项弹窗**：宽度 42rem（+50%）；类型默认「功能测试」、优先级默认「高」；类型选择器用 Command 两列网格，支持代号（DC）、名称、拼音首字母（gncs）模糊搜索；已建静态类型自动收起并在描述里说明。
- **关联需求**：按来源文档分组（研制总要求 / 需求规格说明…），chip 与手风琴行都显示来源文档名，多文档场景可分辨。
- **需求描述手风琴**：默认只占一行（来源 + 章节号 + 名称 + 行尾箭头），点开后展示结构化正文（表格 / 图片，旧数据回退纯文本；内部滚动，最高 22rem）；收起零请求、图片进视口才加载（2026-10-12 升级，见文末「打磨收口」）。
- **切换不跳滚动条**：详情滚动容器常驻 `scrollbar-gutter: stable`；切换测试项时动画只作用于容器内内容（`useLayoutEffect` 先归零 `scrollTop`），不动滚动容器本身。
- **焦点荧光绝对定位（2026-10-10 定稿）**：荧光画在单元格的 `::after` 上（`inset:-1px`，`pointer-events:none`，只过渡 opacity），**不占宽高、不参与布局**；编辑器自身只改边框色、不再画 box-shadow。focus 前后任何位移都与荧光无关。
- **编辑态高度钉死（2026-10-10 终稿）**：进入编辑时把单元格高度显式设为展示态实测高度（`getBoundingClientRect().height`），不再依赖"两边算出来一样"——`textarea` 的固有高度比展示态多约 0.2px（亚像素取整），只要不钉死，点下去整行就会被撑高、下面所有行跟着下移。内容真的多出（> 2px，即新起一行）才按 `scrollHeight + 边框` 增高；编辑结束后清掉内联高度。CDP 逐帧实测：点击测试项描述/充分性要求/通过准则，单元格高度、行 top、表格 top **零变化**。
- **多行单元格不重新折行**：`textarea` 出现滚动条会挤窄文字宽度导致重新折行（真正看得见的"跳"），编辑框统一 `scrollbar-width: none` + `::-webkit-scrollbar{width:0}`，并把 `maxRows` 放到 30（内容自增高，基本不需要内滚）。
- **展示态与编辑态同构**：对称 `padding: 0.4rem` + 整数行高 `18px`（textarea 的 `scrollHeight` 是整数，用小数行高会带来 0.5px 行高差）+ 同一 1px 边框；单行文本自然上下居中，多行首行起点一致。实测四个单元格文字位移 0.01px、行高差 ≤0.21px（textarea 亚像素取整，肉眼不可见）。
- **状态切换不得改变布局（2026-10-10，逐帧实测）**：英雄区不放会随状态增删的徽章（隐含需求状态改写在完善度框内）；完善度框定高（缺项 chip 与"已满足"两种状态同高）；追踪关系行高度由按钮决定。用 CDP 逐帧录：切换隐含需求/进入编辑时 hero、表格、用例概况的 top/height 零变化（进入编辑仅剩 0.21px 亚像素）。
- **追踪关系两行布局（2026-10-10）**：操作按钮「关联需求」「隐含需求」在上，需求 chip 在下；两者混排会显得乱（用户实拍反馈）。
- **进入编辑时光标落在文本末尾**：`input` 默认在末尾、`textarea` 默认在开头，必须显式 `setSelectionRange(len, len)` 统一（2026-10-10 实测四个单元格均为末尾）。
- **编辑不跳行（逐像素）**：展示态与编辑态共用同一 1px 边框、同一行高（显式 `line-height: 1.45`）与同 padding；多行单元格进入编辑时以展示态实测高度做编辑框最小高度，实测四个可编辑单元格行高一致（充分性要求残余 0.5px 属亚像素取整）。
- **单元格编辑器统一口径（用例表同样适用）**：单行 `Input` 与多行 `Textarea` 完全同款——1px 边框、2px 圆角、`padding 0.32rem 0.4rem`、`min-height 2rem`、`line-height 1.45`；焦点态统一为 1px 主色边框 + 3px / 12% 柔光，并用更高优先级 + `!important` 压掉全局 `field-state.css` 里 `[data-slot="input"]:focus-visible` 的粗环（否则 Input 与 Textarea 焦点不一致）。
- **单元格文字左缩进基准**：可编辑单元格文字、只读提示（未关联需求 / 尚无测试子项）、追踪关系 chip 行统一从 `0.4rem + 1px` 起排；需求描述手风琴盒子与编辑框盒子左边缘对齐（`0.25rem`），内部文字同样落在同一基准上。
- **焦点环**：1px 主色边框（编辑器自身）+ 3px / 12% 柔光（`::after` 绝对定位），**全局只允许一根实线**——外圈绝不能再画 1px 实线描边，否则就是双边框（2026-10-10 实拍修正，口径照老项目 `border-color + box-shadow 0 0 0 3px rgba(...,0.12)`）。优先级下拉同样只有边框变色 + 柔光。
- **dot 按钮**：关联需求（主色 6px 圆点）、隐含需求（琥珀 6px 圆点，开启时描边高亮）——按钮不再用图标，沿用老项目 `dot` 视觉。
- **自动保存**：单元格失焦保存，保存后 Hero 标签行出现「已自动保存」提示（1.6s 淡出）；失败红色描边 + `sonner` 点名、就地重试。
- **派生规则**：类别色相、拼音首字母表在前端 `test-items-design.ts`；类型字典可配置后拼音挪到 `test_item_types` 字段并由接口返回（代码内已标 shortcut）。

## 测试子项三栏的输入框边框（2026-10-10）

- 口径（老项目）：**子项描述 / 操作步骤 / 通过准则** 三处展示态直接画输入框边框（`--input` 色），用户一眼看出可输入；子项名称维持标题样式不带边框。
- 实现：`EditableCell` 增加 `bordered` 变体（`data-bordered="true"`），只把展示态那根 **本来就有、颜色为透明** 的 1px 边框换成 `--input`；悬停改边框色 + 5% 信息蓝底，不再叠加内阴影（否则和边框叠成双线）。
- 关键约束：不能为了"有边框"去加 `box-shadow` 或改内边距——展示态与编辑态的盒模型必须逐像素相同，否则进出编辑会顶动整行（历史上出现过 0.2px 撑行）。实测带边框后进出编辑单元格高度恒为 176.31px、行位不变。

## 完善度口径：测试方法要看到子项内容（2026-10-10）

- 现象：子项只填了名称、操作步骤与通过准则还空着，详情头部却显示“四项齐全”，树上的“未完善”也不亮——用户看到的是一堆空输入框，却被告知已完善。
- 口径：**测试方法完善 = 至少 1 个子项，且每个子项的“操作步骤”和“通过准则”都非空**；否则详情头部列出“缺 测试方法”，树上该测试项标 `未完善`。
- 落点：子项计数由服务端 `CountItemChildren` 一次算好（`incompleteSubItemCount`：操作步骤或通过准则为空的子项数），列表接口不带子项正文，树与工具栏只读这个计数；详情页用本地子项数组判定（`methodOk`）。两处必须用同一口径，否则会出现“树说未完善、详情说齐全”。
- 静态四类（DC/SA/CR/CW）不参与完善度：默认子项由类型种子预填，详情不显示完善度卡片。

## 打磨收口（2026-10-12，人工验收后）

- **需求描述手风琴 → 正文预览**：展开才请求正文（`enabled: open`），收起与未展开零请求；首次展开后保持挂载，收起动画不丢内容、再次展开不重复请求。内容同源需求工作台：优先 `/blocks` 结构化块（表格 / 图片），旧数据回退 `/content` 纯文本；正文区最高 22rem 内部滚动（`scrollbar-gutter: stable`）。
- **手风琴图片按需**：`IntersectionObserver`（`rootMargin: 200px`）进视口才发 Blob 请求；加载中保持宽高比占位 + 居中 spin「图片加载中」（`aria-busy`），就绪后 0.32s 透明度揭示 + 0.6s 主色光晕；失败按 `assetId` 记账，同一实例复用到另一张图不带旧失败态。
- **手风琴展开反馈**：左侧 2px 信息蓝条 + 名称提色加重，箭头移到行尾且悬停提色；正文 0.26s 透明度过渡；加载失败给 QueryError 就地重试；`prefers-reduced-motion` 关闭 spin / 过渡 / 光晕。
- **分区导航「点谁亮谁」**：点击分区立即点亮目标并锁定，平滑滚动期间的位置推断不抢高亮；用户 wheel / touchstart / keydown 后交还自动推断；`prefers-reduced-motion` 时锚点直跳。
- **保存芯片覆盖子项**：子项名称 / 描述 / 操作步骤 / 通过准则的编辑与保存相位经 `onPhase` 上报详情 `reportPhase`，右上角芯片同步「待自动保存 / 保存中 / 已自动保存 / 保存失败」；子项字段保存与主表同一 `withSavePhase` 出口（「保存中」至少展示 420ms，2026-10-12 修复瞬变）。
- **子项卡 hover 只描边**：不铺主色底，只加深边框 + 1px 主色环 + 16px 柔光；卡片 hover 时拖拽把手加深一档。
- **子项标签对齐与完成脉冲**：子项描述 / 操作步骤 / 通过准则标签 `padding-left: 1px` 与输入框左边框对齐（字号 0.66rem）；完善度从「缺项」转「已满足」播一次性 0.3s 脉冲（非循环），与未完善的琥珀呼吸不同台。
- **用例状态色**：用例行首 3px 状态色条（通过绿 / 未通过红 / 未执行灰）、通过率进度条按 `data-tone` 着色（0% 灰 / 中段主色 / 100% 绿）；新增关联 chip 入场 0.22s（透明度 + 光晕，无位移）；静态测试项进度提示为信息蓝弱化胶囊 + Info 图标。
- **全站直角收口**：清除 56 处 2px / 3px 微圆角（测试项、需求与共享控件，含工作区路由容器上下收角），圆点、胶囊、圆形图标等圆形语义元素除外；口径见 [07/01](../07-前端体验/01-基础视觉与组件/01-视觉方向.md)。

## 易用性打磨（2026-10-13，参考老项目 TreeNav）

- **搜索与快捷筛选（第一刀已完成）**：搜索匹配测试项名称 / 标识 / 子项名 / 用例名 / YL_ID（输入 150ms 防抖后过滤，老项目同口径）；快捷 chips = 全部 / 未完善 N / 有失败 N，与搜索叠加（AND）；搜索或筛选激活时强制展开命中分支（`tree.openAll()`），退出后按 localStorage 记忆还原用户手动开合，且筛选期间不覆写记忆；无结果给空态 +「清除搜索与筛选」；激活时树底显示「显示 X 项 · Y 用例」。子项名随工作台一次下发（`counts[].subItemNames`），不额外请求。
- **展开/收起全部**：筛选行右侧两个图标按钮直接 `openAll()` / `closeAll()`（不进记忆语义，属于临时视图操作）。
- **复制新增测试项**：右键「复制新增」与 `Ctrl+D`；复制内容字段与子项，名称加「-副本」、标识按后缀唯一化重排，副本紧跟原件之后；追踪关系与「隐含需求」不复制（新项要重新决策）；静态四类拒绝复制（同类静态每轮只能一个）。
- **文件夹管理**：右键改名（`PATCH /api/v1/test-item-folders/{id}`）与删除（`DELETE`，仅解散容器，内部测试项 folder_id 置空回到类型根目录，二次确认写明影响条数）。parentId 嵌套目录本版不做。
- **拖拽落位规则**：分组/文件夹只当容器、不可拖；测试项只允许落在同类型分组或文件夹上（跨类型落点直接拒绝，后端还会再校验一次 `ErrFolderMismatch`）；用例只允许落在测试项行上。落点序号在分组层要折算：分组子节点是「文件夹在前 + 类型根测试项在后」，根目录落点 = 树序号 − 该类型文件夹数。
- **乐观落位**：拖拽结束先按后端口径本地重排（`placeTestItem` / `placeCase`：容器内按 sort_order 重排、越界夹取），失败原子回滚，成功后再 invalidate；用例跨项移动会重排标识，故详情缓存一并作废。
- **树 props 稳定**：`renderRow` / `renderNode` / `onMove` / `onToggle` 全部 `useCallback` 固化，`disableDrag` / `disableDrop` 用模块级函数——react-arborist 的拖拽源按 props 变更失效，每次渲染换新回调会让整棵树重挂拖拽源。
- **不做的**：跨文件夹批量移动、文件夹排序、面板级撤销栈（破坏性动作已有二次确认 + 复制新增可兜底），等用例详情（切片 5）落地后再评估。

- **树性能口径（2026-10-13 压测）**：右键菜单是**树级一个**（不是每行一个），行内不挂 `Tooltip`（`react-arborist` 行是 `min-width: max-content`，标签不截断，宽度不够时横向滚动）；展开记忆写 `localStorage` 合并到 200ms 一次（`openAll` 会逐节点回调 `onToggle`）；`未完善` 荧光呼吸画在 `::after` 上只动 `opacity`。数据与门禁见 [21-前端性能优化策略](../21-前端性能优化策略.md) 2026-10-13 节。
