# 视觉规范与打磨记录

> 本文解决什么问题：测试项页面的类型修改、默认话术、类别色相与动效细则，以及 2026-10 起的人工验收修订。上游 [02 测试项页面与交互](../02-测试项页面与交互.md)，相关 [04 静态测试项](../04-静态测试项.md)、[01 数据模型与标识](../01-数据模型与标识.md)。

## 动效与反馈

- 树展开 / 收缩走 FLIP（同需求树口径）；用例行增删、徽章变化使用短动效，不打断当前焦点。
- 吸顶切换：主色玻璃底 + 标题主色 + 按钮实心→描边，180–320ms。
- 保存反馈遵循"无感优先"：只做局部脉冲与状态点，不弹模态；失败才用 `sonner`。
- 页面级入场：轻微上浮淡入 + 分区 stagger。

## 修改类型（2026-10-10 接入）

| 环节 | 口径 |
| --- | --- |
| 入口 | 详情表「类型」单元格整体为按钮（悬停 / 聚焦出现铅笔），点开"修改测试项类型"确认弹窗 |
| 弹窗 | 当前类型 → 新类型（共享类型选择器，排除当前类型与本轮已建静态类型）；选中即预览影响：标识前缀、用例编号、树分组、套话跟随、文件夹移出、静态警告 |
| 服务端事务 | 后缀沿用（被新类型占用则按名称重生成）→ `identifier` 与全部用例编号一起重排；套话未被手工改过时跟随新类型的默认话术；转静态时隐含需求标记清零 |
| 拒绝规则 | **静态四类（DC/SA/CR/CW）类型锁定，任何改类型都拒绝（400，详情「类型」格呈只读、无铅笔）**；本轮已建同类静态（400）；已关联需求转静态（400，需先解除关联）；平台不适用（400）。失败保持弹窗打开，错误由全局 toast 统一提示（业务层不重复弹） |
| 文件夹 | 文件夹按类型归属：跨类型后旧文件夹不再匹配，服务端自动移出（`folder_id=null`），否则测试项会在新分组里"看不见" |
| 数据面 | 需求关联按测试项 ID 保存，改类型不丢关联；树、用例编号、追溯视图都读服务端真值 |

## 视觉与动效口径（2026-10-10 二轮定稿，用户 14 条反馈）

- **类别色相**：静态=信息蓝、功能验证=品牌绿、性能强度=琥珀、环境适配=紫、专项分析=青、审查摸底=红（映射主题 `--primary/--info/--warning/--chart-*`）；树节点色点、类型 chip、类型下拉、Hero 徽章、标题竖线同源。
- **主题色竖线**：Hero 标题与卡片标题前 4px 圆角竖线，颜色跟类型类别，带同色光晕。
- **动效（默认都要有，且「华丽但无卡断」）**：切换测试项时右详情 300ms 上浮淡入；编辑态荧光 220ms 由细渐粗；未完善琥珀呼吸（2.4-2.6s 循环）；保存成功 1.3s 绿脉冲；手风琴展开用 `grid-template-rows` 0fr→1fr 过渡 260ms；未完善行 label 单元格琥珀左色条。
- **编辑不跳版**：展示态与编辑态共用盒模型（普通单元格 `min-height: 2.5rem` + `line-height: 18px`；富文本 `min-height: 2.5rem` + `line-height: 1.8`，同 padding 与 1px 边框），点进编辑行高与表格位置不变。
- **徽章与标签**：标签徽章按语义着色（类型=类别色、优先级=红/绿/灰、隐含需求=琥珀虚线、未完善=琥珀荧光），标签内部永不折行。
- **删除按钮**：低频危险操作降权——描边红常驻、hover 实底红 + 光晕（2026-10-12 调整），与完善度卡片同行右对齐。
- **新增测试项弹窗**：宽度 42rem（+50%）；类型默认「功能测试」、优先级默认「高」；类型选择器用 Command 两列网格，支持代号（DC）、名称、拼音首字母（gncs）模糊搜索；已建静态类型自动收起并在描述里说明。
- **关联需求**：按来源文档分组（研制总要求 / 需求规格说明…），chip 与手风琴行都显示来源文档名，多文档场景可分辨。
- **需求描述手风琴**：默认只占一行（来源 + 章节号 + 名称 + 行尾箭头），点开后展示结构化正文（表格 / 图片，旧数据回退纯文本；内部滚动，最高 22rem）；收起零请求、图片进视口才加载（2026-10-12 升级，见文末「打磨收口」）。
- **切换不跳滚动条**：详情滚动容器常驻 `scrollbar-gutter: stable`；切换测试项时动画只作用于容器内内容（`useLayoutEffect` 先归零 `scrollTop`），不动滚动容器本身。
- **焦点荧光绝对定位（2026-10-10 定稿）**：荧光画在单元格的 `::after` 上（`inset:-1px`，`pointer-events:none`，只过渡 opacity），**不占宽高、不参与布局**；编辑器自身只改边框色、不再画 box-shadow。focus 前后任何位移都与荧光无关。
- **普通字段结构性同构（2026-10-18 终稿）**：`EditableCell` 始终是同一个 `contenteditable="plaintext-only"`，高度、padding、`line-height: 18px` 与 1px 边框全部固定，focus 只改背景 / 边框色 / 光晕，不再切换展示 div 与输入控件。实测 focus 前后元素 top、高度和文字 rect 均 0px 变化。
- **多行读取用 `innerText`**：Chromium 的 contenteditable 回车会生成 `<div>` / `<br>`，`textContent` 会把行拼在一起；提交、自动编号和回填统一读 `innerText` 并归一 `\r\n`。
- **富文本单元格共用盒模型（2026-10-18）**：展示态与 `.ProseMirror` 使用相同的 `min-height: 2.5rem`、padding、1px 边框和 `line-height: 1.8`；`EditorContent` 包装层 `display: contents` 不参与布局；块间统一 0.15rem 间距，`.tableWrapper` 补 0.1rem 底距对齐预览 `tableWrap`。实测「输入及操作」单行文字 rect、含两张表的「实测结果」表格 top 与行高在 focus 前后完全一致。
- **状态切换不得改变布局（2026-10-10，逐帧实测）**：英雄区不放会随状态增删的徽章（隐含需求状态改写在完善度框内）；完善度框定高（缺项 chip 与"已满足"两种状态同高）；追踪关系行高度由按钮决定。用 CDP 逐帧录：切换隐含需求/进入编辑时 hero、表格、用例概况的 top/height 零变化（进入编辑仅剩 0.21px 亚像素）。
- **追踪关系两行布局（2026-10-10）**：操作按钮「关联需求」「隐含需求」在上，需求 chip 在下；两者混排会显得乱（用户实拍反馈）。
- **光标落点**：普通字段由原生 contenteditable 跟随点击位置，不再需要 `setSelectionRange`；富文本仍按 Tiptap 的块级光标规则处理。
- **编辑不跳行（逐像素）**：普通字段已是同一个 contenteditable 元素，不存在展示/编辑两套行高；富文本展示态与编辑态统一 `line-height: 1.8`、同 padding、同 1px 边框，实测文字 rect 与行高 0px 变化（见上条 2026-10-18 终稿）。
- **单元格编辑器统一口径（用例表同样适用）**：普通字段统一为 `EditableCell` 的 `contenteditable="plaintext-only"`——1px 边框、`padding: 11px 0.4rem 9px`、`min-height: 2.5rem`、`line-height: 18px`；单行与多行只差 Enter 行为。焦点态统一为 1px 主色边框 + 3px / 12% 柔光，样式必须落在常驻元素本身，不能再切换控件。
- **单元格文字左缩进基准**：可编辑单元格文字、只读提示（未关联需求 / 尚无测试子项）、追踪关系 chip 行统一从 `0.4rem + 1px` 起排；需求描述手风琴盒子与编辑框盒子左边缘对齐（`0.25rem`），内部文字同样落在同一基准上。
- **焦点环**：1px 主色边框（编辑器自身）+ 3px / 12% 柔光（`::after` 绝对定位），**全局只允许一根实线**——外圈绝不能再画 1px 实线描边，否则就是双边框（2026-10-10 实拍修正，口径照老项目 `border-color + box-shadow 0 0 0 3px rgba(...,0.12)`）。优先级下拉同样只有边框变色 + 柔光。
- **dot 按钮**：关联需求（主色 6px 圆点）、隐含需求（琥珀 6px 圆点，开启时描边高亮）——按钮不再用图标，沿用老项目 `dot` 视觉。
- **自动保存**：单元格失焦保存，保存后 Hero 标签行出现「已自动保存」提示（1.6s 淡出）；失败红色描边 + `sonner` 点名、就地重试。
- **派生规则**：类别色相、拼音首字母表在前端 `test-items-design.ts`；类型字典可配置后拼音挪到 `test_item_types` 字段并由接口返回（代码内已标 shortcut）。

## 打磨收口（2026-10-12，人工验收后）

- **需求描述手风琴 → 正文预览**：展开才请求正文（`enabled: open`），收起与未展开零请求；首次展开后保持挂载，收起动画不丢内容、再次展开不重复请求。内容同源需求工作台：优先 `/blocks` 结构化块（表格 / 图片），旧数据回退 `/content` 纯文本；正文区最高 22rem 内部滚动（`scrollbar-gutter: stable`）。
- **手风琴图片按需**：`IntersectionObserver`（`rootMargin: 200px`）进视口才发 Blob 请求；加载中保持宽高比占位 + 居中 spin「图片加载中」（`aria-busy`），就绪后 0.32s 透明度揭示 + 0.6s 主色光晕；失败按 `assetId` 记账，同一实例复用到另一张图不带旧失败态。
- **手风琴展开反馈**：左侧 2px 信息蓝条 + 名称提色加重，箭头移到行尾且悬停提色；正文 0.26s 透明度过渡；加载失败给 QueryError 就地重试。
- **分区导航「点谁亮谁」**：点击分区立即点亮目标并锁定，平滑滚动期间的位置推断不抢高亮；用户 wheel / touchstart / keydown 后交还自动推断。
- **保存芯片覆盖子项**：子项名称 / 描述 / 操作步骤 / 通过准则的编辑与保存相位经 `onPhase` 上报详情 `reportPhase`，右上角芯片同步「待自动保存 / 保存中 / 已自动保存 / 保存失败」；子项字段保存与主表同一 `withSavePhase` 出口（「保存中」至少展示 420ms，2026-10-12 修复瞬变）。
- **子项卡 hover 只描边**：不铺主色底，只加深边框 + 1px 主色环 + 16px 柔光；卡片 hover 时拖拽把手加深一档。
- **子项标签对齐与完成脉冲**：子项描述 / 操作步骤 / 通过准则标签 `padding-left: 1px` 与输入框左边框对齐（字号 0.66rem）；完善度从「缺项」转「已满足」播一次性 0.3s 脉冲（非循环），与未完善的琥珀呼吸不同台。
- **用例状态色**：用例行首 3px 状态色条（通过绿 / 未通过红 / 未执行灰）、通过率进度条按 `data-tone` 着色（0% 灰 / 中段主色 / 100% 绿）；新增关联 chip 入场 0.22s（透明度 + 光晕，无位移）；静态测试项进度提示为信息蓝弱化胶囊 + Info 图标。
- **全站直角收口**：清除 56 处 2px / 3px 微圆角（测试项、需求与共享控件，含工作区路由容器上下收角），圆点、胶囊、圆形图标等圆形语义元素除外；口径见 [07/01](../../07-前端体验/01-基础视觉与组件/01-视觉方向.md)。
- **完善度进度条语义色**：未完善=琥珀、已完善=绿（复用 data-tone，与缺口 chip 同色相）。
- **用例概况色点图例**：通过 / 未通过 / 未执行三个计数前各带 6px 色点（绿 / 红 / 灰），与行首状态色条同源。
- **需求来源 chip**：默认中性灰，悬停 / 展开提亮为信息蓝（避免与追踪关系蓝 chip 连片）；追踪关系按钮行与 chip 行间距 0.35→0.2rem。
- **子项自动编号**：操作步骤 / 通过准则 label 行右侧各一个图标按钮（ListOrdered，字段级作用域；灰虚线描边、悬停主色浅底 + 柔光、Radix Tooltip 提示）。点击按非空行剥掉已有行首编号（1、1)（1）1. 等变体）统一重排「1、2、3、」，走失焦保存同一条链路（右上保存芯片可见状态）；空内容与已规范内容 no-op（幂等）；mousedown 阶段 preventDefault（编辑框不失焦、不与失焦保存竞态）。明确不做：失焦自动改写、输入时回车续号（破坏原生撤销契约）。

## 易用性打磨（2026-10-13，参考老项目 TreeNav）

- **搜索与快捷筛选（第一刀已完成）**：搜索匹配测试项名称 / 标识 / 子项名 / 用例名 / YL_ID（输入 150ms 防抖后过滤，老项目同口径）；快捷 chips = 全部 / 未完善 N / 有失败 N，与搜索叠加（AND）；搜索或筛选激活时强制展开命中分支（`tree.openAll()`），退出后按 localStorage 记忆还原用户手动开合，且筛选期间不覆写记忆；无结果给空态 +「清除搜索与筛选」；激活时树底显示「显示 X 项 · Y 用例」。子项名随工作台一次下发（`counts[].subItemNames`），不额外请求。
- **展开/收起全部**：筛选行右侧两个图标按钮直接 `openAll()` / `closeAll()`（不进记忆语义，属于临时视图操作）。
- **复制新增测试项**：右键「复制新增」与 `Ctrl+D`；复制内容字段与子项，名称加「-副本」、标识按后缀唯一化重排，副本紧跟原件之后；追踪关系与「隐含需求」不复制（新项要重新决策）；静态四类拒绝复制（同类静态每轮只能一个）。
- **文件夹管理**：右键改名（`PATCH /api/v1/test-item-folders/{id}`）与删除（`DELETE`，仅解散容器，内部测试项 folder_id 置空回到类型根目录，二次确认写明影响条数）。parentId 嵌套目录本版不做。
- **拖拽落位规则**：分组/文件夹只当容器、不可拖；测试项只允许落在同类型分组或文件夹上（跨类型落点直接拒绝，后端还会再校验一次 `ErrFolderMismatch`）；用例只允许落在测试项行上。落点序号在分组层要折算：分组子节点是「文件夹在前 + 类型根测试项在后」，根目录落点 = 树序号 − 该类型文件夹数。
- **乐观落位**：拖拽结束先按后端口径本地重排（`placeTestItem` / `placeCase`：容器内按 sort_order 重排、越界夹取），失败原子回滚，成功后再 invalidate；用例跨项移动会重排标识，故详情缓存一并作废。
- **树 props 稳定**：`renderRow` / `renderNode` / `onMove` / `onToggle` 全部 `useCallback` 固化，`disableDrag` / `disableDrop` 用模块级函数——react-arborist 的拖拽源按 props 变更失效，每次渲染换新回调会让整棵树重挂拖拽源。
- **不做的**：跨文件夹批量移动、文件夹排序、面板级撤销栈（破坏性动作已有二次确认 + 复制新增可兜底），等用例详情（切片 5）落地后再评估。
- **树行与性能口径（2026-10-20 修订）**：右键菜单仍是**树级一个**；`[role="treeitem"]` 同时用 `min-width/max-width: 100%` 覆盖 `react-arborist` 的 `max-content`，长标签通过共享 `TruncatedText` 单行省略，只有真实溢出才挂 Radix Tooltip，禁止文字溢出压住右侧徽章；count / 类型 / 静态进度 / 用例状态收进单一 `.meta` 组并贴右，行尾内边距约 6px。树不使用常驻 `scrollbar-gutter`：无纵向滚动条时内容必须延伸到分栏线，出现滚动时再让原生滚动条占宽，禁止固定空白带。展开记忆写 `localStorage` 合并到 200ms 一次（`openAll` 会逐节点回调 `onToggle`）；`未完善` 荧光呼吸画在 `::after` 上只动 `opacity`。数据与门禁见 [21-前端性能优化策略](../../21-前端性能优化策略.md) 2026-10-13 节。

## 易用性复查（2026-10-18）

- **树快捷键作用域**：`F2` / `Delete` / `Ctrl+D` 只在焦点位于测试项树时生效，避免在详情按钮或空白处误删、误复制树节点。
- **窄屏断点**：纵向布局断点最终定为 1320px（树最小 380px）；1320px 以下改为单列主滚动，树面板高度 `clamp(15rem, 32vh, 22rem)`，步骤表列头允许换行。1366px 宽保持左右分栏，避免常见笔记本把详情挤到首屏下方。
- **空态与文案**：无测试项时右侧不再提示“选择测试项”，改为“还没有测试项”；完善度提示统一为“全部齐全”；未关联需求明确“按未完善处理”。
- **点击目标**：树展开/收起、摘要回填、子项自动编号、需求解除关联、用例行操作等图标按钮命中区统一到至少 24px；需求 chip 的小叉用伪元素扩展命中区但保持视觉尺寸。
- **筛选可访问性**：快捷筛选按钮补 `aria-pressed`，分区导航补 `aria-current`，键盘与屏幕阅读器能识别当前状态。

### 第二轮美观/可用性复查（2026-10-18）

- **行操作不再只在 hover 出现**：用例概况的定位 / 复制按钮常驻低强调图标，悬停整行或键盘聚焦时提亮，鼠标用户不用猜哪里能点。
- **长文本处理**：测试项标题允许换行；用例所属测试项名称允许换行；测试项树标签单行省略，真实溢出时悬停用 Tooltip 查看全文；人员指派触发器限制最大宽度并省略，完整姓名仍保留在 `aria-label`。
- **多栏编辑框对齐**：同一表格行或双栏网格内的多行编辑框，内容较少的一栏保持自身高度，并在可用空间中上下居中；由内容最多的一栏决定共同行高，禁止短框顶端对齐后在下方留下大块空白。用例步骤表、测试项子项的“操作步骤 / 通过准则”统一使用此口径。
- **工作台控件视觉（2026-10-20）**：工作台内的 label、可编辑框、按钮、人员选择器使用同一套轻量控制面语言——浅渐变底、1px 可辨边框、语义色左侧 2px 刻线、180–220ms 的 hover / focus / open 状态；表头使用顶部主色细描线，行标签使用轻渐变与左侧主色刻线。人员指派必须是带人员图标、文本和下拉箭头的按钮，空态用虚线边框，禁止退化成看起来不可点击的纯文本；控件视觉不做位移、不改变行高。
- **工作台工程技术感强化（2026-10-21）**：左栏工具栏拆成“主操作组 / 静态工具组”，中间用细分隔线分组；树使用极低对比网格背景，选中行采用左侧主色轨、浅渐变底和 1px 内描边，分组行保留类别色左轨。右栏 Hero 顶部使用 `TEST ITEM` 微型标签 + 方形状态点、轻网格和右上角定位括号；分区导航用底部 1.5px 活动线；表单行标签和用例卡补轻渐变与主色细线。所有反馈控制在 160–200ms，不移动 hover 元素、不改变选中项字重或行高。
