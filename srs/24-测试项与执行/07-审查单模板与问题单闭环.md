# 审查单模板与问题单闭环

> 返回 [测试项与执行](../24-测试项与执行.md)。本文覆盖 DC 文档审查的两块后台能力：管理员维护审查单模板，以及不通过项立单并与问题单模块闭环。上游见 [04 静态测试项](04-静态测试项.md) 的 DC 章节；轮次带入见 [05 轮次树与轮次复制](05-轮次树与轮次复制.md)。

## 一、审查单模板（管理员配置）

### 现状与目标

- 旧版只有内嵌 `static_catalog.json`，没有配置界面（2026-11-03 前）。
- 新实现把内置模板种子化到数据库，并在「设置 → 审查单配置」提供维护页；模板按“审查文档类型”唯一（需求规格说明 / 详细设计 / 概要设计 / 用户手册 / 任务书），可配置当前使用版本；齐套性不进入 UI，只在 Word 渲染时默认通过。已绑定到 DC 审查单的实例是快照，模板后续修改不影响既有审查单，只影响之后新建/添加的审查单。

### 数据

表 `review_checklist_templates`：

| 字段 | 说明 |
| --- | --- |
| `id` | UUIDv7 |
| `code` | 稳定模板代码（`rc-1`…`rc-4`，自定义模板用 `rc-custom-<随机>`） |
| `name` | 模板名称，添加审查单时作为审查单名称 |
| `document_type` | 审查文档类型（需求规格说明 / 详细设计 / 概要设计 / 用户手册 / 任务书），同类模板唯一 |
| `document_version` | 当前使用版本，新项目与新增审查单自动应用；可在设置页切换 |
| `appendix` | 依据附录（如 `附录A.1`），可为空 |
| `condition` | 适用条件说明（如 `被测软件有界面`），可为空 |
| `sort_order` | 展示顺序 |
| `items_json` | 检查项数组：`seq/category/item/standard/goodPractice/badPractice` |
| `created_at/updated_at` | 时间戳 |

### 种子

- 首次读取模板时若表为空，从内嵌种子写入内置模板；种子同时修复旧数据问题：去掉“标题=类别”的伪检查项，补齐推荐/不推荐做法。齐套性种子保留但不在 UI 暴露。`0032` 为 `document_type` 增加部分唯一索引，空类型（齐套性/历史数据）不参与约束。
- 之后以数据库为准，不再回填种子。

### 接口

- `GET /api/v1/review-checklists`：列出模板（含文档类型、版本、检查项与做法）。
- `POST /api/v1/review-checklists`：新建模板；同一 `document_type` 已存在时返回 409。
- `PUT /api/v1/review-checklists/{id}`：整体保存模板名称、文档类型、版本、附录、条件、检查项。
- `DELETE /api/v1/review-checklists/{id}`：删除模板；已被审查单绑定的实例不受影响。

### 页面

- 路由 `/settings/review-checklists`，导航「设置 → 审查单配置」。
- 列表：文档类型、模板名称、检查项数、当前版本、做法完成度、适用条件、最近更新。
- 编辑弹窗：文档类型/版本、模板基本信息 + 检查项表格（序号、类别、检查项、依据、做法状态），逐项打开发法编辑弹窗，左右两栏富文本编辑推荐做法与不推荐做法。
- 做法为空不展示占位；保存后立即生效于新添加的审查单。

## 二、问题单与 DC 闭环

### 定位

- 问题单是正式缺陷实体，与审查项通过/不通过互相独立；DC 不通过项可一键立单，问题单状态不回写审查结果，只作为本轮记录供下一轮参考。
- 快捷问题草稿（问题草稿）仍不是正式问题单，不进入统计，也不参与闭环。

### 数据

表 `issues`：

| 字段 | 说明 |
| --- | --- |
| `id` | UUIDv7 |
| `project_id` / `round_id` / `round_number` | 发现轮归属 |
| `test_item_id` / `test_item_identifier` | 来源测试项（DC 时为其测试项） |
| `source_sheet_id` / `source_sheet_name` / `source_check_id` | 来源审查单实例（ID 与名称）与检查项 ID |
| `source_check_title` / `target_document` | 检查项标题与受审文档，便于列表直接展示 |
| `title` | 问题标题，默认取检查项标题 |
| `description` | 问题描述，默认取错误描述；可继续编辑 |
| `defect_type` | 缺陷类型，DC 默认「文档问题」 |
| `level` | 等级：重大 / 严重 / 一般 / 建议改进，DC 默认「一般」 |
| `closure_method` | 处理方式：修改文档 / 修改程序 / 不修改，DC 默认「修改文档」 |
| `status` | `open` / `closed` |
| `closure_note` / `closed_by` / `closed_at` | 整改与验证说明、关闭人、关闭时间 |
| `created_by` / `created_at` / `updated_at` | 创建信息 |

### 立单规则

- 仅 DC「不通过」项可立单；同一检查项只允许一个未关闭问题单，已关闭后再次不通过可再立新单。
- 立单时预填：标题=检查项，描述=错误描述（含截图数量提示），缺陷类型=文档问题，等级=一般，处理方式=修改文档，目标文档=审查单受审文档名称/版本。
- 立单只创建独立问题单记录（来源审查单与检查项留痕），DC 表格不显示问题单状态，避免暗示结果联动。

### 闭环规则（2026-11-03 用户纠正）

- 问题单与审查项的通过/不通过**没有关系**：立单、关闭、重开都不回写或影响 DC 检查结果，DC 侧也不展示问题单状态。
- 问题单初始 `open`；填写整改/验证说明并关闭后变 `closed`，记录关闭人与时间；可重新打开。
- 问题单按轮归属，是独立记录，供**下一轮参考**；当前不自动带入下一轮，也不与审查项结果联动。
- 问题单是否补「关联用例 / 下一轮复测」字段待用户单独确认，确认前不实现。

### 接口

- `GET /api/v1/projects/{code}/issues?roundId=`：按轮列出问题单（`roundId=all` 跨轮）。
- `GET /api/v1/issues/{id}`：问题单详情。
- `POST /api/v1/projects/{code}/issues`：立单。
- `PATCH /api/v1/issues/{id}`：更新标题/描述/等级/处理方式，或关闭/重新打开。

### 页面

- 工作区「问题单」页签替换占位：筛选（全部/开放/已关闭）、列表（编号、标题、等级、来源测试项、审查单、状态、轮次），点击打开详情。
- 详情：来源与受审文档、描述、等级/处理方式、时间线（创建/关闭），操作「关闭并记录整改说明」「重新打开」。
- DC 审查单 tab 内立单后不离开页面，只刷新当前行状态。

## 三、验证口径

- `go test ./...`：模板种子与 CRUD、立单/关闭/重开、轮次复制静态项与结果默认通过、导入上轮不通过项。
- `npm run check`：类型、lint、构建。
- 浏览器验收：375 与 1440 截图，覆盖 DC 默认通过、改成不通过并上传截图、立单、关闭问题单、模板编辑、第 2 轮复审带入。
