# 类型覆盖与追溯视图

> 返回 [测试项与执行](../24-测试项与执行.md)

本页记录切片 7 的分析视图口径。当前已实现类型覆盖、追溯矩阵与标注总览。

## 通用入口

- 入口：`测试与执行 → 测试项` 顶部视图切换。
- URL 参数：`view=tree|coverage|trace|annotations`。
- 非树视图使用全宽内容区，不显示左侧测试项树。
- 全局轮次切换器继续生效；`roundId=all` 时分析视图只读。
- `roundId` 与 `view` 同时保留在 URL 中，刷新和浏览器回退可恢复。
- 页签焦点与点击可能连续触发同一视图切换，前端按目标视图去重；一次切换只写一条历史记录，浏览器后退一次即回到上一视图。

## 通过率口径

- 通过率 = 已通过用例数 ÷（已通过 + 未通过）。
- 未执行用例单独计数，不进入分母。
- 分母为 0 时显示 `—`，不显示 `0%`。

## 类型覆盖

### 数据与规则

- 展示启用的 24 类测试项，按类型字典分组和输出顺序排列。
- 每类显示测试项数、用例数、通过率、未执行数。
- 当前轮次有测试项：状态为“已覆盖”，可跳转到树视图并按该类型过滤。
- 当前轮次没有测试项：必须填写“不测评说明”；未填写显示“未说明”。
- 第二轮及以后，`DC`、`SA`、`CR`、`CW` 自动显示“不适用”，不计入未说明；静态项只保留首轮。
- `roundId=all`：按轮聚合展示，每类卡片列出各轮测试项数与状态，不提供说明编辑。
- 不测评说明只允许对具体轮次、无测试项、且适用的类型填写；已有测试项或后续轮静态类型由服务端拒绝。

### 存储

迁移 `0029_type_coverage_notes`：

```text
test_item_type_coverage_notes
- id
- project_id
- round_id
- type_code
- reason_text
- updated_by
- created_at
- updated_at
UNIQUE(round_id, type_code)
```

说明按轮保存，不复制到其他轮次。

### API

```text
GET /api/v1/projects/{code}/type-coverage?roundId=...
PUT /api/v1/projects/{code}/type-coverage/{typeCode}/note?roundId=...
```

### 验证重点

- 通过率分母为 0 时返回 `null`，前端显示 `—`。
- 第二轮静态四类 `applicable=false`、状态 `not_applicable`。
- 全部轮次可同时看到首轮覆盖和后续轮不适用。
- 已有测试项的类型禁止写入不测评说明。
- 全部轮次禁止写入、修改或删除任何说明。
## 追溯矩阵

### 交付口径

- 参考 `knowledge-base/参考的BCD星项目/02_太空探源探路者一号卫星工程地面支撑系统任务运控与决策支持分系统BCD性指令生成与发控软件第三方测试说明V1.10.docx` 的“需求追踪表”。
- 真实交付表的粒度是“需求 × 测试项 × 用例”：正式需求的来源、章节、名称重复归并，测试项和用例逐条展开；一条用例一行，同一需求的多条用例通过合并单元格形成视觉分组。
- 真实交付表包含“大纲章节号”；当前数据模型没有该字段，界面显示 `—` 并提示“大纲章节号尚未建模”，不伪造编号。
- 问题单模块尚未实现，问题单列显示“未接入”并提示“问题单模块尚未实现”，不伪造问题数。

### 数据与规则

- 保留四类缺口行：未关联测试项、已关联测试项但无用例、隐含需求项缺口、未关联需求。
- 每个具体轮次按该轮需求关联、测试项、用例和本轮结果展开；`roundId=all` 按轮展开并在每行显示轮次徽标。
- 通过率沿用统一口径：已通过 ÷（已通过 + 未通过）；未执行不进入分母，分母为 0 显示 `—`。
- `roundId=all` 只读；需求和测试项仍取项目级与各轮实例的真实数据，不通过前端拼接跨轮关联。
- 支持按来源、章节、需求、测试项、用例搜索，以及“全部 / 仅缺口 / 仅未通过”筛选。
- 用例行可定位到对应轮次的树视图并选中目标用例；`roundId=all` 定位时同时切换到该测试项所属轮次。

### API

```text
GET /api/v1/projects/{code}/traceability?roundId=...
```

### 验证重点

- 同需求多用例必须保持一条用例一行，需求与测试项单元格按 `rowSpan` 合并。
- 无测试项、无用例的缺口不能因 `INNER JOIN` 丢失。
- `roundId=all` 行数按轮累加，轮次徽标可区分来源。
- 问题单和大纲章节号缺数据时只能显示“未接入 / —”，不能编造。
- 宽表在窄屏只在表体内部横向滚动，页面本身不能出现横向溢出。
## 标注总览

### 参考边界

- 标注总览不是 02《测试说明》或 06《回归测试记录》中的交付表字段，不伪造交付列；它是工作区内部审阅视图。
- 追溯矩阵继续按 02 文档“需求追踪表”的真实粒度展开；标注总览只复用“来源、对象、定位”的交互组织方式。

### 数据口径

- 不新建标注表；只扫描 `content_blocks.body_json` 中的 `highlight` mark。
- 第一阶段只覆盖需求正文和用例步骤的 `op`（输入及操作）/ `act`（实测结果）。子项“操作步骤 / 通过准则”按设计保持纯文本，不进入本视图。
- 需求正文是项目级数据，在具体轮次和全部轮次都只列一次；步骤标注按 `roundId` 过滤，`roundId=all` 时展示轮次徽标。
- 步骤标注只保留测试项、用例、步骤序号和跳转位置，不查询、不展示关联需求。需求正文标注保留自身所属需求。
- 需求关键词只匹配需求正文标注；步骤标注不参与需求维度搜索或筛选。
- 高亮后用接口或刷新确认 `body_json` 真实持久化；不把前端高亮样式当作落库证据。

### 编辑与定位

- 需求正文工具栏和步骤迷你工具栏都使用 Tiptap `highlight` mark，支持 `Ctrl+Shift+H` 快捷键。
- 点击需求正文标注定位到 `requirements?requirementId=...`；点击步骤标注切到所属轮次的树视图，并选中用例、滚动到目标步骤。
- 需求正文标注显示高亮文字、前后文和所属需求/章节；步骤标注显示高亮文字、前后文、测试项、用例、步骤和轮次。两类都不写正式问题单数据。
- 空状态区分两种原因：项目没有数据时提示“项目还没有高亮标注”；有数据但筛选无结果时提示“筛选后没有匹配结果”并提供清除筛选。

### API

```text
GET /api/v1/projects/{code}/annotations?roundId=...
```

### 验证重点

- 需求正文、op、act 三类标注都能被扫描到；非高亮文本不进入清单。
- 具体轮次只显示该轮步骤标注；`roundId=all` 同时显示各轮步骤和项目级需求标注。
- 搜索、类型筛选、无结果状态和两类定位跳转都要实测。
- 后端白名单必须接受 `highlight`，并清洗非白名单 mark；前端只读渲染、编辑器预览和导出前的正文模型共用同一套 mark 语义。
- Word 是交付内容，不映射高亮到底纹或文字高亮；导出链路保持干净正文。
