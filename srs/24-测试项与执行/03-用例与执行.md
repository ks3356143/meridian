# 用例与执行

> 返回 [测试项与执行](../24-测试项与执行.md)

## 定位

用例归属于测试项（树上是"测试项 → 用例"），是测试说明第 5 章与测试记录第 2 章的取数单位。用例的设计与执行在同一张表内完成——设计时写步骤，执行时填实际结果与通过状态，不再分"设计页 / 执行页"。

## 用例详情

- 入口：树上点击用例行；或测试项详情"用例概况"卡片里点行。
- 结构：Hero（用例标识 + 名称 + 状态标签 + 所属测试项）/ 用例表（字段与顺序见 [01](01-数据模型与标识.md)）/ 步骤表 / 问题单标识（占位，等模块就绪）。
- Word 表格观感与编辑口径同 [02](02-测试项页面与交互.md)：点击即编辑、Tab 走格、失焦保存、必有荧光与必填红边。

## 步骤表（核心工作台）

| 列 | 宽度参考 | 类型 | 说明 |
| --- | --- | --- | --- |
| 序号 | 40px | 只读 | 自动编号，行操作后重排 |
| 输入及操作 | ~31% | 富文本 | 文字 + 图片（不出现表格）；聚焦浮出工具栏 |
| 期望结果与评估标准 | ~23% | 纯文本 | 自动增高，无拖拽手柄 |
| 实测结果 | ~46% | 富文本 | 文字 + 图片 + 表格（执行时粘贴截图） |
| 通过与否 | 自适应 | 三态 | 未执行 → 通过 → 未通过 循环 |

- 列名与列序按模板：`knowledge-base/测试记录.docx` 的用例块为「序号 / 输入及操作 / 期望结果与评估标准 / 实测结果 / 通过与否」，`测试说明.docx` 的设计侧只有前三列。
- 富文本单元格使用项目统一的 Tiptap 编辑器；"输入及操作"与"实测结果"共用同一套扩展与工具栏，图片走项目附件（同一资产接口）。
- 表格中部强制结构：步骤至少 1 行；末行支持"表尾回车新增行"，新增后焦点落在操作列。
- 空单元格显示占位提示（"暂无" / "点击输入"），不显示空框。
- 步骤编辑与执行数据**分轮**保存：逻辑层的步骤定义（操作/预期）与轮次实例的实际结果分开存储，回归轮带入时实际结果与通过状态重置为"未执行"（见 16）。

## 状态联动（单一数据源）

- 规则：任一"未通过" → 用例未通过；全部"通过" → 用例通过；其余 → 未执行 / 进行中。
- 联动范围（一次改状态，全部同步刷新，不做全页重渲）：步骤行样式 → 用例状态标签 → 用例详情 Hero → 树上用例行圆点 → 用例概况卡片统计（总数 / 通过 / 未通过 / 未执行 / 通过率）→ 测试项完成度与树徽章。
- 执行时间：步骤任何改动自动写"今天"，用户手动改过则不再自动覆盖；状态回退到未执行时恢复自动。

## 未执行原因（2026-10-13 移除）

- 原设计：用例状态为"未执行"时必填，含原因 / 涉及测试内容 / 验证情况，作为闭轮预检项。用户比对第三方测试记录 docx 后决定不做，用例表不再保留该行（库表列保留，历史数据不丢）；若闭轮预检日后需要，再按记录模板口径重新引入。

## 录入效率包（第一刀全做）

| 能力 | 交互 |
| --- | --- |
| 从子项生成用例 | 测试方法卡片上"子项 → 用例"，1:1 生成，名称取子项名 |
| 复制上一用例 | 概况卡"复制上一条"，复制名称加"-副本"递增，清空实际结果与通过状态 |
| 跨用例复制步骤 | 选中步骤行复制 → 目标用例右下"粘贴步骤"；跨页签保留剪贴板内容 |
| 批量指派 | 概况卡勾选多行 → 批量设置执行人员 / 状态 / 日期 |
| 行移动 | `Alt+↑/↓` 移动步骤行，`Ctrl+D` 复制当前步骤 |
| 插入 / 删除步骤 | `Ctrl+Shift+Enter` 当前行上方插入；`Ctrl+Backspace` 删除当前行（至少保留 1 行） |
| 切用例 | `Ctrl+←/→` 上/下一条用例（编辑态先保存再切） |
| 撤销 | `Ctrl+Z` 撤销最近一次用例内改动（单用例快照，上限 20）—— ✅ 2026-10-13 随 5a 落地，口径见「实施进度」 |
| 测试项内查找 | 测试项头部查找框，定位到用例与步骤；命中高亮 |
| 拖拽 | 同测试项排序 / 跨测试项移动 / `Ctrl+拖拽` 复制（标识重排规则见 01） |

## 实施进度

### 切片 5a：用例详情面板骨架（2026-10-13 完成）

- **入口**：树上点用例行 / 测试项详情「用例概况」行（点行名或「在目录中定位」）→ 右侧面板切到用例详情并同步高亮树节点；Hero 的「返回测试项」回到所属测试项（选中用例时会把父测试项设为当前项，返回才有落点）。
- **结构**：Hero（用例标识 + 名称 + 状态 + 所属测试项）/ 用例表（字段与顺序见 [01](01-数据模型与标识.md)「用例表」，文本字段点击即编辑走 `EditableCell`）/ 步骤表（序号、期望结果与评估标准、通过与否三态、行操作 上移 / 下移 / 复制 / 删除 + 新增步骤）。
- **docx 二次对齐（2026-10-13 晚）**：按第三方测试记录 docx 再排一遍——执行状态提到测试步骤之后第一位，依次 测试时间 / 测试人员 / 监测人员 / 问题单标识，设计人员附最后；移除「未执行原因」「备注」两行；追踪关系由 chip 改树状目录；新建用例由后端 `caseDefaults`（`internal/modules/testitems/cases.go`）默认填充综述与初始化 / 前提和约束话术，回归测试 `TestCreateCaseFillsDefaults`。
- **字段口径修正（2026-10-13）**：用例表字段与顺序、步骤表列头改为与知识库模板对齐——`测试记录.docx`（用例名称 / 标识 / 追踪关系 / 综述 / 初始化 / 前提和约束 / 测试步骤 / 执行状态 / 测试时间 / 测试人员 / 监测人员 / 问题单标识 / 备注）与 `测试说明.docx`（同前段 + 终止条件 / 通过准则 / 设计人员）。改前是自拟口径：少了「用例标识 / 追踪关系 / 人员」三块、把「测试步骤」压到表格最后、步骤列头写成「预期结果 / 通过」。**模板里没有「审核人员」**，原写的四类人员按模板收敛为三类。
- **数据**：用例本体取自工作台缓存（无新增接口）；步骤用既有 `test-cases/{id}/steps` 系列接口，本地补丁 + 服务端重排；步骤三态切换成功后作废工作台与测试项详情缓存，用例状态、执行时间、树上用例圆点、概况统计同步刷新（服务端 `recomputeCaseStatus` 单一数据源）。
- **空态**：无用例步骤给「新增第一个步骤」引导。
- **后端修复**：`DuplicateStep` 先插后移会撞 `UNIQUE(test_case_id, seq)`（复制中间行必失败），改为负数占位两阶段重排，补 `TestDuplicateStepInsertsAfterSource`；坑位见 [docs/项目记忆/后端与数据库.md](../../docs/项目记忆/后端与数据库.md)。
- **表格口径**（2026-10-13 统一，与测试项详情同源）：行标签列浅灰底 + 居中加粗 + 上下居中；数据单元格一律 `vertical-align: middle`；表格在卡内内浮留白（`padding: 0.75rem 1.1rem`）+ 1px 边框 + 轻阴影；步骤表必须 `table-layout: fixed`（序号 2.6rem / 通过与否 5rem / 行操作 6.8rem / 期望结果与评估标准吃余量）——不定宽时宽屏会把「通过与否」列拉宽、按钮居中在另一列，中间空出一大片；列宽再按内容收紧（2026-10-13 晚），消除「通过」徽章与行操作按钮之间的空白带。步骤列头命名随模板（期望结果与评估标准 / 通过与否）。
- **撤销（Ctrl+Z，2026-10-13 随 5a 落地）**：撤销最近一次**已保存**的字段改动（用例文本字段与步骤「预期结果 / 通过状态」），面板级快照栈上限 20，撤销 = 用旧值再走同一条保存链路并 toast「已撤销：<字段>」；编辑框聚焦时让位给浏览器原生撤销（逐字回退），结构化操作（新增 / 删除 / 移动步骤）不进栈。本文件「录入效率包」里的「撤销」条视为已完成。
