# 用例与执行

> 返回 [测试项与执行](../24-测试项与执行.md)

## 定位

用例归属于测试项（树上是"测试项 → 用例"），是测试说明第 5 章与测试记录第 2 章的取数单位。用例的设计与执行在同一张表内完成——设计时写步骤，执行时填实际结果与通过状态，不再分"设计页 / 执行页"。

## 用例详情

- 入口：树上点击用例行；或测试项详情"用例概况"卡片里点行。
- 结构：Hero（用例标识 + 名称 + 状态标签 + 所属测试项）/ 用例表（字段与顺序见 [01](01-数据模型与标识.md)）/ 步骤表 / 问题单标识（占位，等模块就绪）。
- Word 表格观感与编辑口径同 [02](02-测试项页面与交互.md)：点击即编辑、Tab 走格、失焦保存、必有荧光与必填红边。

## 步骤表（核心工作台）

| 列 | 宽度参考 | 类型 | 说明 |
| --- | --- | --- | --- |
| 序号 | 4% | 只读 | 自动编号，行操作后重排 |
| 输入及操作 | 数据列 4 份 | 富文本 | 文字 + 图片 + 表格；聚焦浮出工具栏 |
| 期望结果与评估标准 | 数据列 3 份 | 纯文本 | 自动增高，无拖拽手柄 |
| 实测结果 | 数据列 6 份 | 富文本 | 文字 + 图片 + 表格（执行时粘贴截图） |
| 通过与否 | 5% | 三态 | 未执行 → 通过 → 未通过 循环 |
| 操作 | 6% | 行操作 | 上移 / 下移 / 复制 / 复制到剪贴板 / 删除，2 列紧凑网格 |

- 版式（2026-10-18）：`测试步骤`标题单独占整行，步骤表占满用例表全宽；六个列宽百分比合计 100%，输入 : 期望 : 实测严格为 4 : 3 : 6。
- 实测结果里的内嵌表格保底列宽 7rem、行高 2rem；内容超宽时由 `RequirementBlocks` 的 `tableWrap` 横向滚动，不允许把列压成竖排。
- 「输入及操作 / 期望结果与评估标准 / 实测结果」三个内容框统一 `2.5rem` 初始高度，内容增加时各自继续增高，不强制拉伸到整行高度；单行内容在预览与编辑态都垂直居中，多行按内容向下扩展。

- 列名与列序按模板：`knowledge-base/测试记录.docx` 的用例块为「序号 / 输入及操作 / 期望结果与评估标准 / 实测结果 / 通过与否」，`测试说明.docx` 的设计侧只有前三列。
- 富文本单元格使用项目统一的 Tiptap 编辑器；"输入及操作"与"实测结果"共用同一套扩展与工具栏，图片走项目附件（同一资产接口）。
- 表格中部强制结构：步骤至少 1 行；末行支持"表尾回车新增行"，新增后焦点落在操作列。
- 空单元格显示占位提示（"暂无" / "点击输入"），不显示空框。
- 步骤编辑与执行数据**分轮**保存：逻辑层的步骤定义（操作/预期）与轮次实例的实际结果分开存储，回归轮带入时实际结果与通过状态重置为"未执行"（见 16）。

## 状态联动（单一数据源）

- 规则：任一"未通过" → 用例未通过；全部"通过" → 用例通过；其余 → 未执行 / 进行中。
- 联动范围（一次改状态，全部同步刷新，不做全页重渲）：步骤行样式 → 用例状态标签 → 用例详情 Hero → 树上用例行圆点 → 用例概况卡片统计（总数 / 通过 / 未通过 / 未执行 / 通过率）→ 测试项完成度与树徽章。
- 执行时间：步骤任何改动自动写"今天"，用户手动改过则不再自动覆盖；状态回退到未执行时恢复自动。

## 未执行原因（2026-10-13 移除）

- 原设计：用例状态为"未执行"时必填，含原因 / 涉及测试内容 / 验证情况，作为闭轮预检项。用户比对第三方测试记录 docx 后决定不做，用例表不再保留该行（库表列保留，历史数据不丢）；若闭轮预检日后需要，再按记录模板口径重新引入。

### 切片 5b：步骤富文本两列 + 用例文本两栏（2026-10-17 完成）

- **步骤表六列**：序号 / 输入及操作（富文本）/ 期望结果与评估标准（纯文本）/ 实测结果（富文本）/ 通过与否 / 操作；2026-10-18 起六列百分比为 4 / 26.15 / 19.62 / 39.23 / 5 / 6，数据三列保持 4 : 3 : 6。
- **存储与接口**：富文本走 `content_blocks`（`owner_type='test_case'`，`block_key='step.{步骤ID}.op|act'`），不改表结构。`GET /api/v1/test-cases/{id}/steps` 返回 StepView（步骤行 + op/act 块视图，空块给空文档）；`PUT /api/v1/test-case-steps/{id}/blocks`（op / act 至少提交一个）保存富文本块并刷新执行时间；用例 `PATCH` 新增 `terminationText` / `passCriteria`（迁移 `0025_test_case_text_fields`）。
- **op / act 均允许表格（2026-10-18 调整）**：两步富文本共用 Tiptap 表格扩展与工具栏「插入表格」按钮，粘贴表格也不再剥离；服务端统一走标准节点白名单，不再对 op 追加 `BannedNodes`。集成测试覆盖 op 表格保存与回读。
- **前端组件**：`step-rich-cell.tsx`（展示态直接渲染结构化内容、点击进编辑、失焦提交、内容未变不发请求、saving → saved 脉冲；Tiptap 挂载后记录规范化 baseline，仅真实改动才触发保存）+ `step-rich-editor.tsx`（复用需求正文扩展集与附件接口；工具栏浮出在单元格上方 0.55rem、不占内容流，底部小箭头指向编辑区——内嵌式会因行高变化吃掉相邻单元格的点击）。编辑器与展示态共用 `RequirementBlocks` 渲染；单元格内正文规格经 `--body-text-size / --body-heading-size / --body-caption-size / --body-table-size` 变量收紧一档；表格超宽时单元格内横向滚动。 步骤行自身已有序号，富文本工具栏不提供「有序列表」按钮；`RequirementOrderedList` 扩展保留，兼容历史内容与粘贴。聚焦时关闭 Tiptap 默认 autofocus，改用 `focus({ preventScroll: true })`；展示态点击进入编辑时记录 `clientX / clientY`，编辑器挂载后用 `view.posAtCoords({ left, top })` 映射光标，表格单元格内也能落到点击位置（键盘激活无坐标时回退文档末尾）。首次拖选同时记录 mousedown / mouseup 两个坐标，编辑器挂载后在 `useLayoutEffect` 首帧前用 `posAtCoords` 设置 anchor/head 范围；顺序必须是先 `focus()` 再 `setTextSelection()`，反过来 focus 会重置选区，产生 collapsed 帧。选区不会因展示态 DOM 卸载而丢失或闪一下。2026-10-18 进一步把展示态与编辑态统一为同一盒模型：两者共用 `min-height: 2.5rem`、同 padding / 1px 边框 / `line-height: 1.8`，`EditorContent` 包装层 `display: contents` 不参与布局，块间 0.15rem 间距与 `.tableWrapper` 0.1rem 底距对齐预览。实测单行文字 rect、两张表的 top、行高在 focus 前后均 0px 变化，不再靠补 1px 掩盖。富文本保存失败时编辑器保持挂载，已输入内容留在原地供重试；成功后才关闭并播放保存脉冲，Esc 仍可主动放弃。
- **Tooltip 与聚焦态（2026-10-18）**：步骤工具栏、通过状态、行操作、用例切换、树展开收起统一使用 Radix `Tooltip`（`@/components/ui/tooltip`），不再使用原生 `title`；Hover 入场约 160ms。步骤内容框参考老项目：静止浅灰底 + 1px 灰色边框，聚焦白底 + 实色主色边框 + `3px / 12%` 柔光；展示态 hover 背景做 `0.15s` 过渡，编辑态 focus 背景直切，避免拖选后选区底色随背景渐变闪动；边框与柔光挂在 `.ProseMirror` 自身，不额外占布局。工具栏出现用 `@starting-style` + 150ms 位移/缩放/淡入，退出时 `closing` 状态保留 150ms 再卸载，支持 reduced-motion 直切。
- **行为**：复制步骤带 `op` 设计内容、不带 `act`（状态重置）；删除步骤清理其内容块；复制用例同样复制步骤 `op`。终止条件 / 通过准则两行在用例表末尾（问题单标识行之后），走 `EditableCell` 与 Ctrl+Z 同一撤销栈。
- **坑位**（[docs/项目记忆/前端视觉与交互](../../docs/项目记忆/前端视觉与交互.md)）：失焦同步提交会立刻把上一格从编辑态切回展示态（行高微变），相邻单元格的 click 因 mouseup 落空而失效——提交改为 `setTimeout(commit, 0)` 让 click 先派发。2026-10-18 另修根因：展示态与 Tiptap 编辑态此前是两套 DOM，段落 line-height 1.8 vs 1.7、EditorContent 多一层包装、表格块间距不同，导致文字与行高微动；现统一盒模型并实测 0px 位移。

## 易用性复查（2026-10-18）

- **撤销按用例隔离**：切换用例时重建用例面板，旧用例的撤销栈不会串到新用例。
- **结构变更刷新状态**：新增、复制、插入、粘贴、删除步骤成功后同步刷新用例状态、详情 Hero、树徽章与用例概况统计，不再只刷新步骤列表。
- **删除保护**：仅剩 1 步时删除按钮禁用，`Ctrl+Backspace` 不弹无效确认，避免提交后才收到服务端拒绝。
- **用例切换可见化**：同一测试项存在多条用例时，Hero 显示上一条 / 下一条和当前序号；`Ctrl+←/→` 继续可用。
- **点击目标与反馈**：行操作、通过状态、人员指派等控件至少 24px；人员下拉增加下拉箭头，当前成员显示勾选；复制到剪贴板摘要优先取 op，其次 act。
- **快捷键入口（2026-10-18）**：移除顶部与步骤工具条两条长提示，步骤工具条在「新增步骤」左侧提供蓝色「快捷键」按钮，打开独立 Dialog 查看用例撤销、切换用例和全部步骤快捷键；编辑框内 Ctrl+Z 的原生撤销口径写进说明。
