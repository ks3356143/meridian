# 快捷问题草稿

> 返回 [轮次树与轮次复制入口](../05-轮次树与轮次复制.md)

## 一、锚点选择

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 挂步骤 | 上下文最精确，适合单步失败、截图和复现 | 一条问题跨多步时难归属；步骤复制/删除后容易失去语义 |
| 挂用例 | 创建入口稳定，适合执行过程中的任意问题 | 不知道具体步骤，整理正式问题单时需要重新回看 |
| 混合：用例必选、步骤可选 | 从步骤记时保留精确上下文，从用例记时也能快速记录 | 数据模型和 UI 多一个可选字段 |

**已定为混合方案。**

- `test_case_id` 必填，保证问题草稿始终属于当前轮的一个用例。
- `test_case_step_id` 可空；从步骤行“记问题”进入时自动填入，从用例级入口进入时留空。
- 不存 `test_item_id`，测试项通过用例反查，避免用例移动后锚点失真。
- `round_id` 单独保存，便于本轮问题列表和闭轮检查。

## 二、表结构（已实现）

```text
quick_issue_notes
- id
- project_id
- round_id
- test_case_id
- test_case_step_id NULL
- note_text
- screenshot_asset_id NULL
- created_by
- created_at
- updated_at
```

- 截图复用现有 `assets` 上传、去重和鉴权链路。
- 当前需求是一句话 + 可选一张截图，因此第一版只放一个 `screenshot_asset_id`。
- 草稿不是正式问题单，不参与未闭环问题统计，也不触发正式缺陷状态机。
- `note_text` 为纯文本，去除首尾空白后必须为 1–500 个 Unicode 字符；前后端使用同一口径。
- `test_case_step_id` 删除时置空，草稿保留为用例级记录；用例删除时草稿级联删除。
- 截图资产删除时 `screenshot_asset_id` 置空；删除草稿本身不删除共享资产，避免误删被其他内容块复用的图片。

## 三、交互流程

1. 用例详情顶部提供“记问题”；每个步骤行提供小图标入口。
2. 入口打开轻量 Popover/Dialog，不打断当前步骤编辑；步骤为空时仍可记录。
3. 表单只有一句话输入和可选截图；截图通过现有 `assets` 上传接口上传，一次最多一张。
4. 保存后立即插入用例的“问题草稿”列表，显示数量徽标和 toast。
5. 用例详情展示当前用例的草稿列表；创建人显示编辑、删除入口，项目其他成员只读。
6. 正式问题单模块未就绪前不增加转换状态字段；后续再建正式问题单与草稿的关联模型。

## 四、已确认规则

- 项目成员都能查看当前用例的草稿；只有创建人可编辑、删除自己的草稿，服务端强制校验。
- 一句话上限 500 字符，前端显示剩余字数；截图第一版严格一张。
- 步骤被删除时草稿转为用例级，不丢问题正文和截图。
- 本轮工作区的草稿汇总、正式问题单转换暂未实现，待问题单模型落地后补齐。
- 历史截图资产不做自动物理清理；如需回收，应由资产引用清理任务统一判断。
