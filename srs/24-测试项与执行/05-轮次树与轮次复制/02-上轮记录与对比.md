# 上轮记录与对比

> 返回 [轮次树与轮次复制入口](../05-轮次树与轮次复制.md)

## 一、第二轮及以后创建流程

推荐三步向导：

1. **轮次信息**：来源轮、名称、被测版本、变更原因、起止日期。
2. **本轮范围**：按上一轮测试项树勾选，默认选中“含未通过用例的测试项”。
3. **确认复制**：展示将复制的测试项、文件夹、用例、步骤数量，确认后一次事务创建。

范围页建议左侧树、右侧摘要：

- 文件夹与类型分组提供全选/半选/取消。
- 测试项行显示“将带入 N 条用例 / 上轮未通过 M 条”。
- 默认筛选“上轮未通过相关项”；可切换“全部项”补充范围。
- 提供“恢复默认 / 全选 / 全不选”。
- 提交前显示重复点击防护和复制进度；失败则整轮回滚，不留下半棵树。

### 选择粒度（已确认）

推荐按**测试项整项**选择：只要某测试项内存在上轮未通过用例，该测试项默认选中，并复制其全部用例与步骤。

理由：当前已确认模型是“整树按轮复制”，按用例裁剪会产生“测试项存在但用例集不完整”的新语义，文档生成和追溯也要额外解释。若要只复制失败用例，应作为新的范围规则单独确认。

### 全不选

已确认允许第二轮及以后创建 0 个测试项的轮次，但必须：

- 轮次状态保持 `draft`。
- 页面明确提示“本轮尚未选择测试项”。
- 创建后可从来源轮继续带入测试项，或手工新建。
- 不把空轮视为可执行、可闭轮。

空数组表示创建空轮；空轮保持 `draft`，不能视为可执行或可闭轮。

## 二、复制事务

单事务内按以下顺序执行：

1. 复制 `test_item_folders`，记录旧 ID → 新 ID，并重写父文件夹与测试项的 `folder_id`。
2. 复制 `test_items`：新 UUIDv7，保留 `lineage_key`、类型、标识、名称、优先级、描述、充分性、通过准则、排序。
3. 复制 `test_sub_items` 及其 `ops/exp` 内容块。
4. 复制 `test_cases`：新 ID，保留 `lineage_key`、名称/综述/初始化/前提/终止条件/通过准则及设计内容。
5. 复制 `test_case_steps`：新 ID，保留 `lineage_key`、序号、期望结果与 `op` 块；**不复制 `act` 块**。
6. 复制 `requirement_test_items` 到新测试项。
7. 重置用例状态为 `pending`；步骤状态为 `none`。

### 已确认的清理字段

第二轮及以后复制时，以下执行字段全部清空：

- `test_cases.exec_date`
- `test_cases.tester_id`
- `test_cases.monitor_id`
- `test_cases.notes`
- `test_cases.not_executed_reason`

原因：这些也是执行数据，不清空会让新轮看起来已被执行或已被指派。

### 静态项

- DC/SA/CR/CW 现有首轮数据保留，不删除。
- 第二轮及以后新建时不显示静态项，不复制 `static_test_workbenches`。
- 即使绕过界面提交静态项，服务端也必须拒绝并返回明确错误。

## 三、创建后的增删范围

- “从来源轮带入”只允许新增当前轮不存在的测试项，按同一复制事务执行。
- 未执行过的测试项可在草稿轮中删除。
- 已产生执行数据后不直接硬删除；是否允许“移出本轮”还是只能保留历史，需要确认。
- 所有增删都必须刷新树、轮次统计和文档预检缓存。

## 四、上轮记录折叠

第二轮及以后打开用例详情时，在步骤表后增加一个默认收起的“上轮实测”区域：

- 标题显示：`上轮实测 · 第 N-1 轮 · 未通过 / 未执行 / 通过`。
- 默认收起，不请求上轮富文本内容。
- 点开后按 `lineage_key` 找到来源轮对应用例，再按步骤 lineage 对齐。
- 内容只读：实测结果、通过状态、执行日期、测试人员；图片/表格沿用只读内容块渲染。
- 上轮步骤比当前多/少时按 lineage 对齐并标注“上轮新增 / 已删除步骤”，不能靠序号猜同一行。
- 第 1 轮或无对应来源用例时不渲染该区域。

建议接口：

```text
GET /api/v1/test-cases/{id}/previous-round-result
```

首次展开才请求，避免列表和详情首屏携带完整 `act` 富文本。

## 五、验收重点

- 默认范围只包含上轮存在未通过用例的测试项；测试项内用例复制策略符合最终确认结果。
- 复制后新轮 ID 全部变化，lineage 保持一致。
- 新轮 `op`、期望结果和设计字段可见；`act`、步骤通过状态、用例状态符合重置口径。
- 修改新轮名称、步骤、状态不影响来源轮，刷新后仍独立。
- 全不选、全选、单测项取消和重复提交均有明确状态。
- 上轮实测默认折叠，展开后有加载态、空态和失败重试。

## 六、阶段 2 后端实施记录（2026-10-29）

- 预览按来源轮统计 `passed` / `failed`，`failed > 0` 自动默认勾选；动态项按类型与树内排序返回，静态项不返回。
- 创建轮次只接受来源轮同一项目的测试项 id；文件夹只复制选中项实际依赖的父链；测试项、子项、用例、步骤和需求关联全部重建新 id。
- 新用例状态为 `pending`，执行日期、测试人员、监测人员、备注和未执行原因清空；步骤状态为 `none`；步骤只复制 `op`，不复制 `act`。
- 空数组创建空轮并保持 `draft`；静态项硬传返回 422 和具体项标识。
- 服务测试覆盖部分复制、lineage、文件夹、需求关联、执行字段、op/act、静态拒绝、空轮和来源轮不变；HTTP 集成测试覆盖两个接口及工作台首轮隔离。
