# 前端体验

## 需求录入铁律

- 所有界面需求、视觉调整、交互反馈和动效要求必须先录入 SRS，再进入实现；不允许只留在对话记录或代码注释里。
- 全局审美、布局、控件质感、反馈、动效和无障碍要求维护在本文；具体模块的信息架构、页面结构、模块颜色和局部交互维护在对应模块 SRS。
- 录入界面需求时必须写清：设计读法、布局层级、信息密度、语义色、组件库选型、交互状态、响应式断点、动效时长、reduced-motion 和移动端表现。
- 美化需求是界面需求录入的必填项：每个页面、卡片、TAB、表格、空态和状态反馈都必须写明视觉层级、轻阴影、语义色或浅色渐变、图标使用、 hover 反馈和动效边界；未写美化口径的需求不得进入实现。
- 卡片类容器必须默认满足“轻阴影 + 颜色层次”：至少包含小面积投影、语义色条 / 语义色浅渐变底 / 等效视觉分组；禁止把纯白底加灰边、无阴影、无语义色的方案作为默认卡片样式。
- 用户验收后提出的“好看 / 不好看 / 顺眼 / 不顺眼”反馈，必须翻译成可执行口径录入 SRS，例如间距、对齐、色彩、层级、留白、边框、阴影、动画范围或状态反馈。
- 每次前端实现前先检查本文和对应模块 SRS；实现后如实际方案与 SRS 有差异，必须回写文档并说明原因。
- 代码验证必须同时覆盖深浅色、键盘可达、焦点可见、文字不溢出、控件不遮挡和 320px 最窄视口。

## 视觉方向

- 未登录访问任何业务深链时，必须在发起业务 API 前进入统一的“访问未授权”全屏状态页，不得显示普通 404、空白页或接口错误页。
- 用户主动退出登录不是未授权访问：必须清空会话与查询缓存，并直接回跳登录页，不得展示 401 状态页。
- 授权状态页和路由 404 使用同一套视觉语言：品牌标识、状态码、路由地址、语义色轨、轻量网格背景和克制的扫描动效；主按钮为“返回登录界面”。
- 从未授权页进入登录并成功后，默认返回原深链；跳转地址必须是本站相对路径，禁止开放跳转。
- 已登录状态下的未知路由显示统一的 404 状态页，提供返回首页和重新加载操作；未登录状态下的未知路由优先按未授权处理。
- 默认按个人自用工具的舒适感优先：界面可以大胆使用品牌装饰与语义色，但必须服务识别、层级和操作愉悦感；交互反馈柔和清晰，避免生硬、干瘪或模板化。
- 默认使用浅色工程风格，支持深浅色切换。信息密度服务任务，不强制高密度，常用页面允许舒适留白。
- 保持直角、细边框、清晰层级和克制的绿色状态色；装饰围绕品牌经线、状态语义和数据层级展开，避免圆润卡片堆叠、单一蓝紫渐变和营销页式布局。
- hover 反馈禁止真实位移；卡片、按钮和选项只通过阴影、边框、背景和颜色变化制造上浮感。active 按压可保留轻微下沉。
- 全站装饰基调：登录面板、筛选栏、指标卡、风险卡、待办分区、项目创建分组、工作台概览和字典管理区统一使用左侧语义色长条；同层级卡片共享小面积软阴影。
- 所有卡片必须有可见的轻阴影和颜色层次：基础态至少包含 1 层小面积投影、1 条语义色线或浅色渐变底；不得交付纯白底加灰边的“素卡片”。阴影扩散控制在 14px 内，hover 只增强轮廓与轻投影，不做大范围悬浮。
- 指标卡 hover 阴影保持小面积软投影：外层扩散不超过 14px，边缘轮廓用 1px outline 单独过渡，禁止大范围重阴影制造生硬悬浮感。
- 首页与工作台指标卡必须形成明显数字层级：项目总数、执行率等主数值使用等宽字体、放大字号、粗体和 `tabular-nums`；指标名称用小字号 semibold，补充说明用弱色常规字重，禁止三类文字看起来同层级。
- 页面功能标题统一使用 `PageHeader`，标题为 foreground 黑色 700 粗体；语义图标、计数徽标、经线光带和低强度网格/光晕装饰可以叠加，但不得遮挡内容或降低对比度。
- `ChenMeridian` 品牌字标使用炫彩渐变和慢速流动动画，应用在登录页品牌区、侧边栏和移动抽屉；页面功能标题不使用炫彩渐变。
- 全局控件采用 Material 质感语言，但不引入 MUI 组件库：按钮、输入框、卡片和标签使用主题感知阴影、颜色和边框反馈；直角仍是主规则，控件最多 2px 微圆角。
- 界面与小号文字使用系统字体栈：`-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif`，中文回退 Microsoft YaHei；数字和标识数据使用等宽字体，避免表格列宽跳动。
- 按钮必须有 pointer 位置触发的点击水波纹，并有 hover 阴影增强和 active 轻微下沉反馈。按钮与下拉框 hover 状态禁止位移。
- 表格表头一律水平居中，基础 `TableHead` 组件必须内置居中；数值、状态、标签、徽标、操作等短列的表头和单元格内容必须同时居中，长文本列仅正文单元格可左对齐，表头不允许左对齐。表头必须比普通单元格更重，统一使用 `font-semibold` 与 foreground，允许用浅底色区分但不允许弱化成普通正文。
- 表格长文本统一用 `TruncatedText`：单元格显示省略号，只有真实溢出时用 Radix Tooltip 展示全文，延迟控制在 150ms 左右，禁止原生 `title` 提示。
- 接收文件队列的非待确认行使用只读文本展示对象类型、名称、版本和提供方，不用禁用输入框模拟只读；视觉上保持灰底、降透明度和不可点击光标，只读文本同样遵守省略号与 Tooltip 规则。平台不展示、不编辑，由项目平台派生。
- 表格可排序表头和操作列按钮必须使用带边框、浅底和 hover 变化的 Button；操作列禁用灰色无边框 ghost 图标导致用户看不出可点击，破坏性操作用 destructive 色表达。
- Tooltip 出现和消失必须使用 120-180ms 微动画，并在 reduced-motion 下关闭。
- Dialog、AlertDialog、Sheet 和 Select 打开、关闭动画期间必须保持页面滚动条和内容宽度稳定，禁止 body 滚动锁造成横向抖动。
- 项目工作区一级导航切换的懒加载期不得继续保留旧路由内容；必须立即切换为统一加载面板。工作区路由与卡片入场只做透明度过渡，不做纵向位移，避免临界高度下滚动条闪现。

## 组件库铁律

### CSS Module 铁律

1. 组件自定义样式必须与组件同目录同名：`Button.tsx` 对应 `Button.module.css`，组件内 `import styles from './Button.module.css'`，自定义 `className` 使用 `styles.xxx`。
2. 变体使用 `styles.primary` / `styles.ghost` 等语义类；状态使用 `data-state`、`data-invalid`、`data-selected` 等 data 属性和 CSS 属性选择器，不在 JS 中拼接表现类。
3. Tailwind 仅保留少量布局工具和 shadcn/Radix 既有组合；业务视觉、主题变体、动画、状态和密集选择器必须进入 CSS Module。
4. CSS Module 选择器和导出名使用 camelCase；第三方子元素通过 `:global([data-slot='...'])` 定位，不用标签选择器扩大影响面。
5. 新增或改造组件时必须同步迁移该组件既有自定义全局样式；同一业务域允许按布局、树、表单、弹窗拆分多个同名组件 Module，禁止继续增长全局大 CSS。

需求与追踪页已完成本轮迁移：布局、树、统计卡、详情、创建、删除、彻底删除、审计、已删除管理和快捷键说明分别使用同目录同名 `.module.css`；树导线偏移由 `data-guide-level` CSS 属性选择器定义，不在组件中写 inline style。基础 `Button`、`ContextMenu` 和 `Textarea` 也已迁移，Button 变体使用 `styles.primary` / `styles.outline` / `styles.ghost` 等类。

- 接收文件录入页紧跟工作区一级 TAB，减少无用顶部留白；桌面端左侧只保留窄版文件投放区和接收信息，右侧工作对象队列占据主要宽度。
- 删除工作对象必须使用 AlertDialog 二次确认，确认文案说明数据库记录和接收文件会一起删除；已确认对象不提供直接删除入口。
- 撤回确认和作废必须填写操作原因；已确认、已被替代、已作废版本在接收队列中只读，并用独立状态徽标区分。
- 已确认版本的对象类型、名称、版本或提供方录入错误使用“登记纠错”弹窗处理，必须展示原始值、填写新值和纠错原因；不得引导用户通过作废或撤回修正录入错误。平台不参与登记纠错。
- 生命周期记录使用 Dialog 展示，按时间倒序呈现状态迁移、原因和操作时间。
- 上传全流程需要完整加载态：上传请求、文件落盘、数据库保存和列表刷新期间应提供工作区级动画进度条或进度面板，禁止只显示局部 spinner 导致页面其余区域像可操作状态。
- 上传加载态必须区分“真实字节传输”和“服务端处理”：批量上传使用 `XMLHttpRequest.upload` 读取已发送字节与总字节；网络传输完成后切换为服务端落盘与入库处理态；接口返回后切换为列表刷新态。大文件期间用户必须看到文件数、总量、已传输量和百分比，禁止把不确定等待伪装成已完成。
- 上传进度层使用 shadcn/Radix Dialog 呈现：模态遮罩覆盖页面；上传请求、服务端处理和列表刷新期间禁止关闭按钮、Esc 和点击遮罩中断上传，避免用户误以为已取消。完成后进入“保存完成”态，保留结果并允许用户通过关闭按钮、Esc 或点击遮罩手动关闭，不得自动消失。内容包含品牌工程面板、动画进度条、阶段轨、当前状态和文件摘要。浅色模式使用品牌绿与信息蓝的细渐变进度，深色模式保持足够对比；流光只作用于 transform / opacity，周期不短于 2.6 秒，reduced-motion 下保留静态进度与完成图标。
- 接收文件工具栏的空白区域禁止作为文本选择起点；从工具栏空白处按住拖动不得扩展选择区或触发浏览器选择异常。标题、说明文字节点本身仍允许正常选中，操作按钮和表单控件不受影响。
- 全局静态文字选中后不得触发浏览器原生拖拽复制和拖影；用户仍可用鼠标创建选择区、用 `Ctrl+C` 复制，输入框、文本域、内容可编辑区域和显式标记为可拖拽的元素不受影响。文件投放区继续支持文件拖入。
- 前端设计、改版和视觉问题处理必须先读取并使用项目本地 `.agents/skills` 中匹配场景的技能：数据密集界面优先 `ui-ux-pro-max`、`shadcn`、`tailwind-4-docs`；动效优先 GSAP 系列；仅营销页、作品集或探索性视觉才考虑 `design-taste-frontend` 等风格技能。实现仍以当前主题、组件体系和本文件铁律为准。
- 前端卡顿、输入长任务、滚动掉帧、切换慢和拖动假死必须先按《21-前端性能优化策略》定位与验收；不允许只凭感觉删除视觉层或引入新依赖。
- 每次修改页面、组件、样式、交互或动效前，必须横向检查同类型页面和组件，并先划分影响域：全局基础组件、业务组件、单页面或全局主题。凡属于同类结构的能力必须保持整体结构一致，不能只修当前反馈页面或留下同类页面不一致。
- Select 打开和关闭过渡期间页面纵向滚动条必须保持可见，布局宽度不得变化。
- 标签使用 shadcn/Radix Badge 体系，不同语义变体保持一致尺寸；不得通过外扩阴影制造视觉高度差。
- 能使用成熟组件库的交互组件必须使用组件库：优先 shadcn/ui 与 Radix UI；表格、路由、数据使用 TanStack、React Router 等专业组件库。仅纯展示、布局或确无组件库能力时允许手写，但必须补齐无障碍、键盘操作、焦点态和微动效。
- 新增交互组件前先检查 `web/src/components/ui` 是否已有对应组件。
- 数据表格统一基于 TanStack Table 与 `DataTable` 封装，排序、空态、选中态、行键盘操作不得在业务页重复手写。
- 查询加载态统一使用 Skeleton 与 `QueryLoading`，错误态统一使用 Alert 与 `QueryError`，禁止裸文本居中充当状态页。
- 表单内多选统一使用 `Popover + Command + Badge` 组合的 `MultiSelectCombobox`，必须提供搜索、已选徽标、键盘选择和错误态。
- 多选已选徽标选入时必须有轻量插入动画，移除时先做压缩淡出再卸载；动画只使用 transform/opacity，并在 reduced-motion 下关闭。
- 启用/停用等二元设置使用 Radix Switch；Checkbox 仅用于批量选择或明确的多选项语义。
- 移动端抽屉导航使用 shadcn Sheet，不使用居中 Dialog 模拟侧边栏。
- 图标按钮和图标型触发器需要 Tooltip 或明确的 `aria-label`。
- 提供自研快捷键的高频作业面必须在工具栏提供快捷键说明入口：图标按钮带 Tooltip，点击打开 Radix Dialog；说明按“快捷键”和“功能说明”分组，快捷键使用键帽、适用范围和结果三列表达，功能说明解释对应业务行为。弹窗支持键盘导航和 Esc 关闭，窄屏仅允许说明表横向滚动。

## 目录结构

前端位于 `web/src`，使用传统 Vite SPA 结构：

- `src/api/`：HTTP 客户端和接口封装。
- `src/components/provider/`：全局 Provider。
- `src/components/router-util/`：路由加载和错误状态。
- `src/components/shared/`：跨业务页面的组合组件和状态组件。
- `src/components/ui/`：shadcn/ui 基础组件。
- `src/components/brand/`：品牌标识组件（BrandLogo）。
- `src/features/<模块>/`：业务模块，内部拆 `api.ts`、`types.ts`、`components/`。
- `src/layouts/`：页面布局。
- `src/lib/`：GSAP 等通用能力。
- `src/pages/`：路由页面组件。
- `src/router/`：`createBrowserRouter` 路由定义。
- `src/stores/`：Zustand 状态。
- `src/styles/`：全局样式。

新增模块优先放入 `features/`，不把业务代码混入基础组件目录。

## 路由模式

- 使用 React Router 8 SPA Data Mode。
- 使用 `createBrowserRouter` + `RouterProvider`。
- 路由页面支持 lazy 加载，并按 Data Mode 约定导出 `Component`。
- 认证判断放在布局或页面组件中，后续可扩展 loader 和 action。
- 根路由提供 HydrateFallback，避免初始 lazy 加载警告。

## 动画

- 主页面必须提供统一的入场反馈：使用页面级 `useGSAP` 作用域、专属 reveal 类、轻微上浮淡入和 stagger；数据页需等主要内容加载完成后触发，并尊重 reduced-motion。同类主页面不得出现有的有入场动画、有的没有的结构差异。
- 使用 GSAP 和 `useGSAP` 管理动画生命周期。
- 动画快速、精致，优先突出层级和状态，不得拖慢录入效率。
- 状态卡与阶段条允许使用低速渐变流动、柔光扫过和进度条微光，用于表达 active / partial / ready 状态；循环周期不短于 2.6 秒，只动画渐变位置、透明度和 transform，禁止布局属性动画。
- 独立工作区顶栏属于高频作业入口：项目身份、轮次和状态切换必须有 180-320ms 的状态过渡；顶栏底部可使用匀速细流光，但不得影响文字对比度。
- 顶栏底部流光在浅色模式也必须清晰可辨：轨道使用品牌绿到信息蓝的 2px 渐变线，流光带增加小半径辉光；暗黑模式保持白色流光。两套主题的流光节奏一致，reduced-motion 下均关闭。
- 独立工作区顶栏必须主题感知：浅色模式使用浅色玻璃、品牌绿淡渐变、左侧品牌色轨和深色文字，避免突兀的黑绿色横幅；暗黑模式使用深绿 cockpit 和白色透明度文字。顶栏内按钮、下拉框、指标胶囊和用户胶囊共享同一套顶栏表面 token，hover / focus 只增强边框、轻背景和内高光；不得复用 `primary-foreground` 作为顶栏文字色。
- 必须尊重 `prefers-reduced-motion`。
- 循环动画起点和终点必须在容器外不可见区域，循环重置不允许可见跳变。
- 流光类动效一律匀速。
- 可动画 transform、opacity、filter、box-shadow、color、background-color、border-color；禁止动画 width、height、top、left 等明显触发布局的属性。
- 阴影、颜色、边框等质感过渡时长 180-320ms；多层阴影的基础态和激活态保持相同层数，避免无法插值导致跳变。
- 非必要循环动画在 reduced-motion 下关闭；一次性 hover / focus 反馈可保留但去掉位移。

## 品牌视觉

品牌视觉以“经线”（Meridian）为核心意象：经线球体线框、匀速流光、信号传递流程条构成统一动效语言。

- 品牌图标：`web/src/components/brand/logo.tsx` 的 BrandLogo（currentColor），登录页左上角、侧边栏、favicon 同源。
- favicon：`web/public/favicon.svg` + `favicon.ico`，`index.html` 先 SVG 后 ICO。
- 炫彩渐变只用于 `ChenMeridian` 品牌字标和品牌装饰，不扩散到正文、页面功能标题和控件。
- `brand-wordmark` 用于侧边栏与移动抽屉：炫彩渐变文字，12 秒慢速流动；reduced-motion 下保留静态渐变。
- 登录页大字标：逐字符炫彩渐变、stagger 上浮入场、14 秒 hue-rotate 慢转。
- 登录页经线流光：字标下方 1px 线上一条辉光光带匀速滑过，5.2 秒一轮，间隔 0.5 秒。
- 登录页流程信号传递：测试项 -> 用例 -> 执行 -> 报告使用 lucide 图标节点与连续进度轨；信号点匀速推进，按 active / completed 状态点亮，循环结束前整体淡出。
- 流程轨首尾节点必须贴齐同一段落的左右边界。
- 流程轨节点必须等距分布：相邻节点中心间距一致（网格用等宽列 + space-between 实现，禁止首尾定宽列加中间 1fr 列造成两端短中间长的间距）；信号点推进的等分时间必须与节点等距位置对齐，信号点到达节点时刻即该节点激活时刻。
- 登录页背景光斑：两个 primary 径向光斑 4.8 秒呼吸。
- 登录页右上角经线球线框：嵌套椭圆 SVG，70 秒匀速旋转。
- 登录按钮：hover 白色光泽扫过（`btn-sheen`，0.7 秒 cubic-bezier）。
- 工作台标题保持黑色粗体；标题下方可保留匀速流光线，指标条 stagger 入场，数字从 0 滚动到目标值。

## 首屏启动动画

白屏期是应用给用户的第一印象：Vite 冷启动需要按需编译模块，React 挂载前 `#root` 只有空白 DOM，必须用预挂载首屏把"编译 / 加载中"翻译成"正在校准经线"的品牌仪式感。

- 设计读法：全屏唯一焦点层，居中纵向排列：经线球线框（外圈轨道 9 秒匀速旋转）-> `ChenMeridian` 炫彩字标（12 秒慢速流动）-> 2px 经线轨道流光（5.2 秒一轮，与登录页流光同节奏）-> 弱色状态文字"正在校准经线"。
- 信息密度：零业务信息；不显示版本号、后端状态等可变内容，只保留固定品牌文案，避免加载期间状态跳变。
- 语义色：背景跟随主题（浅色 `oklch(0.975 0.005 125)`，暗色 `oklch(0.165 0.012 150)`），球体与流光使用 primary，字标使用全局 wordmark 渐变，状态文字为 primary 与背景的中低强度混合；允许一层 primary 低强度径向光晕（透明度不超过 10%）制造层次，不引入新语义色。
- 组件库选型：预挂载首屏必须零 JS 依赖，内联在 `index.html` 用纯 CSS 实现（React 组件在模块编译完成前无法渲染，无法覆盖白屏期）；React 挂载后的路由加载态使用本地 `ShinyText`（CSS 光泽扫过文字）+ 品牌 wordmark + 经线球组合，不再使用骨架屏充当路由加载态。数据查询加载态仍统一使用 Skeleton。
- 交互状态：首屏不可交互、不遮挡后续内容；React 挂载后整层自然替换，不做退场动画（退场动画会推迟可交互时间）。
- 暗色模式：`index.html` 头部预置极小脚本读取 next-themes 存储键 `theme`，首帧前把 `dark` class 挂到 `html`；暗色用户首屏直接进入深色背景，消除主题闪白。
- 响应式断点：320px 最窄视口字标不溢出不换行（clamp 字号），球体 48-64px 自适应，流光轨道 `min(15rem, 60vw)`；内容全部居中。
- 动效时长：球体轨道 9s/圈匀速、字标渐变 12s、流光 5.2s/轮匀速、状态文字光泽 2.4s 扫过；只动画 transform、background-position，禁止布局属性动画；循环起点终点都在容器外不可见区域。
- reduced-motion：首屏全部动效关闭，保留静态渐变、静态球体和 2px 静态轨道；ShinyText 通过 CSS `prefers-reduced-motion` 关闭光泽动画。
- 移动端表现：布局与桌面一致，仅缩小间距和球体尺寸；不使用 WebGL 等高开销渲染，避免低端设备首屏更卡。
- 美化口径：首屏元素间距 16-24px 呼吸，光晕只作为背景层次；严禁在首屏堆卡片、按钮或营销文案。

## 登录页

- 首屏即登录表单，不做营销落地页。
- 左侧展示品牌、服务、SQLite、认证和运行模式状态。
- 右侧登录表单放在带左侧品牌长条的卡片面板中，保持高密度但不局促。
- 登录失败在表单附近给出明确错误。
- 登录成功进入工作台。

## 反馈

- 操作成功、失败和网络异常统一使用 `sonner`，全局位置顶部居中。
- 表单字段校验错误保留在字段附近。
- `Toaster` 必须开启 `richColors`，否则成功、警告、错误的自定义语义背景和边框变量不会应用到 toast 本体；深浅色主题下都必须检查实际渲染结果。
- `sonner` 成功、警告、错误 toast 背景统一使用 `var(--popover)`：浅色模式必须是白色，暗黑模式使用主题暗色弹层底色；边框直接使用 `--success`、`--warning`、`--destructive`，不得改成白色或中性边框。
- sonner 顶部 toast 必须整体让开固定顶栏：Toaster 顶部安全偏移统一引用 `--toast-safe-top`（基础顶栏高度 + 12px 间距），`offset` 与 `mobileOffset` 同步设置；导航 View Transition 期间顶栏快照层不得遮挡 toast，深浅色与窄视口都要验证。
- 401 时清理本地登录态并回到登录页。
- 语义色体系：主题/成功为绿色，警告为橙色，错误/危险为红色，信息为蓝色或中性色。品牌绿只代表主品牌和主操作，不得吞并警告、危险、停用和信息语义。
- 启用/停用必须一眼可辨：启用用 success 绿色和确认图标，停用用 danger 红色、关闭图标和“停用”文字；将执行停用操作的按钮使用 destructive 红色，启用操作不得使用危险色。
- `sonner` 按结果选择语义：成功 success，停用/需注意 warning，失败 error，说明 info。

## 表单层级

- 全局 `Textarea` 使用成熟的 `react-textarea-autosize` 方案：不显示原生右下角拖拽手柄，按内容自动增高；默认提供合适的基础行数和最大行数，超过最大高度后内部滚动。业务可在语义明确处覆盖基础行数（例如删除原因 3 行、需求描述 5 行），但不得恢复拖拽手柄或绕过统一组件。
- 字段标签使用 `font-semibold` 与 foreground，和辅助说明、占位文案形成三级明显层级。
- 字段标签与输入框、下拉框保持 `for/id` 关联以保留语义，但点击标签不得激活或聚焦关联控件；控件仍通过直接点击和键盘获得焦点。
- 输入内容使用 foreground 和中等字重；placeholder 使用独立弱色和常规字重，禁止复用 `muted-foreground`。
- 必填字段展示必填标记；多选字段同时提供“待选择 / 已选”状态，不只用颜色表达。
- 长表单底部固定操作区展示当前缺失项，提交错误点名缺失字段或分组。
- 提交表单必须使用 `noValidate` 的自定义校验，禁止浏览器原生气泡。字段错误通过红色边框、阴影或字段内提示表达，并可用 `sonner` 汇总。
- 字段错误文字出现与消失必须成对动画：出现时做 180-240ms 的淡入与轻微上移，错误占位高度使用 `grid-template-rows: 0fr -> 1fr` 平滑展开；用户修正错误后做 160-220ms 的淡出、轻微上移与 `1fr -> 0fr` 收起，并用等值负 margin 抵消字段 gap 造成的瞬时跳动。退出帧保留视觉内容但移除 `role=alert` 并标记 `aria-hidden`，动画结束后再卸载；不得造成横向位移。`prefers-reduced-motion` 下关闭位移和高度动画，错误修正后直接静态消失。
- 输入框和选择器 focus 时同时出现品牌色边框、内描边、静态 2px 荧光 ring 和外扩散阴影。
- 校验错误同时出现红色边框、2px 起步的红色荧光脉冲和外扩散阴影；错误状态优先于 focus 保持红色语义。
- 状态切换使用 240-320ms 平滑过渡；错误先入场淡入，再进入循环脉冲。reduced-motion 下关闭动画并保留静态三层阴影。

## 弹窗与日期

- Dialog 关闭期间禁止 remount：编辑器组件的 `key` 只能在打开时变化，关闭瞬间换 key 会杀掉 Radix 退场动画。
- 日期选择使用 `Popover + YearMonthCalendar`（react-day-picker 日期网格 + shadcn Select 年月切换头部），禁止原生 `input[type=date]` 和 react-day-picker 原生 select 覆盖层。
- 弹窗表单同样适用表单校验铁律：`noValidate`、自定义校验、`aria-invalid` 红边框阴影、字段内提示、`sonner` 点名汇总。
- 弹窗内必填字段展示红色 RequiredMark。

## 标签页与分段筛选

- 页签与筛选分段一律使用组件库 Tabs（shadcn/Radix）。
- 默认使用胶囊分段变体：激活态背景高亮、图标、计数徽标。
- `line` 下划线变体用于工具栏和紧凑场景：明确底边、品牌色 2px 激活下划线。
- 禁止手搓按钮组充当筛选器。

## 控件光标与图标

- Tailwind 4 preflight 把按钮光标重置为 default，必须全局恢复：`button`、`[role="button"]`、`[role="combobox"]`、`a[href]`、`summary` 未禁用时 `cursor: pointer`。
- 下拉框触发器 hover 同时有边框加强和轻背景反馈，不能只依赖 focus 态。
- 功能图标使用语义色或继承前景色，禁止裸白色图标；primary 按钮内部图标随白色前景除外。
- 关闭按钮 X 使用 muted-foreground，hover 加深为 foreground，禁止语义色圆底白叉。

## 炫酷组件参考

用户明确要求“炫酷组件”时，优先使用 React Bits：shadcn registry `@react-bits` 已在 `web/components.json` 配置，组件落位 `src/components/ui/`，动画依赖 `motion` 并必须接入 `useReducedMotion`。Aceternity UI、Magic UI 等仅作效果与交互思路参考；引入前必须适配 React 19、Tailwind CSS 4、shadcn/Radix、直角工程风格、深浅色、无障碍和 `prefers-reduced-motion`，不盲目复制与主题冲突的样式。
