# DOCX 解析经验

> 返回 [工程经验索引](README.md)

本文沉淀 ChenMeridian 里可复用的 DOCX 解析经验。后续解析研制总要求、任务书、测试说明、测试记录、测评报告等文档时，先对照这里的策略，再按文档类型补充专项规则。

## 基础策略

1. `.docx` 本质是 ZIP 包，正文读取 `word/document.xml`。不要把 XML 整体读成字符串后用正则拆内容；使用流式 XML decoder 处理段落、表格和嵌套元素，避免大文档占用过多内存。
2. 解析粒度先保留段落序号。每条章节、候选或证据都记录 `DOCX 段落 N` 一类原文锚点，方便后续回溯和调试。
3. 段落解析要跟踪：
   - `w:p`：一个段落；
   - `w:pStyle`：Word 样式；
   - `w:numPr / w:numId / w:ilvl`：自动编号和多级层级；
   - `w:t`：正文文本；
   - `w:tab`：转换为空格；
   - `w:drawing`：记录 `[图片]` 占位；
   - `w:tbl`：进入表格层级。
4. 表格内段落第一版不要直接当正文或标题，统一降级为 `[表格]` 占位。这样能避免版本表、日期表、参数表误生成章节或需求。后续做结构化表格时，再按文档类型定义列语义。
5. 图片只保留 `[图片]` 占位，先不把图片资产写入解析结果。

## 标题与章节

1. 优先识别 Word 标题样式；无样式但满足 `1.1 标题` 形态的显式编号只作为兜底。
2. 目录、日期、版本号、页眉页脚不是章节。带表格内段落、句号、日期格式的短文本不能因为行长短就识别成标题。
3. Word 标题样式有多种写法：`1`、`Heading 1`、`标题 1` 等都可能出现。解析前先归一化大小写，再按结尾数字或专用映射推导层级。
4. 使用 Word 多级自动编号时，显式编号可能不在标题文本里，应根据样式层级维护章节计数器。不要假定 `w:t` 中一定有 `1.2.3`。
5. 全书章节仍然写入章节表，便于保留原文目录和上下文；是否生成业务候选由文档类型和专项规则决定。

## 需求解析口径

1. SRS 需求以原文章节为最小单元，不自动合并、拆分或聚合；外部接口是当前唯一明确例外。
2. 标题形如 `[RQGN001-XXX-001] 名称` 的显式叶子需求优先识别，外部标识写入需求记录。
3. 需求组内的“子功能概述 / 输入信息 / 业务处理需求 / 输出信息”合并进叶子需求描述，不单独成需求。
4. 第三方测评口径下，只有标题明确包含“外部接口”或“对外接口”的章节生成接口候选；泛化“接口”和“内部接口”不生成候选。
5. 外部接口章节连同其子章节和表格占位合并为一条候选描述；如果外部接口下已有显式 `RQGN` 叶子需求，则显式叶子优先，父章节不重复生成。
6. 描述中必须保留原文片段或上下文，候选审阅页要能让用户判断漏项、重复和误识别。

## 数据替换与保留

1. 重解析只替换当前来源的 `parsed + candidate`，已确认、已排除、已替代记录保留。
2. 手工章节、手工需求和已有需求引用不得因重解析被静默删除。
3. 解析章节清理必须检查子节点和需求引用；只有原文中已不存在且无引用的解析章节才允许删除。
4. `.doc` 不能直接解析；允许为已确认对象版本补传 `.docx` 解析副本，只替换解析来源，不改变对象版本信息。

## 验证经验

1. 解析器规则用 Go 单元测试覆盖，构造段落或最小 OOXML 夹具，不依赖真实项目数据。
2. 每类新文档至少覆盖：正常章节、目录干扰、表格干扰、嵌套层级、边界标题、应生成的候选、不应生成的候选。
3. 专项规则要写清文档来源和业务口径，例如“外部接口才是第三方测评需求”不是通用文本规律，而是测评业务规则。
4. 涉及界面展示时，用浏览器截图检查标识、列宽、Tooltip 和换行；不要只用 DOM 文本判断视觉结果。

## 当前坑位

- 现象：表格内日期、版本号或短文本被当成章节。原因：只按文本长度和编号形态判断标题。规避方式：表格内段落第一版一律不生成章节，先保留 `[表格]` 占位。
- 现象：Word 样式标题被重复编号或章节号错位。原因：样式标题文本里可能有显式编号，同时多级编号又提供层级。规避方式：优先使用样式和多级编号推导层级，避免把标题文本编号重复拼进数据。
- 现象：背景说明、接口表格行被误判成需求。原因：只看“应 / 须”等规约词不够。规避方式：普通章节必须同时满足标题特征和规约词；特殊类型（如外部接口）必须由标题和业务口径明确授权。
- 现象：重解析后已有候选状态或人工判断丢失。原因：把重解析当成全量重建。规避方式：只替换 `parsed + candidate`，保留 `official / excluded / superseded` 及审计记录。
