# 项目记忆与坑位记录

后续工作中遇到可复用的坑位时，必须在本文件追加记录。记录格式固定为“现象、原因、规避方式”，只记录对后续开发有价值的信息，不记录无意义的过程噪音。

## Huma 与 SQLite

- 现象：Huma v2 的 Go adapter 包容易找错。原因：adapter 不在根包下。规避方式：使用 `github.com/danielgtaylor/huma/v2/adapters/humago`，配合 `huma.DefaultConfig`、`humago.New`、`huma.Register`。
- 现象：OpenAPI 文档入口容易误判为不存在。原因：Huma 默认已自动挂载 `/docs`、`/openapi.json`、`/schemas`。规避方式：除非明确要换文档路径，否则不要重复手写文档路由。
- 现象：SQLite 依赖可能引入 CGO，影响 Windows/麒麟交叉编译。原因：传统 GORM SQLite driver 依赖 CGO。规避方式：统一使用 `github.com/glebarez/sqlite`，DSN 通过 `_pragma` 配置 `foreign_keys`、`journal_mode(WAL)`、`busy_timeout`。

## Windows 与 PowerShell

- 现象：用 PowerShell 检查 JSON 内容时，`Invoke-WebRequest.Content` 可能是字节数组，直接调用字符串 `.Contains` 会得到误报。原因：响应被解析为 `byte[]`。规避方式：先判断类型，必要时用 `[System.Text.Encoding]::UTF8.GetString($response.Content)` 再检查。
- 现象：后台服务状态容易误判。原因：进程启动失败、端口占用或旧进程残留。规避方式：启动前检查端口，启动后记录 PID，并用实际 HTTP 请求验证服务，而不只看进程存在。

## 工具与工程操作

- 现象：安装大型 GitHub 仓库中的 skill 时，包管理器可能长时间停留在 clone 阶段。原因：仓库本体过大且只需要其中一个 skill。规避方式：优先选择轻量来源；确需精确安装时用 raw 文件或精确路径下载，并同步维护 `skills-lock.json`。
- 现象：对包含中文内容的文件做补丁时，上下文匹配偶尔失败。原因：编码、换行或上下文匹配细节不稳定。规避方式：优先用无上下文追加；必须修改中文段落时，先读取文件再用小范围补丁或整文件替换，不要连续盲试。
- 现象：使用 `npx shadcn@latest init` 初始化 Vite / React Router 工程时，项目文件已生成，但依赖安装失败，报 `EALLOWSCRIPTS: --allow-scripts is not allowed in project-scoped installs`。原因：当前 npm 使用项目级脚本白名单策略，命令行/执行器传入的 `allow-scripts` 不允许作用于项目安装。规避方式：在 `web/package.json` 中为确需安装脚本的包添加 `allowScripts` 白名单，再执行普通 `npm install`；不要在项目安装中使用 `--allow-scripts` 参数。
- 现象：React Router 相关包交错升级时出现 `ERESOLVE`。原因：`react-router`、`@react-router/dev`、`@react-router/node`、`@react-router/serve` 通过 peer dependency 互相约束。规避方式：先在 `package.json` 中把相关包同时改成同一版本，再一次性安装；不要用 `--force` 掩盖冲突。
- 现象：React Router framework mode 的文件路由页面显示空内容，控制台提示 matched leaf route 没有 element 或 Component。原因：把 `createBrowserRouter` 的 lazy 导出约定 `export function Component()` 错用到 `routes.ts` 文件约定中。规避方式：两种模式必须明确区分；本项目最终固定使用 Data Mode + `createBrowserRouter`，lazy 页面导出 `Component`。
- 现象：删除 `isbot` 后 React Router framework mode 的 `npm run dev` 失败。原因：React Router dev 启动器要求 `isbot` 依赖。规避方式：本项目已切换普通 Vite SPA，不需要保留 `isbot`；如果回到 framework mode，则必须保留该依赖。
- 现象：依赖变化后开发页面卡在加载态，控制台出现 Vite `504 Outdated Optimize Dep`。原因：Vite 预构建依赖缓存过期或正在重建。规避方式：重启 `npm run dev`，让 Vite 完成 re-optimize 后再验证页面。
- 现象：TypeScript 7 报 `Option 'baseUrl' has been removed`。原因：TS7 移除了 `baseUrl` 配置。规避方式：删除 `baseUrl`，直接在 `paths` 中写相对项目根的映射，例如 `"@/*": ["./src/*"]`。

## 前端动效

- 现象：GSAP 无限循环动画在 repeat 重置时元素突然"跳回"起始位置，视觉上像荧光从中间闪回顶部。原因：动画起点（如 yPercent: -30）仍在容器可见区域内，循环重置时元素位置跳变被肉眼捕捉。规避方式：循环动画的起点和终点都必须放在容器外不可见区域（如 xPercent: -100 到 100，元素宽度等于容器宽度时两端都在画面外），或在循环间加 repeatDelay 且确保重置瞬间不可见；所有动画只用 transform 和 opacity。

## 网络与下载

- 现象：curl 访问 GitHub 报 \CRYPT_E_NO_REVOCATION_CHECK\，看起来像网络不通或需要登录认证。原因：Windows curl 使用 schannel TLS，网络环境拦截了证书吊销检查（OCSP/CRL），TLS 握手失败；与 GitHub 账号登录无关。规避方式：加 \--ssl-no-revoke\ 参数跳过吊销检查即可正常访问；下载 skill 单文件用 raw.githubusercontent.com，列仓库文件树用 api.github.com 的 git/trees 接口。

## 前端依赖

- 现象：按 v8 教程写 useReactTable/getCoreRowModel 在 TanStack Table v9 下编译失败。原因：v9 是全新 API，hook 改名且改为 features 注册制。规避方式：v9 用 useTable({ features, columns, data, state, onSortingChange })，features 用 tableFeatures({ rowSortingFeature, coreRowModel: createCoreRowModel(), sortedRowModel: createSortedRowModel(), sortFns: { alphanumeric: sortFn_alphanumeric } })；列助手 createColumnHelper 需要两个类型参数（features 与数据类型）；行单元格遍历用 row.getAllCells()（getVisibleCells 已移除）。
- 现象：内容宽度超出视口，整个右列被撑出屏幕。原因：CSS Grid 1fr 轨道的隐式最小尺寸是 min-content，宽表格会把轨道撑开。规避方式：主布局列定义写 minmax(0, 1fr)，配合表格容器 overflow-x-auto 让表格内部横向滚动。

## 跨会话记忆

- 现象：新会话未找到上次写在全局记忆里的任务备忘。原因：只查看了 `~/.codex/memories` 根目录的 `MEMORY.md` 和 `memory_summary.md`，任务备忘实际存放在 `extensions/ad_hoc/notes/` 子目录。规避方式：开工先读 `srs/12-跨会话记忆.md`；查找时用 `rg` 对 memories 全目录做关键词搜索，不依赖根目录文件清单。
