# 项目记忆与坑位记录

后续工作中遇到可复用的坑位时，必须在本文件追加记录。记录格式固定为“现象、原因、规避方式”，只记录对后续开发有价值的信息，不记录无意义的过程噪音。

## Huma 与 SQLite

- 现象：Huma v2 的 Go adapter 包容易找错。原因：adapter 不在根包下。规避方式：使用 `github.com/danielgtaylor/huma/v2/adapters/humago`，配合 `huma.DefaultConfig`、`humago.New`、`huma.Register`。
- 现象：OpenAPI 文档入口容易误判为不存在。原因：Huma 默认已自动挂载 `/docs`、`/openapi.json`、`/schemas`。规避方式：除非明确要换文档路径，否则不要重复手写文档路由。
- 现象：SQLite 依赖可能引入 CGO，影响 Windows/麒麟交叉编译。原因：传统 GORM SQLite driver 依赖 CGO。规避方式：统一使用 `github.com/glebarez/sqlite`，DSN 通过 `_pragma` 配置 `foreign_keys`、`journal_mode(WAL)`、`busy_timeout`。

## Windows 与 PowerShell

- 现象：用 PowerShell 检查 JSON 内容时，`Invoke-WebRequest.Content` 可能是字节数组，直接调用字符串 `.Contains` 会得到误报。原因：响应被解析为 `byte[]`。规避方式：先判断类型，必要时用 `[System.Text.Encoding]::UTF8.GetString($response.Content)` 再检查。
- 现象：后台服务状态容易误判。原因：进程启动失败、端口占用或旧进程残留。规避方式：启动前检查端口，启动后记录 PID，并用实际 HTTP 请求验证服务，而不只看进程存在。

## 工具与工程操作

- 现象：安装大型 GitHub 仓库中的 skill 时，包管理器可能长时间停留在 clone 阶段。原因：仓库本体过大且只需要其中一个 skill。规避方式：优先选择轻量来源；确需精确安装时用 raw 文件或精确路径下载，并同步维护 `skills-lock.json`。
- 现象：对包含中文内容的文件做补丁时，上下文匹配偶尔失败。原因：编码、换行或上下文匹配细节不稳定。规避方式：优先用无上下文追加；必须修改中文段落时，先读取文件再用小范围补丁或整文件替换，不要连续盲试。
