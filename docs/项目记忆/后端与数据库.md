# 项目记忆：后端与数据库

> 返回 [项目记忆索引](../项目记忆.md)

## 后端与数据库

- 现象：Huma v2 的 Go adapter 包容易找错。原因：adapter 不在根包下。规避方式：使用 `github.com/danielgtaylor/huma/v2/adapters/humago`，配合 `huma.DefaultConfig`、`humago.New`、`huma.Register`。
- 现象：OpenAPI 文档入口容易误判为不存在。原因：Huma 默认已自动挂载 `/docs`、`/openapi.json`、`/schemas`。规避方式：除非明确调整路径，否则不重复手写文档路由。
- 现象：SQLite 依赖可能引入 CGO，影响 Windows/麒麟交叉编译。原因：传统 GORM SQLite driver 依赖 CGO。规避方式：统一使用 `github.com/glebarez/sqlite`，DSN 通过 `_pragma` 配置 `foreign_keys`、`journal_mode(WAL)`、`busy_timeout`。
- 现象：SQLite 重建表并创建同名索引时报 `index ... already exists`。原因：`ALTER TABLE ... RENAME TO` 会保留旧索引名。规避方式：先 `DROP INDEX IF EXISTS` 旧索引，再创建新表索引；外键依赖表按生命周期子表到父表顺序重建。
- 现象：新增需求审计动作后写入事件失败。原因：`requirement_events.action` 建表时带 SQLite `CHECK` 枚举约束。规避方式：新增审计动作必须同时补显式迁移重建事件表，并覆盖 create、update、confirm、exclude、restore、parse 全集；集成测试必须写入新动作验证约束。
- 现象：同一秒内连续删除和恢复时审计顺序偶发颠倒。原因：SQLite DATETIME 精度与查询执行环境叠加，`operated_at, created_at` 可能完全相同。规避方式：审计这类只追加事件按 `rowid` 排序，重建事件表的迁移复制数据时显式 `ORDER BY rowid`。同一问题也出现在工作对象生命周期事件（`internal/modules/assets/service.go`）：2026-10-10 补 `rowid DESC` 兜底后 `TestWorkObjectUploadConfirmAndVersionFlow` 由偶发失败转为稳定通过；凡「同一秒可能写多条」的只追加事件查询都要带 rowid 兜底。
- 现象：部分按钮迁入 CSS Module 后，左侧菜单 active/hover 和组合框的原有 Tailwind 状态样式失效。原因：Tailwind v4 工具类处于 `@layer utilities`，未声明 layer 的 CSS Module 属于无层样式，级联时优先于普通 layer；即使 Module 选择器使用 `:where()` 降为零优先级，也不会让位给工具类。规避方式：组件状态与布局规则写入同目录 `.module.css`，不要依赖传入 Tailwind 工具类覆盖；共享组件若必须允许外部工具类覆盖，基础 Module 要纳入 `@layer components`，并以浏览器计算样式验证。
- 现象：用户管理等页面的表格外边框缺失。原因：共享 Table 容器只声明了滚动和背景，没有统一边框，页面层也没有可靠补齐。规避方式：所有表格由 `table.tsx` 的 `data-slot="table-container"` 统一提供 1px 主题外框和轻阴影，页面不要重复手写外框。
- 现象：需求树迁移到 CSS Module 后，GSAP 行位移动画失效。原因：动画工具仍通过旧的全局类名 `.requirement-tree-row` 查询 DOM，而 Module 编译后的类名已经变化。规避方式：动画和脚本不要依赖样式类名，使用稳定的 `data-*` 标记，例如 `data-tree-row`。
- 现象：PowerShell 检查 JSON 时可能误报字符串不存在。原因：`Invoke-WebRequest.Content` 可能是 `byte[]`。规避方式：先判断类型，必要时用 UTF-8 解码后再检查。
- 现象：历史数据字段不符合当前编辑 schema 时，列表页仅切换启停也提示 `validation failed`。原因：前端把原有字段整包提交到 PUT，Huma 对旧数据中的非法字段重新执行完整校验。规避方式：创建与更新 schema 按需拆分；状态切换更新时允许空日期表示保留原值，业务层只在新增时强制必填。

- 现象：需求更新接口在写事务里加了一次“顺带查询”后，接口永久挂起（测试跑到 90s 超时才报错），`database/sql` 的 `Tx.awaitDone` 一直等锁。原因：GORM 的 `Transaction` 已持有 SQLite 写锁，代码却用 `s.db`（另一个连接）去读同一张表，glebarez/sqlite 单写者模型下两边互等。规避方式：事务内的任何查询都必须用事务句柄 `tx` 发起，需要复用的查询封装成 `xxxWith(ctx, db *gorm.DB, ...)` 形式（本次为 `bodyPlainTextWith`），禁止在 `Transaction` 回调里用 `s.db` 读；接口测试一旦出现 90s 级超时，先查是不是写事务里开了第二连接。

## 唯一约束下的顺序重排必须两阶段写入（2026-10-10）

- 现象：删除/拖拽后按顺序逐行更新 `seq`（测试子项、用例、步骤）时偶发 `UNIQUE constraint failed: (parent_id, seq)`，重排中断。
- 原因：逐行写最终序号会与尚未更新的兄弟行占用同一序号，SQLite 立即校验唯一索引。
- 规避方式：先把所有行写成临时负序号（`seq = -(index+1)`，同时写 `sort_order`），再写最终序号与派生标识（如 `YL_..._{NNN}`）；同一事务内完成。测试项/用例/子项/步骤四处重排都走这个模式。

## nil 切片序列化成 null 会让前端数组消费崩溃（2026-10-10）

- 现象：测试项工作台/详情接口在空子项、空关联需求时返回 `null`，前端读 `.length` 直接整页异常（"Cannot read properties of null (reading 'length')"）。
- 原因：Go 的 `var items []T` 是 nil 切片，Huma/encoding/json 会序列化成 `null`，不是 `[]`；前端类型按数组消费。
- 规避方式：API 层出参统一用 `nonNil` 帮助函数把 nil 切片转成空切片（见 `internal/api/v1/testitems/routes.go`）；新增列表字段一律套用，别只修当前报错的那一处。
