# 项目记忆：前端视觉与交互

> 返回 [项目记忆索引](../项目记忆.md)

## 前端视觉与交互

- 现象：独立项目工作区在桌面端内容超出视口后底部不可见，作业台、资料与对象等页面没有滚动条。原因：外层 `workspace-shell` 使用 `h-svh + overflow hidden`，而主内容 `main.workspace-route` 的纵向滚动只写在 1100px 以下媒体查询里，桌面端没有任何滚动祖先。规避方式：`main.workspace-route` 在全部宽度承担工作区唯一主纵向滚动；有内部作业树的模块（如需求与追踪）内部继续声明 `height: 100% / min-height: 0`，让树自己滚动并保持路由 `scrollHeight <= clientHeight`，不要把滚动规则只挂在窄屏分支。
- 现象：前端设计时技能选错，出现风格不统一或评审口径混乱。原因：没有固定的技能优先级顺序。规避方式：前端设计类任务按固定顺序使用技能——先 `design-taste-frontend` / `frontend-design` 定风格与品味，再用 `ui-ux-pro-max` 查设计系统与 UX 规则落地细节。
- 现象：`sonner` 成功提示浅色下背景偏红。原因：语义背景与无彩色弹层做 `color-mix` 插值时 hue 参与计算。规避方式：成功、警告、错误背景固定 `var(--popover)`，语义只放在边框和图标，并保持 `richColors` 开启。
- 现象：GSAP 循环动画重置时可见跳回。原因：动画起点仍在容器可见区。规避方式：循环首尾都放在不可见区域，必要时加 `repeatDelay`；动画只用 transform 和 opacity。
- 现象：Dialog 内嵌 Select 开闭时页面横向抖动。原因：两层 `react-remove-scroll` 锁定状态叠加导致滚动条消失又出现。规避方式：保留 `scrollbar-gutter: stable`，并在 Dialog/Select 开闭动画周期内恢复 body 的 overflow 和 margin。
- 现象：编辑正文 Dialog 内再嵌套 Radix AlertDialog，点击“放弃修改”同时关闭两层弹窗时，浏览器标签页卡死。原因：两层 Radix 焦点陷阱在同一帧卸载并互相恢复焦点，形成循环。规避方式：需要确认的交互不要嵌套第二个 Radix 弹窗；在主 Dialog 内使用同层 role=alertdialog 覆盖层，或者先关闭确认层、再在独立提交阶段关闭主 Dialog，禁止在同一次 React 状态更新里关闭两层模态组件。
- 现象：编辑正文后关闭弹窗，再点击左侧需求树或切换需求，浏览器标签页再次卡死；同时控制台出现 Radix 模态 `aria-hidden` 焦点警告。原因：详情组件按 `requirement.id` 设 key，Tiptap 在切换时被销毁；含 Tiptap 的 Radix 模态 Content 使用 `forceMount` 后，`hideOthers` 在关闭状态仍持续给背景 `aria-hidden`。规避方式：富文本详情跨需求保持挂载，详情查询用 `keepPreviousData`，切换期间用覆盖式加载态桥接，内容用 `session` 计数器重置；正文编辑弹窗改用原生 `<dialog>` + `showModal()`；图片节点用原生 ProseMirror NodeView，不再用 `ReactNodeViewRenderer`。禁止对含 Tiptap 的 Radix 模态 Content 使用 `forceMount`。
- 现象：Word 复制粘贴带首行缩进的段落，编辑器里有时识别不到 `data-first-line-indent`。原因：ProseMirror 的粘贴 slice 路径会丢掉独立的自定义属性，只有 `data-align` 能稳定存活。规避方式：粘贴清洗阶段把首行缩进编码成 `data-align="left+indent2"`，`align.parseHTML` 用 WeakMap 把缩进标记转交给 `firstLineIndent.parseHTML`；默认无显式对齐时按左对齐落库，用户仍可再改为居中 / 右对齐 / 两端对齐。
- 现象：在表格表头或单元格内点击“插入表格 / 插入图片”，保存时后端返回 422：`table / assetImage` 不允许出现在 `tableHeader` 下。原因：Tiptap 允许在表格内继续插入块节点，但内容块契约不允许表格嵌套表格或图片。规避方式：工具栏在 `state.table` 为 true 时禁用“插入表格”和“插入图片”，表格内只保留行列、表头、对齐和合并拆分操作。
- 现象：打开 F12 后视口高度变小，“测试项的需求描述”整体被压成一条线或被下方内容遮住。原因：详情 `.body` 使用 `overflow: hidden`，描述卡片又是 `flex: 1 1 auto; min-height: 0`，在短视口下允许被压到接近 0。规避方式：`.body` 改为 `overflow-y: auto`，描述卡片保留 `min-height: 16rem`，字段区和正文卡片整体滚动；禁止把正文卡片作为可无限压缩的弹性项。
- 现象：`box-shadow` 状态切换出现跳变——表单控件在默认与错误态之间闪一下，需求树或表格行点击后左侧选中条“先半截、约 150~220ms 后才突然变整行高”。原因：阴影列表在层数不一致，或内缩 `inset` 与外扩阴影混用时无法逐层插值，浏览器按离散跳变处理；色条还同时叠了伪元素与关键帧两个来源，出现时机不同就表现为半截条突然长高。规避方式：同一元素同一时刻只保留一个色条绘制来源，宽高固定、只过渡 `opacity`；参与过渡的 `box-shadow` 保持层数与 `inset` 标记一致；选中高亮关键帧不写色条，只改背景与描边；同位置的 `:focus-visible` 内阴影条要与色条同高；表格未选中态 hover 过渡保持原样，active 直接显示完整条，`prefers-reduced-motion` 下直接切换。
- 现象：字段错误修正后提示瞬间消失，入场展开动画无法对称收起。原因：调用方使用条件渲染，错误一变空就卸载 `FieldError`，退出动画没有可播放的 DOM 宿主。规避方式：表单始终渲染 `FieldError` 并传入当前错误，由组件保留最后一帧错误内容播放淡出与高度收起，动画结束后再卸载。
- 现象：批量替换未输入查找词、只输入替换词时，预览把名称和标识的每个字符都标成替换结果。原因：空字符串执行 `split("")` 会拆成单字符数组，预览构建误把空查找词当成有效关键词。规避方式：空查找词视为替换未启用，预览和提交载荷都短路；同时保留字段必填星号、失焦错误和提交禁用反馈。
- 现象：同一表单里的普通下拉框使用 `h-9`，共享副类型多选触发器仍保留默认 `min-height: 2.5rem`，导致编辑弹窗中两个下拉框高度不一致。原因：多选触发器有独立的组件默认高度，而业务表单只给普通下拉框设置高度，没有为同组表单控件统一声明控件高度。规避方式：同一表单的 `Input`、`Select` 触发器、`MultiSelectCombobox` 触发器必须显式使用同一控件高度；多选触发器用 `min-height` 对齐、`height: auto` 允许多标签换行，不能只给普通下拉框加 `h-*`。修改后至少测量普通下拉框与多选触发器的实际渲染高度，并检查单行与多标签状态。

- 现象：卡片 hover 时 Tailwind 阴影类看起来无效。原因：后加载的 `panel-surface` 基础阴影覆盖组件类阴影。规避方式：用稳定 `data-tone` / `data-risk-card` 属性在最终样式层定义基础、hover、深色阴影，并把边框轮廓拆到 outline 过渡。
- 现象：TanStack Table v9 反复提示 `sortFn 'text'/'alphanumeric' (auto) is not registered`。原因：v9 的 auto 排序不自动携带全部内置函数，features 只注册了别名。规避方式：同一个 `tableFeatures` 实例注册 `text`、`alphanumeric`、`basic`，业务表复用。
- 现象：Windows 下界面中文字体观感紧凑发闷，拉丁字符与数字回落系统字体。原因：字体栈把 `Microsoft YaHei UI` 放在标准 YaHei 前，且 Geist 未启用。规避方式：`PingFang SC` 放最前，让用户本机安装或自行下载的同名字体优先命中（同时负责拉丁与中文字形）；`Geist Variable` 紧随其后，作为未安装 PingFang SC 时的拉丁兜底；删除 `Microsoft YaHei UI`，并在入口 import 字体包。
- 现象：一次性脚本拆分大 CSS 文件后，格式化工具将部分产物清空。原因：脚本未检查片段边界、选择器数量和花括号平衡，失败后也没有可回滚的中间校验。规避方式：优先用小补丁或带断言的 Node 脚本；拆分前后记录规则数与字节数，检查首尾选择器和括号平衡，完成后再跑构建与浏览器样式断言。
- 现象：`background-clip: text` 的渐变文字在部分动画相位下整体不可见。原因：渐变里使用 `currentColor`，而元素自身 `color: transparent`，`currentColor` 解析为全透明。规避方式：渐变文字的底色和高光用显式颜色或自定义属性表达，`currentColor` 只用于继承前景色的装饰元素；改动后用计算样式或截图验证各动画相位。
- 现象：工作区路由切换时滚动条看起来先出现再消失。原因：路由和卡片入场动画做纵向位移，临界高度下会把内容推出滚动边界；未统一的内部滚动条还会回落到浏览器默认样式。规避方式：工作区入场动画只改透明度，模块内滚动条统一 8px 直角主题样式，并用逐帧 DOM 检查确认 transform 为 `none`。
- 现象：需求树行数增多后在左栏出现纵向滚动条，树面板没有贴到工作区底部。原因：独立项目工作区路由外层没有可继承高度，`h-full` 按内容高度解析；需求工作台又用 `100svh` 减固定偏移估算高度，左侧 Tabs 内容层和 `react-arborist` 高度也被固定值截断。规避方式：独立工作区外壳直接使用 `h-svh`，内部逐级 `flex-1`、`min-h: 0`、`height: 100%`，仅让树内容区自身滚动；树高度取容器实际 `clientHeight`，不要再设置会撑破父级的固定最小值。
- 现象：需求删除与彻底删除弹窗都关闭时 React 反复警告 duplicate key `none`。原因：两个常驻弹窗都在关闭态使用同一个 fallback key。规避方式：多个同类弹窗的 fallback key 加业务前缀，例如 `delete-none`、`purge-none`。
- 现象：待确认需求树里子树比视口高的节点（如 §4 工程需求）折叠/展开完全没有动画、直接瞬变，和短节点表现不一致；有的节点展开时新旧内容对向交叉，看起来像重影。原因：①早期实现按元素引用做 FLIP 位置过渡——折叠时子树行立即从 DOM 移除、只对剩余行做位移，当子树自身就占满视口、其后没有已渲染行时，FLIP 没有任何可动画对象，整棵子树于是瞬变；②`react-arborist` 是虚拟列表，渲染窗口外的行根本没有挂载，子树整体位移一旦把可见部分推到窗口外，动画中段就会露出空白；③展开时后续行位移方向写反，后续内容与正在展开的子树对向交叉，表现为重影；④按元素引用记录坐标，在 React 复用行节点时会张冠李戴。规避方式：折叠/展开统一改为「高度裁剪 + 后续行同步位移」（`useRequirementTreeMotion`）——折叠时保持树打开，把子树按行高从底部向上逐行裁剪（`clip-path: inset()`，不改透明度、不做缩放），后续行同步上移相同的 travel；展开反向执行，裁剪线从子树顶部向下推进，后续行从「展开前的位置」回到原位；裁剪线与后续行位移必须共用同一个 travel（方向写反就是重影）；子树比视口高时按可视比例重排时间轴（视口外位移只占固定的一小段时间），否则大子树会先静止一大半时长再飞快擦掉；动画期间用 overscan 扩窗，把动画中会进入视口的行提前挂载；子树超过 120 行不做动画、直接切换。两棵树共用同一 Hook，改动天然同时生效。
- 现象：待确认需求左侧目录树点击叶子节点完全没有反应，右侧审阅表和详情不跟随。原因：自定义 `renderRow` 完全替换了 `react-arborist` 的默认行渲染，库内默认的“点击 → 选中 / 聚焦”行为随之消失，只剩下 `onActivate`（双击 / Enter）和树级 `onFocus` 回调；已确认需求树之所以正常，是因为它自己在 `renderRow` 里补了 `onClick`。规避方式：凡是自定义 `renderRow` 的树，都在行容器里显式补 `onClick`（`setSelection` + `focus({ scroll: false })`）与 `Enter` / 空格的等价键盘处理，选中再通过树级 `onFocus` / `onSelect` 回传业务层。
- 现象：需求树滚动到底部后点击可见行，滚动条仍小幅跳动。原因：`react-arborist` 默认点击会执行 `select()`，内部固定用 `smart` 对齐重新计算滚动位置；贴底时 `react-window` 会把已可见行再次对齐。规避方式：用自定义 `renderRow` 在点击路径调用 `setSelection` 和 `focus({ scroll: false })`，外部选中同步不再走受控 `selection` prop；键盘导航仍保留库内自动滚动。
- 现象：批量粘贴弹窗关闭时没有退场动画，新增确认需求弹窗正常。原因：组件 `key` 跟随 `open` 状态变化，关闭时 React 直接卸载弹窗，Radix 没有机会播放退出状态。规避方式：常驻弹窗不要用 `open` 作为 `key`；通过打开边沿重置内部状态，关闭时保留 Radix `data-state=closed` 的退场周期。
- 现象：删除需求时淡出动画落在已分离的旧行。原因：选中项变化导致行渲染函数身份变化，React 更换行 DOM。规避方式：行事件通过 ref 传递并保持 renderer 稳定，删除成功后先对当前真实行淡出，再刷新工作台数据。
- 现象：窄屏需求工作台上下排列后出现路由、树、详情多层滚动条。原因：外层 `h-svh + overflow hidden` 只能裁切，内部又分别给树和详情固定高度，形成嵌套滚动。规避方式：1100px 以下只保留工作区路由一个主纵向滚动，`react-arborist` 按当前展开内容传自然高度，统计和详情正文随内容展开；仅多行文本达到最大高度或表格真实横向溢出时允许局部滚动。
- 现象：自动增高 Textarea 在窄屏空内容时也涨到最大高度。原因：`react-textarea-autosize` 会用 placeholder 参与高度计算，长占位文案在窄容器中多次换行。规避方式：统一组件设置 `minRows/maxRows` 并禁用拖拽手柄，已有标签的场景不依赖长占位文案；需求描述 5 到 12 行，删除原因 3 到 6 行，超过上限后内部滚动。
- 现象：需求表中长文本（如原文描述）的 Tooltip 内容被挤在很窄的宽度里，阅读需要频繁左右扫视。原因：`TruncatedText` 默认 Tooltip 使用固定较窄 `max-width`，长描述被压缩成大量短行。规避方式：为需要展示大段原文的场景提供宽 Tooltip 变体（宽上限约 52rem，且不超出视口），白空格保留换行、允许长串折断，样式写入组件同名 CSS Module；Hover 仍只在文本真实截断时出现。（2026-10-13 复核：该宽变体从未被任何调用方启用，已随 `TruncatedText` 精简删除；长文场景统一用 `tooltipValue` 传全文、样式沿用 18rem 上限。）
- 现象：需求树折叠/展开出现 100ms 级长任务，Long Animation Frame 归因里 forcedStyleAndLayoutDuration 占大头。原因：①早期用 GSAP Flip 逐行读写布局；②改成手写 FLIP 后仍在 for 循环里「写一行样式 → 读一行 rect」，每行都触发一次强制同步布局；③行坐标改回 getBoundingClientRect、快照与当前值混用 rect 和内联 top，会产生 padding 常量误差。规避方式：行坐标统一读 react-window 写在行上的内联 top（不触发布局），滚动条与视口尺寸在写样式之前一次性量好，写入阶段不再读任何布局；结构快照同样使用内联 top；扩窗量取「子树行数」与「渲染窗口下方剩余行数」的较小值，只覆盖会进入视口的那段位移；展开的扩窗量必须在点击处理的同一次提交里按数据模型推算（`countExpandableRows`），晚一步补 setState 会多出一次整树布局；扩窗窗口保留 1.5s 再回缩，连续切换同一节点不再反复挂载同一批行；并用 `content-visibility: auto` + `contain-intrinsic-size: auto 30px` 让屏幕外的行跳过样式/布局/绘制（react-window 只裁渲染窗口，挂载的行仍会参与布局；这也是展开时挂载 60+ 行长任务的主要来源，实测加上后大多数折叠/展开不再产生长任务、起动画 12-54ms）；此外必须用 `.tree [role="treeitem"] { min-width: 0 !important }` 压掉 react-arborist 内联的 `min-width: max-content`——否则每行都要做一次内容固有宽度测量，折叠路径 forcedStyleAndLayout 实测 58ms→4-8ms。生产构建实测（R2657 候选树 66 行）：§4.2 这类小节点折叠/展开 14ms 起动画、无长任务；§4（62 行子树）折叠 25-56ms 起动画、阻塞 1-45ms，展开 44-58ms 起动画、单次长任务 52-100ms（一次挂载 60+ 行的布局成本，重复切换同一节点时该批行被复用、长任务消失）；§4.3（37 行）折叠 47-57ms 起动画、展开 102ms 起动画。
- 现象：资料与对象（接收文件录入）页头在窗口越大、越宽时顶部空白带越明显，窗口小或内容多时又看不出来。原因：`.received-assets-workbench` 是撑满视口的定高 CSS Grid，两行都是 auto 行；Grid 默认 `align-content: normal` 等同 `stretch`，把剩余高度平均分给 auto 行，而 `.received-header` 又是 `align-items: flex-end`，多出来的高度全部留在页头内容上方。规避方式：定高网格里"按内容高"的行必须显式声明 `grid-template-rows: max-content minmax(0, 1fr)`（或让该行不参与 stretch），不要让 auto 行吃 `stretch`；改动后用 1440/1920/2560 多档宽度复核页头高度与首行元素间距是否恒定。

- 现象：TanStack v9 列上写了 `meta.width`、`meta.hiddenUntil`，运行时却完全不生效，还出现 `as DataTableMeta` 断言。原因：列元数据没有通过 v9 的 `columnMeta` 类型槽注册，`meta` 被推断成空对象；`meta.width` 也没有任何消费方。规避方式：在 `table-features.ts` 中用官方 `columnMeta: metaHelper<DataTableColumnMeta>()` 声明列元数据；只保留真正被 DataTable 消费的 `hiddenUntil`，列宽改由 CSS Module 的列规则负责，禁止把未接入的 width 写进 meta。
- 现象：表格行用了 `memo`，但某些表每次渲染仍整表重绘。原因：`leftAlignedColumns` 由调用方传内联数组（如 `[1]`），每次都是新引用，memo 浅比较必然失败。规避方式：DataTable 内部把 `leftAlignedColumns` 归一化为按 join 签名缓存的 `Set`，行组件只接收稳定 Set；调用方可以继续传数组，但不要把这个归一化责任散落到每张表。
- 现象：共享 DataTable 逐渐堆入没有调用方的 `rowClassName`、`virtualized.height`、`virtualized.overscan` 等配置。原因：为假想需求保留灵活性，实际只有候选表使用 `rowHeight`。规避方式：shared 组件只暴露有真实调用方的能力；需要第二套配置时再按实际场景增加，避免未使用的 props 进入 memo 比较和文档口径。
- 现象：重要功能按钮的高光扫过效果被复制到不同业务 CSS Module，角度、时长和透明度容易不一致。原因：缺少共享能力，复制实现逐步漂移。规避方式：统一使用共享 `<Button sheen>`；光泽实现集中在 `Button.module.css`，业务组件只传 `sheen`，禁止重复伪元素和渐变；`prefers-reduced-motion` 下关闭扫光。

- 现象：保存“测试项的需求描述”时 Dialog 几乎立刻关闭，用户看不到保存反馈，也不确定正文是否已落盘；若把刷新阶段放在 Dialog 内又会拖慢关闭感知，并在保存后残留脏状态。原因：保存、关闭和详情刷新没有拆成清晰阶段，编辑器初始化/主动 update 还会误触 dirty。规避方式：`保存中…` 阶段保留 Dialog 并显示按钮 spinner、编辑器临时只读；保存成功后立即关闭 Dialog，在“测试项的需求描述”卡内显示“正在刷新正文…”覆盖态和 `aria-busy`，直到详情 query 刷新完成；刷新期间禁用“编辑正文”。保存成功必须清除 `bodyDirty` 并忽略 busy/关闭后的编辑器内部 update，禁止随后切换需求时再次弹“正文尚未保存”。

- 现象：网络慢或主线程忙时，用户点击后界面仍停在旧状态，容易把加载 waiting 误判为系统卡死。原因：交互状态被设计成“请求成功后再提交”，加载态又遮住了旧界面，用户看不到任何已确认反馈。规避方式：执行乐观交互铁律——先提交本地可见状态（选中、展开、切页、缓存写入、乐观条目），再用 pending / `aria-busy` / spinner 表示同步中；服务端返回后 reconcile，失败原子回滚并给出重试。加载态只说明“正在同步”，不替代即时反馈，禁止让用户猜测点击是否生效。

- 现象：Playwright MCP 页面一旦渲染进程卡死，后续 `browser_*` 调用会持续等待，代理也会跟着长时间停住。原因：浏览器进程失去响应时，MCP 调用没有业务级超时，默认等待时间过长。规避方式：任一 `browser_*` 调用超过 15–20 秒未返回就按卡死处理；按 `--user-data-dir` 找到 `mcp-msedge-*` 根进程并强制结束，重新打开 `about:blank` 恢复。测试脚本内的 `goto`、`click`、`waitFor` 全部显式设置短超时，禁止 300 秒级无界等待。

- 现象：正文编辑弹窗改成原生 `<dialog>` 后打开、关闭没有动画，和项目其他 Radix Dialog 不一致。原因：`showModal()` / `close()` 默认直接切换 `display`，没有 Radix 的 `data-state=open/closed` 动画阶段。规避方式：原生 dialog 必须补 `@starting-style` + `transition-behavior: allow-discrete`，与标准 Dialog 统一为 220ms `cubic-bezier(0.32, 0.72, 0, 1)` 的淡入淡出 + `scale(0.97)` + 下移 8px；关闭时 `display:none` 要等退出动画结束。右上角 X 使用标准 DialogClose 的 1.75rem 细边框方形按钮样式。

- 现象：需求正文很长时“编辑正文”按钮随卡片头滚出视口，要手动回滚到顶部才能编辑；把卡片头改成吸顶后，吸顶栏上方又漏出半行被裁的表格内容。原因：卡片头原本没有吸顶；吸顶后滚动容器 `.body` 用 `padding-top` 留白，而滚动内容的裁剪边是 padding box——内容会穿过顶部内边距区域，12.8px 的 padding 条变成内容露出带。规避方式：卡片头 `position: sticky; top: 0` + 不透明背景（`var(--card)`）+ `z-index`；唯一滚动容器的顶部间距改由首个子元素 `margin-top` 承担，禁止在滚动容器上用 `padding-top`，否则任何吸顶元素上方都会漏出滚动内容。吸顶状态需要让用户看得出来时，在卡片内挂 1px 哨兵并用 `IntersectionObserver`（`root` 为该滚动容器）判定，禁止监听 `scroll` 逐帧算位置；吸顶态换主色玻璃底（`color-mix` 主色 14% + `card` 92% 透明 + `backdrop-filter: blur(10px)`，透明度低于 0.93 时表格线会透过吸顶栏显脏）、标题转主色深调、左竖线加高、主按钮由实心切描边，过渡统一 0.26s 并在 `prefers-reduced-motion` 下关闭。验证方式：滚到正文中部与底部，读取吸顶头 `getBoundingClientRect().top` 与滚动容器 `top` 相等且截图无内容露出；真实滚轮上下滚动全程 `PerformanceObserver` 收到的 longtask 必须为 0（实测 0 条）。

- 现象：正文题注与表格的字号/间距在只读预览和编辑器里各写一份，改一处另一处不同步（两次出现「预览与编辑器不一致」）。原因：CSS Module 里样式挂在 `p[data-variant]` / `table` 等元素选择器上，无法跨文件 `composes`，只能复制声明。规避方式：抽共享模块 `requirement-body-content.module.css`，规则写成 `.surface p[data-variant=…]` / `.surface table`，两个容器（预览 `.viewport`、编辑器 `.proseMirror`）都 import 同一 module 并挂 `.surface` 类——容器差异（滚动容器、上下留白、单元格对齐机制、选中态）留在各自 module；共享规则特异度 `.surface` + 元素 + 属性 = (0,2,1)，能稳定压过 `.proseMirror p` 这类 (0,1,1) 基础规则。

## button 默认 text-align:center 会把弹性盒子里的文字顶到中间（2026-10-10）

- 现象：需求描述手风琴行里"需求名称"明明用了 `flex:1 1 auto`，文字却显示在行中间偏右，看着像右对齐。
- 原因：`<button>` 的 UA 默认样式是 `text-align:center`；弹性子项占满剩余宽度后，文字在盒子内部被居中。
- 规避方式：凡是按钮内部要靠左排的文字容器（名称、标题、说明）显式写 `text-align:left`；本项目的 `.display`（单元格展示态）与 `.accordionName` 都已标注原因。

## 内联编辑框不要"算高度"，要"钉高度"（2026-10-10）

- 现象：点击多行单元格（测试项描述 / 充分性要求 / 通过准则）进入编辑时，单元格下边框往下走一点点，下面所有行跟着位移；单行的 input 单元格不出现。
- 原因：`textarea` 由浏览器算出的固有高度比展示态多约 **0.2px**（`scrollHeight` 是整数 + 设备像素取整）。只要编辑态高度由内容重新计算，就必然有亚像素差；此前用"对称内边距 + 整数行高 + 同边框"也只是把它压到 0.2px，压不成 0。
- 规避方式：进入编辑时**把单元格高度显式钉成展示态实测高度**（`getBoundingClientRect().height`），编辑框固有高度只用于判断"内容是否真的多出一行"（阈值 2px）才允许增高；退出编辑清掉内联高度。CDP 逐帧（rAF）验证：单元格高度、行 top、表格 top 零变化。
- 顺带两条同类坑：`<button>` 默认 `text-align:center`（弹性子项文字会被居中）；全局 `field-state.css` 对 `[data-slot="input"]` 的焦点环带 `!important`，而 `textarea` 不在其中（同一表格里两种编辑器的焦点会不一致）。

## 内联编辑器要非受控，否则 Ctrl+Z 失效（2026-10-10）

- 现象：在内联单元格里全选删除后按 Ctrl+Z，内容回不来（原生撤销栈被清空）。
- 原因：编辑器写成受控（`value={draft}` + `onChange`），React 在每次渲染后把 `value` 写回 DOM；浏览器只在"值由用户输入产生"时才积累撤销记录，程序化写值会让撤销栈失效。
- 规避方式：编辑框改**非受控**（`defaultValue={value}`），实时值存 `draftRef`（提交读 ref，`draft` 只服务高度计算/重排）；**编辑框还要常驻 DOM**（展示态/编辑态用 `data-editing` 切 `display`，不要条件渲染卸载），否则每次重进都是新元素、原生撤销栈照样归零；只在"外部真的改了值"时才写回 DOM（进入编辑时 `if (el.value !== value) el.value = value`），提交后重进不写值，撤销历史才能跨会话保留。

## 光标落点跟随点击（2026-10-10）

- 现象：点单元格任意位置进入编辑，光标总在末尾（textarea 反而在开头），用户想改中间的字得先按方向键。
- 原因：进入编辑是"用另一个控件替换展示态"，输入框自己的点击位置与展示态点击点无关；早期为统一 input/textarea 的默认差异，显式 `setSelectionRange(len, len)`。
- 规避方式：点展示态时用 `document.caretPositionFromPoint` / `caretRangeFromPoint` 把点击坐标换算成字符偏移（仅接受落在文本节点上的结果），存 ref，聚焦时 `setSelectionRange(offset, offset)`；键盘激活（`event.detail === 0`）没有坐标，回退到末尾。

## 错误提示不要重复弹（2026-10-10）

- 现象：改测试项类型被服务端拒绝时，同时出现两条内容相同的 `sonner` 错误 toast。
- 原因：`web/src/api/client.ts` 的 `request()` 已对所有非 2xx（含网络错误）统一 `toast.error(detail)`；业务层 catch 里再弹一次就成双份。
- 规避方式：业务层只在需要"保持弹窗打开 / 回滚 / 记状态"时 catch，不再自行弹 toast；确需自定义文案时传 `skipErrorToast: true` 并由业务层接管提示。

## 中文“看着靠上”是字形光学偏差，不是布局写错（2026-10-10）

- 现象：按钮 / 徽章 / TAG 里的中文总感觉贴着上边框，同一容器里图标又像是比文字低一截。
- 原因：CJK 字形墨迹的视觉重心比行盒中心高约 0.3–0.5px（字号越小越明显）；图标走的是几何居中，于是“文字偏上 + 图标偏低”叠加，肉眼更明显。
- 规避方式：容器顶部 +1px、底部 -1px（固定高容器只加顶部 1px）做光学补偿；成对出现的图标用 `margin-bottom` 反向补偿（Button 现为 `--btn-icon-shift: 2px`）；验收按“墨迹盒上下留白差 ≤ 0.5px”判，不要用 DOM 行盒判断——行盒中心相同，墨迹照样可能偏上。应用内浏览器 evaluate 是只读沙箱（没有 `createElement` / canvas），只能 `Page.captureScreenshot` 拿 JPEG 后自己解码统计；布局异步刷新会让 DOM 与截图错位，测量前后各取一次 rect 校验一致再采信。

## 中文字体走 `local()` 的度量覆盖在应用内浏览器不生效（2026-10-10）

- 现象：给中文回退字体写 `@font-face { src: local("MicrosoftYaHei"), …; ascent-override: 109% }` 并塞进 `--font-sans`，`document.fonts.check('12px "ChenMeridian CJK"')` 返回 false，字形位置与像素测量完全不变（把 override 改成 180% 也不动）。
- 原因：应用内浏览器的 Chromium 沙箱不解析 `local()` 字体源，这条 @font-face 永远不会激活。
- 规避方式：需要修正中文基线/度量时不要走 `local()` 路线，改用组件级 `padding-top` 光学补偿；真实浏览器支持 `local()`，但本仓库验收以应用内浏览器为准，不引入无法验证的方案。

- 原因：工具栏内“新增测试项 / 从需求创建 / 新建文件夹 / 两个静态操作 / 轮次芯片”总宽 388px，父面板 `overflow-x: auto` 把差值变成滚动条；轮次在右侧详情 Hero 已经展示，芯片属于重复信息。
- 规避方式：给 `.treePane` 声明 `container-type: inline-size`，在 `@container (max-width: 420px)` 下隐藏 `.roundChip`；不要直接给工具栏加 `overflow: hidden`，否则窄屏会丢失操作入口。改完用 `scrollWidth - clientWidth` 和截图同时验收。

## `prefers-reduced-motion` 规则被后置基础动画覆盖（2026-10-20）

- 现象：开启系统“减少动态效果”后，顶栏流光视觉上不可见，但 `getComputedStyle(::after).animationName` 仍是 `workspace-topbar-sweep`，浏览器继续跑循环动画。
- 原因：reduced-motion 媒体查询写在基础 `.workspace-topbar-beam::after` 规则之前，同特异度下后置的 `animation` 声明胜出；`opacity: 0` 只是把动画藏起来。
- 规避方式：reduced-motion 覆盖规则必须放在对应基础动画之后，或提高选择器特异性；验收时同时检查 `animationName === "none"`，不能只看截图。

## 深色模式下已勾选 Checkbox 变成“空框”（2026-10-20）

- 现象：深色主题里 `aria-checked="true"`、`data-state="checked"`，但复选框仍是灰底空框，勾选图标看不见。
- 原因：共享 Checkbox 的 `dark:bg-input/40` 覆盖了 `data-[state=checked]:bg-primary`，根节点计算背景仍是深色；同时 `text-primary-foreground` 是深色，浅色勾选图标也被换成深色，形成暗底暗字。
- 规避方式：共享 Checkbox 必须补 `dark:data-[state=checked]:bg-primary` 和 `dark:data-[state=checked]:text-primary-foreground`；验收时用计算样式确认勾选态背景是品牌绿、前景色与品牌色有足够对比，不能只看 `data-state`。

## 工作区首屏编排放不能把主面板延迟成空白（2026-10-20）

- 现象：工作区首页改成 hero → 指标 → 面板的分段 GSAP 入场后，刷新 260ms 截图里主面板仍未出现，首屏短暂只有 hero 和空白背景。
- 原因：主面板 `opacity: 0` 且时间线顺序串行，面板真正开始进入前用户已经看到大片空区；首屏内容不能为了完整编排牺牲可读性。
- 规避方式：首屏主面板初始透明度不低于 `0.2`，hero / 指标 / 面板时间线允许重叠，整体在约 350ms 内完成；保留 stagger 但不延迟主体可见时间，reduced-motion 直接显示。截图至少检查 250ms 中间帧。

## 虚拟树背景不能挂在滚动行宿主上（2026-10-20）

- 现象：选中用例行的绿色背景延伸到树滚动槽，和分组行/普通测试项行右边界不一致；红框截图里像“用例背景超出去”。
- 原因有两层：① `background / hover / selected` 写在绝对定位的 `rowHost` 上，背景面和可视内容面不是同一层；② `react-arborist` 给每行内联了 `min-width: max-content`，长用例名会把该行撑得比短分组行更宽。
- 规避方式：`rowHost` 只负责定位、高度和左侧状态条，背景和选中内描边挂到内部 `.row`；`[role="treeitem"]` 同时锁 `min-width/max-width: 100%`，行与标签都裁切，标签使用共享 `TruncatedText` 输出省略号，不能再让文字溢出；count / 类型 / 静态进度 / 用例状态收进 `.meta` 单组并 `margin-left: auto` 贴右，行尾只保留约 6px 内边距。测试项树没有高度动画，不能常驻 `scrollbar-gutter: stable`——那会在无纵向滚动条时留下约 15px 空白，叠加行尾间距后在分栏线前形成整条空带；改用默认 `auto`，出现滚动条时再占宽。背景过渡跟着 `.row` 走，`reduced-motion` 关闭 `.row` 过渡。验收要在宽树、窄树、真实纵向滚动、浅色和深色下同时看右边界，并确认悬停省略标签能看到全文。

## 双栏编辑框短栏必须上下居中（2026-10-20）

- 现象：测试项子项的“操作步骤”和“通过准则”并排时，左边内容把整行撑高，右边的空编辑框仍固定在顶部，下面留下一大块空白；用例步骤表里的短输入框却是上下居中的。
- 原因：双栏 Grid 的两列会被拉到同一高度，但编辑框外层只是普通块级 flex 子项，默认贴着标签下方排列，不会消费列内剩余空间。
- 规避方式：给同一行内的 `EditableCell` 统一挂共享类，短栏用 `margin-block: auto` 在标签以下的剩余空间内上下居中；内容多的一栏继续决定整行高度。验收时读取编辑框与同一列顶部、底部的实际间距：短栏上下间距必须接近，不能出现一侧为 0、另一侧上百像素。

## 工作台控件必须保持同一种可交互语言（2026-10-20）

- 现象：人员指派只有透明背景、无边框的“未指派”文字和一个小箭头，和只读文本几乎一样，用户第一眼不认为可以点击；同时同一张用例表中的表格标签、编辑框、人员选择器使用了三套不同强度的界面语言。
- 原因：人员选择器触发器使用了 `border: 1px solid transparent` 和透明背景，只在 hover 时出现反馈；而表格 label 与 `EditableCell` 各自维护独立样式，缺少统一的控制面、hover 轨道和焦点层级。
- 规避方式：工作台控件统一采用浅渐变面、可见 1px 边框、hover / focus / open 时出现语义色左侧刻线和轻光晕；人员选择器增加固定人员图标、32px 触发器高度和空态虚线边框；表头用顶部主色线，行标签用左侧主色线。所有状态只改颜色、边框和阴影，不位移、不改行高，并补 reduced-motion。

## 条件挂载会吃掉高度 transition（2026-10-21）

- 现象：批量选择操作条 CSS 已写 `max-height / opacity / transform` 过渡，但勾选复选框时仍是一整块高度瞬间出现；取消选择时也瞬间消失。
- 原因：父组件在 `selectedCount > 0` 时才挂载操作条，第一次渲染已经直接进入展开态，没有 `0 → 1` 的起始帧；卸载时 DOM 立即移除，也没有退出帧。只写 transition 不等于会产生动画。
- 规避方式：需要双向高度动画的面板常驻挂载，由父级条件只切换 `data-visible`；外层用 `display:grid` + `grid-template-rows:minmax(0,0fr) → minmax(0,1fr)`，内层 `min-height:0; overflow:hidden`，配合透明度与不超过 4px 的轻位移。隐藏态加 `visibility:hidden`、`pointer-events:none` 和 `inert`，避免隐藏控件进入键盘顺序；不能用固定 `max-height` 猜高度，也不能直接 transition `height:auto`。同类需求折叠面板已同步为 `minmax(0,0fr)`，reduced-motion 直切。
