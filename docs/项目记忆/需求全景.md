## 一、项目与轮次

- **目标**：项目是全部测评流程的基点；轮次是“测试说明 + 测试记录 + 本轮执行数据”的快照上下文，不是所有数据的父节点（`srs/16:5-9`）。
- **输入**：项目标识、名称、测评性质、平台、软件类型、密级、安全等级、技术字典、依据标准、负责人与成员（`srs/13:7-58`）。
- **输出**：`projects`、字典/标准/成员关联；同事务自动创建第 1 轮（`srs/13`、`internal/modules/projects/service.go:275`）。
- **规则**：标识 `R` + 4–5 位数字、全局唯一；名称不唯一；状态初始“编制大纲中”；字典与标准各至少一项；负责人自动成为成员（`srs/13:13-58`）。
- **状态**：项目状态为 编制大纲中 → 大纲已评审 → 测试执行中 → 回归验证中 → 报告编制中 → 已完成；轮次状态 `draft/ready/executing/closed`，两者分开维护（`srs/16:28-45`、`srs/11:34`）。
- **大纲评审**：时序第一节点是“测评大纲评审生成”，先于第 1 轮执行，此时测试项已存在；不建阶段对象、不做门槛、不加页面，只决定报告的大纲评审时间字段；项目状态由测试人员手动从“编制大纲中”改为“大纲已评审”，时间后续人工填写（`srs/16` 大纲评审节）。
- **轮次复制**：整树复制 `test_items`（带 `round_id`）、文件夹、子项、用例、步骤、需求关联；内部 ID 全新、`lineage_key` 保留；步骤只复制 op 块，执行字段与步骤三态清空（`srs/24/05`、`internal/modules/testitems/rounds.go:198`）。
- **静态项**：SA/CR/CW 仅第 1 轮；DC 每轮自动创建空工作台，上轮不通过记录仅在新建轮次向导勾选后作为历史参考带入（`srs/24/05` 静态测试项跨轮规则）。
- **验收**：创建事务失败不污染项目/字典；标识唯一；第 1 轮存在；轮次复制来源必须是最新轮；预览排除静态项、硬传静态项 422（`srs/24/05` 接口与轮次上下文）。
- **边界**：需求树、问题单、执行记录归属见后续模块；首页/项目详情只读驾驶舱，录入在工作区（`srs/11:40-52`）。
- **实现**：项目创建/列表/详情、第 1 轮、轮次列表/复制/切换已实现；项目编辑/删除/归档、模板绑定、阶段门槛为规划（`srs/13:95-99`、`srs/16:51`）。

## 二、接收文件

- **目标**：把委托方交付的文档与代码包登记为项目工作对象版本，作为需求解析与文档引用的唯一来源（`srs/14/03:7-15`）。
- **输入**：多文件上传或手工登记；对象类型、名称、版本、来源、接收日期、接收方式；主 SRS 可补传同版本 DOCX 解析副本。
- **输出**：`work_objects`、`work_object_versions`、`received_assets`（原文件、SHA-256、路径）、`work_object_lifecycle_events`；文件存 `data/file-assets/`（`srs/14/03:24-45`）。

- **状态**：`draft` 可编辑/删除、`confirmed` 仅登记纠错、`superseded`、`revoked`；确认新版本自动替代旧版；撤回回到 draft 并恢复旧版；作废保留文件与审计（`srs/14/03:72-91`）。
- **验收**：同版本冲突不覆盖；批量上传失败回收本批文件；字段保存失败回滚显示；纠错必须改至少一个字段并写事件；只有 draft 可物理删除（`srs/14/03:21,69-91`）。
- **边界**：解析与需求登记由需求模块消费；文档生成引用已确认版本；附件二进制存文件目录，业务只存关系（`srs/15`）。
- **实现**：上传、手工登记、确认/撤回/作废/纠错、解析副本、生命周期已实现；新旧版本差异比对与引用影响检查为规划（`srs/14/03:91`）。

- **输入**：已确认主 SRS（DOCX 解析）或手工录入；章节、需求名称、描述、类型/副类型/标签、来源版本。
- **输出**：`requirement_sections`（章节树）、`software_requirements`（需求）、`requirement_events`（审计）；需求正文存 `content_blocks(requirement.body)`（`srs/22/06:5`）。

- **状态**：候选 → 正式 / 已排除 / 已替代；排除可撤回到候选，已删除确认需求可恢复正式（`srs/22/03:22-33`）。
- **验收**：重解析不丢正式/排除/替代与手工章节；候选页展示原文上下文；创建测试项事务内校验并返回汇总；同一需求+类型+名称幂等（`srs/22/03:12,39-43`）。
- **边界**：需求树项目级唯一、不复制到轮次；测试项、用例、问题单只作追踪预览，不在需求树编辑；文档生成按需取需求与追溯（`srs/22/03:36`、`srs/16:101-113`）。
- **实现**：手工树、批量粘贴、DOCX 解析/候选确认/排除/回收站、正文块、创建测试项已实现；解析入口只在“待确认需求”页、来源限已确认且解析状态 ready 的 SRS；SRS 版本差异比对、顶层依据（研制总要求等）解析为规划（`srs/22/03:33`、`web/src/features/projects/components/project-workspace/requirements/requirements-candidate-workbench.tsx:360`）。
