# 项目全景

> 目标：一页讲清 ChenMeridian 的定位、边界、数据模型与当前完成度，供恢复上下文使用。只写有依据的事实，依据在括号内；拿不准的需求口径列在文末「待确认」，不当结论。最后通读：2026-11-03。

## 一、项目定位

- 本地测评工作台，面向军用软件第三方测评：项目、接收文件、需求追踪、测试项与执行、问题单、交付文档（`README.md`、`srs/12-跨会话记忆.md`）。
- 当前阶段：主链路（项目 → 接收文件 → 需求 → 测试项/用例 → 轮次执行 → 静态测试 → 问题单）已实现；Word 生成链路未开始（`srs/12-跨会话记忆.md` 第 7 行）。
- 安全约束：`R2657` 只读；`knowledge-base/接收文件/` 禁止提交/移动/删除；自动化不得在真实数据上触发写操作（`srs/12-跨会话记忆.md`、根 `CLAUDE.md`）。

## 二、技术栈

- 后端：Go + Huma v2 + GORM + SQLite（`github.com/glebarez/sqlite` 纯 Go），显式 SQL migration，UUIDv7 主键（`.claude/rules/02-engineering.md`、`srs/03-技术路线.md`）。
- 认证：bcrypt + JWT + Casbin RBAC（规则文档）；实际数据表 `users` 无角色列（`migrations/0005_remove_...`），当前只有固定管理员 `admin`（`internal/modules/users/service.go:17`）。
- 前端：Vite + React 19 + React Router 8 Data Mode + Tailwind 4 + shadcn/Radix + Zustand + TanStack Query/Table/Virtual + GSAP + dnd-kit + Tiptap；oxlint/oxfmt（`.claude/rules/02-engineering.md`、`web/package.json`）。
- 外部文档引擎 OfficeCLI：可选、不常驻，当前 1.0.160（`srs/03-技术路线.md`）。
- 依赖与构建：前端固定 npm + `package-lock.json`；检索引擎可用 rg/fd（用户 2026-11-03 指示），终端统一 pwsh。

## 三、目录与模块边界

- `cmd/chenmeridian`：进程入口；`internal/api/api.go` 组装 Huma；`internal/api/v1/register.go` 按模块注册 7 个 API 包（assets/auth/contentblocks/health/projects/quickissues/requirements/testitems/users）。
- `internal/modules/`：
  - `projects`：项目、字典、依据标准、相关方。项目创建事务内调用 `testitems.EnsureFirstRound`（`projects/service.go:275`，反向依赖，待评估）。
  - `assets`：工作对象、版本生命周期（draft/confirmed/superseded/revoked）、上传与解析副本（`assets/service.go`）。
  - `contentblocks`：DOCX 内容块抽取、需求正文块、步骤富文本块（`contentblocks/service.go`、`importer.go`）。
  - `requirements`：需求解析、章节树、候选/正式/排除/替代状态、批量建树（`requirements/service.go`）。
  - `testitems`：轮次与整树复制、测试项/子项/用例/步骤、需求关联、静态工作台、类型覆盖、追溯、标注、问题单、审查单模板（22 个文件；`static*.go`、`rounds.go`、`issues.go`、`review_templates.go`）。
  - `quickissues`：用例内快捷问题草稿（`quickissues/service.go`）。
  - `users`/`auth`/`settings`：用户、JWT、KV 配置；`settings` 无 API 路由（`internal/api/v1/register.go`）。
- `web/src`：路由 `router/index.tsx` 全部懒加载；页面壳在 `pages/`，业务实现集中在 `features/projects/components/project-workspace/{requirements,test-items,assets}`；`features/review-checklists` 为审查单配置页；数据层 `api/client.ts`（fetch/XHR + Huma problem）与 TanStack Query；全局状态仅 `stores/auth-store.ts`。
- 规则入口：根 `CLAUDE.md` 索引 `.claude/rules/01-05`（协作、工程、效率、前端、知识库）。

## 四、数据模型（migrations/0001–0032）

- 项目域：`projects`（code 唯一、安全等级/平台/状态）；`dictionary_items`、`reference_standards` 及项目多对多桥表；`related_parties`；`work_objects`/`work_object_versions`/`received_assets`/`work_object_lifecycle_events`（版本四态与事件）。
- 需求域：`requirement_sections`（章节树）→ `software_requirements`（candidate/official/excluded/superseded）；`requirement_events`；`content_blocks`（7 类 owner，正文/步骤/文档块）+ `assets`（图片）。
- 测试域：`test_item_types`（24 类种子）→ `test_item_folders`/`test_items`（0027 起带 `round_id`、`lineage_key`）→ `test_sub_items` / `test_cases` → `test_case_steps`；`requirement_test_items` 多对多；`test_rounds`（(project, round_number) 唯一）。
- 轮次：每轮复制 `test_items` 子树（0027 起，`round_id` + `lineage_key`），不再有轮次实例中间表（`srs/24-测试项与执行/05-轮次树与轮次复制.md`）。
- 静态测试：`static_test_workbenches`（payload_json + version 乐观锁）、`project_static_seeds`、`review_checklist_templates`（0030 建表、0031 增加文档类型/版本；内置 3 张可见模板，齐套性仅保留数据）。
- 问题与说明：`quick_issue_notes`（草稿）、`issues`（正式问题单，开放/关闭）、`test_item_type_coverage_notes`（不测评说明）。
- 迁移执行：启动自动 up，版本记录 `schema_migrations`；`migrations/embed.go`。

## 五、关键业务流程

1. 项目：创建时同事务建第 1 轮（`projects/service.go:275`）；安全等级+平台决定推荐静态项（`testitems/static_seed.go:18`）。
2. 接收文件：上传工作对象 → 版本 → 确认/替代/撤回/作废/纠错事件；同版本重复上传 409（`assets/service.go`、`srs/14-项目工作区与前端模块/03`）。
3. 需求：手动树状录入或 SRS 解析入候选池；候选确认成正式需求；正文存 `content_blocks`，`plain_text` 为权威源（`srs/22-需求录入与解析/06`）；待补描述需求不能关联测试项（`requirements`、`testitems` 校验）。
4. 测试项：类型分组 → 文件夹/测试项 → 用例；需求↔测试项显式多对多；静态四类有专属工作台与壳用例（`srs/24-测试项与执行/01-04`）。
5. 轮次：新建后续轮从最新轮复制选中动态项子树，执行字段清空；DC 每轮自动创建空工作台，上轮不通过记录需在向导勾选「导入上轮文档审查不通过记录」才作历史参考带入，本轮默认通过，复审记录「前一轮文档问题全部解决」（`rounds.go:198`、`static_rounds.go`）。
6. 静态 DC：默认全部通过，挑不通过填错误描述+截图，可立问题单；问题单是独立记录，与审查结果互不影响，供下一轮参考（`srs/24-测试项与执行/04、07`）。
7. 问题单：当前只实现来源 DC 的正式单，开放/关闭/重开与整改说明，独立于审查结果（`issues.go`）；问题草稿独立，不进入正式统计（`quickissues`）。
8. 文档生成：未实现。DC 正文按 BCD 星实样进入 TD/回归说明的测试项/用例表、TN/回归记录的已执行用例表、报告叙述与审查文档清单表；审查单仅附录不计入审查内容，当前不做 DC 专用 DOCX（`srs/17/01`）。
