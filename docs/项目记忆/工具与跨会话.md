# 项目记忆：工具与跨会话

## 工具与跨会话

- 现象：设计或新增功能时先手写交互和数据结构，后续发现生态里已有成熟方案，返工成本高。原因：没有先检索项目内封装和开源成熟实现。规避方式：凡涉及设计与功能新增，先查项目内已有封装，再查 GitHub/官方生态的成熟方案并核对活跃度、兼容性和维护成本；确无成熟方案或改造成本过高才局部手写，并在 SRS 记录原因、边界和验证方式。
- 现象：只改一处组件或样式时，其他页面出现同类回归甚至布局崩坏。原因：改动前没有划分影响域，全局基础组件、共享组件和单页业务组件的边界没有确认。规避方式：每次改代码前先做影响域分析，确认改动目标属于全局基础组件、业务共享组件还是单页组件，再横向检查引用方；改动后按影响范围补验证。
- 现象：执行读取或验证命令时误把终端 shell 设置成 bash，导致 PowerShell 命令和 `$code` 变量未执行。原因：复制命令模板或连续调用时未检查当前执行器。规避方式：本项目默认且必须使用 `pwsh` 语义；Claude Desktop 中长命令走 Terminal 面板（PowerShell）或显式 `pwsh` 命令，Bash 工具只做只读短查询；仅在用户明确要求 POSIX、Git Bash 或 WSL 时才使用其他 shell。
- 现象：安装大型 GitHub skill 仓库时长时间停在 clone。原因：只需要单个 skill 但拉取了整个仓库。规避方式：优先轻量来源；确需精确安装时用 raw 文件或精确路径，并记录来源与版本哈希。
- 现象：新会话找不到上次全局任务备忘。原因：只查看了记忆根目录，没查 `extensions/ad_hoc/notes/`。规避方式：开工先读 `srs/12-跨会话记忆.md`，并用 `rg` 搜索全局记忆全目录。
- 现象：Windows curl 访问 GitHub 报证书吊销检查失败。原因：schannel TLS 的 OCSP/CRL 检查被网络环境阻断。规避方式：加 `--ssl-no-revoke`；列仓库树用 GitHub API。
- 现象：apply_patch 对含中文路径环境下的既有文件反复匹配失败。原因：工具在中文路径环境下的行为限制。规避方式：优先拆小补丁；必要时先读全文再整文件替换，并确保锚点唯一。
- 现象：PowerShell 双引号字符串中的中文弯引号导致 ParserError。原因：PowerShell 把 Unicode 弯引号识别为字符串定界符。规避方式：包含弯引号的文本用单引号字符串。
- 现象：PowerShell 双引号字符串中的反引号使 Markdown 内容损坏。原因：反引号是 PowerShell 转义符。规避方式：包含反引号、`$` 或需保持字面的内容用单引号字符串或字面 here-string。
- 现象：Go 测试文件引用其他测试文件辅助函数报 undefined。原因：`package api` 与 `package api_test` 是两个包。规避方式：共用测试辅助函数时统一测试包名。
- 现象：升级 Go 到 1.27.1 后 `go test` / `go vet` 可通过，但 `go build` 在 `internal/strconv` 报重复声明和未定义类型。原因：覆盖安装导致 `GOROOT/src` 混入不同版本标准库文件，测试缓存掩盖了部分问题。规避方式：不要覆盖旧安装目录；保留旧目录或换新目录解压完整发行包，用干净工具链执行一次真实 build 验证。
- 现象：npm install 后 `playwright-core` 从 `node_modules` 消失。原因：它原本是传递依赖且未显式声明，安装时被 prune。规避方式：项目实际使用的工具写入 package.json。
- 现象：在 `web/` 下用仓库根相对路径读写文件报不存在。原因：exec 工作目录随命令变化。规避方式：统一先切换到仓库根，或使用绝对路径。
- 现象：整页截图缩放后误判元素颜色。原因：缩略分辨率下色彩与位置混淆。规避方式：对可疑区域裁剪放大后再判断。
- 现象：重构后留下无人引用的 CSS Module 类名，构建、类型检查和 `oxlint` 都不报错，样式文件持续膨胀。原因：CSS Module 类名是运行时字符串，静态检查无法判断是否被引用。规避方式：全局整理时用脚本扫描——提取每个 `*.module.css` 的点号类名，再在 `web/src` 的 TS/TSX 里匹配 `styles.<类名>`（含 `styles["类名"]`），人工复核后删除零引用条目；`:global(.dark)` 这类全局选择器要排除，避免误删。
- 现象：Playwright 使用 Edge headless 模拟 `reducedMotion: reduce` 时，JS `matchMedia` 返回 true，但 CSS 媒体查询的计算样式可能不更新，曾导致验证结论不可靠。原因：该环境对 CSS 媒体特性模拟不稳定。规避方式：本项目已全站关闭 reduced-motion 降级（2026-11-08 用户拍板，`AnimateUIProvider` / `MotionConfig` 均为 `never`，CSS 中禁止再写 `prefers-reduced-motion` 分支），动效验收不再依赖模拟该系统设置。
- 现象：Edge/Chromium 中先框选静态文字，再继续拖动可能出现文字拖影，复杂工作区页面甚至无响应。原因：浏览器对已有文本选择启动原生 drag-copy 会话；大面积渐变、backdrop-filter 和业务表格会放大拖影重绘成本。规避方式：在应用根部的捕获阶段拦截非可编辑区域且有选中文字的 `dragstart`；复制统一走 `Ctrl+C`，输入框和文件拖入不受影响。
- 现象：用户要求开始工作或启动前后端时只启动服务，长期未检查依赖，错过最新稳定版和安全修复。原因：开工流程没有把全部依赖库检查列为强制步骤。规避方式：每次开工分别执行 `go list -u -m all` 和 `npm outdated`，覆盖 Huma v2 等全部后端 Go 库及全部前端 npm 库；有更新时先升级、更新锁文件并完成对应验证，再启动或重启服务。无更新时也在开工汇报中明确说明已检查。
- 现象：做 React 性能优化时只凭当前经验，漏用本机已安装的最新技能。原因：技能已安装但没有进入固定优化流程。规避方式：优化前先读取 `react19-concurrent-patterns` 和 `vercel-react-best-practices`，再按《21-前端性能优化策略》做生产测量、修改和验收；Next.js/RSC 专属规则只参考，不套用到 Vite SPA。
- 现象：下班时没有盘点本次使用的 skills，导致已安装技能长期不更新或代理擅自更新影响稳定性。原因：skills 更新决策没有纳入下班流程。规避方式：下班时列出本次实际使用的 skills，检查更新状态并提醒用户决定由代理更新还是用户更新；未获明确决定前不得升级、重装或删除 skills。
- 现象：OfficeCLI 处理过的 docx 会被 resident 进程锁住删不掉，或 Go 端读到修改前的旧内容（联调时表现为“解析出来是空文档”）。原因：`query` / `view` 等只读命令也会自动拉起 resident 并保持文件句柄；resident 生效期间写入延迟落盘。规避方式：集成调用必须显式 `close <file>` 收尾（Go 侧由 `officecli.Client.Close()` 统一封装）；非 OfficeCLI 程序读文件前先 `save` 或 `close`。
- 现象：解析 SRS 后提示“正文块未生成”，被误判成解析代码故障。原因：后端进程找不到 OfficeCLI 引擎时按设计降级为纯文本；本机 `officecli` 不在 PATH。规避方式：启动后端必须带 `OFFICECLI_BINARY` 指向引擎绝对路径（定位命令见 `srs/03-技术路线.md` 版本与更新节）；见到降级提示先查环境变量再查代码。
- 现象：OfficeCLI 更新到新版本后，旧版 MCP 配置启动失败（配置中硬编码的旧版本 `vendor\officecli.exe` 路径随 mise 升级被删）；或 `vendor` 只剩 `officecli.exe.download`，直接启动报 EBUSY 或文件不存在。原因：CherryStudio 的 mise 升级会删除旧版本目录；native 二进制由 npm postinstall 或 launcher 懒下载，下载中断只留 `.download` 残留；下载写入期间文件被写句柄占用，启动 exe 会报 EBUSY。规避方式：MCP 改用 `mise x npm:@officecli/officecli -- officecli mcp` 动态调用（`MISE_DATA_DIR` 指向 CherryStudio 工具链数据目录），不硬编码版本目录；升级后跑一次 `officecli --version` 触发懒下载并用官方 SHA256SUMS 校验；遇 EBUSY 等写入停止后重试。
- 现象：在 pwsh 里执行 `officecli` 提示命令不存在，误判 OfficeCLI 未安装并用 `npm i -g` 重装了一份，与 CherryStudio 工具链里的同版本并存。原因：本机正式安装走 CherryStudio mise 工具链（版本与引擎路径见 srs/03-技术路线.md），CLI 不在 PATH；npm 10+ 默认拦截 postinstall，npm 全局副本的安装脚本实际被跳过。规避方式：检查 OfficeCLI 版本用 srs/03 记录的引擎绝对路径，不使用 npm -g 安装；若已产生 npm 全局副本，及时卸载避免两份版本漂移。
- 现象：浏览器自动化点击报 `Input.dispatchMouseEvent` 超时，但点击其实已经生效；脚本重试后出现第二次落点，多弹出一个删除确认框。原因：In-app Browser 的 CDP 通道偶发抖动，超时只代表没拿到回执，不代表动作没执行。规避方式：报超时先截图或查 DOM 核对页面状态再决定是否重试；破坏性按钮的弹窗先读文案再确认；自动化会话失效（token 不可用）时用 getState/getTab 重新绑定已有标签，不要重复创建；只读 evaluate 沙箱不提供 performance、focus 等 API：长任务量测改用 CDP Runtime.evaluate 注入 PerformanceObserver({type:"longtask"})，其余量测改用 DOM 属性检查或定位器原生能力。
- 现象：Playwright 自动化清理夹具数据时清错对象（2026-10-12 实际清掉了 DC 项操作步骤，靠立即回填原文恢复）。原因：页面刷新 / 重载后树与列表的选中态会重置回默认项，脚本假设了上一次的选中还在。规避方式：清理或删除前先核对当前选中对象（断言目标文本或读选中态）再执行操作。
- 现象：按“原文精确替换”编辑 CSS Module 时匹配失败；PowerShell 把多行 here-string 组合进单条命令时抛 ParserError。原因：oxfmt 会重排样式文件（换行与缩进与写入时不一致）；PowerShell here-string 终止符必须独占行首且不能嵌套在同类 here-string 组合里。规避方式：文件操作统一在仓库根目录用同一套相对路径；替换前先读当前片段选唯一锚点，多行替换用数组 join 拼接而不是嵌套 here-string；改完跑 `npm run fmt` 与 `npm run check`。
- 现象：Claude Code 添加 GitHub 插件市场时 clone 超过 120s 超时（`early EOF`）。原因：GitHub 直连慢，且 Clash Verge 只运行了核心、系统代理与 TUN 未开启。规避方式：给命令设置 `HTTPS_PROXY=http://127.0.0.1:7897`（Clash Verge 混合端口）与 `CLAUDE_CODE_PLUGIN_GIT_TIMEOUT_MS=300000` 后重试；不需要改系统代理设置。
- 现象：npx 安装 `@developer.k/ms-office-mcp` 报 404。原因：本机 npm 默认阿里源（`registry.npmmirror.com`）元数据存在但缺该包 tarball。规避方式：该包单独加 `--registry=https://registry.npmjs.org`（可配合 Clash 代理），其余依赖继续走阿里源。
- 现象：MCP 服务器用 npx 冷启动超过 Claude Code 30s 健康检查，显示 `Failed to connect`；损坏的 npx 缓存还会报 `Cannot find module`。原因：npx 启动时校验并下载依赖，冷启动慢；上次安装中断可能留下不完整 `node_modules`（EPERM 清理失败）。规避方式：把 npm 包安装到固定目录（如 `~/.claude/mcp/<name>`），MCP 配置直接指向 `node <包入口>`；必要时清理 `%LOCALAPPDATA%\npm-cache\_npx\<hash>` 后重装。
- 现象：迁移期全局记忆、Claude 持久记忆与项目 SRS 出现三套口径。原因：迁移时只搬工具，没有约定记忆分工。规避方式：项目事实只写 `srs/12-跨会话记忆.md` 与 `docs/项目记忆/`；Claude 持久记忆只放用户画像、工具偏好与指针。
- 现象：仓库同时存在 `CLAUDE.md` 和 `AGENTS.md`，Claude 只读了 CLAUDE.md，AGENTS.md 里的铁律整体失效。原因：Claude Code 默认 Project instructions 为 `claude-md-or-agents-md`，工作目录及以上只要存在任一 `CLAUDE.md`，就不再读取 `AGENTS.md`；`.agents/` 目录同样不会被读取。规避方式：只保留 `CLAUDE.md`（正文可拆到 `.claude/rules/`）作为唯一规则源；若必须保留 AGENTS.md，就在 CLAUDE.md 首行写 `@AGENTS.md` 导入，并在新会话用 `/context` 确认 Memory files 中出现该文件。
- 现象：执行“删除第三方 Agent 全部内容”前只保留了会话最后几条消息，完整工作上下文随目录一起删除，无法恢复。原因：`Remove-Item` 不进回收站，删除前没有先导出会话索引与关键消息。规避方式：删除任何 Agent 数据前，先把会话索引、关键用户消息和未完成项完整导出到项目 SRS 或笔记，确认摘要覆盖未完成项后再删；迁移记录见 [srs/12](../../srs/12-跨会话记忆.md)。
- 现象：想用 OpenDesign 的设计能力时去查 daemon 的项目 / 技能清单，`list_projects` / `list_skills` 全为空，误以为本机没有设计参考。原因：OpenDesign 的技能随应用内置，不属于用户项目，daemon 只列出用户安装或项目级技能；用户的本意是借鉴这些内置技能。规避方式：直接读安装目录 `D:\programs\opendesign\resources\open-design\skills`（200+ 个技能目录，含 redesign-skill、taste-skill、web-design-guidelines 与 design-templates/dashboard 等），按任务挑 1–3 篇读规则即可，不运行 OpenDesign 生成，也不把技能复制进项目。
- 现象：打开 Claude Desktop Code 标签页看不到 `~/.claude/skills` 里的个人技能，误以为技能丢失。原因：个人技能由模型按名称 / 描述自动调用，不在 Code 标签页列成清单；插件技能和声明 `user-invocable: true` 的技能才显示为 `/` 命令。规避方式：用 `Get-ChildItem $HOME\.claude\skills` 检查，或直接让 agent 调用一个技能名验证；新会话会重新扫描。
- 现象：Claude Desktop Terminal 面板执行带中文路径的命令被 hook 拒绝（`characters outside printable ASCII`）。原因：`run_in_terminal` 只接受可打印 ASCII，防止审批卡显示与实跑内容不一致。规避方式：含中文路径的删除、脚本类操作改用 Bash 工具或先写 `.ps1` / `.cjs` 脚本文件再执行，命令行本身不出现中文。
- 现象：`npm run preview` 报 4173 端口占用，但 `curl 127.0.0.1:4173` 返回 000，误判预览没启动而重复启动失败。原因：vite preview 绑定 `localhost`（IPv6 `::1`），`127.0.0.1` 探测不到。规避方式：探测统一用 `http://localhost:4173`；提示端口占用即说明预览已在运行，直接复用。
- 现象：Bash 工具里执行 `fd` 报 command not found。原因：fd 与 mise shims 只挂在 PowerShell PATH，Git Bash 不继承。规避方式：文件检索用 Glob / rg 工具，或显式 `pwsh -NoProfile -Command` 执行 fd。
- 现象：内置浏览器面板截图偏淡、表格行空白，误判样式没生效。原因：面板标签隐藏时 `document.visibilityState` 为 `hidden`，rAF 暂停，GSAP 入场动画冻结在 opacity 0 / 0.78。规避方式：视觉与动效验收改用本机 Playwright（msedge channel；深色模式用 localStorage 预置 `theme=dark`），并断言页面无残留 opacity 为 0 的元素。
- 现象：`node -e "…中文…"` 反复报 Invalid string escape 或参数被拆散。原因：多层 shell 引号规则叠加中文字符。规避方式：含中文或多行的脚本先写 `.cjs` / `.ps1` 文件再执行，不用 `-e` 内联。
