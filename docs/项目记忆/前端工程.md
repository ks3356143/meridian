# 项目记忆：前端工程

> 返回 [项目记忆索引](../项目记忆.md)

## 前端工程

- 现象：全局 `Button` 传入 `disabled` 后只有部分内部逻辑生效，DOM 按钮仍可点击，表单校验失败也能触发提交。原因：组件把 `disabled` 从 props 中解构后漏传回渲染元素。规避方式：修改共享 Button 时必须检查透传 props；功能行为用自动化测试验证禁用态，视觉状态用截图由视觉模型确认，不能只看透明度样式。
- 现象：项目级 npm 安装脚本被拒绝。原因：当前 npm 启用了项目级脚本白名单。规避方式：在 `web/package.json` 的 `allowScripts` 中白名单确需脚本的包，再普通安装；不传 `--allow-scripts`。
- 现象：React Router 相关包升级出现 `ERESOLVE`。原因：相关包通过 peer dependency 互相约束。规避方式：把 `react-router` 及配套包改到同一版本后一次性安装，不用 `--force` 掩盖冲突。
- 现象：React Router framework mode 文件路由显示空内容。原因：把 Data Mode 的 lazy `Component` 约定误用到 framework `routes.ts` 约定。规避方式：本项目固定使用 Data Mode + `createBrowserRouter`。
- 现象：依赖变化后页面卡在加载态。原因：Vite 预构建缓存过期或重建中，控制台出现 `504 Outdated Optimize Dep`。规避方式：重启 `npm run dev`，等待 re-optimize 完成。
- 现象：开发服务冷启动后首次直接打开懒加载路由显示 500，刷新后恢复。原因：Lucide 图标在转换阶段才生成具体模块深路径，`optimizeDeps.entries` 只扫描到聚合入口，首访发现新依赖后重新预构建并与路由导入竞态。规避方式：在 `vite.config.ts` 的 `lucideDeepImports` 插件 `config` 阶段把源码用到的具体图标模块写入 `optimizeDeps.include`，同时保留 `optimizeDeps.entries` 扫描 `src` 和 `server.warmup.clientFiles` 预热源码；冷启动后等待预构建完成再访问。
- 现象：Vite 开发服务在 `5173` 监听，但 `http://127.0.0.1:5173` 被拒绝。原因：当前 Vite 默认只绑定 IPv6 `::1`。规避方式：联调访问 `http://localhost:5173`；确需 `127.0.0.1` 时配置 `server.host`。
- 现象：TypeScript 7 报 `baseUrl` 已移除。原因：TS7 删除该编译项。规避方式：删除 `baseUrl`，在 `paths` 中写相对 `tsconfig` 的映射。
- 现象：TanStack Table v9 用 v8 教程编译失败。原因：v9 改为 features 注册制，多个 API 改名。规避方式：按 v9 传入 `tableFeatures`、core/sorted row model 和对应类型参数；列助手也需要 features 类型。
- 现象：宽内容把 Grid 右列撑出视口。原因：`1fr` 隐式最小尺寸是 `min-content`。规避方式：主布局使用 `minmax(0, 1fr)`，表格容器用 `overflow-x-auto`。
- 现象：前后端冷启动后首次打开页面出现白屏。原因：Vite 开发模式按需编译，首次导航要请求并转换大量模块；`index.html` 的 `#root` 在 React 挂载前是空 DOM，`HydrateFallback` 只能覆盖挂载之后的加载。规避方式：`index.html` 内联零 JS 的预挂载首屏（React `createRoot` 接管 `#root` 后自动移除），并同步用预置脚本消除暗色主题闪白；生产构建首屏由代码分包和资源预加载覆盖。
- 现象：react-day-picker v10 日历 `captionLayout="dropdown"` 的年月下拉样式错乱。原因：v10 重构 DOM 和 classNames，shadcn v9 模板不能照抄。规避方式：使用 shadcn Select 年月头部 + 纯日期网格，保留 `mode="single"`，固定日历宽度和表格布局。
- 现象：React 19 开发环境反复提示 `Encountered a script tag while rendering React component`。原因：`next-themes` Provider 在客户端渲染内联 `<script>`，React 19 对组件树中的可执行 script 给出开发警告。规避方式：SPA 已由 `index.html` 内联脚本完成首帧主题初始化，给 Provider 传入非执行数据块类型，例如 `scriptProps={{ type: "text/x-theme-init" }}`，主题状态仍由 Provider effect 和本地存储维护。
- 现象：CDP `CSS.getPlatformFontsForNode` 对有子元素的节点返回空数组。原因：该接口只统计节点直接文本渲染的字形。规避方式：先找到包含目标文字的叶子元素再查询。
- 现象：React `memo` 在 80 行表格输入时完全失效，所有行每输入一次都重渲染。原因：父组件把合并后的新对象和未稳定的回调传给行组件，默认浅比较被引用变化击穿。规避方式：传服务端原始行 + 当前行补丁，用 `useCallback`/ref 稳定回调；必要时实现只比较渲染输出字段的行级比较器。
- 现象：`oxlint` 报 `react(set-state-in-effect)`，位置在“props 变化后同步本地状态”的 effect 里（回落筛选、写高亮 id）。原因：把由 props 派生的状态同步写进了 effect，触发级联渲染。规避方式：能直接派生的在渲染期派生（例如 `highlightedId = signal && visible ? signal.id : ""`）；确需一次性调整（筛选回落）用 React 官方“渲染期调整状态”模式并配去重标记，effect 只留早退分支；带时限的清理放到 `setTimeout` 回调里异步改状态，effect 内不同步 `setState`。
- 现象：`oxlint` 报 `jsx-a11y(click-events-have-key-events)` 和 `jsx-a11y(interactive-supports-focus)`，位置在 `react-arborist` 自定义 `renderRow` 行容器。原因：行容器带 `role="treeitem"` 与 `onClick`，可聚焦与键盘行为依赖库内部 `attrs.tabIndex`，静态检查看不到。规避方式：行容器显式补 `tabIndex={-1}`（与库内 `rowAttrs.tabIndex` 同值，不影响 roving focus）和 `Enter`/空格的 `onKeyDown`，与鼠标点击共用同一个选中函数；键盘事件不要 `stopPropagation`，保留库内方向键、展开与 `Enter` 编辑逻辑。
