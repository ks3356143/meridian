### 性能与加载

- 现象：需求树节点多时滚动明显掉帧（生产构建 425 行、窗口渲染 39 行时约 65-77ms/帧），但同一棵树的折叠/展开已经没有长任务。原因：树本身不是瓶颈——右侧候选审阅表没有虚拟化，317 行 × 约 20 格 ≈ 6300 个单元格常驻 DOM，任何整页样式重建都要把它算进去；A/B 实测把表格 `display: none` 后，树滚动从 77ms/帧 降到 17ms/帧。规避方式（树侧已做）：行内容按原始值 memo（react-window 每次滚动都会重渲染窗口内的行）、树行加 `content-visibility: auto` + `contain-intrinsic-size`、压掉 `min-width: max-content` 的固有宽度测量；表格侧的修复见下一条。
- 现象：需求树节点多时整页滚动掉帧（生产构建 425 行树 + 317 行候选表时约 77ms/帧）。原因：候选审阅表没有虚拟化，317 行 ≈ 6300 个单元格常驻 DOM，任何整页样式重建都要把它算进去（A/B：隐藏表格后 17ms/帧）。规避方式：给共享 `DataTable` 增加可选 `virtualized`（`@tanstack/react-virtual` + 上下 spacer 行，保留真实 table 布局与列宽），候选表开启后整页 DOM 10.4k→1.5k、树滚动 77→9ms/帧；列表"原文描述"列只渲染 80 字摘要（`TruncatedText` 新增 `tooltipValue`，悬浮看全文）、长文本列左对齐短文本居中；"章节"列宽 5.5rem→7.5rem；表格滚动容器撑满面板剩余高度（不留底部空白）并把滚动条统一成 8px 直角主题样式（原生白条会显得像空白）；列表与正文的分层方案见 `srs/23-数据加载与渲染性能.md`（全局契约）与 `srs/22-需求录入与解析/05-数据加载与渲染性能.md`（模块实施记录）。
- 现象：切换“已确认需求 / 待确认需求”标签页有卡顿；即使两个面板都 `forceMount`，首次切到待确认仍出现约 89ms 长任务。原因：非活动面板用 `display: none`，首次显示时 `ResizablePanelGroup`、虚拟树和表格才开始测量真实尺寸，触发一次布局/样式重排（实测布局 48ms、样式 30ms），不是 React 渲染本身。规避方式：需求页 Tabs 根容器改为单格 Grid，两个 `TabsContent` 叠在同一格；候选面板首次激活时先渲染 `QueryLoading` 骨架，用 `startTransition` 后台挂载重内容，提交后 `data-panels-ready=true`，之后两个面板常驻网格、切换只切 visibility。实测首屏只剩 1 次 78ms 长任务；候选首次挂载的 127ms+54ms 长任务落在骨架屏可见的 50–255ms 窗口内，之后切 TAB、点行、弹窗、批量编辑均 0 长任务。不要在首屏内容已可见后用 `requestIdleCallback` 预热隐藏面板，那会把 250ms 级冻结放到用户可见阶段；`hidden` 属性仍在，自动化查询需要 scope 到 `:visible`。
- 现象：需求页约 40 个树行 + 29 个表格行时，React Fiber 树约 1 万，点击行、打开弹窗、切 TAB 会产生 59–139ms 长任务。原因：每个 `TruncatedText` 单元格都各自挂一套 Radix `TooltipProvider`，且关闭态的 `TooltipContent`/Portal/Popper 也常驻，Radix 组件树随单元格数量膨胀。规避方式：`AppProviders` 只挂一个全局 `TooltipProvider`；`Tooltip` 只渲染 Root；`TruncatedText` 仅在 `open` 时挂 `TooltipContent`；共享 `DataTable` 的行用 `memo`，并传入 `renderVersion = table.options.columns`，列定义变化时强制行重渲染；需求树、Hero、详情、候选工作台、资料对象表按数据/状态 props memo。优化后生产环境切 TAB、点行、解析弹窗、切回、批量编辑均 0 长任务。副作用：Tooltip 关闭时 Content 立即卸载，退出动画会缩短；若要完整退出动画，应使用 Presence 做延迟卸载，不要恢复每格 Provider。
- 现象：即使关闭 React DevTools 扩展，`5173` 开发服务器仍比 `4173` 生产预览卡；打开 F12 更卡。原因：React 19 development 构建的 `createRoot` 会无条件设置 `ProfileMode`（`react-dom-client.development.js`），即使没有 DevTools 录制也记录每个组件的渲染耗时、props diff 和 `performance.measure`；Vite 开发服务器还提供大量模块、HMR 与 source map，F12 打开后要同时解析模块图和源码映射。规避方式：性能验收只使用 `npm run build` + `npm run preview`（4173），开发服务器只验证功能；减少组件/Fiber 数和重渲染可以减轻 dev 卡顿，但不能把 development 构建变成 production 构建。

- 现象：需求与追踪首屏虽然不卡，但开发模式 F12 模块图仍然很大，候选树/候选表相关代码首屏就要解析。原因：`requirements-candidate-tree` 和 `requirements-candidate-workbench` 被静态导入，`react-arborist`、TanStack Virtual、候选弹窗等进入首屏模块图。规避方式：用 React `lazy` + `Suspense` 拆成独立 chunk；候选 TAB 的 `pointerenter` / `focus` / `pointerdown` 预加载；首次激活用 `useTransition` + `QueryLoading` 骨架兜底，提交后再进入双面板单格 Grid。实测首屏 LCP `120ms → 76ms`、长任务 `78ms → 0`；首次激活 fallback 16ms 可见、57ms 长任务后 109ms 出表；首次激活后切 TAB、点行、解析弹窗、批量编辑均 0 长任务。

- 现象：`React.lazy` 拆分后 chunk 失败没有局部入口，HMR 可能保留旧 lazy 引用；Tooltip 退出动画变短；双面板 `visibility: hidden` 仍可能被键盘访问。规避方式：用 `LazyChunkBoundary` 捕获 lazy/chunk 错误并给出局部“重新加载”；需求布局模块变更时 `import.meta.hot.invalidate()` 整页失效；Tooltip 用 `mounted` 状态延迟 140ms 卸载保留退出动画；非活动 `TabsContent` 加 `inert`。开发工作流新增 `npm run preview:watch`（`vite build --watch` + `vite preview`，production React，改完手动刷新）。

- 现象：F5 刷新后首次悬停“待确认需求”TAB 再点击，Tooltip 仍会在切换瞬间上移或飘向页面顶部；普通点击、再次切换时反而不明显。原因：旧修复只重建触发器，没有消除中间布局态。首屏 `data-panels-ready` 由 `startTransition` 延后提交，而 `workbenchTab` 是紧急更新，首次点击会短暂渲染“已切到候选页但双面板尚未就绪”的状态，已确认面板仍走 `display: none`，Tooltip 的 reference 元素瞬间变成 0×0，Popper 按左上角重新定位；`hideWhenDetached` 也未开启，锚点脱离布局后仍按错误 rect 渲染。规避方式：新增 `panelsReady` 状态，与 `workbenchTab` 在同一次紧急更新中提交，`data-panels-ready` 改由它控制，使首次切换直接从单面板 `display: none` 进入双面板 `visibility: hidden`，不再出现中间布局态；候选重内容仍由 `candidateActivated + startTransition + QueryLoading` 控制，性能策略不变。TAB 内 Tooltip 同时传 `hideWhenDetached` 作为兜底，reference 一旦脱离布局就隐藏而不是重定位。验证：F5 后首次 hover → click，在 4× CPU throttle 下 Tooltip 始终保持原坐标直到 `closed` 淡出，全程未出现 0,0；不要再把“依赖当前 TAB 重建 Tooltip”当成该问题的唯一修复。


### 数据分层与表格

- 现象：需求列表瘦身、去掉完整 `description` 后，复制需求或打开详情/编辑时正文为空，用户会误以为解析丢了描述。原因：列表 DTO 只保留 `descriptionExcerpt/hasDescription`，复制链路仍假设列表对象带完整正文。规避方式：详情、候选编辑和复制都按需求 id 请求 `GET /api/v1/software-requirements/{id}/content`；详情 query key 用 `["software-requirements", id, "content"]`，保存成功后把单条响应写回该缓存，不依赖 Workbench 列表失效重拉。
- 现象：需求列表的“原文描述”列仍挂 hover Tooltip 时，表格 Fiber/Portal 数量随行数增长，长正文还会把完整文本带进渲染管线。原因：摘要列复用 `TruncatedText`，其 tooltipValue 仍持有完整正文。规避方式：该列直接渲染服务端 `descriptionExcerpt` 的纯文本 span，CSS 单行省略；Tooltip 只保留给章节、标识、名称等短字段，不要为了看全文在表格里挂 Portal。
- 现象：把需求搜索从前端改为服务端后，输入每次击键都请求搜索接口，候选表格还会丢掉来源文档名/版本等本地字段的匹配。原因：服务端搜索只覆盖章节、名称、标识、描述、标签，前端直接改成只认接口命中 id。规避方式：搜索 hook 统一做 220ms debounce + TanStack Query `keepPreviousData` + `staleTime`；候选表格用服务端命中 id 过滤正文/名称等字段，再叠加来源文档名、版本、sourceAnchor 的本地匹配；树搜索只保留当前可见树的命中 id，避免把其它状态的需求定位进来。
- 现象：详情或候选编辑弹窗按需加载正文时用 `useEffect` 同步 `draft`，触发 `react(set-state-in-effect)` 警告并可能多一次级联渲染。原因：异步 query data 被当成需要同步到本地 state 的外部源。规避方式：把表单拆成只在内容就绪后挂载的子组件，用内容作为 `key` 的初始化输入；加载态用带 `animation-delay: 250ms` 的骨架槽，内容未就绪时不挂表单，快速请求不会闪骨架。

- 现象：TanStack v9 列上写了 `meta.width`、`meta.hiddenUntil`，运行时却完全不生效，还出现 `as DataTableMeta` 断言。原因：列元数据没有通过 v9 的 `columnMeta` 类型槽注册，`meta` 被推断成空对象；`meta.width` 也没有任何消费方。规避方式：在 `table-features.ts` 中用官方 `columnMeta: metaHelper<DataTableColumnMeta>()` 声明列元数据；只保留真正被 DataTable 消费的 `hiddenUntil`，列宽改由 CSS Module 的列规则负责，禁止把未接入的 width 写进 meta。
- 现象：表格行用了 `memo`，但某些表每次渲染仍整表重绘。原因：`leftAlignedColumns` 由调用方传内联数组（如 `[1]`），每次都是新引用，memo 浅比较必然失败。规避方式：DataTable 内部把 `leftAlignedColumns` 归一化为按 join 签名缓存的 `Set`，行组件只接收稳定 Set；调用方可以继续传数组，但不要把这个归一化责任散落到每张表。
- 现象：共享 DataTable 逐渐堆入没有调用方的 `rowClassName`、`virtualized.height`、`virtualized.overscan` 等配置。原因：为假想需求保留灵活性，实际只有候选表使用 `rowHeight`。规避方式：shared 组件只暴露有真实调用方的能力；需要第二套配置时再按实际场景增加，避免未使用的 props 进入 memo 比较和文档口径。
- 现象：重要功能按钮的高光扫过效果被复制到不同业务 CSS Module，角度、时长和透明度容易不一致。原因：缺少共享能力，复制实现逐步漂移。规避方式：统一使用共享 `<Button sheen>`；光泽实现集中在 `Button.module.css`，业务组件只传 `sheen`，禁止重复伪元素和渐变；`prefers-reduced-motion` 下关闭扫光。


## 测试项树工具栏在默认宽度撑出横向滚动条（2026-10-20）

- 现象：测试项 TAB 左侧目录默认 380px 宽时，底部出现一条横向滚动条，工具栏看起来比目录宽一截。
- 原因：工具栏内“新增测试项 / 从需求创建 / 新建文件夹 / 两个静态操作 / 轮次芯片”总宽 388px，父面板 `overflow-x: auto` 把差值变成滚动条；轮次在右侧详情 Hero 已经展示，芯片属于重复信息。
- 规避方式：给 `.treePane` 声明 `container-type: inline-size`，在 `@container (max-width: 420px)` 下隐藏 `.roundChip`；不要直接给工具栏加 `overflow: hidden`，否则窄屏会丢失操作入口。改完用 `scrollWidth - clientWidth` 和截图同时验收。


## 共享 DataTable 的横向滚动有两层容器（2026-10-22）

- 现象：375px 下项目、用户、字典表格仍被压成窄列，表头和数字只能逐字显示；虽然页面没有横向滚动，但内容不可读。
- 原因：`Table` 自带 `[data-slot="table-container"] { overflow-x:auto }`，外层页面没有参与；同时表格仍是 `width:100%; table-layout:fixed`，没有最小宽度，所以浏览器继续压列而不是滚动。
- 规避方式：共享 `DataTable` 在非虚拟化分支补一个仅用于作用域和测试定位的外层，720px 以下把内部真实 `[data-slot="table"]` 设为 `min-width:42rem`；虚拟化分支也使用同一规则。验收要看表格内部横向滚动、文档根节点无横向溢出，并截图确认 ID、状态、操作列仍可读。

## 表格行入场 transform 触发瞬时纵向滚动条（2026-10-22）

- 现象：从项目首页切到字典配置、用户管理时，表格右侧会闪出一小会儿纵向滚动条，表格宽度随之缩一下，页面像跳了一帧。
- 原因：共享 `Table` 内层 `[data-slot="table-container"]` 只有 `overflow-x:auto`；按 CSS 规则另一轴会计算为 `auto`。行入场从 `translateY(3px)` 开始时，表格临时多出 3px 纵向溢出，浏览器显示 17px 滚动条并压缩内容宽度。
- 规避方式：该容器明确设置 `overflow-y:hidden`，纵向滚动交给页面或显式外层；验收时在入场动画 0–180ms 内读取 `scrollHeight - clientHeight` 和 `offsetWidth - clientWidth`，必须没有滚动条宽度差（只剩 1px 边框）。



## 自动化点击会污染 4x CPU 长任务测量（2026-10-23）

- 现象：4x CPU 下用 Playwright `getByRole(...).click()` 连续切测试项和分区，长任务出现 985–1013ms；同一页面改用 DOM 事件派发点击后，最大长任务只有 55ms。
- 原因：Playwright 点击会先把目标滚进视口，而页面自身又在做 `scrollIntoView({ behavior: "smooth" })`；两套滚动互相拉扯，`click()` 单次耗时可达 10s，期间统计到的长任务属于自动化与平滑滚动叠加，不是 React 渲染。
- 规避方式：测交互长任务时用 `page.evaluate(() => el.dispatchEvent(new MouseEvent("click", { bubbles: true })))` 或先关掉平滑滚动；报告前必须同时给出 1x 与 4x 两组数据，1x 出现长任务才是真问题。参考基线：测试项页 1x 0 条，4x 最大 55ms。
