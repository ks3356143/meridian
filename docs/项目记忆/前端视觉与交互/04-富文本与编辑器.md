### 正文编辑器与调试

- 现象：保存“测试项的需求描述”时 Dialog 几乎立刻关闭，用户看不到保存反馈，也不确定正文是否已落盘；若把刷新阶段放在 Dialog 内又会拖慢关闭感知，并在保存后残留脏状态。原因：保存、关闭和详情刷新没有拆成清晰阶段，编辑器初始化/主动 update 还会误触 dirty。规避方式：`保存中…` 阶段保留 Dialog 并显示按钮 spinner、编辑器临时只读；保存成功后立即关闭 Dialog，在“测试项的需求描述”卡内显示“正在刷新正文…”覆盖态和 `aria-busy`，直到详情 query 刷新完成；刷新期间禁用“编辑正文”。保存成功必须清除 `bodyDirty` 并忽略 busy/关闭后的编辑器内部 update，禁止随后切换需求时再次弹“正文尚未保存”。

- 现象：网络慢或主线程忙时，用户点击后界面仍停在旧状态，容易把加载 waiting 误判为系统卡死。原因：交互状态被设计成“请求成功后再提交”，加载态又遮住了旧界面，用户看不到任何已确认反馈。规避方式：执行乐观交互铁律——先提交本地可见状态（选中、展开、切页、缓存写入、乐观条目），再用 pending / `aria-busy` / spinner 表示同步中；服务端返回后 reconcile，失败原子回滚并给出重试。加载态只说明“正在同步”，不替代即时反馈，禁止让用户猜测点击是否生效。

- 现象：Playwright MCP 页面一旦渲染进程卡死，后续 `browser_*` 调用会持续等待，代理也会跟着长时间停住。原因：浏览器进程失去响应时，MCP 调用没有业务级超时，默认等待时间过长。规避方式：任一 `browser_*` 调用超过 15–20 秒未返回就按卡死处理；按 `--user-data-dir` 找到 `mcp-msedge-*` 根进程并强制结束，重新打开 `about:blank` 恢复。测试脚本内的 `goto`、`click`、`waitFor` 全部显式设置短超时，禁止 300 秒级无界等待。

- 现象：正文编辑弹窗改成原生 `<dialog>` 后打开、关闭没有动画，和项目其他 Radix Dialog 不一致。原因：`showModal()` / `close()` 默认直接切换 `display`，没有 Radix 的 `data-state=open/closed` 动画阶段。规避方式：原生 dialog 必须补 `@starting-style` + `transition-behavior: allow-discrete`，与标准 Dialog 统一为 220ms `cubic-bezier(0.32, 0.72, 0, 1)` 的淡入淡出 + `scale(0.97)` + 下移 8px；关闭时 `display:none` 要等退出动画结束。右上角 X 使用标准 DialogClose 的 1.75rem 细边框方形按钮样式。

- 现象：需求正文很长时“编辑正文”按钮随卡片头滚出视口，要手动回滚到顶部才能编辑；把卡片头改成吸顶后，吸顶栏上方又漏出半行被裁的表格内容。原因：卡片头原本没有吸顶；吸顶后滚动容器 `.body` 用 `padding-top` 留白，而滚动内容的裁剪边是 padding box——内容会穿过顶部内边距区域，12.8px 的 padding 条变成内容露出带。规避方式：卡片头 `position: sticky; top: 0` + 不透明背景（`var(--card)`）+ `z-index`；唯一滚动容器的顶部间距改由首个子元素 `margin-top` 承担，禁止在滚动容器上用 `padding-top`，否则任何吸顶元素上方都会漏出滚动内容。吸顶状态需要让用户看得出来时，在卡片内挂 1px 哨兵并用 `IntersectionObserver`（`root` 为该滚动容器）判定，禁止监听 `scroll` 逐帧算位置；吸顶态换主色玻璃底（`color-mix` 主色 14% + `card` 92% 透明 + `backdrop-filter: blur(10px)`，透明度低于 0.93 时表格线会透过吸顶栏显脏）、标题转主色深调、左竖线加高、主按钮由实心切描边，过渡统一 0.26s 并在 `prefers-reduced-motion` 下关闭。验证方式：滚到正文中部与底部，读取吸顶头 `getBoundingClientRect().top` 与滚动容器 `top` 相等且截图无内容露出；真实滚轮上下滚动全程 `PerformanceObserver` 收到的 longtask 必须为 0（实测 0 条）。

- 现象：正文题注与表格的字号/间距在只读预览和编辑器里各写一份，改一处另一处不同步（两次出现「预览与编辑器不一致」）。原因：CSS Module 里样式挂在 `p[data-variant]` / `table` 等元素选择器上，无法跨文件 `composes`，只能复制声明。规避方式：抽共享模块 `requirement-body-content.module.css`，规则写成 `.surface p[data-variant=…]` / `.surface table`，两个容器（预览 `.viewport`、编辑器 `.proseMirror`）都 import 同一 module 并挂 `.surface` 类——容器差异（滚动容器、上下留白、单元格对齐机制、选中态）留在各自 module；共享规则特异度 `.surface` + 元素 + 属性 = (0,2,1)，能稳定压过 `.proseMirror p` 这类 (0,1,1) 基础规则。


## 内联编辑器要非受控，否则 Ctrl+Z 失效（2026-10-10）

- 现象：在内联单元格里全选删除后按 Ctrl+Z，内容回不来（原生撤销栈被清空）。
- 原因：编辑器写成受控（`value={draft}` + `onChange`），React 在每次渲染后把 `value` 写回 DOM；浏览器只在"值由用户输入产生"时才积累撤销记录，程序化写值会让撤销栈失效。
- 规避方式：编辑框改**非受控**（`defaultValue={value}`），实时值存 `draftRef`（提交读 ref，`draft` 只服务高度计算/重排）；**编辑框还要常驻 DOM**（展示态/编辑态用 `data-editing` 切 `display`，不要条件渲染卸载），否则每次重进都是新元素、原生撤销栈照样归零；只在"外部真的改了值"时才写回 DOM（进入编辑时 `if (el.value !== value) el.value = value`），提交后重进不写值，撤销历史才能跨会话保留。


## 光标落点跟随点击（2026-10-10）

- 现象：点单元格任意位置进入编辑，光标总在末尾（textarea 反而在开头），用户想改中间的字得先按方向键。
- 原因：进入编辑是"用另一个控件替换展示态"，输入框自己的点击位置与展示态点击点无关；早期为统一 input/textarea 的默认差异，显式 `setSelectionRange(len, len)`。
- 规避方式：点展示态时用 `document.caretPositionFromPoint` / `caretRangeFromPoint` 把点击坐标换算成字符偏移（仅接受落在文本节点上的结果），存 ref，聚焦时 `setSelectionRange(offset, offset)`；键盘激活（`event.detail === 0`）没有坐标，回退到末尾。


## blur 同步提交会吃掉相邻单元格的点击（2026-10-17）

- 现象：用例步骤富文本单元格，一个编辑器开着时点相邻单元格，第一次点击只退出旧编辑器、不进入新编辑，要点两次。
- 原因：mousedown（新单元格）→ blur（旧编辑器）→ 同步 `setState` 提交让旧格从编辑态切回展示态，行高变化导致本次点击的 mouseup 落点偏移、click 丢失；工具栏内嵌在编辑态里（占内容流）会放大这个高度差。
- 规避方式：① blur 提交改为 `setTimeout(commit, 0)`，让 click 先完整派发；② 编辑态工具栏**浮出**（`position: absolute; bottom: 100%`）不占内容流，编辑/展示态行高保持一致。


## 富文本单元格 focus 时文字 / 行高微动（2026-10-18）

- 现象：点击「输入及操作 / 实测结果」后文字上移约 0.2px；实测结果含表格时整行缩约 4.6px，第二张表上移约 4px。
- 原因：展示态 `RequirementBlocks` 段落是 `line-height: 1.8`，Tiptap `.ProseMirror` 继承 1.7；编辑态多一层 `EditorContent`，外框和 1px 补偿却挂在 `editorWrap`；预览每个块有 0.15rem 节距、`tableWrap` 有 0.1rem 底距，编辑态 `.tableWrapper` 没有同等间距。
- 规避方式：`EditorContent` 用 `display: contents`；`.ProseMirror` 自身承担与展示态完全相同的 `min-height` / padding / 1px 边框 / `line-height: 1.8`；块间统一 `margin-bottom: 0.15rem`，`.tableWrapper` 补 `padding-bottom: 0.1rem`。用 `getBoundingClientRect` 验收：单行段落 rect、两张表 top、行高在 focus 前后完全一致。不要再用补 1px 或 auto height transition 掩盖。


## contenteditable 回车换行不能用 textContent 读取（2026-10-18）

- 现象：期望结果输入两行后保存，重新打开变成一行。
- 原因：Chromium 的 `contenteditable="plaintext-only"` 回车生成 `<div>` / `<br>`，`textContent` 只拼接文本节点，不包含块级换行。
- 规避方式：提交、自动编号、回填统一读 `innerText`，并统一 `\r\n` 为 `\n`；空值判断用 `trim()`，否则清空后残留的 `<br>` 会产生 `"\n"`。


## Tiptap 富文本“打开即关闭”不能按原始 JSON 判脏（2026-10-18）

- 现象：只点开步骤富文本单元格、不改内容再点走，也会发 `PUT .../blocks`，保存 spinner 闪一下并触发步骤列表刷新。
- 原因：Tiptap 加载时会给节点补齐默认 attrs（如 `align` / `firstLineIndent` / `variant`），`editor.getJSON()` 与后端原始 `doc` 的 `JSON.stringify` 不相等；用两者对比必然误判为有改动。
- 规避方式：编辑器挂载完成后记录一次 `baselineRef = JSON.stringify(editor.getJSON())`，失焦提交时与 baseline 比较；`changed=false` 时只退出编辑，不调用 `onSave`。真实输入后仍按原链路保存，清空回 baseline 也不会发空请求。


## 富文本单元格点击后光标总在末尾（2026-10-18）

- 现象：实测结果里有表格，点击某个单元格进入编辑后，光标总落在整个富文本文档末尾，而不是点击的表格单元格/文字位置。
- 原因：编辑器挂载时无条件执行 `setTextSelection(editor.state.doc.content.size)`，展示态点击坐标没有传入编辑态，ProseMirror 无法知道用户点在哪里。
- 规避方式：展示态点击时记录 `clientX / clientY`，编辑器挂载完成后用 `editor.view.posAtCoords({ left, top })` 得到文档位置并 `setTextSelection`；返回 null 或键盘激活时再回退末尾。表格内文本需实测 `window.getSelection().anchorOffset` 随点击位置变化，不能只看编辑器是否获得焦点。


## 富文本首次拖选选区丢失 / 绿色高亮闪一下（2026-10-18）

- 现象：输入及操作、实测结果首次拖选文字后，选区消失；修好后绿色 `::selection` 仍会闪一下。
- 原因：展示态 DOM 在 mouseup 后被编辑器替换，原实现只按 mouseup 坐标设置 caret，没有保留拖选首尾；选区在 `useEffect` 里才写入，首帧会先画无选区；编辑态背景还有 0.15s 过渡，使半透明选区底色跟着变化。另一个隐藏原因是先 `setTextSelection` 再 `focus()`——focus 会把浏览器默认光标写回，rAF 轨迹里能看到 2 帧 collapsed。
- 规避方式：展示态同时记录 mousedown / mouseup 坐标，编辑器挂载后用 `posAtCoords` 取 anchor/head，在 `useLayoutEffect` 首帧绘制前**先 focus、再 setTextSelection({ from, to })**；编辑态 background 不做过渡。验收用 rAF 轨迹逐帧检查：从展示态切换后第一帧就应同时满足 `pmFocus=true` 且选区文本非空；随后 Ctrl+X / Ctrl+Z 可正常剪切和撤销。


## EditableCell 换成 contenteditable 后遗留 input 选择器失效（2026-10-18）

- 现象：测试项标识后缀只剩一个 42px 小盒，和 `XQ_SU_` 前缀脱节，难以点击编辑。
- 原因：`.identCell input { width: 7rem }` 仍按旧 `<input>` 写；`EditableCell` 改成 `div[contenteditable]` 后选择器匹配不到，宽度退回内容宽度。
- 规避方式：给 `EditableCell` 传业务 className（如 `identEditor`）并作用在外层 wrapper 上；组件迁移后全局搜索旧标签选择器，不要只改组件实现。
