# 项目记忆：03-表单与组件

## button 默认 text-align:center 会把弹性盒子里的文字顶到中间（2026-10-10）

- 现象：需求描述手风琴行里"需求名称"明明用了 `flex:1 1 auto`，文字却显示在行中间偏右，看着像右对齐。
- 原因：`<button>` 的 UA 默认样式是 `text-align:center`；弹性子项占满剩余宽度后，文字在盒子内部被居中。
- 规避方式：凡是按钮内部要靠左排的文字容器（名称、标题、说明）显式写 `text-align:left`；本项目的 `.display`（单元格展示态）与 `.accordionName` 都已标注原因。


## 错误提示不要重复弹（2026-10-10）

- 现象：改测试项类型被服务端拒绝时，同时出现两条内容相同的 `sonner` 错误 toast。
- 原因：`web/src/api/client.ts` 的 `request()` 已对所有非 2xx（含网络错误）统一 `toast.error(detail)`；业务层 catch 里再弹一次就成双份。
- 规避方式：业务层只在需要"保持弹窗打开 / 回滚 / 记状态"时 catch，不再自行弹 toast；确需自定义文案时传 `skipErrorToast: true` 并由业务层接管提示。


## Button asChild 当卡片/列表行会被固定尺寸卡死（2026-10-17）

- 现象：项目列表「风险与活动」卡与「待执行用例」行出现文字被裁剪、上下留白失衡、两行文字重叠。原因：`Button asChild` 的 Link 继承了 `Button.module.css` 里未分层的 `height: 2rem`、`padding-top: var(--btn-text-shift, 1px)`、`line-height` 与 `overflow: hidden`，而 `h-auto` / `py-2.5` 这些 Tailwind 类在 `@layer utilities` 里优先级天然低于未分层 Module，覆盖失败——内容（两行 36px）塞不进 32px 高、被 `overflow: hidden` 裁掉。
- 规避方式：**卡片、列表行这类非按钮尺寸的容器不要用 Button asChild 底座**，直接用 `Link` + 业务 CSS Module（本项目 `risk-activity-bar.module.css` / `todo-panel.module.css`）；排查「样式莫名不生效」时先确认是不是未分层 Module 盖掉了 @layer 内的工具类（同口径见「Tailwind v4 utilities 属于独立 layer」条目）。


## 页面级快捷键必须按焦点作用域隔离（2026-10-18）

- 现象：测试项树选中一行后，焦点移到右侧详情按钮再按 `Delete`，仍弹出“删除用例”确认框；`F2` / `Ctrl+D` 也会在详情区误作用于树节点。
- 原因：全局 `keydown` 只检查了当前编辑控件（`input / textarea / contenteditable`），没有检查焦点是否真的在树内；`treeRef.current?.focusedNode` 会保留上一次树焦点，页面其他区域按键也会命中。
- 规避方式：页面级树快捷键必须先判断 `event.target.closest('[role="tree"]')`，焦点离开树就立即返回；只有焦点作用域成立后，才读取 `focusedNode` 执行重命名、删除或复制。


## disabled button 不能触发 Radix Tooltip（2026-10-18）

- 现象：步骤上移/下移在禁用时悬停没有任何提示，用户不知道为何不可点；用例上一条/下一条同理。
- 原因：原生 disabled 按钮不派发 pointer 事件，Radix TooltipTrigger 直接包 button 时收不到 hover/focus。
- 规避方式：TooltipTrigger 改为包一个非 disabled 的 `span` 包装层，button 放在 span 内并保留 `aria-label` 与 disabled；包装层只负责 tooltip 命中，不改变点击语义。


## `::selection` 不能通过 padding 增高（2026-10-19）

- 现象：即时输入框选中文字的高亮上下偏紧，想给编辑器加 1–2px padding 改善。
- 原因：`::selection` 只绘制文本行框，编辑器的 padding 不参与选区绘制，给 `::selection` 写 padding 也不会生效。
- 规避方式：保持 `.editor` 单行总高 40px，把 `line-height` 18px → 22px、垂直 padding 11/9 → 8/8 对消；同时用 `.editor::selection` 的 26% 主色背景提高可见度。若需要更厚的单行高亮，只能自绘选区，不做。


## 深色模式下已勾选 Checkbox 变成“空框”（2026-10-20）

- 现象：深色主题里 `aria-checked="true"`、`data-state="checked"`，但复选框仍是灰底空框，勾选图标看不见。
- 原因：共享 Checkbox 的 `dark:bg-input/40` 覆盖了 `data-[state=checked]:bg-primary`，根节点计算背景仍是深色；同时 `text-primary-foreground` 是深色，浅色勾选图标也被换成深色，形成暗底暗字。
- 规避方式：共享 Checkbox 必须补 `dark:data-[state=checked]:bg-primary` 和 `dark:data-[state=checked]:text-primary-foreground`；验收时用计算样式确认勾选态背景是品牌绿、前景色与品牌色有足够对比，不能只看 `data-state`。


## 工作台控件必须保持同一种可交互语言（2026-10-20）

- 现象：人员指派只有透明背景、无边框的“未指派”文字和一个小箭头，和只读文本几乎一样，用户第一眼不认为可以点击；同时同一张用例表中的表格标签、编辑框、人员选择器使用了三套不同强度的界面语言。
- 原因：人员选择器触发器使用了 `border: 1px solid transparent` 和透明背景，只在 hover 时出现反馈；而表格 label 与 `EditableCell` 各自维护独立样式，缺少统一的控制面、hover 轨道和焦点层级。
- 规避方式：工作台控件统一采用浅渐变面、可见 1px 边框、hover / focus / open 时出现语义色左侧刻线和轻光晕；人员选择器增加固定人员图标、32px 触发器高度和空态虚线边框；表头用顶部主色线，行标签用左侧主色线。所有状态只改颜色、边框和阴影，不位移、不改行高，并补 reduced-motion。


## 外部状态控制的 Dialog 不会自动找回触发焦点（2026-10-22）

- 现象：用户管理、删除确认等弹窗由页面级 state 打开而不是 `DialogTrigger`，关闭后焦点丢到 `body`，键盘用户不知道当前位置。
- 原因：Radix 只有在使用 `Trigger` 时才知道保存和返回哪个触发元素；纯受控 Dialog 没有这层关系。
- 规避方式：共享 `DialogContent` / `AlertDialogContent` 在 `onOpenAutoFocus` 记录 `document.activeElement`，在 `onCloseAutoFocus` 中恢复仍连接的节点；调用方若主动 `preventDefault()` 则尊重调用方决定。验收要覆盖“打开后首个字段聚焦 + Escape 关闭后返回原按钮”。

## 页面头部不能用 overflow:hidden 裁掉操作按钮焦点环（2026-10-22）

- 现象：键盘 Tab 到 `PageHeader` 右上角主按钮时，按钮只有底色变化，看不到完整 focus ring；鼠标点击时更难发现。
- 原因：PageHeader 为裁切背景网格给根节点加了 `overflow-hidden`，按钮右边缘与根节点齐平，2px outline + 2px offset 被裁掉。
- 规避方式：PageHeader 根节点用 `overflow: clip; overflow-clip-margin: 6px`，既阻止背景光晕扩大文档滚动宽度，又给 2px outline + 2px offset 留出绘制余量；装饰层继续 `pointer-events:none`。验收用键盘 Tab 到最后主操作，确认文档根节点无横向溢出且焦点环四个方向均可见。

## 给 data-slot=input / select-trigger 写 Tailwind 焦点阴影是死代码（2026-10-22）

- 现象：在 `input.tsx` / `select.tsx` 的 `focus-visible:shadow-[...]` 里加内嵌左轨，浏览器计算出来的 `box-shadow` 仍是全局的三层焦点环，改动完全看不见。
- 原因：`web/src/styles/field-state.css` 对 `[data-slot="input"]`、`[data-slot="select-trigger"]`、`[data-slot="composite-input"]` 的焦点/错误态写了未分层的 `!important` 阴影；Tailwind 工具类属于独立 layer，优先级天然更低，`--tw-shadow` 变量虽然被写好也不会进入最终 `box-shadow`。
- 规避方式：输入类控件的焦点与错误视觉一律改 `field-state.css`（唯一事实源），不要在组件里再叠工具类。错误态阴影有多层且在 keyframes 里插值，层数与顺序必须与基础态一致；要加新层必须同时改基础态、focus、错误、reduced-motion 和三个 keyframe，否则动画会跳变。


## 图标按钮的前侧竖条和下划线内缩（2026-10-22）

- 现象：绿色“+”按钮和富文本工具栏的“正文段落”状态按钮被看成“不是正方形”，用户还要求去掉按钮前面的浅色竖条；测试项详情的“基本信息”活动下划线两端各空出约 6.7px，没有占满整个 Tab。
- 原因：主按钮 `::before` 加了 2px `--primary-foreground` 竖条，图标按钮本身是正方形时视觉重心被这条竖条带偏；下划线写了 `left: 0.42rem; right: 0.42rem` 的内缩。另有隐藏来源：需求树“新增确认需求”在容器查询里只改 `padding-inline`，文字收起后得到 28.7×32 的非正方形。
- 规避方式：主按钮不加前侧竖条，状态只靠底色、描边和单次高光表达；活动下划线一律 `left:0; right:0` 贴满控件；任何“文字收起后变图标”的按钮必须在同一断点里把宽度对齐高度（本次用 `width:2rem` 对齐 `size=sm` 的 2rem），工具栏图标按钮用 `min-width:1.75rem; padding-inline:0` 对齐 `size=xs`。验收直接量 `getBoundingClientRect()`，宽高差 < 1px 才算方形。
