# 项目记忆：02-动效与反馈

> 返回 [前端视觉与交互索引](../前端视觉与交互.md) · [项目记忆索引](../../项目记忆.md)

## 步骤工具栏出现 / 消失没有动画（2026-10-18）

- 现象：点击富文本单元格时工具栏瞬间出现，失焦/ Esc 时瞬间消失。
- 原因：工具栏跟随编辑器条件挂载，React 直接卸载节点，CSS 没有进入和退出状态。
- 规避方式：工具栏进入用 `@starting-style` + `transition: opacity/transform 150ms cubic-bezier(...)`；退出时 `StepRichCell` 先置 `closing`，150ms 后再卸载编辑器。`prefers-reduced-motion` 下关闭过渡并直接切换。


## `prefers-reduced-motion` 规则被后置基础动画覆盖（2026-10-20）

- 现象：开启系统“减少动态效果”后，顶栏流光视觉上不可见，但 `getComputedStyle(::after).animationName` 仍是 `workspace-topbar-sweep`，浏览器继续跑循环动画。
- 原因：reduced-motion 媒体查询写在基础 `.workspace-topbar-beam::after` 规则之前，同特异度下后置的 `animation` 声明胜出；`opacity: 0` 只是把动画藏起来。
- 规避方式：reduced-motion 覆盖规则必须放在对应基础动画之后，或提高选择器特异性；验收时同时检查 `animationName === "none"`，不能只看截图。


## 条件挂载会吃掉高度 transition（2026-10-21）

- 现象：批量选择操作条 CSS 已写 `max-height / opacity / transform` 过渡，但勾选复选框时仍是一整块高度瞬间出现；取消选择时也瞬间消失。
- 原因：父组件在 `selectedCount > 0` 时才挂载操作条，第一次渲染已经直接进入展开态，没有 `0 → 1` 的起始帧；卸载时 DOM 立即移除，也没有退出帧。只写 transition 不等于会产生动画。
- 规避方式：需要双向高度动画的面板常驻挂载，由父级条件只切换 `data-visible`；外层用 `display:grid` + `grid-template-rows:minmax(0,0fr) → minmax(0,1fr)`，内层 `min-height:0; overflow:hidden`，配合透明度与不超过 4px 的轻位移。隐藏态加 `visibility:hidden`、`pointer-events:none` 和 `inert`，避免隐藏控件进入键盘顺序；不能用固定 `max-height` 猜高度，也不能直接 transition `height:auto`。同类需求折叠面板已同步为 `minmax(0,0fr)`，reduced-motion 直切。


## Radix TabsContent 首屏会内联禁用动画（2026-10-22）

- 现象：给共享 `TabsContent` 写了 180ms 淡入，首屏 active 面板的 `getComputedStyle(...).animationDuration` 仍是 `0s`，但切到另一个 Tab 后同一动画正常为 `0.18s`。
- 原因：Radix `TabsContent` 在首次挂载时给内容节点写入内联 `animation-duration: 0s`，用于阻止首屏入场动画；该内联样式只在后续重渲染时清掉，不会在 mount effect 后主动触发一次渲染。
- 规避方式：不要和 Radix 的内联时长硬抢首屏动画；把共享 TabsContent 动画定义为“后续 Tab 切换入场”，验收时必须实际切换一个 Tab 再看计算样式。若产品确实要求首屏面板动画，应在 `TabsContent` 内部再包一层自有节点并对内层做动画，不能删掉 Radix 的内联防闪逻辑。


## 同一伪元素不能同时承担 Tab 下划线和扫光（2026-10-22）

- 现象：工作区一级导航 active 态只有底部一条 2px 线，写在 CSS Module 里的整面渐变扫光完全看不到；公式上 opacity 已是 1，但视觉像没有动画。
- 原因：共享 `TabsTrigger` 已用 `::after` 绘制活动下划线，业务自定义又占用了同一个 `::after`，两层声明互相覆盖，并且自定义伪元素缺少 `position:absolute` / `display:block`，最终高度为 0。
- 规避方式：共享下划线固定保留 `::after`；业务扫光改用 `::before`，并显式补齐 `position:absolute; inset:0; display:block`。验收同时读取两个伪元素的计算高度：下划线约 2px，扫光必须覆盖整个 Trigger 高度。


## 悬浮展开按钮不要 transition 宽高和内边距（2026-10-22）

- 现象：需求详情右下角“创建测试项”悬浮按钮 hover 时从图标位展开成文字按钮，视觉上能用，但每帧同步改 `width / max-width / gap / padding`，属于布局动画。
- 原因：组件把折叠和展开当成盒子尺寸变化处理；绝对定位只能避免影响兄弟节点，不能避免自身反复布局和绘制。
- 规避方式：按钮始终保留展开后的固定盒宽，收起态用 `clip-path: inset(0 0 0 calc(100% - 2rem))` 只露出右侧图标区；hover / focus 时 clip 展开，图标与文字只做 transform / opacity。加 `outline-offset:-2px` 防止 clip-path 裁掉焦点环，reduced-motion 下直切。

## root View Transition 会淡入旧页面滚动条（2026-10-22）

- 现象：首页切字典/用户时，右侧旧页面滚动条在过渡开始的一瞬仍可见，随后淡出，看起来像滚动条闪现并导致跳动。
- 原因：侧栏导航启用了原生 View Transition，`::view-transition-old(root)` 对整页截图做交叉淡入；旧页面截图包含当时的文档滚动条，而目标页高度更短、滚动条消失。
- 规避方式：业务路由不要对 root 做整页 View Transition；移除 `NavLink viewTransition` 和 root 截图规则，只保留 `main` 的 240ms 内容淡入。侧栏、顶栏和 `html` 的 `scrollbar-gutter: stable` 保持不动。

## Tab 下划线扫光结束后留下深色渐变块（2026-10-22）

- 现象：工作区一级导航 active 下划线闪光结束后，线内仍有一段偏深的绿色/亮色拼接，看起来像背景里残留一块脏色。
- 原因：把主色深浅渐变直接当整条下划线背景，并用 `background-position` 扫动；动画结束位置仍在可见区，最终状态不是纯主色。
- 规避方式：下划线底色保持纯 `var(--primary)`，高光单独用一层透明→白色→透明的窄 `background-image`；动画起点和终点都把高光移出 2px 可见区，终态只剩均匀主色线。光晕控制在低强度，不再叠加 inset 底线。



## Line Tab 底轨被 border-bottom 抬起（2026-10-23）

- 现象：工作区一级 Tab、项目详情和字典页的绿色活动线看起来没有贴住 Tab 栏底边，下面还露出一条浅色缝。
- 原因：`TabsList` 同时使用 `border-bottom` 和 Trigger 的 `::after` 活动线，`bottom:0` 对齐的是边框内侧；项目详情与字典页最初都存在约 1px 的垂直偏差，横向滚动时边框底色还会随内容移动。
- 规避方式：`line` 变体的容器边框设为 0，底轨用固定在容器底边的 `background-image` 绘制；Trigger 的 `::after` 保持 `bottom:0`。验收同时读取容器与活动 Trigger 的 `getBoundingClientRect().bottom`，差值应为 0，并在 390px 横向滚动后复测底轨仍覆盖可视区。


## 字体就绪回调和 ResizeObserver 需要取消标记（2026-10-24）

- 现象：快速切换工作区 Tab 或调整窗口后，旧 Tab 可能被重新滚入视野，活动指示器偶尔回到上一个位置。
- 原因：effect 的 cleanup 只断开 ResizeObserver，没有取消已经挂起的 `document.fonts.ready.then(...)`；旧闭包仍会在字体就绪后执行，并读取旧的 active key。
- 规避方式：在 layout effect 内声明 `cancelled`，字体回调和 ResizeObserver 回调开头统一检查；cleanup 先置 `cancelled = true` 再断开 observer。同一模式适用于滚动定位和实测指示器。


## DialogContent 加 position: relative 会覆盖 Radix 固定定位（2026-10-24）

- 现象：快速切换弹层在长页面里出现在视口底部，甚至被页面滚动带着走，而不是居中悬浮。
- 原因：共享 `DialogContent` 依赖 Tailwind 的 `fixed` 定位；业务 CSS Module 给同一个节点写了 `position: relative`，同层后写规则覆盖了固定定位。
- 规避方式：不要在 `DialogContent` 本体上改 `position`。需要伪元素时直接利用它已有的 fixed 定位上下文；确需自定义定位，使用更高层包裹节点，不能用 relative 抢掉 Radix 的 fixed。


## 全局命令面板不能叠开第二个模态（2026-10-24）

- 现象：字典或编辑弹窗打开时按 `Ctrl+K`，会在已有模态之上再打开快速切换，形成两层焦点陷阱与遮罩。
- 原因：全局键盘监听只判断了快捷键和编辑器焦点，没有检查当前是否已有 `role="dialog"` / `role="alertdialog"` 模态。
- 规避方式：用 `openRef` 区分自身打开状态；自身未打开时优先检查共享 `DialogContent` / `AlertDialogContent` / `SheetContent` 的 `data-slot` + `data-state="open"`，再用 `[role="dialog"][aria-modal="true"]` / `[role="alertdialog"][aria-modal="true"]` 做兜底，命中任一条件就忽略快捷键；自身打开时仍允许 `Ctrl+K` 关闭。仅查 role 在本项目 Radix 实测会漏掉，任何新的全局命令面板都必须按 data-slot 优先保护。
